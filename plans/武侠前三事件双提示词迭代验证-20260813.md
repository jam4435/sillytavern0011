# 武侠前三事件双提示词迭代验证（2026-08-13）

## 固定测试方法

- 真实前端使用 `--restart-from-first-reply` 回到第一条 assistant 回复，每个新版本推送世界书后重新加载，再只重生成这一条 assistant swipe。
- 首个计数样本必须在 `main-input` 和 `variable-input` 分别命中 COT/变量指导的唯一版本标记。
- 首回复之后的每条 user 输入均且仅为 `合理推进剧情`；没有输入日期、地点、事件名或预定行动。
- 发现事件或持久变量的重大错误就停轮；不在提示词中硬编目标时间或目标剧情。

## v28–v30 实测

### v28：首次最小三段闸门

- COT：`E2E-EA3-v28-首次最小三段闸门-20260813`
- 变量：`VAR-E2E-v28-首次三段结果校验-20260813`
- 修改：首次要求 3–6 段，并要求最后一段保留事件末尾必要结果。
- 失败：E1 仍只输出两段；正文已明说高宗，标签却将“曲三点破高宗”留为未进行。变量模型正确判定冲突并拒绝坐标。
- 证据：`wuxia-e2e-ea3-v28-run1-first-regenerate-20260813.json`

### v29：固定三段+核心事实

- COT：`E2E-EA3-v29-固定三段核心事实-20260813`
- 变量：`VAR-E2E-v29-固定三段核心校验-20260813`
- 修改：改为恰好三段（开端关键行动｜核心推进｜必要结果）；正文出现原定主语+核心动词+对象后，该段不得仍为未进行。
- 结果：E1 首回固定三段、正文/状态/时间相符；第二回正确演完 E1，但又输出了一次行动行，审计也误写模式 A。
- 证据：`wuxia-e2e-ea3-v29-run1-first-regenerate-20260813.json`、`wuxia-e2e-ea3-v29-run1-turn01-20260813.json`

### v30：前序开标签模式锁（当前候选）

- COT：`E2E-EA3-v30-前序开标签模式锁-20260813`
- 变量：`VAR-E2E-v30-前序与当前分离校验-20260813`
- 修改：模式不再依赖模型解释“完整历史标签”。只要当前 user 之前的任一 assistant 出现同名短开标签，主模型必须用模式 B；变量模型只在【前序只读完整轮次】做该判断。
- 版本命中：首回 `main-input` 含 COT v30，`variable-input` 含 VAR v30。
- E1：首回恰好三段；第二回正确使用模式 B，输出 `<射雕第一回01>已完成｜已完成｜已完成</射雕第一回01>`；13:00 结算，结局原定，未提前演 E2。
- E1→E2：唯一输入 `合理推进剧情`；正文明写“两个时辰”，变量模型按 4 小时从 13:00 推至 17:00，本回未演 E2，结束后调度器启动 E2 的弹性窗口 17:00–21:00。
- E2：首回恰好三段，正文完整演出郭杨夜猎撞见、曲三杀三名官兵、揭示身世和盗宝缘由、赠金壶/金杯；21:00 结算，结局原定，未演 E3。
- 变量侧轻微问题：E2 完成回合中，变量模型直接把原定事件快照同步到角色数据，而不是完全等事件系统结算。最终快照中只有一份经历/物品/关系，值与原定快照一致，未形成重复键或数值冲突，故记录为未导致最终状态错误的流程瑕疵。
- 证据：`wuxia-e2e-ea3-v30-run1-first-regenerate-20260813.json`、`wuxia-e2e-ea3-v30-run1-turn01-20260813.json`、`wuxia-e2e-ea3-v30-run1-after-e1-inspect-20260813.json`、`wuxia-e2e-ea3-v30-run1-transition-e2-20260813.json`、`wuxia-e2e-ea3-v30-run1-e2-start-inspect-20260813.json`、`wuxia-e2e-ea3-v30-run1-e2-turn01-20260813.json`、`wuxia-e2e-ea3-v30-run1-after-e2-inspect-20260813.json`。

## 当前阻塞：第一轮存档的调度日期与当前源数据不一致

按用户要求，发现这类问题后停止，不用 COT/变量指导截断时间或强制选事件。

- 当前世界书源文件：E3 为 1200/12/10 19:00–21:00；E4 为 1200/12/10 22:00–12/11 02:00。
- 当前前端生成的 `src/武侠/data/事件信息汇总.json` 和 `src/事件脚本/generated/event-data/manifest.json` 也都为 12/10，且运行时存档的 `manifestHash` 与当前 manifest `contentHash` 同为 `b6618829482330a4e9c376f03ab1637014abe04d108fd7058116af126e3f7b86`。
- 但从“回到第一轮”恢复的该聊天 `stat_data` 内，未发生 E4 仍保存为 1200/12/05 22:00，比 E3 的源触发日期早五天。
- 证据位置：`wuxia-e2e-ea3-v30-run1-after-e2-inspect-20260813.json` 的世界时间是 1200/08/15 21:00，已完成 E1/E2，参与事件为空；其“未发生事件”中 E4 是 12/05 22:00。
- 影响：继续只用 `合理推进剧情` 推进时，这条存档很可能先触发 E4，从而在 E3 前演出后续事件。这会让测试结果失去意义。
- 判断：当前条目文件本身不是 12/05；问题是第一轮存档中的事件调度数据没有随当前 manifest 重建。“回到第一轮”恢复了旧的第一轮状态，并不等于按当前源数据新建了一份调度状态。
