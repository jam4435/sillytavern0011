# 六部原文历史事件资料续跑

本轮由 Codex 负责程序、规划与验收，dsh 的 CodeBuddy `buddy / deepseek-v4.1-flash` 负责原文语义判断。原任务日志、旧批次文档、世界书、预加入事件与 src 均保持原状，所有新文件集中在本目录。

## 已执行的程序盘点

旧批次 Markdown 中共有 1741 个卡片标题，包含拼接中间文件和重复副本。按文件身份选取 12 份主批次文档、倚天 `_body.md`、笑傲后半部三个分片后，得到 1501 张候选卡，无重复旧 ID。其余中间副本不直接重复计入成果。

程序从六部 UTF-8 原文逐字定位每一段引文，保留嵌套引号，不忽略短于八字的片段，不去除标点，也不将模糊匹配当作通过。自然对话中的省略号先作为原文字面匹配，只有整段不匹配才按摘引省略拆段。当前 1491 张可精确定位、10 张存在歧义或引号/引文问题。恢复副本已由程序重建位置字段，85 张与旧命中行不同。以上仅是引文验收，不能替代事实或差分验收。

机器清单位于 `inventory/`；生成副本位于 `recovered/`。旧卡的 ID 只在其来源文件内标识记录，新流程以“相对路径#旧ID”为稳定键，避免跨批引用混淆。

## 执行顺序

1. **程序盘点与回归检查**：冻结语料 SHA-256、旧文件 SHA-256、章节区间和全部卡片键；执行本目录测试，验证错误标点、伪造短引文、歧义位置、缺字段、越界证据都不会误判通过。
2. **小规模真模型试跑**：用此前缺口最大的鹿鼎开篇验证路由、空工具清单、单步限制、JSON 完整性和证据切取；再选择有旧卡的天龙片段验证旧卡验收。真实回执写入 `runs/*.events.jsonl`。
3. **原文全覆盖与旧卡语义验收**：先补鹿鼎、倚天、笑傲缺口，再审已有天龙、射雕、神雕。每章按完整行切成至多约 16000 字符的窗口，当前章内队列 599 批。跨章节证据只作为有明确来源的补充窗口，不继承任何上一会话历史。卷首与附录另列覆盖，不将目录扫描算作阅读。
4. **差分**：程序从现有原文件读取完整正文。当前有 2421 份文档，包含人物登场记录和 24 份背景文本，均保留参与检索，区别于旧索引宣称的 2354 条。程序检索、排序候选，模型对照完整候选正文判断“已有完整节点、部分已有、只有讲述、只有结果、未找到匹配、证据不足”。每事件最多给 8 份完整候选，候选截断与检索词必须写进回执，检索无命中不能宣称全库已经证明缺失。
5. **跨批、跨书去重与汇总**：相同引文、相似题名和共享人物只生成去重候选，语义上同一历史事实才合并；不同时间的讲述场景和真正过去事件分开处理。统一输出事件表、来源证据、差分表、覆盖表与未完成清单。

## 每批执行限制

- 必须通过仓库 `scripts/run_task.py` 启动 dsh 的 `headless` profile，提示词经临时 YAML 文件传递。模型、provider 均固定，不使用聚合路由或其它模型回退。
- 思考档使用本模型支持的 `low`。校准中 `high` 和 `low` 都曾耗尽 12000 上限而无正文，故将总输出上限改为 32768 以容纳推理与 JSON。成功试批不要求用满此上限。
- 每批是全新 Session，工具调用集合为空，最多一个模型步骤，最多 32768 输出 tokens，进程超时 300 秒。进程失败、JSON 不完整或配额错误都记录并停止控制器，不自动重试；校准期的手工修正均保留独立回执。
- 提示词不超过 52000 字符；下一批开始前，累计已记录 tokens 加 90000 的保守预留不得超过 1500 万。达到预算即停止并保留续跑位置，不擅自扩大预算。
- 模型只返回真实行号和短定位锚，程序检查该锚属于本批供给的原文，再切取最多 120 字的原文引文、生成列号/回次和语料哈希。不得让模型凭记忆重写引文或自行“修正”行号。
- 每个结果分别标明机械验收、模型语义验收与差分状态。模型给出的覆盖声明和事实判断仍属于模型审阅结果，不伪称人工独立复核。
- 文件写入由控制器执行。每批先写持久化回执和结果，再更新 `queue.json`；已验收批次不因续跑重复执行。控制器锁防止两个进程同时推进同一队列。

## 运行方式

在本目录执行 `python -X utf8 pipeline.py inventory` 做程序盘点，`python -X utf8 -m unittest test_pipeline -v` 做引文验收回归，`python -X utf8 differ.py` 建完整正文基线。

首次生成队列使用 `python -X utf8 orchestrate.py prepare`。已有队列应保留，续跑使用 `python -X utf8 orchestrate.py run --limit 1 --books 鹿鼎记` 或其它明确的小批次范围。`python -X utf8 orchestrate.py status` 返回聚合状态与累计用量。

完整控制器为 `supervise.py`，启动时检查旧输入哈希，再串行推进原文、差分和去重队列。`supervisor-state.json` 记录 PID、阶段、停止原因和用量；`deliverables/进度.md` 在每批后更新。需要暂停时在本目录创建名为 `PAUSE` 的文件，控制器完成当前请求后停止，不丢弃已完成批次。再次启动前保留所有结果与队列，只处理待执行项。

失败批次由规划者读取结构化结束原因后安排修正；不原地续接旧 Session。尚有失败、待修或未覆盖窗口时，报告明确列为未完成，不宣称六部提取已完成。
