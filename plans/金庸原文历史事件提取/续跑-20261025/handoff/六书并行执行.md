# 六书并行原文寻找

首批真实六书并行已通过 `accept_parallel_trial.py` 验收，详见 `parallel-trial-acceptance.json`：六个独立Session、请求重叠峰值6、指定路由、单步0工具、正常结束、所有结果严格重验通过，原文覆盖及未选任务未变。试批新增176966 tokens，累计2114875；随后已启动持续六书并行，PID及日志见 `parallel-controller-launch.json`。启动前为78/606个窗口 reviewed、528 pending、871条事件记录、45张旧卡完成本轮模型审阅；其中鹿鼎72/124、天龙2/114，射雕/神雕/倚天/笑傲各完成1个窗口。这些数字是启动前快照。

用户于2026-10-25授权通过 dsh 并行寻找各书尚未完成的历史事件。并行前最近汇总显示鹿鼎记已审69/124、天龙八部1/114，射雕英雄传0/89、神雕侠侣0/87、倚天屠龙记0/96、笑傲江湖0/96；这些是窗口数量，既不是章节数，也不是最终事实验收数。实时进度以工作目录 `queue.json`、`supervisor-state.json` 和 `deliverables/progress.json` 为准。

执行仍固定为 `buddy / deepseek-v4.1-flash`、low、单步、0工具、每调用新Session，保留32768输出tokens及300秒超时。原始任务输入、输出和回执仍写各自唯一调用ID。模型负责语义工作，控制器负责规划调度、精确引文和程序验收。

`parallel_source.py` 按书名选择最多六个任务，每本书只取队列中第一个 pending 窗口，书内顺序不变。所有提示词和原文哈希先通过检查，再由六个线程各启动独立 dsh 进程；线程只写独立调用文件，主线程统一更新结果和活动队列。整个并行批持有 `.controller.lock`，supervisor 持有 `.supervisor.lock`，从而阻止其他控制器重复推进。

每个调用沿用90000 tokens预留，一次六调用预留540000。批次开始前根据全部历史回执用量一次决定可提交数量，不分别使用六份预算。所有已发出的调用收齐后才计算累计用量、汇总资料或执行精确坐标修复；批次进行中的状态用量是最近已结算批次的数值。`handoff/parallel-waves/` 逐批保留任务ID、预留、用量和各个终态。

一条调用失败不会抹掉其他已发出调用的结果。主线程收齐它们，保存失败和用量后停止下一批。唯一逐字匹配的错行可以按既有流程修复；改写锚、歧义匹配及截断仍需处理，不自动重试或提高输出上限。`PAUSE` 在当前整批收齐后生效，不能作为立即中断已发出调用的指令。

先验收一批：`python -X utf8 -B supervise.py --parallel-books 6 --source-waves 1`。验收真实路由、Session独立性、单步0工具、完整结束、证据结果和共享预算后，持续执行使用 `python -X utf8 -B supervise.py --parallel-books 6`。已有进程或锁时不能启动另一份。原文寻找全部结束后仍由同一supervisor串行推进完整正文差分和跨书去重。

执行前25项单元测试通过，覆盖既有证据规则、精确任务选择、证据修复和锁所有权、每书一任务、整批预算限制、并发重叠、单写入者、一失败后收齐其他结果、重复控制器拒绝、限一批停止，以及修复拒绝时不启动模型。测试命令：`python -X utf8 -B -m unittest test_pipeline test_orchestrate test_repair_pending test_parallel_source -v`。

并行不会把 `reviewed` 改成人工独立语义审计；差分、跨书去重、事件独立性和来源可信度的待核限制继续保留。最终世界书YAML、人物快照和预加入事件文件不在本阶段修改范围内。
