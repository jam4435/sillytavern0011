# 武侠事件条目时长审计

## 结论

本次递归审计 `世界书` 下文件名含“事件条目”的 630 个事件：

| 指标 | 数量 |
| --- | ---: |
| 成功解析 | 630 |
| 解析失败 | 0 |
| 原始标注时长不超过 2 小时 | 567 |
| 三个并行分片初判：明确过短 | 118 |
| 三个并行分片初判：较可能过短 | 4 |
| 严格事件边界复核后剔除 | 16 |
| 最终保守确认 | 102 |
| 最终较可能 | 4 |

因此，“事件详情所需叙事时间明显长于事件时间窗”的保守问题数是 **102 条**；若把没有精确时间词、但存在明显长途移动的 4 条也计入，候选总数是 **106 条**。

按作品划分：

| 作品 | 保守确认 | 较可能 |
| --- | ---: | ---: |
| 射雕 | 25 | 2 |
| 神雕 | 77 | 2 |

保守结果中，标注时长不超过 2 小时的有 93 条确认项和 4 条较可能项，共 97 条。其余 9 条虽然原时间窗超过 2 小时，仍短于详情明确写出的数日、数月或半年。

## 用户报告条目

`射雕第7回-03-黑松林解围` 是明确问题：

- 标注时间窗：1219-10-20 16:00 至 18:00，共 2 小时。
- 详情先写侯通海在客店约郭靖“次日”赴黑松林，随后才写赴约和黄蓉解围。
- 这不是回忆或背景介绍，而是同一条详情内的连续因果过程，必然跨到翌日。

## 判定口径

并行子任务只拿到提取后的 `触发条件`、`事件结束时间`、`事件详情`，各自复核 210 条。初判完成后又按更严格的事件边界复核：

- 保留：本条当前动作明确跨夜、跨日、持续数月，或单个动作已超过标注时长。
- 剔除：条目开头单独用于承接上一条的“次日/次晨”。
- 剔除：`已经`、`连日来`、`传了大半年` 等只解释当前状态的既往背景。
- 剔除：仅计划“明日”行动、但本条并未实际叙述到明日。
- 降为“较可能”：没有精确时间词，但“朝行晚宿”等远距离移动不可能在一两小时内完成。

这个口径刻意偏保守；102 是明确矛盾项，不是所有可能需要重新编排时间线的条目总数。

## 产物与复现

提取脚本：

```text
scripts/audit-wuxia-event-durations.mjs
```

复现命令：

```bash
node scripts/audit-wuxia-event-durations.mjs \
  --event-dir 世界书 \
  --output-dir plans/武侠事件时长审计 \
  --shards 3
```

主要产物：

- `extracted-events.json`：630 条完整三字段、标注时长和统计。
- `review-shard-01.json` 至 `review-shard-03.json`：三个等量复核分片。
- `assessment-shard-01.json` 至 `assessment-shard-03.json`：并行初判。
- `qc-shard-02.json`、`qc-shard-03.json`：严格边界复核记录。
- `conservative-adjudication.json`：最终保守合并结果。

本轮没有修改任何世界书事件条目。若要修复，应先按连续剧情段制定时间锚点并确认，再批量改写和验证，避免只把单条结束时间机械延长后造成后续事件重叠。
