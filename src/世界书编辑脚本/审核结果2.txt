## 二、新发现的问题

### 新问题 1：导航列表 ID 与现有代码不一致（中等风险）

**描述：** v2 第 36 行将导航列表 ID 写为 `id="ai-workspace-desktop-nav-list"`，但现有代码 `buildDesktopShellMarkup()` 第 2255 行使用的是 `id="ai-workspace-mobile-nav-list"`（类名为 `ai-nav-list`）。`syncNavigationState()` 与 `bindEvents()` 中引用的是 `#ai-workspace-mobile-nav-list` 及 `.ai-nav-list`。若实施时按 v2 字面采用 `ai-workspace-desktop-nav-list`，将导致移动端导航展开/折叠逻辑失效。

**解决方案：** 实施时保留现有 ID `ai-workspace-mobile-nav-list`，或同步更新 `syncNavigationState()`、`setMobileNavExpanded()` 等所有引用。建议在 v2 中明确标注此 ID 保留原值。

### 新问题 2：导航按钮内层结构新增 `<span>` 图标，与现有 markup 不一致（低风险）

**描述：** v2 第 39-42 行导航按钮结构为 `<button class="ai-mode-nav-button"><i class="fa-solid ..."></i><span>直接修改</span></button>`，而现有 `buildDesktopShellMarkup()` 第 2266-2274 行的按钮结构为 `<button class="ai-mode-nav-button"><span>${item.label}</span>${item.key === 'generate' ? '<small>敬请期待</small>' : ''}</button>`，无 `<i>` 图标，且 generate 项有 `<small>` 子元素。新增图标需同步修改 `NAV_ITEMS` 数据结构以包含图标字段，并保留 generate 项的 `<small>` 标记。

**解决方案：** 实施时在 `NAV_ITEMS` 中新增 `icon` 字段，并在 `buildDesktopShellMarkup()` 的 map 中渲染 `<i>` 与 `<span>`，同时保留 generate 的 `<small>` 逻辑。v2 应补充 `NAV_ITEMS` 数据结构变更说明。

### 新问题 3：助手按钮结构与现有代码不一致（低风险）

**描述：** v2 第 52-57 行将助手按钮放在 `.ai-nav-footer` 内，使用 `data-ai-open-assistant-tab="chat"`；现有代码第 2259 行的助手按钮位于 `.ai-mobile-menu-title` 内，同样使用 `data-ai-open-assistant-tab="chat"`，但外层结构不同。此外现有代码第 2251 行还有一个 `id="ai-workspace-open-assistant"` 的按钮在 `.ai-nav-title` 内。v2 未提及 `#ai-workspace-open-assistant` 的处理。

**解决方案：** 实施时需确认 `#ai-workspace-open-assistant` 的绑定逻辑是否迁移到新结构，或保留原 `.ai-nav-title` 内按钮。建议 v2 补充说明两个助手按钮的归属与绑定保留情况。

### 新问题 4：预览区列宽 35% 在窄屏未声明切换布局（低风险）

**描述：** v2 第 250 行 `grid-template-columns: minmax(300px, 35%) 1fr`，在窄屏（<600px）下 300px 最小宽度仍可能挤压右侧详情区。现有代码 `ensureStyles()` 第 2497 行在 `@media (max-width:900px)` 下将 `.ai-result-grid` 切换为 `grid-template-columns:1fr`（上下布局）。v2 未明确说明新 `.ai-preview-layout` 在窄屏下是否同样切换为单列。

**解决方案：** 实施时在 `@media (max-width:900px)` 断点下为 `.ai-preview-layout` 补充 `grid-template-columns:1fr` 规则，与现有 `.ai-result-grid` 响应式行为保持一致。

### 新问题 5：`max-height: 65vh` 仍含 vh 单位（低风险，可接受）

**描述：** v2 第 254 行预览区 `max-height: 65vh` 仍使用 vh 单位。虽然作为上限（而非固定高度）风险较低，但项目规则明确"禁止使用 vh 单位等会受宿主高度影响的单位"。在 iframe 中 vh 参照 iframe 视口，通常与容器高度一致，实际影响较小，但严格而言仍违反规则。

**解决方案：** 可将 `max-height: 65vh` 改为 `max-height: 600px` 或其他固定值，或保留但注明此为上限且在 iframe 内 vh 与容器高度一致、影响可控。此问题不阻塞实施。

### 评价

v2 修订方案针对第一轮提出的全部问题进行了系统性修复，核心策略调整为"**保留现有 ID 和关键类名，新增 `modern-*` 样式类**"，从根本上规避了 HTML 结构大规模重构带来的 JS 选择器失效风险。具体亮点：

3. **功能区域补全完整**：步骤指示器、调试信息区、回滚面板、操作按钮区、Instruction/Planning/Generate 页面均已补全，与现有 `buildResultMarkup()`、`buildInstructionMarkup()`、`buildPlanningMarkup()`、`buildGeneratorMarkup()` 对应。
4. **响应式与 iframe 适配合规**：移除 `calc(100vh - 200px)` 固定高度，改用 `flex-grow` + `min/max-height`，补充中等屏幕断点。
5. **ensureStyles() 处理策略清晰**：保留、选择性覆盖、独立注入三段式策略，降低实施风险。

### 新问题风险等级

新发现的 5 个问题中，新问题 1（导航列表 ID）为中等风险，需在实施时明确保留原 ID；其余 4 个为低风险，可在实施时顺手处理，不阻塞方案落地。
