世界书编辑脚本 - 修改计划（修订版）
更新日期：2026-03-06

说明
- 本计划已根据二次审视结果重排，并补齐关键实现决策，目标是让后续执行不再需要临场拍板。
- 实施顺序调整为：2 -> 6A -> 4 -> 3 -> 7 -> 1 -> 5 -> 6B。
- 关键决策已经锁定：
  - 回退功能拆为 `6A` 和 `6B`，先做高风险事务回退，再做完整 undo/redo。
  - AI 调用统一走酒馆 `generate()` 能力，并通过 `custom_api` 接外部模型接口。
  - 文件夹不复用酒馆原生 `group` 字段。
  - 文件夹持久化采用“元数据条目”方案，插件默认隐藏，并在主题/设置中提供显示开关。
- 每项完成后执行基础检查：`pnpm build`，并做主流程手工冒烟。

测试安排

==================================================
改进项 6A：高风险事务回退
==================================================
目标
- 先为高风险写操作提供“一次事务可回滚”的安全网，不做完整多步 undo/redo。

范围
- 覆盖以下操作：
  - 批量修改
  - 批量删除
  - AI 改写
  - 复制覆盖
  - 文件夹元数据写入

代码级修改计划
1. 新增事务回退模块
- 文件（新增）：`modules/features/history.js`
- 建议导出：
  - `beginMutationTransaction`
  - `commitMutationTransaction`
  - `rollbackLastTransaction`
  - `getLastTransactionMeta`

2. 在状态层增加单次事务快照
- 文件：`modules/state.js`
- 修改点：
  - 为每本世界书维护最近一次成功事务快照。
  - 快照内容包括：
    - 条目数组快照
    - 元数据条目快照
    - 时间戳
    - 操作类型

3. 接入统一 mutation 层
- 文件：`modules/api.js`
- 修改点：
  - 在统一 mutation 包装器中加入：
    - 操作前取快照
    - 操作成功后标记为最近可回滚事务
    - 操作失败时自动丢弃快照

4. 接入 UI
- 文件：`modules/ui/list.js`、`modules/commands/titleBarCommands.js`、`modules/events.js`
- 修改点：
  - 工具栏新增“回滚上一步高风险操作”按钮。
  - 无“重做”。
  - 当无可回滚事务时禁用按钮。

测试安排
A. 直接功能测试
- 批量开关后回滚。
- 批量删除后回滚。
- 复制覆盖后回滚。
- AI 改写后回滚。
- 文件夹移动导致的元数据变更后回滚。

B. 耦合影响测试
- 模块：`ui/list.js`
  - 回滚后虚拟列表、计数、筛选状态正常。
- 模块：元数据条目
  - 回滚同时恢复元数据条目内容。

改进项 3：调用 LLM API 实现单个/批量修改条目
==================================================
目标
- AI 实际调用统一走酒馆 `generate()`，并利用 `custom_api` 接外部模型。

锁定决策
- 不直接自行 `fetch` 外部 OpenAI 兼容接口。
- 调用统一依赖酒馆助手 `generate()`。
- 外部 provider 配置由插件管理，并注入到 `generate({ custom_api })`。

代码级修改计划
1. 新增 AI 客户端模块
- 文件（新增）：`modules/features/llmClient.js`
- 职责：
  - 封装 `generate()` 调用
  - 注入 `custom_api`
  - 统一处理超时、空响应、格式错误

2. Provider 配置与设置
- 文件：`modules/settings.js`、`modules/ui/theme.js` 或单独新增设置面板
- 修改点：
  - 增加以下配置：
    - `apiurl`
    - `key`
    - `model`
    - `source`
  - 默认 `source` 为 `openai`
  - 提供“使用酒馆当前默认模型 / 使用自定义外部接口”切换

3. 响应解析
- 文件：`modules/features/aiActions.js`
- 修改点：
  - 约束模型返回 JSON。
  - 若返回非 JSON，先走提取与修复逻辑。
  - 修复失败则报错，不落库。

4. 批量并发控制
- 文件：`modules/features/aiActions.js`
- 修改点：
  - 批量执行并发固定为 2。
  - 每条失败最多重试 1 次。

测试安排
A. 直接功能测试
- 自定义外部接口生成成功。
- 未配置 key 或 model 的报错提示。
- 空响应、非 JSON、超时、单条失败、批量部分失败。

B. 耦合影响测试
- 模块：`generate()` 集成
  - 静默生成不污染主聊天。
- 模块：`ui/editor.js`、`ui/contentEditor.js`
  - AI 改写后手工继续编辑不冲突。

改进项 1：条目文件夹功能新增
==================================================
目标
- 实现单层文件夹，并持久化到世界书内部的“元数据条目”中。

锁定决策
- 不使用酒馆原生 `group` 字段保存文件夹。
- 文件夹第一版是单层，不支持嵌套。
- 文件夹数据通过一条保留的元数据条目持久化。
- 插件默认隐藏该条目，可在主题/设置中切换显示。

元数据条目设计
- 标题：固定前缀，如 `__WI_META_FOLDERS__`
- `enabled: false`
- `strategy.type: selective`
- `strategy.keys: []`
- `content`：JSON 字符串
- 建议内容结构：
  - `version`
  - `folders`
  - `entryFolderMap`

代码级修改计划
1. 新增元数据识别与读写工具
- 文件（新增）：`modules/features/folderMeta.js`
- 职责：
  - 查找元数据条目
  - 创建元数据条目
  - 解析/校验 JSON
  - 写回元数据条目
  - 判断某条目是否为保留元数据条目

2. 设置项与显示开关
- 文件：`modules/settings.js`、`modules/ui/theme.js`
- 修改点：
  - 增加 `showFolderMetaEntry` 布尔设置。
  - 默认 `false`。

3. 文件夹状态与渲染
- 文件：`modules/state.js`、`modules/ui/list.js`、`modules/ui/panel.js`
- 修改点：
  - 增加文件夹折叠状态。
  - 列表层将普通条目按元数据映射分组渲染。
  - 未被映射的条目归入“未分类”。

4. 文件夹操作
- 文件：`modules/commands/titleBarCommands.js`、`modules/commands/entryCommands.js`
- 修改点：
  - 新增操作：
    - 新建文件夹
    - 重命名文件夹
    - 删除文件夹
    - 移动条目到文件夹
    - 移出文件夹
  - 所有操作最终只改元数据条目，不改普通条目字段。

5. 导入导出兼容
- 文件：`modules/utils.js`
- 修改点：
  - 导出时元数据条目保持为合法世界书条目。
  - 不使用插件的酒馆导入时，不会因格式非法报错。
  - 使用插件时会自动重新识别并隐藏元数据条目。

测试安排
A. 直接功能测试
- 新建/重命名/删除文件夹。
- 移动单条与多条条目到文件夹。
- 元数据条目自动创建。
- 主题中切换“显示元数据条目”。

B. 耦合影响测试
- 模块：AI
  - AI 必须跳过元数据条目。
- 模块：复制、删除、批量
  - 默认不作用于元数据条目。
- 模块：导入导出
  - 重新导入后文件夹结构恢复。
- 模块：不用插件的酒馆
  - 导入不报格式错误。
