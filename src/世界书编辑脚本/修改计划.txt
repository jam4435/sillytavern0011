# AI 修改工作流优化方案

## Context

当前 AI 工作区的信息区（`<信息>`）只包含只读条目和已修改批次的内容。用户希望增强信息区，加入聊天上下文和手动资料，同时优化提示词结构和预览交互体验。

## 改动概览

三大改动方向：
1. **信息区增强**：新增「上下文区」（自动拉取最近 N 条聊天消息）和「资料区」（手动输入 + 内嵌 AI 助手对话窗）
2. **提示词结构优化**：`<用户指令>` 中移除世界书名
3. **预览交互升级**：分条目独立解析、预览区可直接编辑 afterEntry、单条重新生成

---

## 1. 信息区增强

### 1.1 上下文区（聊天上下文）

**目标**：在 `<信息>` XML 中加入酒馆当前聊天的最近 N 条消息，让 AI 理解角色扮演的上下文。

**关键文件**：
- `ui/aiWorkspace.js` — UI：新增 drawer、条数输入框、预览区
- `features/aiActionsBatch.js` — 提示词组装：`buildContextualBatchPromptV2()` 和 `buildPlanningPrompt()` 中注入聊天上下文
- `settings.js` — 持久化 `chatContext.messageCount` 设置

**实现**：
- 在 `ensureMarkup()` 的 HTML 模板中，在「条目列表」drawer 之前新增「上下文区」drawer
  - 包含：条数输入框（默认 10）、「刷新」按钮、只读预览区（显示拉取到的消息摘要）
- 使用酒馆助手 API `getChatMessages()` 获取最近 N 条消息（`@types/function/chat_message.d.ts` 已定义）
  - 调用方式：`getChatMessages(`0-${getLastMessageId()}`)` 然后取最后 N 条，或用负数 range
- 在 `aiActionsBatch.js` 中新增 `buildChatContextXml(messages)` 函数，生成：
  ```xml
  <聊天上下文>
    <user>用户消息内容</user>
    <assistant>AI回复内容</assistant>
    ...
  </聊天上下文>
  ```
- 在 `buildContextualBatchPromptV2()` 的 `<信息>` 段中，在 `<改造方案>` 之后、`<只读条目>` 之前插入聊天上下文 XML
- state 中新增 `chatMessages: []` 存储拉取到的消息

### 1.2 资料区（手动输入 + AI 助手）

**目标**：用户可以手动粘贴参考资料，也可以通过内嵌的简易 AI 对话窗与 AI 讨论后选取内容放入资料区。

**关键文件**：
- `ui/aiWorkspace.js` — UI：新增资料区 drawer + AI 助手对话窗
- `features/aiActionsBatch.js` — 提示词组装：注入资料区内容
- `settings.js` — 持久化资料区文本

**实现**：
- 在 `ensureMarkup()` 中新增「资料区」drawer，包含：
  - 一个大 textarea（`#ai-workspace-reference-material`），用户可手动粘贴/编辑
  - 一个可折叠的「AI 助手」子区域：
    - 聊天历史显示区（只读，显示对话气泡）
    - 输入框 + 发送按钮
    - 每条 AI 回复旁有「选取到资料区」按钮
- AI 助手对话使用 `llmClient.js` 的 `requestLlmText()` 发送请求
  - 提示词构成：破限提示词 + 资料区当前内容 + 用户对话输入
  - 不携带世界书条目，纯粹作为讨论助手
- 在 `buildContextualBatchPromptV2()` 的 `<信息>` 段中新增：
  ```xml
  <参考资料>
  用户粘贴或AI助手产出的资料内容
  </参考资料>
  ```
- state 中新增 `referenceMaterial: ''` 和 `assistantChatHistory: []`

## 3. 预览交互升级

### 3.1 分条目独立解析（容错）

**目标**：AI 返回的 JSON 中，即使某个条目的数据有问题，其他条目仍然可以正常展示。

**关键文件**：
- `features/aiActionsBatch.js` — `buildAttemptItems()`

**改动**：
- 在 `buildAttemptItems()` (L1930) 中，对每个条目的 `normalizeAiDraft()` 调用包裹 try-catch
- 单条 normalizeAiDraft 失败时，该条目记入 errors 数组（附带具体错误信息），其余条目继续处理
- 当前实现已经对「缺失 UID」做了 per-entry 错误处理，只需要扩展到 draft 解析/normalize 阶段

### 3.2 预览区可直接编辑

**目标**：用户点击预览条目后，在弹窗中可以直接编辑 afterEntry 的内容（标题、内容、关键词），而不是只读查看。

**关键文件**：
- `ui/aiWorkspace.js` — `openPreviewModal()`、`buildPreviewModalSections()`、预览弹窗 HTML

**改动**：
- 修改 `openPreviewModal()` (L1080)：
  - 将预览弹窗中「预览」列的 textarea 从 `readonly` 改为可编辑
  - 弹窗 footer 新增「保存修改」按钮
- 「保存修改」按钮的处理逻辑：
  - 从弹窗中读取用户编辑后的值
  - 更新 `state.previewResult.items` 中对应 uid 的 `afterEntry`
  - 重新计算该条目的 `diffs` 和 `changed` 状态
  - 刷新预览列表和应用按钮状态
- 修改 `buildPreviewModalSections()` 返回结构，增加 `fieldKey` 标识以便回写

### 3.3 单条重新生成

**目标**：预览弹窗中增加「重新生成」按钮，对单条条目重新请求 AI。

**关键文件**：
- `ui/aiWorkspace.js` — 预览弹窗 UI + 事件绑定
- `features/aiActionsBatch.js` — 复用 `executePreviewAttempt()` 或新增单条重生成函数

**改动**：
- 预览弹窗 footer 新增「重新生成此条」按钮
- 点击后：
  - 仅对该条目构建提示词（复用 `buildContextualBatchPromptV2()`，entries 只包含该条目）
  - 调用 `executePreviewAttempt()` 获取新结果
  - 成功后更新 `state.previewResult.items` 中对应条目
  - 刷新弹窗内容和预览列表
- 重新生成期间弹窗显示 loading 状态，按钮禁用

## 实现顺序

1. **提示词结构优化**（最小改动，先做）— 移除 `<用户指令>` 中的世界书名
2. **分条目独立解析**（小改动）— `buildAttemptItems()` 加 try-catch
3. **预览区可编辑 + 单条重新生成**（中等改动）— 预览弹窗交互升级
4. **上下文区**（中等改动）— 聊天消息获取 + UI + 提示词注入
5. **资料区 + AI 助手**（较大改动）— 手动输入 + 内嵌对话窗

## 验证方式

1. 打开 AI 工作区，确认新增的上下文区、资料区 drawer 正常显示
2. 设置聊天上下文条数，点击刷新，确认能正确拉取聊天消息
3. 在资料区输入文本，确认生成预览时提示词中包含 `<参考资料>` 和 `<聊天上下文>` 段
4. AI 助手对话窗能正常发送/接收消息，「选取到资料区」按钮能正确追加内容
5. 生成预览后，点击条目弹窗，确认 textarea 可编辑，保存后 diff 正确更新
6. 单条重新生成按钮能正确请求 AI 并更新该条目预览
7. 确认 `<用户指令>` 中不再包含世界书名
8. 故意构造一个会导致部分条目解析失败的场景，确认其他条目仍正常展示
9. `pnpm build` 无报错
