# 用户设定脚本术语说明

## 角色区分

- `char 角色`：指酒馆里的角色卡，也就是聊天对象。
- `当前角色`：一律指当前打开的 `char`。
- `绑定到当前角色`：一律指把配置绑定到当前 `char`。
- `user 人设`：指用户自己的 Persona。

`char 角色` 和 `user 人设` 是两套完全不同的对象，不是同一个“角色”。

## 自动切换目标

这个插件要解决的是：

- 在不同 `char` 下，自动切换不同的配置。
- 在同一 `char` 的不同聊天下，自动切换不同的配置。

这里的配置可以包括：

- `user 人设`
- `user 人设条目快照`
- `预设`
- `世界书`
- `脚本`
- `插件设置`

## 切换机制

切换检测基于两类信号：

- 聊天切换事件
- `char` 角色切换事件

插件拿到切换后的“当前聊天”和“当前 char”后，会重新计算：

1. 现在应该生效的是哪套聊天绑定。
2. 现在应该生效的是哪套角色绑定。
3. 目标状态和当前已应用状态之间有哪些差异。

应用时不是简单“全清空再全打开”，而是按资源类型计算差异后同步到目标状态：

- 不该继续生效的内容会被移除。
- 新应该生效的内容会被应用。
- 没变化的内容不会重复操作。

也就是说，本质上是：

- 检测聊天或 `char` 切换
- 重新计算绑定结果
- 对比前后差异
- 把当前实际状态同步到新的目标状态

## user 人设绑定规则

当你在 `用户人设` 页点击：

- `绑定到当前聊天`
- `绑定到当前角色`

记录下来的不是文件夹，也不是旧的 profile 容器，而是：

- `当前 user 人设`
- `当前手动启用中的条目 ID 集合`

文件夹只负责整理条目，不进入聊天/角色绑定。

触发时会这样处理：

1. 切到目标 `user 人设`
2. 把该人设的手动启用条目改成绑定时保存的快照
3. 如果这套绑定不再生效，就把这个 `user 人设` 恢复到进入绑定系统前的基线状态

## 关于“联动方案”

`联动方案` 只是内部的一组配置容器。

它的意义是把这些东西打包在一起：

- `user 人设`
- `预设`
- `世界书`
- `脚本`
- `插件设置`

然后再绑定到某个聊天或某个 `char`。

如果界面里直接显示“当前聊天绑定了什么 / 当前角色绑定了什么”已经足够清楚，那么把“联动方案名称”单独摆在前台，价值确实不高。
