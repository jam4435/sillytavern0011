# 绑定plus

## 功能定位

`绑定plus` 是一个给 SillyTavern 用的“聊天 / char 角色自动切换配置”面板。

它解决的是这类需求：

- 不同 `char 角色`，自动切不同配置
- 同一 `char` 的不同聊天，自动切不同配置
- 第一次绑好以后，下次游玩时自动恢复

这里的配置目前可以包括：

- `user 人设`
- `预设`
- `酒馆助手脚本`
- `酒馆正则`
- `世界书`
- `世界书条目`

## 先记住两件事

- `char 角色` 是聊天对象，也是“绑定到当前角色”里的角色
- `user 人设` 是用户自己的 Persona，是被切换的资源之一

两者不是同一个东西。

## 当前绑定模型

绑定目标只有两类：

- `当前角色`
- `当前聊天`

触发顺序固定为：

1. 先应用当前 `char 角色` 绑定
2. 再应用当前聊天绑定
3. 聊天绑定覆盖角色绑定

插件内部会重新计算目标状态，再按差异同步，不是简单“全关再全开”。

## user 人设页

`用户人设` 页现在分成两部分：

- 上方：当前 `user 人设` 基础描述
- 下方：`左文件夹 / 右条目` 的 MD 结构

其中：

- 文件夹只负责整理和折叠大量条目
- 文件夹不参与聊天/角色绑定
- `未分组条目` 是固定分组，不会写成真实文件夹

### 绑定 user 人设时到底绑定什么

在 `用户人设` 页点击顶部：

- `绑定到当前聊天`
- `绑定到当前角色`

写入的是：

- 当前 `user 人设`
- 该人设当前“手动启用中”的条目 ID 集合

也就是：

- `userPersonaAvatarId`
- `userPersonaEnabledTraitIds`

不是绑定文件夹，也不是绑定旧的 profile 容器。

### user 人设条目恢复规则

- 新绑定会写入“当前启用条目快照”
- 触发后会把该 `user 人设` 的手动启用状态改成这份快照
- 当这套绑定不再生效时，会恢复到它进入绑定系统前的基线状态
- 老数据如果只有 `user 人设`、没有条目快照，仍可读取，但不会强改条目启用状态

## 其他资源页

其他资源页按“左侧资源列表，右侧 detail”工作：

- `预设`
- `酒馆助手脚本`
- `酒馆正则`
- `世界书与条目`

在这些页里，顶部 `绑定到当前聊天 / 绑定到当前角色` 表示：

- 把“当前页选中的资源”加入当前聊天或当前角色绑定
- 再点一次则移除当前选中资源

## 顶部按钮

- `绑定到当前聊天`：把当前页选中的资源绑定到当前聊天
- `绑定到当前角色`：把当前页选中的资源绑定到当前 `char`
- `设为默认人设`：调用酒馆现有默认 Persona 按钮逻辑
- `设为默认预设`：本插件自己的默认预设回退。当前聊天/角色都没绑预设时使用

## YAML 导入

`用户人设 -> 条目与文件夹` 支持 YAML 批量导入。

推荐格式：

```yaml
性格:
  - 傲娇: 嘴上不承认在意，但会用行动偷偷照顾对方。
  - 慢热:
      描述: 熟悉之前会克制表达，建立信任后才逐渐主动。

外挂:
  - aaa: 学习能力极强
  - bbb: 天生惹人怜爱

通用备注: 默认保持第一人称，不主动替 char 做决定。
```

规则是：

- `键值对` = 单独条目
- `键值对` 的上层 = 文件夹
- 顶层裸键值对 = 未分组条目
- 导入的条目默认 `关闭`

## 存储

主要使用这些本地存储键：

- `tavern_helper_persona_traits_{avatarId}`：user 人设条目
- `tavern_helper_persona_advanced_{avatarId}`：文件夹、规则、旧 profile 数据
- `tavern_helper_persona_base_desc_{avatarId}`：基础描述
- `tavern_helper_persona_snapshot_{avatarId}`：快照
- `tavern_helper_context_bindings_v1`：聊天 / 角色全局绑定
- `tavern_helper_persona_plus_applied_global`：当前已应用状态与回退基线
