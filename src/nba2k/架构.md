# NBA2K16 生涯模拟 v3 架构

React 前端运行在酒馆消息 iframe 中，由角色卡 loader 从 `http://localhost:5500/dist/nba2k/index.html` 加载。聊天级 `stat_data` 是唯一持久真相源；Schema拒绝非法状态后进入清档恢复页。

## 状态与数值

- `engine/types.ts` 定义43项能力、身高/体重/臂展、10组成长、动态倾向/徽章/热区、结构化战术与比赛状态。
- `engine/playerAdapter.ts` 将历史球员旧19项种子确定性展开为43项，并按位置补体重/臂展；外部排名CSV不是运行时依赖。
- `engine/lifecycle.ts` 负责多赛季年龄、巅峰、成长/衰退和退役；`data/players.ts` 只保留初始赛季种子，后续赛季由 `getRosterForLeague/getPlayerForLeague` 动态投影当季能力，不在 stat_data 为数百名球员复制43项能力。
- `engine/draft.ts` 每年生成60名程序化虚构新秀；`联盟.生成球员` 只保存紧凑种子，43项能力和CPU倾向按需确定性重建。
- `engine/development.ts` 是可校准配置中心：21级非线性曲线、位置总评、体型影响、24徽章、14热区和创建预算。
- `engine/tendencies.ts` 从43项能力、位置与少量球星覆盖推导 CPU 个人行为倾向；倾向只决定“更愿意做什么”，不改变动作成功率。
- `engine/teamStyle.ts` 根据当前可用 roster 的投射、组织、内线、机动性、防守、篮板和耐力动态推导球队进攻体系、防守方案、节奏、协防强度与篮板取向；生产运行时不再按球队ID硬编码 GSW/CLE/SAS 等历史战术。
- `engine/teamPower.ts` 从当前Roster、伤病/复出限时、轮换深度、教练和TeamStyle派生球队级 ORtg / DRtg / Pace / Power；后台 GameSim 与非玩家季后赛系列赛不再读取 `TEAMS.overall`。
- `schema.ts` 严格校验 `版本=3`、比赛不变量、生涯/场外状态以及联盟战绩、CoachProfile、球员归属、合同册、市场报价、交易记录、生成球员、选秀历史、伤病、StoryHook 和季后赛系列赛状态。

## 三层比赛引擎

### Action Resolution Engine

`resolveAction` 继续是唯一动作数值内核：

```text
动作 + 43项能力 + 主防/协防 + 体型 + 战术 + 体力 + 徽章/热区
→ 多阶段 1d100
→ 五档结果
→ SettlementContract / 合法篮球分支
→ applySettlement
```

玩家手动动作仍经过 `SettlementContract → NBASettlement → 校验/一次修复/fallback → 唯一 ERA VariableEdit`。AI不能重掷、改比分或自由创造统计。

### PossessionEngine

`engine/possession.ts` 在 Action Resolution Engine 之上负责完整 CPU possession：

```text
当前进攻方
→ 根据 usage / 球队战术 / 场上阵容选择发起人
→ 选择持球、挡拆、传导、背身等动作
→ resolveAction
→ 若只创造优势，则自动寻找下一名终结者
→ 最多1～3个动作阶段
→ 投篮 / 失误 / 犯规
→ 自动罚球 / 篮板
→ 比分、助攻、个人统计、时钟、体力、球权全部落地
```

CPU模拟不调用第二套概率公式；真正的动作成败仍全部复用 `resolveAction / applySettlement`。

### RotationEngine

`engine/rotation.ts` 是完整比赛的第三层规则器，只负责“谁在场、打多久、何时换”，不另造比赛结果：

```text
每次 possession 结束 / 节间
→ 读取每名球员目标分钟
→ 比较实际已打分钟与当前比赛进度
→ 结合体力 / 犯规麻烦 / 位置适配 / 当前阵容
→ 末节胶着时适度提高核心优先级
→ 最多进行有限批次换人
→ 按新五人和当前战术重建球场站位
```

- 常规 CPU 轮换目标分钟由阵容强度和耐力生成，并严格归一为每队 240 分钟；加时自然增加额外上场时间。
- MyCareer 主角的目标分钟由球队角色覆盖：边缘轮换 8、轮换 18、第六人 28、首发 32、核心 36 分钟；其他球员自动重新分配剩余分钟。
- “轮换/边缘轮换”主角不会再因为是主角而被强制塞进首发；只有“首发/核心”默认进入开场五人。
- Q1 两犯、Q2 三犯、Q3 四犯会提前保护，五犯强保护，六犯或极低体力强制换下。
- RotationEngine 与“全回合 / 精简比赛 / 关键时刻”无关，三种节奏只决定玩家何时介入，底层轮换完全共用。
- 玩家在死球时仍可手动换人；自动轮换会把这视为当前阵容，并继续按剩余目标分钟做后续调度。

### TeamStyleEngine：阵容驱动的球队体系

`engine/teamStyle.ts` 在每场开赛前、伤病可用名单确定后生成本场 `StructuredTeamTactics`：

```text
今日可用Roster
↓
轮换池（能力 / stamina / durability）
↓
计算：
spacing / passing / handling / initiation
pick&roll handler / screener
post / rim / mobile big
perimeter defense / help / rim protection
rebounding / mobility
↓
OffenseScore：
基础 / 五外 / 四外一内 / 挡拆 / 低位 / 动态进攻
↓
DefenseScore：
人盯人 / 二三联防 / 换防 / 沉退 / 延误
↓
pace / helpIntensity / rebound
↓
MatchState.战术（本场冻结）
```

- 战术只读取当前可用球员，不读取球队名、历史年份或真实战术答案；交易、退役、选秀、生成球员和伤病变化都会在下一场自然重算。
- 同一球队如果唯一空间型内线伤停，五外得分会下降；如果多年后阵容换成大量投射和机动型球员，原本的低位球队也可以自动转成五外、动态进攻或挡拆体系。
- 节奏采用较高的 NBA 相对阈值区分快/标准/慢，避免43项适配后“大家都很运动”导致全联盟误判为快节奏。
- 阵容客观适配之上已经加入持久 `CoachProfile`：教练可偏爱某种进攻/防守、快慢节奏、协防、篮板、短/深轮换、核心负荷和 small-ball，但只提供有限偏置，不能覆盖明显不适配的 roster。
- 2015-16粗粒度球队战术只保存在 `data/calibration/teamStyleBenchmarks2015_16.ts` 供测试。当前校准要求历史期望体系多数落在算法第一梯队，而不是为了逐队标签完全一致重新硬编码球队名。

### CoachProfile：跨阵容持久的教练人格

`engine/coachProfile.ts` 为30队保存独立、可跨比赛持续的教练理念：

```text
LeagueState.教练[teamId]
├─ offensePreference / defensePreference
├─ pacePreference / reboundPreference / helpBias
├─ rotationDepthBias / benchTrustBias / starLoadBias
├─ smallBallBias / playoffShorteningBias
├─ stubbornness
└─ tenureGames
```

- 初始教练人格由 `teamId + generation` 的稳定种子生成小幅差异，**不读取2015真实球队战术答案**；同一存档中人格稳定，换帅后 generation+1 会得到新的独立理念。
- `TeamStyleEngine` 先计算阵容客观体系分，再乘入教练偏好；`DepthChartEngine` 同理先看球员/阵容，再对轮换深度、替补信任、核心负荷、小阵容和季后赛缩轮换做有限修正。
- `stubbornness` 只决定偏好影响强度上限；再固执的教练也不能凭空把没有空间型内线的阵容变成高质量五外。
- 新教练 `tenureGames=0`，理念只部分生效；约15场后完成磨合。联盟每推进一轮，所有现任教练磨合场次+1。
- `replaceTeamCoach()` 是确定性换帅入口：只更换 CoachProfile 并生成“球队关系” StoryHook，不改 roster、球员能力或比赛结果；AI只能演出管理层决定和更衣室反应。
- 生涯页显示当前教练的体系偏好、轮换倾向、核心负荷、小阵容态度、固执度和磨合进度。
- 当前没有自动“输几场就炒教练”的随机规则；未来若加入 CoachSecurityManager，应根据长期战绩、阵容预期和管理层目标独立判定，不能让 AI 自行解雇教练。

### 动态 DepthChart、轮换计划与伤病可用性

RotationEngine 只执行，本场“该用谁、计划打多久”完全由当前世界状态纯模拟生成：

```text
当前可用Roster
+ 43项能力 / overall / 位置
+ 当前球队战术
        ↓
DepthChartEngine
StarterScore / RotationScore / CreationScore / ClosingScore
        ↓
动态 CoachRotationProfile
轮换深度 / 替补信任 / 核心负荷 / small-ball / stagger / 季后赛缩轮换
        ↓
AvailabilityManager
联盟.伤病 → 休战 / 恢复中 / 可复出分钟限制
        ↓
RotationPlanBuilder
动态分钟权重 + 主角球队角色 + 伤病 + 季后赛
        ↓
MatchState.轮换
        ↓
RotationEngine执行
```

- 生产运行时**不读取真实历史分钟**，也没有球员姓名级 closing/stagger 白名单；即使赛季推进多年、阵容由交易/选秀/生成球员重构，DepthChart 仍只根据当时 roster 与能力重新排首发、轮换、核心错峰和终结优先级。
- `DepthChartEngine` 根据位置适配、攻防能力、创造力、耐力/耐久与当前战术计算 Starter/Rotation/Closing 分数；教练用人倾向由阵容深度本身推导，而非“勇士固定深轮换/骑士固定死操核心”。
- 基础分钟使用通用分钟曲线 + 队内相对实力、首发身份、耐力、核心负荷、替补深度做纯算法分配，最后严格归一到每队240分钟。
- 动态 `staggerGroups` 会自动寻找场上最强的两名主要创造者；正常轮换尽量保证至少一人在场，Closing/垃圾时间不强制。
- Closing Priority 由球员本身的 overall、镇定、攻防稳定性、创造、投射、防守与本场计划动态生成；领先时进一步偏控球/罚球/防守/篮板，落后时偏投射/创造，不依赖历史终结阵容名单。
- `联盟.伤病` 真正参与开赛名单：`休战/恢复中` 不进入可用阵容；`可复出` 可带 `分钟限制`。无显式限制时按严重度与复出后天数确定性推导恢复梯度；显式分钟限制也会随后续比赛逐步放宽并最终解除。
- 受伤DNP不计个人出场、成长奖励或负面教练评价，但球队赛程与联盟结果照常推进。
- 2015-16真实分钟现在只保存在 `data/calibration/rotationBenchmarks2015_16.ts`，仅供测试：用历史阵容跑**纯模拟**，再比较输出与真实分钟误差；生产 bundle 不把历史答案作为轮换输入。

### GameContext 与临场轮换

`engine/gameContext.ts` 将比赛阶段压成四种轮换语义：

- **正常**：追踪赛前目标分钟、体力和犯规。
- **终结阵容**：第四节最后6分钟且分差≤10时，弱化“欠分钟补课”，强化 `closingPriority`；小阵容倾向高的球队允许 PF 顶 C、SF 顶 PF。
- **软垃圾时间**：领先方逐步撤核心；落后方仍保留追分阵容，最后3分钟才更深地用替补。
- **硬垃圾时间**：双方优先深板凳，显著压低高分钟首发优先级。

垃圾时间阈值随剩余时间变化，并带4-5分退出迟滞，避免比分在阈值附近每个 possession 来回切换。

### CoachRoleManager

`engine/coachRole.ts` 把“球队角色”从静态标签改成长期教练判断：

```text
每场真实出赛
→ 本场表现 + 胜负
→ 教练信任缓慢变化
→ 保存最近5场评分
→ 每5场正式评估一次
→ 结合信任 / overall / 近期表现
→ 最多升降一级
```

长期角色仍为 `边缘轮换 / 轮换 / 第六人 / 首发 / 核心`，只决定长期待遇；伤病顶替等“本场首发”属于 RotationPlan 临时职责，不会立刻改永久角色。角色变化会生成确定性的“球队关系” StoryHook，AI只能解释原因，不能改判。技术统计在垃圾时间仍完整记录，但 `垃圾时间秒数` 会让这部分表现对教练信任最多降权45%，避免深板凳刷分直接冲高长期角色。

`engine/fullGameSimulation.ts` 用同一套 `PossessionEngine + RotationEngine` 跑真正的 48 分钟高精度整场，只用于审计/测试和需要高精度的玩家比赛，不替代联盟其他球队的低精度 GameSim。

当前持续回归会批量跑 96 场、8 组不同体系对阵，检查 Pace、比分、三分/罚球结构、失误、前场板、助攻、抢断、盖帽、替补分钟、核心分钟和终场体力；另跑勇士/骑士球星样本检查个人数据层级。测试只设宽松 NBA 区间，防止明显漂移，不要求复刻历史赛季到小数点。


## Possession 数值校准原则

PossessionEngine 只要求“大致接近真实 NBA”，不追求逐项复刻真实统计。当前校准目标是让长期模拟避免明显失真：

- 发起权与终结权分离：`initiation` 控制谁主导回合，`usage` 更偏谁完成终结；明星覆盖只修正风格，不改动作成功率。
- 投篮倾向采用非线性权重，低三分倾向的大个不会因为“30分倾向”仍持续投三分。
- `advantage/reset` 会写入瞬时 Possession Flow Context；成功传导、挡拆和突破分球会真实提高下一动作质量，失败重置则增加持球压力。
- 投篮模型使用较缓的能力/干扰 logistic 系数；空位、协防、五外、体力、冷热区、徽章只作温和修正，避免顶级射手常态出现60%+三分成功线。
- 失误不再只绑定固定“大失败”：普通失败也根据动作风险、传控能力与对手压力决定是否失误，并区分抢断与非受迫失误。
- 投篮犯规、两/三次罚球、and-one、进攻犯规均由前端合法分支产生；罚球不能由 AI 自由创造。
- 篮板先判球队级进攻篮板概率，再在赢家一侧按篮板能力分配球员；基础目标约在联盟常见区间，`冲抢/优先退防` 只做有限偏移。
- 球权转换后按新进攻方战术重新生成半场站位；下半场换边。24秒时钟按真实流逝递减，归零触发违例。
- 场上所有球员按上场时间缓慢消耗体力，动作参与者另有小幅额外消耗；替补按休息时间恢复。
- `.github/workflows/nba2k-core-tests.yaml` 对站位、动作合同、完整 possession、RotationEngine、48分钟整场与宽松统计区间做持续回归检查。

## 三种比赛节奏

`engine/simulationMode.ts` 只定义“何时暂停让玩家介入”，不改变比赛数值：

- **全回合**：细粒度操作，主角在场时频繁暂停给玩家决策。
- **精简比赛**：主角作为发起人、配合人或主要防守者时介入，其余 possession 由 CPU 连续真实模拟。
- **关键时刻**：大部分比赛连续模拟，只在末节胶着、主角直接参与、犯规危机、火热状态、里程碑等节点暂停。

比赛节奏是 UI 偏好，保存于 localStorage，可在比赛中随时切换；底层状态与规则完全共用。

## 多赛季生命周期

`engine/lifecycle.ts` 让静态2015-16种子可以跨多年继续模拟：

```text
初始球员种子
↓
estimateInitialAge / estimatePeakAge
↓
LeagueState.赛季序号
↓
逐赛季 evolveRatingsOneSeason
├─ 年轻球员：按潜力空间成长
├─ 巅峰：能力基本稳定
├─ 运动能力：更早衰退
├─ durability / stamina：30岁后逐步下降
├─ 投射 / 传球 / IQ / composure：更晚、更慢下降
└─ retirementPressure：年龄 + overall + durability + 严重伤病 + 球队角色
↓
当季 PlayerData
↓
TeamStyle / DepthChart / Rotation / Possession
```

- 年龄估算不读取真实历史年龄表；真实2015-16年龄只保存在 `data/calibration/ageBenchmarks2015_16.ts` 用于测试，当前15名代表球员平均绝对误差约0.67岁。
- NPC球员不持久保存每年完整43项能力。只要 `联盟.赛季序号` 改变，就从不可变初始种子确定性重算当季投影，因此长期存档不会因为数百名球员能力副本急剧膨胀。
- 主角单独持久保存 `年龄 / 巅峰年龄 / 生涯赛季数 / 退役状态`；休赛期进入下一季时只结算一次年龄与能力变化。主角比赛使用 `生涯.能力` 的当季投影，训练/升级与年龄衰退都会真实进入比赛数值。
- 生涯阶段为 `新秀 / 成长 / 巅峰 / 下滑 / 暮年 / 退役`。退役不是固定年龄：核心/首发倾向延长生涯，低overall、低durability和严重伤病会提高退役压力；44岁为硬上限。
- 退役NPC会直接从 `getRosterForLeague` 的当季名单中过滤，因此下一场的 TeamStyle、DepthChart 和 Rotation 会自然重算。
- 如果关闭新秀补充，原始联盟球员数会从约372人下降到第5年约264人、第10年约147人；正常生涯现在每年由 DraftEngine 新增60名候选并完成两轮选秀，抵消长期退役人口。
- 休赛期实际顺序为 `DraftEngine → 15人名单整理 → 到期合同/自由市场 → beginNextSeason()`，赛季标签、年龄、能力与新名单随后一起进入下一年度。

## DraftEngine / 程序化新秀

`engine/draft.ts` 负责未来赛季的新人口来源，不读取真实未来选秀名单：

```text
上一季30队战绩
↓
generateDraftClass()
60名虚构新秀
├─ 19～22岁
├─ PG/SG/SF/PF/C + 可选副位置
├─ 身高 / 体重 / 臂展
├─ POT与初始OVR
├─ 神射手 / 组织核心 / 突破手 / 双向侧翼
│  禁区终结者 / 护框中锋 / 空间内线 / 全能前锋
└─ 紧凑生成种子
↓
43项能力按模板 + 身体 + 种子确定性重建
↓
CPU倾向由43项能力动态派生
↓
战绩倒序基础顺位
↓
天赋榜 + 当前球队位置需求
↓
两轮60签
↓
球员归属 + 新秀合同
↓
同一Roster / Lifecycle / TeamStyle / Rotation / Possession链
```

- 生成新秀的存档不保存一整份43项能力，也不额外保存13项CPU倾向；只保存姓名、入盟赛季、准确年龄、巅峰年龄、位置/副位置、身体、潜力、初始目标OVR、模板与生成种子。读取时重建能力，进入后续年份再由 LifecycleEngine 推进成长/衰退。
- 新秀行为倾向不是第二套隐藏能力。`deriveCpuTendencies()` 直接读取重建后的43项能力，因此神射手更偏三分、组织核心更偏传控、突破手更偏攻框、内线更偏掩护/低位；球员成长后倾向也会随能力自然变化。
- 当前基础选秀顺位按常规赛胜率倒序，战绩相同再看净胜分与稳定ID；这是低复杂度近似，暂不实现真实乐透概率、交易选秀权、签位保护或选秀夜换签。
- 每队两轮各一签，共60签。选人时以当前OVR/POT的天赋榜为主，以球队位置短板为次，不允许“缺中锋就无视明显更强的状元级后卫”。
- 首轮新秀默认4年合同、次轮2年；薪资按顺位和赛季通胀生成，不读取现实未来新秀工资表。
- 选秀完成后先执行15人Roster上限：保护主角和当届首轮秀，超额的最低市场价值边缘球员进入自由市场，再进行到期合同/自由市场签约。
- `buildLeagueRosterSnapshot()` 一次投影当前全部现役球员并按30队分组，Draft/FreeAgency在同一休赛期复用快照。5个连续休赛期（300名程序化新秀）压力测试约1.1秒，避免多年后查询复杂度平方增长。
- 5届连续选秀后测试中的30队现役Roster合计约440人，所有球队保持≤15人；因此现在长期联盟不会再因为原始球员退休而逐年空掉。
- 真实历史数据仍只可作为校准/测试答案；未来赛季的姓名、顺位、能力和发展全部来自模拟。

## Roster / Contract / Transaction Engine

`engine/transactions.ts` 把交易、续约和自由市场统一成同一条阵容变动链：

```text
初始球员种子
+ 联盟.球员归属（稀疏覆盖）
+ 联盟.合同册（稀疏覆盖）
        ↓
getRosterForLeague()
        ↓
TeamNeeds
        ↓
交易 / 续约 / 自由市场正式报价
        ↓
玩家接受 或 CPU规则落地
        ↓
球员归属 / 合同册 / 交易记录
        ↓
下一场重新读取Roster
        ↓
TeamStyle / DepthChart / Rotation 自动重算
```

- `球员归属` 不复制全联盟名单：没有发生过变动的球员仍沿用初始球队；只有交易、签约、成为自由球员等变动写稀疏覆盖，`null` 代表自由球员。
- 初始NPC没有真实历史合同运行时依赖；系统按球员种子稳定生成初始合同期限和市场价值。历史真实合同不会绑住未来架空赛季。
- TeamNeeds 按当前Roster的五位置首发质量、替补质量和深度计算。正式报价再结合球队战绩/竞争力、球员overall/potential和价值匹配。
- 玩家常规赛交易窗口可生成最多3份固定报价；报价一旦进入 `联盟.市场报价` 就不会因叙事回合重新抽取。接受后球员真正从旧Roster消失、进入新Roster，并同步下一场赛程、球队角色、教练信任和队友关系。
- CPU交易截止日采用轻量规则：每赛季最多约2笔需求驱动的中层轮换互换，避免联盟完全不交易，也避免球星无理由频繁乱飞；主角不会被CPU后台自动交易。
- 休赛期到期NPC先进入自由市场，再按30队需求快照自动签约。需求采用一次批量快照并在签约后局部修正，避免逐球员反复扫描全联盟Roster。
- 主角合同到期后会收到最多3份正式自由市场报价，未签约不能直接进入下一赛季；若只剩一年合同，可出现可选提前续约，不接受则原合同继续履行。
- `场外.合同` 只是正式联盟合同的UI投影，正式合同真相在 `联盟.合同册`。AI不得修改报价、薪资、年限、交易筹码或球员归属。
- 当前刻意**不实现完整NBA CBA**：没有鸟权、工资帽例外、奢侈税、硬帽等复杂规则。第2步目标是长期生涯需要的阵容变动闭环，而不是完整GM模拟器；以后确有需要再在本层上方扩展。
- 程序化新秀已经直接接入同一 `球员归属 + 合同册` 抽象；被选中后下一场就按当前Roster参与 TeamStyle、DepthChart、Rotation 与比赛。

## TeamPowerEngine：长期球队实力

`engine/teamPower.ts` 让后台29队和玩家看到的世界使用同一份Roster真相：

```text
当前 LeagueState
+ LeagueRosterSnapshot
+ 伤病 / 复出分钟限制
+ CoachProfile
        ↓
可用轮换池
        ↓
TeamStyle + DynamicDepthChart
        ↓
按预计轮换权重聚合
├─ offenseSkill
├─ defenseSkill
├─ reboundSkill
├─ weightedOverall / topEnd / depth
├─ offenseFit / defenseFit
└─ paceScore
        ↓
相对当季30队均值映射
        ↓
offenseRating / defenseRating / netRating / pace / power
        ↓
低精度后台 GameSim / 非玩家季后赛
```

- 球队实力**不持久化**到 `stat_data`。每个联盟推进轮次重新从当前Roster派生，因此交易、自由市场、新秀成长、老将衰退/退役和伤停会在下一轮立即改变后台战力。
- `TEAMS.overall` 仍可作为首季静态展示数据，但不再进入后台赛果公式。测试已验证在完全虚构球队ID下，只要Roster能力结构相同，TeamPower仍能正常计算。
- 伤病不是简单扣固定球队分：休战球员从可用轮换移除，复出限时会降低其分钟权重，继而改变进攻、防守、深度和体系适配。
- 低精度GameSim不逐 possession 生成box score；它用动态 ORtg/DRtg 与双方 Pace 估计单场得分，再叠加近钟形单场波动和主场优势。强队长期胜率更高，但单场保留明显爆冷概率。
- 2015-16联盟约102.7分/场、95.8 Pace、106.4 ORtg只用于量纲校准。首季纯Roster推导目前可自然得到 SAS/GSW/CLE/OKC 位于高净效率梯队、PHI位于低位；未来年份不读取任何真实历史球队强弱答案。
- 生涯页显示主队当前联盟动态Power排名、ORtg、DRtg、Pace、体系和可用人数；这些是即时派生UI，不新增存档字段。
- 回归测试已用固定种子验证极端净效率差约27的对局：当前单场分数噪声为“三个均匀随机数之和居中后×18”，600场强队胜率约90.3%，弱队仍有58次爆冷，场均每队约103.44分；不需要为制造爆冷降低长期球队净效率差。
- `teamPower.test.ts` 另用独立30队82轮测试赛历（**仅供回归，不是生产第7步赛程**）检验真实后台GameSim：模拟10份同赛程的82场赛季，Curry从GSW改归属PHI后，GSW平均胜场54.2→48.3，PHI为24.9→30.5。
- 连续8年按每年**模拟战绩**进行选秀、名单整理、自由市场和赛季成长/退休，再重建30队画像；初始前五SAS/GSW/CLE/OKC/LAC，8年后前五SAS/UTA/BOS/ATL/DEN，22队Net Rating改变超过2，480名程序化新秀中386人仍在现役名单。长测确认不存在“沿用2015静态球队强弱排名”的胜负捷径，但只是确定性压力测试，不等于未来8年的真实预言。

## 联盟赛季统计与正式奖项（第5步）

`engine/leagueStats.ts` 将每轮15场比赛中的个人表现收敛到当季紧凑累计账本：

```text
当前30队Roster / Availability / DynamicDepthChart
+ TeamPower即时 ORtg/DRtg/Pace / 低精度球队最终比分
      ↓
后台28队：分钟与使用率、43项能力、倾向
      ↓
分配球队已结算得分、篮板、助攻、抢断、盖帽、失误
      ↓
FG/3P/FT 命中与出手、GP与MIN（只累计）
      ├─ stat_data.联盟.球员赛季统计[playerKey]
      └─ 不持久化29队的逐场Box Score

玩家球队的亲自比赛
      ↓
真实 MatchState.球员状态 → 增量累计
      ↓
与后台共同生成得分/篮板/助攻/抢断/盖帽五榜
      ↓
常规赛第82轮统一比较全联盟合格球员
      ↓
MVP / 最佳新秀 / DPOY / 最佳阵容一二三阵 / 最佳防守一二阵
      ↓
联盟.奖项记录（保留最近20季）；AI只能演出颁奖
```

- `球员赛季统计` 每人固定只保存 **GP、MIN、PTS、REB、AST、STL、BLK、TOV、FGM/FGA、3PM/3PA、FTM/FTA** 与最后所属球队。球队赛果仍由 TeamPower 单独决定，球员得分合计严格等于该队赛果，不另生成一份背离比分的 Box Score。
- 后台轮换按实际健康状态排除伤停球员，使用当季球员能力和动态 DepthChart 分配分钟及主要球权；从准确累计生成各种场均值与命中率。玩家亲自参与的两队则使用真实比赛 Box Score，不二次随机模拟。
- 交易后的赛季成绩继续累积在同一个球员 key 下，更新归属但不清空已打比赛；赛季切换清空当季统计、保留获奖历史。所有累计账本和获奖结果均由前端写入，只读于AI。
- 年终评选按出场资格、个人场均表现、球队胜率与防守能力排名；首季原始球员通过年龄近似判定最佳新秀资格，未来程序化新秀严格按 `entrySeason` 判定。最佳阵容按G/F/C合理分组、组内不得重复。
- 当前不做逐场联盟个人 Box Score、历史真实获奖者白名单或未来赛季官方获奖预测。第8步可再以这个奖项记录为起点扩展里程碑和历史档案。
- 本步骤 CI 新增 `leagueStats.test.ts`，覆盖伤病停赛、精确球队得分与240分钟、玩家真实数据只记一次、交易跨队累计、全联盟排名、收官评奖、赛季切换Schema。

## InjuryManager：赛后新伤病与日期康复（第6步）

`engine/injury.ts` 用纯前端规则在赛后裁定新的伤病；不在已经结算的这场比赛中途改写身体状态：

```text
已确定的本场结果
├─ 主角/对手：MatchState 球员真实分钟 + 终场剩余体力
└─ 其他28队：LeagueStats低精度分钟 + 当季Roster
          ↓
43项耐久、耐力 / 年龄 / 出场分钟
+ 当季平均分钟负荷 / 既往严重伤史 / 伤愈限时
+ 赛季·回合·日期·球员ID确定性PRNG
          ↓
小概率新伤（轻微/中等/严重）
          ↓
联盟.伤病（仅沿用原有结构）
          ↓
Availability → RotationPlan / TeamStyle / TeamPower
          ↓
后续赛程日期 → 恢复 / 可复出分钟限制 / 恢复正常出场
```

- `applyGameInjuries()` 只依据本场出场者判定；DNP和已经休战的球员不会凭空再次受伤。不同伤势对应不同缺席天数，伤情只以实际发生的确定性结论写入 `联盟.伤病`，同一场重算不会产生第二份伤病。
- 球员真实比赛在 `advanceLeagueAfterGame()` 赛后结算伤病；后台常规赛沿用 `simulateTeamSeasonLines()` 产生的预计分钟；非玩家季后赛每场低精度赛果也会计算伤病暴露，但不会把季后赛个人统计错写入常规赛账本。完整正式奖项仍只比较常规赛。
- 受伤概率会因大量分钟、耐久差、年纪增长、疲劳、持续重负荷和既往重伤而提高；常规水平默认单场低概率，不把球星强制编成长期伤病名单。高影响伤病写轻量 StoryHook，AI不能决定具体伤情/恢复日期。
- `advanceInjuryRecovery()` **按实际日期**计算伤后可用与分钟恢复，避免重复调用导致同一天虚假快速痊愈。跨休赛期时 `beginNextSeason()` 自动复核旧伤，不会把已过期伤势带进新赛季。
- 为控制多年存档规模，已经痊愈120天以上的轻/中等伤病记录会清理；既往严重伤保留，继续供 `LifecycleEngine` 评估长期耐久和退役风险。不新增第二套伤病计数或逐场伤病日志。
- 第7步赛程完成前，当前每轮的真实休息日按简化赛历推进；未额外模拟真实连续背靠背风险。CI 的 `injury.test.ts` 覆盖风险变化、可复现/不重复、伤停即时战力下降、按日期恢复、跨休赛期恢复和多轮全联盟自然负荷。

## CalendarEngine：全联盟唯一赛程（第7步）

```text
15队东部 + 15队西部 / 6个分组
          ↓
29轮完整互换主客的循环赛（每对1主1客）
+ 同组额外2主2客 / 同分区三场与四场交手配额
          ↓
30队共1230场、每队82场（41主41客）
          ↓
确定性年份种子 + 日期排程
          ↓
每队独立的出场日、休息天数与背靠背
          ↓
玩家比赛 → 日期窗口内的其他球队全部比赛
          ↓
战绩 / 个人累计 / 动态实力 / 伤病
```

`getLeagueCalendar(yearOffset)` 只缓存生成结果，不写入 `stat_data`；玩家 `getScheduledGame(teamId,index)` 和后台对阵指向同一个正式赛程。联盟日期随着主角下一场比赛走，幕后其他球队在两个主角比赛日期之间可打不同数量比赛。此处赛程是合成 NBA 格式、非真实2015年历史表，真实2015–16仅供校准。

## SeasonEngine

`engine/season.ts` 不采用武侠式通用事件系统，而是固定赛历 + 联盟状态：

- `engine/calendar.ts` 已在第7步接管常规赛唯一赛程：每赛季重建30队×82场÷2＝**1230场**，完整覆盖10月27日至次年4月13日；不复制真实历史赛程或持久化完整比赛清单，跨年份对阵与日期按种子确定性变化。
- 交手分配：跨分区每支球队15×2＝30场；同分区同组4×4＝16场；同分区其他10队中6队×4＋4队×3＝36场，合计82场；每队主客场各41场。对手、日期和主客场在30队间严格互为镜像，同一天同一队不能打两场。
- 玩家场与后台所有球队共用一套赛历；`advanceLeagueAfterGame` 根据玩家下一场的实际开赛日期推进后台比赛，不再以“玩家一场=其余队各一场”的假同步规则结算。连续82场结束时30队各82场、联盟共1230场，以完整赛季回归守护。
- 有休息日、背靠背、实际可复现的日历；InjuryManager按球队真实赛间休息天数评估疲劳风险，恢复期按实际日期处理。新赛季重新排主客与对手日期，季后赛保留已有七场四胜/主客场规则，后续可再引入更精细的飞行距离与电视转播限制。
- 玩家亲自参与的比赛走 PossessionEngine；其他球队比赛走低精度 `GameSim`，只计算结果与联盟战绩，不逐 possession 模拟。
- 常规赛结束按东西部战绩取前8；首轮采用 1–8 / 4–5 / 2–7 / 3–6，系列赛七场四胜、2-2-1-1-1 主场顺序；其他系列赛继续低精度模拟。
- `联盟.故事钩子` 只是经过条件检查后交给 AI 的叙事入口，不代表剧情结果。

## 场下专用 Manager

`engine/offCourtSystems.ts` 采用多个小型规则器而不是万能 EventEngine：

- Trade / Contract 的 StoryHook 只负责提示市场话题；正式球队需求、报价生成、续约、自由市场和Roster落地由 `engine/transactions.ts` 决定。
- Sponsorship：按比赛间隔生成履约检查。
- Injury：按日期推进恢复并生成复出入口。
- TeamDynamics：低胜率、低好感或低教练信任只生成矛盾苗头。
- Awards：按数据与球队战绩给出奖项参考分。

这些 Manager 只生成确定性结果或轻量 StoryHook；谈判、采访、更衣室互动等具体表现交给 AI，AI不得越过前端规则直接改联盟结果。

## 状态结构

`stat_data.版本=3`，顶层为：

```text
比赛   当前单场高精度状态
生涯   主角能力、年龄/巅峰/退役状态、成长、徽章、热区、赛季统计
场外   资金、声望、经纪人、代言、合同、关系、日程
联盟   赛季标签/赛季序号、日期、阶段、30队战绩、30队CoachProfile、球员归属、合同册、市场报价、交易记录、生成球员、选秀历史、伤病、StoryHook、季后赛
```

联盟与赛程属于前端只读系统状态。正文模型不得修改 `联盟`，也不得自行推进 `场外.日程.日期/下一场`。

## 回合与恢复

一次 AI 生成采用回合事务：先取得隐藏楼层锁，再以 `refresh:none` 持久化 user/assistant，等待匹配的 `era:writeDone` 后释放锁并同步最终楼层。assistant 落楼前失败回滚孤立 user；ERA 超时保留完整回合供手动同步。

暂停、换人、逐次罚球、训练和升级目前仍属于确定性前端操作；比赛 CPU 批量模拟会先在前端得到最终状态，再让 AI 仅压缩演出既定结果。

## UI与恢复

- 自建支持2K16/自由模拟两模式、三项身体、100点能力组预算与实时总评。
- 生涯面板显示当前赛季、年龄、生涯阶段、成长、24徽章、14热区、教练信任、球队战绩、动态球队实力排名/ORtg/DRtg/Pace、当前合同、最近选秀、正式交易/续约/自由市场报价与联盟 StoryHook；休赛期合同到期时必须先签约才能进入下一赛季。
- 比赛面板显示计分板、球场、技术统计、动作面板与三档比赛节奏切换。
- `CHAT_CHANGED` 直接重载iframe，清除瞬时组件状态。重新开始会二次确认并清除聊天级 `stat_data`。
- 布局遵循消息iframe文档流，不使用100vh或强制宿主高度。

构建：`pnpm build:src:fast`。打包：`node tavern_sync.mjs bundle nba2k`。
