# NBA2K16 生涯模拟 v3 架构

React 前端运行在酒馆消息 iframe 中，由角色卡 loader 从 `http://localhost:5500/dist/nba2k/index.html` 加载。聊天级 `stat_data` 是唯一持久真相源；v3 不迁移旧存档，Schema拒绝后进入清档恢复页。

## 状态与数值

- `engine/types.ts` 定义43项能力、身高/体重/臂展、10组成长、动态倾向/徽章/热区、结构化战术与比赛状态。
- `engine/playerAdapter.ts` 将373名球员的旧19项种子确定性展开为43项，并按位置补体重/臂展；外部排名CSV不是运行时依赖。
- `engine/development.ts` 是可校准配置中心：21级非线性曲线、位置总评、体型影响、24徽章、14热区和创建预算。
- `schema.ts` 严格校验 `版本=3`、数组、枚举、坐标、比分/技术统计不变量、回合阶段与待处理情境。

## 比赛事务

```text
ActionPanel 只选择主角合法情境动作
→ resolveAction 读取对位、18单位协防、体型、战术、体力、徽章、热区并执行多阶段1d100
→ SettlementContract 锁定等级、合法分支和柔性数值范围
→ 非流式 generate 返回叙事 + NBASettlement
→ assistant落楼前校验；非法则只修复生成一次，仍非法用参考分支
→ 前端应用比分/统计/犯规/时钟/球权不变量并生成唯一 VariableEdit
→ 只持久化一条assistant，等待匹配的 era:writeDone 后释放 nba2k 回合锁
```

初次生成不重复传 `user_input`；修复请求有意只携带合同、非法提案与错误，不落为独立消息。assistant落楼前失败回滚孤立user；ERA超时保留完整消息供手动同步。

## 判定边界

- 前端确定阶段骰子、五档结果、合法篮球分支、比分与个人统计算术。
- AI在合同内选择分支、耗时、体力、投篮时钟、球权、站位和叙事表现；前端规范化后才允许ERA执行。
- 暂停、换人、逐次罚球、训练和升级为确定性前端操作；AI只叙事。
- 比赛自由文本只能对话或表达战术，不能推进比赛；比赛不显示模型options。

## UI与恢复

- 自建支持2K16/自由模拟两模式、三项身体、100点能力组预算与实时总评。
- 生涯面板显示成长、24徽章、14热区、教练信任；比赛面板按持球/无球/防守/篮板/罚球/替补席切换。
- `CHAT_CHANGED` 直接重载iframe，清除所有瞬时组件状态。重新开始会二次确认并清除聊天级 `stat_data`。
- 布局遵循消息iframe文档流，不使用100vh或强制宿主高度。

构建：`pnpm build:src:fast`。打包：`node tavern_sync.mjs bundle nba2k`，输出 `角色卡/nba2k.png`。
