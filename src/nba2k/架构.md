# NBA2K16 生涯模拟 v3 架构

React 前端运行在酒馆消息 iframe 中，由角色卡 loader 从 `http://localhost:5500/dist/nba2k/index.html` 加载。聊天级 `stat_data` 是唯一持久真相源；Schema拒绝非法状态后进入清档恢复页。

## 状态与数值

- `engine/types.ts` 定义43项能力、身高/体重/臂展、10组成长、动态倾向/徽章/热区、结构化战术与比赛状态。
- `engine/playerAdapter.ts` 将373名球员的旧19项种子确定性展开为43项，并按位置补体重/臂展；外部排名CSV不是运行时依赖。
- `engine/development.ts` 是可校准配置中心：21级非线性曲线、位置总评、体型影响、24徽章、14热区和创建预算。
- `engine/tendencies.ts` 从43项能力、位置与少量球星覆盖推导 CPU 个人行为倾向；倾向只决定“更愿意做什么”，不改变动作成功率。
- `engine/teamStyle.ts` 根据当前可用 roster 的投射、组织、内线、机动性、防守、篮板和耐力动态推导球队进攻体系、防守方案、节奏、协防强度与篮板取向；生产运行时不再按球队ID硬编码 GSW/CLE/SAS 等历史战术。
- `schema.ts` 严格校验 `版本=3`、比赛不变量、生涯/场外状态以及联盟战绩、伤病、StoryHook 和季后赛系列赛状态。

## 三层比赛引擎

### Action Resolution Engine

`resolveAction` 继续是唯一动作数值内核：

```text
动作 + 43项能力 + 主防/协防 + 体型 + 战术 + 体力 + 徽章/热区
→ 多阶段 1d100
→ 五档结果
→ SettlementContract / 合法篮球分支
→ applySettlement
```

玩家手动动作仍经过 `SettlementContract → NBASettlement → 校验/一次修复/fallback → 唯一 ERA VariableEdit`。AI不能重掷、改比分或自由创造统计。

### PossessionEngine

`engine/possession.ts` 在 Action Resolution Engine 之上负责完整 CPU possession：

```text
当前进攻方
→ 根据 usage / 球队战术 / 场上阵容选择发起人
→ 选择持球、挡拆、传导、背身等动作
→ resolveAction
→ 若只创造优势，则自动寻找下一名终结者
→ 最多1～3个动作阶段
→ 投篮 / 失误 / 犯规
→ 自动罚球 / 篮板
→ 比分、助攻、个人统计、时钟、体力、球权全部落地
```

CPU模拟不调用第二套概率公式；真正的动作成败仍全部复用 `resolveAction / applySettlement`。

### RotationEngine

`engine/rotation.ts` 是完整比赛的第三层规则器，只负责“谁在场、打多久、何时换”，不另造比赛结果：

```text
每次 possession 结束 / 节间
→ 读取每名球员目标分钟
→ 比较实际已打分钟与当前比赛进度
→ 结合体力 / 犯规麻烦 / 位置适配 / 当前阵容
→ 末节胶着时适度提高核心优先级
→ 最多进行有限批次换人
→ 按新五人和当前战术重建球场站位
```

- 常规 CPU 轮换目标分钟由阵容强度和耐力生成，并严格归一为每队 240 分钟；加时自然增加额外上场时间。
- MyCareer 主角的目标分钟由球队角色覆盖：边缘轮换 8、轮换 18、第六人 28、首发 32、核心 36 分钟；其他球员自动重新分配剩余分钟。
- “轮换/边缘轮换”主角不会再因为是主角而被强制塞进首发；只有“首发/核心”默认进入开场五人。
- Q1 两犯、Q2 三犯、Q3 四犯会提前保护，五犯强保护，六犯或极低体力强制换下。
- RotationEngine 与“全回合 / 精简比赛 / 关键时刻”无关，三种节奏只决定玩家何时介入，底层轮换完全共用。
- 玩家在死球时仍可手动换人；自动轮换会把这视为当前阵容，并继续按剩余目标分钟做后续调度。

### TeamStyleEngine：阵容驱动的球队体系

`engine/teamStyle.ts` 在每场开赛前、伤病可用名单确定后生成本场 `StructuredTeamTactics`：

```text
今日可用Roster
↓
轮换池（能力 / stamina / durability）
↓
计算：
spacing / passing / handling / initiation
pick&roll handler / screener
post / rim / mobile big
perimeter defense / help / rim protection
rebounding / mobility
↓
OffenseScore：
基础 / 五外 / 四外一内 / 挡拆 / 低位 / 动态进攻
↓
DefenseScore：
人盯人 / 二三联防 / 换防 / 沉退 / 延误
↓
pace / helpIntensity / rebound
↓
MatchState.战术（本场冻结）
```

- 战术只读取当前可用球员，不读取球队名、历史年份或真实战术答案；交易、退役、选秀、生成球员和伤病变化都会在下一场自然重算。
- 同一球队如果唯一空间型内线伤停，五外得分会下降；如果多年后阵容换成大量投射和机动型球员，原本的低位球队也可以自动转成五外、动态进攻或挡拆体系。
- 节奏采用较高的 NBA 相对阈值区分快/标准/慢，避免43项适配后“大家都很运动”导致全联盟误判为快节奏。
- 阵容客观适配之上已经加入持久 `CoachProfile`：教练可偏爱某种进攻/防守、快慢节奏、协防、篮板、短/深轮换、核心负荷和 small-ball，但只提供有限偏置，不能覆盖明显不适配的 roster。
- 2015-16粗粒度球队战术只保存在 `data/calibration/teamStyleBenchmarks2015_16.ts` 供测试。当前校准要求历史期望体系多数落在算法第一梯队，而不是为了逐队标签完全一致重新硬编码球队名。

### CoachProfile：跨阵容持久的教练人格

`engine/coachProfile.ts` 为30队保存独立、可跨比赛持续的教练理念：

```text
LeagueState.教练[teamId]
├─ offensePreference / defensePreference
├─ pacePreference / reboundPreference / helpBias
├─ rotationDepthBias / benchTrustBias / starLoadBias
├─ smallBallBias / playoffShorteningBias
├─ stubbornness
└─ tenureGames
```

- 初始教练人格由 `teamId + generation` 的稳定种子生成小幅差异，**不读取2015真实球队战术答案**；同一存档中人格稳定，换帅后 generation+1 会得到新的独立理念。
- `TeamStyleEngine` 先计算阵容客观体系分，再乘入教练偏好；`DepthChartEngine` 同理先看球员/阵容，再对轮换深度、替补信任、核心负荷、小阵容和季后赛缩轮换做有限修正。
- `stubbornness` 只决定偏好影响强度上限；再固执的教练也不能凭空把没有空间型内线的阵容变成高质量五外。
- 新教练 `tenureGames=0`，理念只部分生效；约15场后完成磨合。联盟每推进一轮，所有现任教练磨合场次+1。
- `replaceTeamCoach()` 是确定性换帅入口：只更换 CoachProfile 并生成“球队关系” StoryHook，不改 roster、球员能力或比赛结果；AI只能演出管理层决定和更衣室反应。
- 生涯页显示当前教练的体系偏好、轮换倾向、核心负荷、小阵容态度、固执度和磨合进度。
- 当前没有自动“输几场就炒教练”的随机规则；未来若加入 CoachSecurityManager，应根据长期战绩、阵容预期和管理层目标独立判定，不能让 AI 自行解雇教练。

### 动态 DepthChart、轮换计划与伤病可用性

RotationEngine 只执行，本场“该用谁、计划打多久”完全由当前世界状态纯模拟生成：

```text
当前可用Roster
+ 43项能力 / overall / 位置
+ 当前球队战术
        ↓
DepthChartEngine
StarterScore / RotationScore / CreationScore / ClosingScore
        ↓
动态 CoachRotationProfile
轮换深度 / 替补信任 / 核心负荷 / small-ball / stagger / 季后赛缩轮换
        ↓
AvailabilityManager
联盟.伤病 → 休战 / 恢复中 / 可复出分钟限制
        ↓
RotationPlanBuilder
动态分钟权重 + 主角球队角色 + 伤病 + 季后赛
        ↓
MatchState.轮换
        ↓
RotationEngine执行
```

- 生产运行时**不读取真实历史分钟**，也没有球员姓名级 closing/stagger 白名单；即使赛季推进多年、阵容由交易/选秀/生成球员重构，DepthChart 仍只根据当时 roster 与能力重新排首发、轮换、核心错峰和终结优先级。
- `DepthChartEngine` 根据位置适配、攻防能力、创造力、耐力/耐久与当前战术计算 Starter/Rotation/Closing 分数；教练用人倾向由阵容深度本身推导，而非“勇士固定深轮换/骑士固定死操核心”。
- 基础分钟使用通用分钟曲线 + 队内相对实力、首发身份、耐力、核心负荷、替补深度做纯算法分配，最后严格归一到每队240分钟。
- 动态 `staggerGroups` 会自动寻找场上最强的两名主要创造者；正常轮换尽量保证至少一人在场，Closing/垃圾时间不强制。
- Closing Priority 由球员本身的 overall、镇定、攻防稳定性、创造、投射、防守与本场计划动态生成；领先时进一步偏控球/罚球/防守/篮板，落后时偏投射/创造，不依赖历史终结阵容名单。
- `联盟.伤病` 真正参与开赛名单：`休战/恢复中` 不进入可用阵容；`可复出` 可带 `分钟限制`。无显式限制时按严重度与复出后天数确定性推导恢复梯度；显式分钟限制也会随后续比赛逐步放宽并最终解除。
- 受伤DNP不计个人出场、成长奖励或负面教练评价，但球队赛程与联盟结果照常推进。
- 2015-16真实分钟现在只保存在 `data/calibration/rotationBenchmarks2015_16.ts`，仅供测试：用历史阵容跑**纯模拟**，再比较输出与真实分钟误差；生产 bundle 不把历史答案作为轮换输入。

### GameContext 与临场轮换

`engine/gameContext.ts` 将比赛阶段压成四种轮换语义：

- **正常**：追踪赛前目标分钟、体力和犯规。
- **终结阵容**：第四节最后6分钟且分差≤10时，弱化“欠分钟补课”，强化 `closingPriority`；小阵容倾向高的球队允许 PF 顶 C、SF 顶 PF。
- **软垃圾时间**：领先方逐步撤核心；落后方仍保留追分阵容，最后3分钟才更深地用替补。
- **硬垃圾时间**：双方优先深板凳，显著压低高分钟首发优先级。

垃圾时间阈值随剩余时间变化，并带4-5分退出迟滞，避免比分在阈值附近每个 possession 来回切换。

### CoachRoleManager

`engine/coachRole.ts` 把“球队角色”从静态标签改成长期教练判断：

```text
每场真实出赛
→ 本场表现 + 胜负
→ 教练信任缓慢变化
→ 保存最近5场评分
→ 每5场正式评估一次
→ 结合信任 / overall / 近期表现
→ 最多升降一级
```

长期角色仍为 `边缘轮换 / 轮换 / 第六人 / 首发 / 核心`，只决定长期待遇；伤病顶替等“本场首发”属于 RotationPlan 临时职责，不会立刻改永久角色。角色变化会生成确定性的“球队关系” StoryHook，AI只能解释原因，不能改判。技术统计在垃圾时间仍完整记录，但 `垃圾时间秒数` 会让这部分表现对教练信任最多降权45%，避免深板凳刷分直接冲高长期角色。

`engine/fullGameSimulation.ts` 用同一套 `PossessionEngine + RotationEngine` 跑真正的 48 分钟高精度整场，只用于审计/测试和需要高精度的玩家比赛，不替代联盟其他球队的低精度 GameSim。

当前持续回归会批量跑 96 场、8 组不同体系对阵，检查 Pace、比分、三分/罚球结构、失误、前场板、助攻、抢断、盖帽、替补分钟、核心分钟和终场体力；另跑勇士/骑士球星样本检查个人数据层级。测试只设宽松 NBA 区间，防止明显漂移，不要求复刻历史赛季到小数点。


## Possession 数值校准原则

PossessionEngine 只要求“大致接近真实 NBA”，不追求逐项复刻真实统计。当前校准目标是让长期模拟避免明显失真：

- 发起权与终结权分离：`initiation` 控制谁主导回合，`usage` 更偏谁完成终结；明星覆盖只修正风格，不改动作成功率。
- 投篮倾向采用非线性权重，低三分倾向的大个不会因为“30分倾向”仍持续投三分。
- `advantage/reset` 会写入瞬时 Possession Flow Context；成功传导、挡拆和突破分球会真实提高下一动作质量，失败重置则增加持球压力。
- 投篮模型使用较缓的能力/干扰 logistic 系数；空位、协防、五外、体力、冷热区、徽章只作温和修正，避免顶级射手常态出现60%+三分成功线。
- 失误不再只绑定固定“大失败”：普通失败也根据动作风险、传控能力与对手压力决定是否失误，并区分抢断与非受迫失误。
- 投篮犯规、两/三次罚球、and-one、进攻犯规均由前端合法分支产生；罚球不能由 AI 自由创造。
- 篮板先判球队级进攻篮板概率，再在赢家一侧按篮板能力分配球员；基础目标约在联盟常见区间，`冲抢/优先退防` 只做有限偏移。
- 球权转换后按新进攻方战术重新生成半场站位；下半场换边。24秒时钟按真实流逝递减，归零触发违例。
- 场上所有球员按上场时间缓慢消耗体力，动作参与者另有小幅额外消耗；替补按休息时间恢复。
- `.github/workflows/nba2k-core-tests.yaml` 对站位、动作合同、完整 possession、RotationEngine、48分钟整场与宽松统计区间做持续回归检查。

## 三种比赛节奏

`engine/simulationMode.ts` 只定义“何时暂停让玩家介入”，不改变比赛数值：

- **全回合**：细粒度操作，主角在场时频繁暂停给玩家决策。
- **精简比赛**：主角作为发起人、配合人或主要防守者时介入，其余 possession 由 CPU 连续真实模拟。
- **关键时刻**：大部分比赛连续模拟，只在末节胶着、主角直接参与、犯规危机、火热状态、里程碑等节点暂停。

比赛节奏是 UI 偏好，保存于 localStorage，可在比赛中随时切换；底层状态与规则完全共用。

## SeasonEngine

`engine/season.ts` 不采用武侠式通用事件系统，而是固定赛历 + 联盟状态：

- 玩家球队常规赛为可重算的简化82场固定赛历，覆盖 2015-10-27 至 2016-04-13；后续可直接替换为真实2015-16赛程数据而不改变存档结构。
- 玩家亲自参与的比赛走 PossessionEngine；其他球队比赛走低精度 `GameSim`，只计算结果与联盟战绩，不逐 possession 模拟。
- 常规赛结束按东西部战绩取前8；首轮采用 1–8 / 4–5 / 2–7 / 3–6，系列赛七场四胜、2-2-1-1-1 主场顺序；其他系列赛继续低精度模拟。
- `联盟.故事钩子` 只是经过条件检查后交给 AI 的叙事入口，不代表剧情结果。

## 场下专用 Manager

`engine/offCourtSystems.ts` 采用多个小型规则器而不是万能 EventEngine：

- Trade：交易窗口与交易关注度。
- Contract：能力、表现、声望等生成市场报价锚点。
- Sponsorship：按比赛间隔生成履约检查。
- Injury：按日期推进恢复并生成复出入口。
- TeamDynamics：低胜率、低好感或低教练信任只生成矛盾苗头。
- Awards：按数据与球队战绩给出奖项参考分。

这些 Manager 只生成确定性结果或轻量 StoryHook；谈判、采访、更衣室互动等具体表现交给 AI，AI不得越过前端规则直接改联盟结果。

## 状态结构

`stat_data.版本=3`，顶层为：

```text
比赛   当前单场高精度状态
生涯   主角能力、成长、徽章、热区、赛季统计
场外   资金、声望、经纪人、代言、合同、关系、日程
联盟   日期、阶段、30队战绩、30队CoachProfile、伤病、StoryHook、季后赛
```

联盟与赛程属于前端只读系统状态。正文模型不得修改 `联盟`，也不得自行推进 `场外.日程.日期/下一场`。

## 回合与恢复

一次 AI 生成采用回合事务：先取得隐藏楼层锁，再以 `refresh:none` 持久化 user/assistant，等待匹配的 `era:writeDone` 后释放锁并同步最终楼层。assistant 落楼前失败回滚孤立 user；ERA 超时保留完整回合供手动同步。

暂停、换人、逐次罚球、训练和升级目前仍属于确定性前端操作；比赛 CPU 批量模拟会先在前端得到最终状态，再让 AI 仅压缩演出既定结果。

## UI与恢复

- 自建支持2K16/自由模拟两模式、三项身体、100点能力组预算与实时总评。
- 生涯面板显示成长、24徽章、14热区、教练信任、球队战绩与联盟 StoryHook。
- 比赛面板显示计分板、球场、技术统计、动作面板与三档比赛节奏切换。
- `CHAT_CHANGED` 直接重载iframe，清除瞬时组件状态。重新开始会二次确认并清除聊天级 `stat_data`。
- 布局遵循消息iframe文档流，不使用100vh或强制宿主高度。
