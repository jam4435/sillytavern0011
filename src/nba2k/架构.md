# NBA2K16 生涯模拟前端架构入口

## 项目边界

运行在酒馆助手消息 iframe 中的 React 前端（平行于 `src/武侠`），由 `角色卡/nba2k` 的「游戏页面」正则通过 `http://localhost:5500/dist/nba2k/index.html` 拉起。

- 聊天级 `stat_data` 是唯一持久真相源（`比赛` / `生涯` / `场外` 三棵子树）。
- React 状态只是 UI 投影；消息边界事件（MESSAGE_RECEIVED 等）触发兜底重读。
- **判定在前端完成**：属性加权对抗 + 情境修正 + 1d100，AI 只演出结果并结算变量，不得改判。
- 深度世界书通过 `{{ERA:$ALLDATA}}` 给模型注入本回合开始时的完整无 `$meta` 状态快照；AI 通过 ERA 指令块（`<VariableInsert/Edit/Delete>`）提交增量，由 ERA变量框架脚本落库。
- 前端仅在建档（带入现役/自定义新秀）和开赛初始化时直写 `chat` 变量；其余推进只消费 ERA 已提交状态。
- 每次生成是一个带隐藏楼层锁的回合事务：`refresh:none` 写 user → 非流式生成 → `refresh:none` 写 assistant → 等待对应楼层 ERA 写入完成 → 释放锁并同步最终外壳。assistant 落楼前失败会删除孤立 user；ERA 超时后保留完整回合，避免已生成内容与变量写入被误回滚。

## 核心循环（比赛回合）

```
CourtView 展示 10 人站位 → ActionPanel 选动作（含选传球目标/掩护人）
→ resolveAction 判定（对位=最近对手，空位程度=对位距离）
→ buildTurnPrompt 拼 <行动判定> 块 → runTurnTransaction
→ AI 叙事 + ERA 变量块 → 等待 ERA 提交完成 → 重读 stat_data → 视图更新
```

| ---- | ---- |
| `App.tsx` | 装配；开局建档、开赛初始化、事务式回合发送、事件监听 |

| `components/SplashScreen.tsx` | 开局标题画面（聚光灯海报风），选择「带入现役 / 自定义新秀」 |

| `components/CreatePlayer.tsx` | 自定义新秀：位置/模板/身高/号码 + 五维雷达预览 + 加盟球队 |
| `utils/customPlayer.ts` | 新秀原型模板（6 种）、按位置的总评计算、自定义球员构建 |
| `utils/statReader.ts` | stat_data 投影、正文剥离（ERA/判定/选项块）、选项解析 |

| `utils/turnTransaction.ts` | 回合锁、user/assistant 持久化、等待 ERA 提交与失败回滚 |

| `data/teams.ts` / `data/players.ts` | 2K16 全 30 队 / 373 名球员数据（来源见 data/README.md） |

## 稳定约束

1. 判定等级由前端骰子产生，prompt 中明确禁止 AI 改判。
2. 球场坐标系统一：x 0-100 左端线→右端线，y 0-100 下边线→上边线（SVG 渲染时翻转 y）。
3. 球员 key 全局用 `players.ts` 的英文 `name` 字段；中文名仅用于显示。自定义球员 key 为 `MyPlayer_<名字>`，完整数据存于 `stat_data.生涯.自定义球员`，前端每次刷新时经 `registerCustomPlayer` 重新注册；开赛用 `starterEntriesWith` 保证主角顶替同位置首发。
4. `data/players.ts` 由 JSON 数据源生成，不要手改单个数值——改源重新生成。
5. 构建零配置：webpack 自动发现 `src/nba2k/index.tsx`，产出自包含单文件 `dist/nba2k/index.html`。
6. 本地 loader 地址固定为 `http://localhost:5500/dist/nba2k/index.html`；静态服务必须以仓库根目录为根。
