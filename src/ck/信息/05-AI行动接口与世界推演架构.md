# AI 行动接口与世界推演架构

> 状态：根据用户反馈重写。取消“所有政治协议都必须由玩家确认”的通用门槛；AI 和 NPC 可以主动采取行动，合法行动经规则校验后默认执行。界面中的政治协议卡改为事后凭证、未决义务和执行记录。

## 一、核心决定

### 1. AI 必须能行动

如果 AI 只能说话、不能改变世界，NPC 永远只是等待玩家点击的布景。完整目标应是：

- AI 能根据角色身份、已知信息、性格和目标选择行动；
- 行动通过注册接口进入规则引擎；
- 合法行动自动执行，非法行动被拒绝或转成失败事件；
- 行动产生硬状态、事件、记忆和信息传播；
- 玩家随后从地图、来信、传闻、当面反应和世界摘要中看到后果。

### 2. 取消通用“玩家确认”

以下结果不应询问玩家是否接受：

- NPC 宣战、结盟、加入派系或退出派系；
- NPC 对玩家好感、信任、恐惧或怀疑的变化；
- 摄政侵吞资金、扩张权力或撤换亲信；
- 领地项目完成、失败、超支或遭到破坏；
- NPC 订婚、结婚、旅行、赴宴、拒绝邀请；
- NPC 发起计谋、散播流言、写信、赠礼或索债；
- 玩家已经在对话中明确作出的承诺；
- 战斗、疾病、继承、派系期限和其他规则结算。

只有**游戏规则要求玩家作出回应**时才暂停：

- 对方向玩家提出婚约、最后通牒、赎金或交换条件；
- 事件明确给玩家多个处置方案；
- 玩家需要选择路线、活动意图、继承安排等尚未发生的主动行动；
- 对话含义确实不明确，NPC 在世界内追问，而不是弹出系统确认框。

### 3. 政治协议卡变成什么

协议卡不是许可按钮，而是：

- 已达成协议的正式文书；
- 未履行义务和期限的账本；
- 自动执行结果的收据；
- 争议发生时可追溯的证据；
- 玩家理解 AI 为什么行动的解释面板。

卡片状态可为：草案、已提出、待对方回应、已生效、履行中、已完成、已违约、已撤销、因条件失效而终止。

一项对玩家不利但已经合法发生的结果，卡片只能显示和解释，不能让玩家用“不确认”将其取消。

## 二、不要给 AI 任意改状态，而要给它语义行动

### 错误接口

- 把某人好感设为 -50；
- 给自己增加 500 金币；
- 把某伯爵领所有者改成自己；
- 杀死目标；
- 把战争设为胜利；
- 直接把两个人设为已婚；
- 对世界状态执行任意 JSON Patch。

这些接口让 AI 同时扮演行动者、裁判和数据库管理员，无法校验，也无法为模组提供稳定语义。

### 正确接口

- 当众羞辱某人；
- 赠送某笔可支付的金钱；
- 对某头衔使用某种宣战理由宣战；
- 授予自己有权授予的头衔；
- 发起谋杀计谋；
- 提出婚约；
- 接受或拒绝婚约；
- 启动一个已定义的领地工程；
- 请求某封臣支持指定议案；
- 背弃一项已登记承诺。

规则引擎再根据行动、人物、法律、见证者和事件结果计算好感、恐惧、金钱、婚姻、战争等变化。

用户希望 AI 可以“增减好感度”，可以通过两级权限实现：

1. **角色 AI**只能提交语义社会行动，例如侮辱、称赞、背约、赠礼、宽恕、公开支持；
2. **事件/模组效果**可以调用受限的关系修正效果，但必须指定来源、持续时间、可见性和上限，不能直接覆盖总好感。

## 三、行动接口的统一定义

每种行动都注册为一个 ActionDefinition，至少包含：

| 字段 | 作用 |
|---|---|
| id / version | 稳定命名空间与存档兼容 |
| actorScopes | 哪类人物、职位或组织能使用 |
| targetSchema | 允许选择哪些人物、头衔、地点、战争或项目 |
| parameterSchema | 参数类型、范围、枚举和默认值 |
| channel | 当面、信件、使者、公开仪式、内部命令 |
| visibility | 公开、参与者可见、秘密 |
| candidateFilter | 快速生成合法候选，避免把全世界塞给 AI |
| preconditions | 执行前硬条件 |
| costs | 金钱、威望、虔诚、压力、行动位、时间 |
| reservations | 延迟行动需预留哪些资源 |
| duration / executeAt | 立即、延迟或持续多久 |
| cooldown | 角色、目标和全局冷却 |
| aiUtility | AI 评分因子和禁止条件 |
| resolver | 成功、失败、反抗、谈判或随机检定规则 |
| effects | 只能调用注册过的内部效果 |
| knowledgeEffects | 谁知道发生了什么 |
| memories | 哪些人物形成何种记忆 |
| followUps | 后续事件、来信、报复、承诺或期限 |
| logPolicy | 公开日志、秘密日志与调试追踪 |

角色 AI 每次只看到当前真正可用的行动及少量目标，不会收到数百个完整接口说明。

## 四、对话如何自动转成行动

### 1. 对话输出不只是一段台词

一次场景中的角色 AI 返回三部分：

- speech：角色说了什么；
- socialSignals：侮辱、称赞、威胁、让步、承认、撒谎等社会行为；
- actionCalls：角色决定立刻或延迟采取的注册行动。

所有 actionCalls 在 AI 回复展示前先验证并结算。展示给玩家的对白与动作描述必须与实际结算结果一致。

### 2. 玩家话语不需要系统确认，但要区分语气

系统不能把“我也许可以给你一块地”当成授地，也不能让玩家说完“我发誓”后再通过不确认逃避。建议将承诺强度分为：

| 强度 | 示例 | 系统处理 |
|---|---|---|
| 假设 | 如果局势允许，我或许会考虑 | 只记录谈判线索 |
| 意向 | 我愿意讨论把职位给你 | 创建未决议题，不形成义务 |
| 明确提议 | 你支持我，我任命你为总管 | 自动创建可回应的正式提议 |
| 明确接受 | 成交；我答应你的条件 | 自动创建协议和义务 |
| 正式命令 | 立即拨款五十金币修缮城堡 | 校验后自动执行或返回失败 |

若模型无法可靠区分，优先让 NPC 用角色内语言追问：“这是你的正式承诺吗？”这属于谈判本身，不是系统层确认弹窗。

### 3. 传入证据，不凭空抽取

每个从自然语言识别出的行动都保留：

- 来源消息 ID；
- 支持该判断的原文片段；
- 发言者；
- 作用对象；
- 场景与见证者；
- 解析模型版本；
- 置信度；
- 最终执行或拒绝原因。

这使错误能被调试、重放，也使 NPC 将来可以引用原话指控玩家背约。

### 4. 自动执行流水线

    玩家发言或 NPC 决策
      → 对话 AI 输出 speech、socialSignals、actionCalls
      → Schema 校验
      → 根据当前 stateRevision 预检
      → 资源预留与冲突检查
      → 规则 resolver 自动结算
      → reducer 原子写入硬状态
      → 事件、记忆、知识和后续计划生成
      → 协议/行动记录显示
      → AI 仅叙述已提交结果

不存在“所有结果最后再让玩家确认”这一步。

## 五、行动调用的生命周期

### 1. Command

AI 或玩家生成的行动请求，包含：

- commandId：幂等键；
- definitionId / definitionVersion；
- actorId；
- targetIds；
- parameters；
- issuedAt / executeAt；
- stateRevision；
- sourceSceneId / sourceMessageId；
- knowledgeSnapshotId；
- priority；
- resourceReservations。

### 2. ValidationResult

验证结果不是简单 true/false，而是：

- valid：可执行；
- invalid：身份、地点、资源或法律不允许；
- needsResponse：需要目标人物作出选择；
- delayed：信件、旅行、建设、围城等稍后执行；
- contested：可能遭到抵抗，需要 resolver；
- stale：世界版本已变化，应重新规划；
- redundant：同一命令已经执行。

### 3. Resolution

resolver 返回：

- committed events；
- state diffs；
- costs paid；
- public/secret knowledge；
- generated memories；
- follow-up schedules；
- failure reason；
- narrative facts。

只有 reducer 可以提交 state diffs。角色 AI 不能自己编写差分。

### 4. 事务与幂等

同一行动可能因酒馆重试、网络重连或 AI 重生成被重复提交。必须：

- commandId 保证只执行一次；
- stateRevision 防止旧计划覆盖新世界；
- 多个效果在同一事务中全部成功或全部失败；
- 延迟行动在真正执行时重新检查人物是否存活、头衔是否仍属于其、资源是否仍预留；
- 已结算的随机结果保存种子与结果，不在重载时重新抽取。

## 七、AI 自主行动不等于每个 NPC 都调用一次大模型

### 1. 四层决策模型

#### 第一层：世界局势分析

输入是经过规则汇总的硬状态，不是整份存档。输出是“当前压力与机会”：

- 诺曼渡海准备；
- 某地区粮食不足；
- 玩家合法性下降；
- 降权派系接近最后通牒；
- 某条道路因战争危险；
- 某伯爵无嗣且健康恶化。

这一层不能直接修改世界，只能产生 Issue 和 Agenda 候选。

#### 第二层：领国/集团规划

每个重要领国、派系、社团或家族定期决定：

- 想达成什么目标；
- 当前优先级；
- 可投入多少资源；
- 允许哪些角色代为执行；
- 什么条件下暂停或放弃。

例如降权派系的目标不是“让 AI 自由发挥”，而是结构化为：

- 目标：降低公爵权力；
- 期限：30 日；
- 当前支持力：42%；
- 所需支持力：60%；
- 行动预算：两次游说、一次威胁；
- 可执行者：派系领袖及一名亲信。

#### 第三层：角色决策

角色依据自身：

- 已知信息而非全局真相；
- 人格、关系、压力和记忆；
- 职位与法律权限；
- 当前个人目标；
- 所属领国/家族/派系目标；
- 可用行动、目标和预算；

选择一个行动或保持不动。规则评分先生成候选，LLM 只在重要角色、复杂冲突或需要自然语言理由时重排/补充。

#### 第四层：场景 AI

当前与玩家同场或通信的角色：

- 生成台词；
- 观察玩家言行；
- 调用当前场景允许的行动；
- 提出条件、撒谎、拖延或突然行动。

它仍受第三层目标和角色知识约束，不会因为玩家一句提示就忘记整个政治计划。

#### 第五层：规则结算与叙事

所有层的行动统一进入命令总线。规则引擎结算后：

- 当前场景得到即时叙述；
- 相关人物收到记忆和知识；
- 远方结果进入来信/传闻；
- 玩家收到按重要度汇总的世界摘要。

## 八、一次世界 Tick 的推荐顺序

    0. 冻结本 Tick 的只读快照和随机种子
    1. 结算时间、旅行、信件、项目、伤病、期限等确定性队列
    2. 从新状态生成 Issue 图：威胁、机会、债务、空缺、冲突
    3. 更新领国、派系、家族、社团的 Agenda
    4. 选择本 Tick 真正需要决策的活跃角色
    5. 为每名活跃角色生成合法行动候选
    6. 规则评分；重要角色可调用 LLM 重排并给出 actionCalls
    7. 统一预留资源，解决同一头衔、人物、职位和地点冲突
    8. 按阶段自动执行命令
    9. 处理反应、抵抗、事件和二次命令，但限制连锁深度
    10. 更新知识、记忆、关系修正和历史日志
    11. 为玩家生成地图变化、信件、传闻和摘要
    12. 提交新 revision，等待下一次推进

不要采用“宏观 AI 直接写一篇世界发生了什么，然后再照文章改数据”。正确方向是宏观 AI 只提出 Agenda，角色 AI 只提出 Action，规则引擎逐项提交。

## 九、同时行动与冲突

若多个 NPC 基于同一快照行动，必须处理：

- 两人同时申请同一职位；
- 两方同时向一人提婚；
- 目标在信件送达前死亡；
- 两支军队同时进入一个伯爵领；
- 两个派系同时拉拢同一封臣；
- 玩家已把准备赠出的金钱花掉；
- 一个伯爵先被逮捕，后续旅行命令失效。

建议分阶段：

1. 生死、继承、头衔和囚禁；
2. 战争、军队和占领；
3. 法律、派系、职位和契约；
4. 旅行、活动和项目；
5. 婚姻、社交、书信和信息；
6. 关系、记忆和摘要。

同阶段按明确优先级、行动速度或同时 resolver 处理，不能依赖 LLM 输出顺序。

## 十、分层模拟与调用预算

| 层级 | 对象 | 推进频率 | 是否调用 LLM |
|---|---|---|---|
| 焦点 | 当前对话、宴会、玩家身边人物 | 每轮/每场景 | 是 |
| 重要 | 玩家直属封臣、摄政、派系领袖、主要邻国 | 重大事件或每周 | 只在复杂决策时 |
| 活跃 | 当前地图普通领主、重点廷臣 | 每周/月 | 通常不用，规则评分 |
| 背景 | 地图外人物、普通人口 | 月/季度摘要 | 不用 |

第一条竖切只有 18—30 名重点人物，不需要 30 个常驻 AI。一次世界推进只挑出真正面临决策的人；多数角色“没有必要行动”也是合法结果。

## 十一、AI 选择行动的评分骨架

候选行动先由规则计算基础效用：

    utility =
      目标推进价值
      + 个人利益
      + 家族/派系/领国利益
      + 性格匹配
      + 对目标的关系
      + 机会窗口
      - 金钱与时间成本
      - 法律/暴政风险
      - 暴露和报复风险
      - 与既有承诺冲突
      - 信息不确定性

LLM 可以：

- 在排名接近的合法候选中选择；
- 说明角色为什么选；
- 提出注册接口允许的参数；
- 决定角色是否撒谎或掩饰动机。

LLM 不可以：

- 把非法候选改为合法；
- 创建不存在的资源或权限；
- 查看角色不知道的秘密；
- 修改 resolver 的成功率；
- 宣布行动已经成功。

## 十二、世界局势层如何避免“导演强推剧情”

世界局势 AI 应输出 Issue，而不是结局：

| 可以输出 | 不可以输出 |
|---|---|
| 诺曼征服使沿海领主感到不安 | 威廉已经获胜 |
| 降权派系有机会拉拢某伯爵 | 某伯爵已经加入派系 |
| 科南二世健康/战事带来继承风险 | 科南二世必须在本月死亡，除非历史硬事件明确如此 |
| 粮价上涨可能推动请愿和盗匪事件 | 直接扣除所有县的金钱 |
| 摄政权力上升是当前重要议题 | 摄政已经篡位 |

历史剧本可有“历史锚点”，但每个锚点应定义：

- 固定事实：无论玩家如何行动都发生；
- 条件事实：满足历史条件才发生；
- 压力事件：世界倾向发生，但允许偏离；
- 纯背景：只用于新闻和氛围。

这样 1066 年 9 月 28 日的诺曼登陆可以是外部世界固定/条件锚点，而玩家所在小公国内部的派系结果仍由游戏状态决定。

## 十三、错误处理

### AI 调用了非法行动

- 不执行；
- 记录验证失败原因；
- 若角色有理由意识到失败，生成“命令被拒绝/资源不足”的事件；
- 若只是模型格式错误，静默回退到无行动或重新生成一次；
- 不允许模型通过改写台词假装行动成功。

### AI 台词与 actionCall 冲突

以已结算 actionCall 为事实，重新生成或模板修正台词。不得为了迁就台词修改状态。

### AI 没有返回行动

合法。角色可以只说话、拖延、保持沉默或等待。

### AI 频繁反复

通过目标承诺、冷却、行动预算、状态记忆和计划锁抑制；不能只靠提示词写“请保持一致”。

## 十四、首条竖切需要实现的最小接口

不必首发全部接口。建议先做：

1. communication.send_letter；
2. activity.accept_invitation / decline_invitation；
3. travel.plan / depart / reroute；
4. regency.delegate；
5. social.praise / insult / threaten；
6. politics.request_support / grant_support / withdraw_support；
7. promise.make / accept / fulfill / break；
8. economy.gift_gold / grant_stipend；
9. office.appoint；
10. contract.propose_change；
11. politics.join_faction / leave_faction；
12. politics.issue_ultimatum。

第一条竖切暂不需要真正执行 military.declare_war，但应把接口定义和验证测试写好，确保失败结局能自然接到后续战争版本。

## 十五、验收标准

1. NPC 可在玩家没有点击的情况下主动发信、加入派系或撤回支持；
2. NPC 对玩家不利的合法行动无需玩家确认；
3. 明确接受的口头协议自动登记；
4. 假设和试探不会误登记为承诺；
5. 每个执行结果可追溯到角色、消息、行动定义和状态版本；
6. AI 只能调用当前角色真正可用的行动；
7. 宣战接口不能指定胜者，谋杀接口不能直接杀人；
8. 好感变化能追溯到具体事件/修正，而非 AI 任意设值；
9. 两个冲突行动能按规则稳定结算；
10. 重试和读档不会重复执行命令；
11. 背景人物不需要逐人调用 LLM；
12. 世界局势层只能创建议题和目标，不能直接写结局；
13. 玩家能从协议卡、事件日志和角色反应看懂世界为何变化；
14. 模型失败时规则状态仍保持一致。

## 十六、结论

理想分工不是“规则引擎玩游戏，AI 只写文案”，也不是“AI 说什么世界就变成什么”，而是：

**AI 是拥有目标、知识和行动权限的角色；规则引擎是所有角色共同受约束的世界。**
