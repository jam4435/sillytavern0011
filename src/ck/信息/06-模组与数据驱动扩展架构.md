# 模组与数据驱动扩展架构

> 目标：让核心规则、历史剧本、人物、事件、互动、AI 目标和文本尽可能通过可读文件扩展，达到接近 CK2/CK3“改文本即可加内容”的体验，同时适应浏览器、SillyTavern 与 AI 行动接口的安全边界。

## 一、最重要的原则

### 1. 官方内容也必须使用模组格式

如果本体事件写死在 TypeScript，只有第三方内容使用简化格式，这套格式永远不会真正成熟。建议：

- 引擎只提供通用能力：时间、图、存档、规则求值、命令总线、事件调度、AI 网关；
- 1066 布列塔尼剧本作为一个内置内容包；
- 本体人物、事件、决议、互动和 AI 目标也从相同目录加载；
- 开发者日常制作本体内容时，就是在使用未来模组作者使用的工具。

这正是接近 CK 可修改性的关键，不只是“以后开放几个配置项”。

### 2. 数据模组优先，代码模组分级

模组分三层：

| 等级 | 能力 | 默认安全性 |
|---|---|---|
| 内容包 | 人物、地图、头衔、事件、决议、互动、AI 目标、文本、素材 | 默认可加载 |
| 受限 UI 包 | 主题、图标、布局槽位、数据面板配置 | 需要声明权限 |
| 代码插件 | 新 resolver、算法、渲染器、外部接口 | 仅可信来源，明确警告 |

首版先完整支持内容包。不要为了追求“什么都能改”而在浏览器里直接执行未知模组 JavaScript。

### 3. 没有任意 eval

条件、效果和 AI 权重使用声明式 DSL：

- 条件由 all、any、not、eq、gt、hasTrait、isAtLocation 等注册操作组成；
- 效果只能调用注册过的 action/effect；
- 选择器只能访问允许的 scope；
- 不允许数据文件嵌入任意 JavaScript；
- 不允许内容模组直接访问文件、网络、DOM 或 SillyTavern 全局对象。

## 二、文件格式选择

### 推荐：JSON5 作为主要结构化格式

仓库已经安装 json5、yaml 和 zod。建议以 JSON5 为主，而不是自己发明一门完整 CK 脚本语言：

- 支持单行/多行注释；
- 支持尾逗号；
- 键名通常不必加引号；
- 仍然是对象、数组、字符串、数字和布尔值，容易解析；
- 可以直接通过 Zod 做运行时校验并得到明确错误路径；
- 对 TypeScript 友好；
- 普通 JSON 也是合法 JSON5，工具转换容易。

JSON5 官方说明其目标就是让 JSON 更适合人工编写，并提供注释、尾逗号、单引号与非引号键。[JSON5 官方说明](https://json5.org/)

### 其他格式的分工

| 格式 | 用途 |
|---|---|
| JSON5 | 人物、头衔、事件、互动、行动、AI 目标、规则、清单 |
| Markdown | 长叙事模板、写作风格、世界说明、模组文档 |
| SVG / GeoJSON | 伯爵领多边形、道路和地点 |
| PNG/WebP/SVG | 人物、纹章、地点、事件素材 |
| CSV | 批量编辑人物和本地化的可选导入/导出，不作为唯一源文件 |
| YAML | 可兼容导入，但不建议与 JSON5 并列为本体主格式 |

不建议把扩展名伪装成 txt。直接使用 .json5 能获得编辑器高亮；如果以后需要更像 CK 的体验，可以提供 .ckg 扩展名并将语法声明为 JSON5。

## 四、manifest

每个包必须有 manifest.json5：

    {
      id: 'example.brittany_1066',
      name: '1066：布列塔尼风云',
      version: '0.1.0',
      engine: '>=0.1 <0.2',
      schemaVersion: 1,

      dependencies: [
        { id: 'core.medieval', version: '^0.1.0' },
      ],

      optionalDependencies: [],
      loadAfter: [],
      incompatibleWith: [],

      content: {
        history: true,
        events: true,
        ai: true,
        prompts: true,
        ui: false,
        code: false,
      },

      permissions: {
        promptFragments: true,
        customAssets: true,
        uiSlots: [],
        executableCode: false,
        network: false,
      },
    }

manifest 负责：

- 命名空间；
- 版本和引擎兼容；
- 依赖与可选依赖；
- 加载顺序；
- 冲突声明；
- 内容能力；
- 安全权限；
- 存档所需的包指纹。

## 五、命名空间

所有公开对象必须使用全局唯一 ID：

- core.action.declare_war；
- core.event.feast_seating_dispute；
- brittany1066.character.conan_ii；
- brittany1066.title.duchy_brittany；
- mymod.event.secret_betrothal。

规则：

1. 模组只能自由新增自己命名空间的对象；
2. 修改其他包对象必须放入 patches 并明确声明目标；
3. 同 ID 重复定义默认报冲突，不静默覆盖；
4. 本地化、事件后续、AI 目标和行动引用都使用稳定 ID；
5. 重命名需提供 alias 或 migration。

这比“最后加载者悄悄覆盖”更安全，也更容易解释模组冲突。

## 六、声明式条件 DSL

一个事件条件可写成：

    {
      all: [
        { scope: 'actor', isAlive: true },
        { scope: 'actor', hasTrait: 'core.trait.ambitious' },
        { scope: 'actor', atActivity: 'feast' },
        {
          compare: {
            left: { relation: ['actor', 'target', 'opinion'] },
            op: '<',
            right: -20,
          },
        },
      ],
    }

引擎把它编译为只读判断，并自动生成解释：

- 角色必须存活；
- 角色必须有“野心勃勃”；
- 角色必须正在宴会；
- 角色对目标的好感低于 -20。

模组作者不需要写代码，玩家和开发者也能在调试器中看到哪个条件失败。

### 作用域

建议保留 CK 式 scope 思想，但让名称更明确：

- actor；
- target；
- host；
- guest；
- liege；
- spouse；
- location；
- county；
- title；
- war；
- activity；
- scheme；
- promise；
- savedScopes。

选择器必须声明返回类型和最大数量，避免一条模组规则无意遍历所有活人。

## 七、声明式效果

事件效果不是修改字段，而是调用注册效果：

    effects: [
      {
        effect: 'core.relationship.add_modifier',
        from: 'actor',
        to: 'target',
        modifier: 'mymod.publicly_insulted',
        duration: { months: 12 },
      },
      {
        effect: 'core.memory.create',
        owner: 'target',
        memory: 'mymod.memory.insulted_at_feast',
        about: 'actor',
      },
      {
        effect: 'core.event.schedule',
        event: 'mymod.event.demand_apology',
        delay: { days: [3, 10] },
      },
    ]

关系修正本身也由数据定义：

    {
      id: 'mymod.publicly_insulted',
      opinion: -15,
      trust: -10,
      tags: ['insult', 'public'],
      stacking: 'refresh',
      maxStacks: 1,
      defaultDuration: { months: 12 },
    }

角色 AI 不能直接调用 relationship.add_modifier；这是事件和 resolver 的内部效果。角色 AI 可以调用 social.insult 等语义行动，也可以调用单次 -10 到 +10 的 relationship.adjust；后者经累计上限、来源和权限校验后，由 resolver 转换为带来源的关系修正。模组可以配置允许的维度、默认期限和上下限，但不能开放绝对值覆盖。

## 八、事件定义

一个可扩展事件需要：

    {
      id: 'mymod.event.feast_seating_dispute',
      version: 1,
      category: 'activity',
      tags: ['feast', 'conflict', 'public'],

      on: ['core.on_activity_phase_started'],
      trigger: { ... },
      weight: { base: 20, modifiers: [ ... ] },
      cooldown: { scope: 'activity', years: 1 },

      scopes: {
        actor: { fromSignal: 'host' },
        target: { select: 'guest_with_rank_dispute' },
      },

      presentation: 'choice',
      title: 'mymod.event.feast_seating_dispute.title',
      description: 'mymod.event.feast_seating_dispute.desc',

      options: [
        {
          id: 'honor_target',
          allowedIf: { ... },
          effects: [ ... ],
          aiWeight: { ... },
        },
        {
          id: 'follow_protocol',
          effects: [ ... ],
          aiWeight: { ... },
        },
      ],

      after: [ ... ],
    }

事件由 onAction、决议、互动、活动阶段或其他事件触发，而不是每个事件自己不断扫描世界。CK3 的事件资料也采用 trigger、scope、option、AI chance、after 和 onAction 的分层结构。[CK3 Event modding 镜像](https://ck3wiki.popush.cloud/index.php/%E3%82%A4%E3%83%99%E3%83%B3%E3%83%88_Mod)

## 九、行动接口也必须可扩展

大多数模组不应创建新的底层 resolver，但可以：

- 新增已有 resolver 的配置化行动；
- 修改谁能使用某行动；
- 增加前置条件、成本、冷却和 AI 权重；
- 增加新目标选择器；
- 给行动追加事件和关系后果；
- 通过 patch 调整原行动。

例如“请求宴会支持”和“请求宗教投票支持”可共用 politics.request_support resolver，只替换：

- 支持对象类型；
- 谁有资格支持；
- 可提出的条件；
- 到期时间；
- 公开性；
- 失信后果；
- AI 权重。

只有真正改变结算算法时才需要代码插件。

## 十、AI 目标也应由数据定义

一个 AI 目标包含：

    {
      id: 'mymod.ai_goal.lower_ducal_authority',
      validFor: { ... },
      activateWhen: { ... },
      priority: { base: 30, modifiers: [ ... ] },
      successWhen: { ... },
      abortWhen: { ... },
      budget: {
        gold: 100,
        actionsPerMonth: 2,
      },
      allowedActions: [
        'core.politics.request_support',
        'core.promise.make',
        'core.social.threaten',
        'core.information.blackmail',
      ],
      stages: [
        'recruit_support',
        'issue_ultimatum',
        'negotiate_or_rebel',
      ],
    }

模组作者可以不写 AI 代码，就让 NPC 理解新内容该怎样使用。规则引擎生成合法候选，LLM 只负责重要角色的取舍和表达。

## 十一、Prompt 扩展不能变成任意提示词注入

酒馆角色卡比普通单机游戏多一层风险：模组文本会进入 LLM 上下文。建议：

- Prompt 文件只能放入预定义槽位：世界风格、角色口吻、场景写作、内容禁区；
- 模组不能替换系统级安全规则、状态边界和行动 schema；
- 每个 prompt fragment 声明用途、优先级、最大 token 和适用对象；
- 加载器过滤“忽略上文、调用未授权工具、泄露完整状态”等越权指令；
- AI 可用行动列表永远由引擎生成，不从模组自然语言里解析；
- 不可信内容包默认不获得 promptFragments 权限；
- 调试界面显示本次生成实际拼装了哪些片段。

长对白素材可以使用 Markdown，但它只能影响表达，不能定义硬效果。

## 十二、加载、覆盖与冲突

### 1. 加载顺序

1. 引擎内建 schema 和 resolver；
2. core 基础内容包；
3. 依赖图拓扑排序；
4. 用户 playset 顺序；
5. patches；
6. 本地开发热重载层。

### 2. 四种明确操作

| 操作 | 含义 |
|---|---|
| add | 新增 ID；已存在则报错 |
| replace | 完整替换，必须显式声明 |
| patch | 只修改指定字段 |
| remove | 删除或禁用对象，必须说明存档回退策略 |

不能默认“最后加载者悄悄覆盖”。若两个模组 patch 同一字段：

- 加载器显示冲突；
- 用户可选择顺序；
- 调试器展示最终有效值和每一层来源；
- 严重引用冲突可阻止开局，但不破坏已有文件。

### 3. Patch 示例

    {
      operation: 'patch',
      target: 'core.action.declare_war',
      changes: [
        {
          op: 'add',
          path: '/preconditions/all/-',
          value: { scope: 'actor', hasModifier: 'mymod.war_permission' },
        },
      ],
    }

Patch 路径只能作用于 schema 允许的字段，不能修改函数或任意运行时对象。

## 十三、编译与校验流程

模组不应在运行中边读边猜。开局前执行：

    读取文件
      → JSON5/Markdown/GeoJSON 解析
      → Zod schema 校验
      → 命名空间和引用解析
      → 依赖、循环和冲突检查
      → 条件/效果 DSL 编译
      → 本地化和素材检查
      → AI 行动可达性检查
      → 测试场景
      → 生成内容哈希
      → 启动游戏

Zod 可把同一 schema 同时用于 TypeScript 类型推导和运行时解析，并能返回具体错误位置。[Zod 官方文档](https://zod.dev/basics)

模组错误应给出：

- 文件和行列；
- 对象 ID；
- 字段路径；
- 期望类型；
- 实际值；
- 相关定义来源；
- 修复建议。

一个普通内容包出错时优先禁用该包并给出报告，不让整个酒馆页面白屏。

## 十四、必须提供的模组工具

CK 的易修改不只来自文本格式，也来自能够快速试错。建议内置：

### 1. 内容检查器

- 搜索最终有效定义；
- 查看对象来自哪个包；
- 展示被哪些 patch 修改；
- 跳转到引用和反向引用。

### 2. Trigger 解释器

对选定人物/事件显示：

- 哪些条件通过；
- 哪些失败；
- 当前 scope 是谁；
- 哪个值来自哪条规则。

### 3. AI 决策追踪

- 当前目标；
- 候选行动；
- 每项效用分；
- LLM 是否参与；
- 为什么最终行动合法或被拒绝。

### 4. 事件浏览器

- 手动触发事件；
- 查看候选权重；
- 冻结随机种子；
- 跳转事件链；
- 查看冷却和唯一键。

### 5. 命令控制台

只调用注册命令，不开放 eval：

- 触发事件；
- 推进日期；
- 切换人物；
- 给资源；
- 查看/设置调试标记；
- 验证一个行动；
- 导出当前快照。

### 6. 热重载

开发模式中允许重载：

- 本地化；
- 事件文本；
- 权重；
- 条件；
- AI 目标；
- 非结构性 UI 配置。

改变地图拓扑、schema、历史人物 ID 或 resolver 时要求重新载入剧本。

### 7. 无头测试

每个内容包可附 tests：

- 给定世界夹具；
- 在固定日期、人物、地点发出命令；
- 期望事件是否可触发；
- 期望行动合法/非法；
- 期望状态差分；
- 运行 100 次模拟检查分布和死循环。

## 十五、存档兼容

存档必须记录：

- 引擎版本；
- schema 版本；
- 内容包 ID、版本和哈希；
- 加载顺序；
- 已实例化事件和行动所使用的 definitionVersion；
- 随机种子；
- 迁移记录。

模组升级可以提供：

    migrations/
      1_to_2.json5
      2_to_3.json5

迁移能：

- 重命名 ID；
- 替换失效特质；
- 将旧字段映射到新字段；
- 为新增字段补默认值；
- 终止已经不存在的事件链并生成说明。

若卸载模组：

- 纯文本/素材缺失可用占位；
- 失效关系修正可安全移除；
- 失效头衔、人物、地图或 resolver 可能阻止读取，并明确告诉用户依赖；
- 不允许静默删除大片世界状态。

## 十六、UI 模组边界

首版不要承诺 CK3 级完整 GUI 改写。可以先提供：

- 主题色和字体；
- 图标、纹章和地图纹理；
- 人物卡字段分组；
- 侧栏自定义数据块；
- 事件卡皮肤；
- 地图模式定义；
- 通过受限组件库组成新面板。

禁止内容包直接插入任意 HTML、script 或全局 CSS。需要自定义代码的 UI 插件进入可信代码层。

## 十七、与 SillyTavern 角色卡的关系

建议把“大前端卡”拆成：

- 引擎包：随卡或扩展提供；
- 核心规则包：中世纪通用规则；
- 历史剧本包：1066 布列塔尼；
- 对话风格包：人物口吻和场景写作；
- 用户模组包：导入的 zip/目录。

角色卡消息变量只保存当前 playset、存档快照和必要索引；大量静态定义不应每次塞进 AI 上下文。AI 网关按当前人物、场景和可用行动裁剪数据。

## 十八、分阶段实现

### M0：内部数据驱动

- JSON5 加载；
- Zod 校验；
- 命名空间；
- 人物、头衔、地点、事件、行动和本地化注册；
- core 内容也用相同格式。

### M1：可用内容包

- manifest；
- 依赖；
- add/replace/patch/remove；
- 冲突报告；
- 内容检查器；
- 导入/启用/停用。

### M2：AI 与脚本扩展

- 数据化 AI 目标；
- Prompt 槽位；
- onActions；
- 自定义互动和活动；
- Trigger 解释器和 AI 追踪。

### M3：创作工具

- 热重载；
- 事件浏览器；
- 可视化编辑器；
- 无头模拟和测试；
- CSV 导入/导出。

### M4：可信代码插件

- 权限模型；
- 独立 API；
- 沙箱/签名策略；
- 自定义 resolver 和 UI 组件。

## 十九、验收标准

1. 不修改 TypeScript 就能新增一个人物、伯爵领、事件和决议；
2. 不修改 TypeScript 就能让 AI 使用一个基于现有 resolver 的新互动；
3. 本体 1066 剧本本身就是可禁用内容包；
4. 条件失败能解释到具体字段；
5. 模组不能通过数据文件执行任意 JavaScript；
6. 两个模组修改同一字段时有明确冲突报告；
7. 加载顺序和最终有效定义可检查；
8. Prompt 模组不能改变硬状态权限；
9. 模组错误不会让整个前端无提示崩溃；
10. 存档记录所有模组版本和哈希；
11. 常见内容修改可热重载；
12. 每个包可带固定种子测试；
13. 普通作者只需文本编辑器即可制作内容；
14. 高级作者以后可通过受信插件扩展算法，但与普通内容包隔离。

## 二十、结论

要接近 CK 的扩展性，重点不是复制它的大括号语法，而是复制它的**分层开放方式**：

- 数据对象可新增；
- 条件和效果可组合；
- 事件与 onAction 可挂接；
- AI 权重可修改；
- 历史与本地化分离；
- 文件夹就是清楚的扩展点；
- 本体和模组使用同一套内容管线；
- 调试器能解释“为什么没有生效”。

在当前仓库里，以 JSON5 + Zod + 注册式规则 DSL 实现这套能力，比重新创造 CK 文本解析器更轻、更安全，也更贴合 TypeScript 和浏览器环境。
