# CK3 机制研究：面向“酒馆领主 RPG”的取舍稿

> 研究日期：2026-08-10  
> 研究范围：地图与领地层级、角色互动、活动与旅行、摄政、宣战/占领/战后领地变化。  
> 标记约定：**CK3 事实**指原作机制；**移植建议**指面向本项目的再设计，不声称与 CK3 完全一致。

## 一页结论

1. 用户记忆中的“子爵领”应纠正为**男爵领（barony）**。CK3 中男爵领是地图上军队移动、地形和围城的省份；一个伯爵领通常包含数个男爵领，但男爵领不会脱离所属伯爵领。**伯爵领（county）才是最低可玩、最稳定的政治版图原子。**[CK3 Dev Diary #2](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-2-the-medieval-map.1274052/) 明确说明 CK3 把男爵领做成地图省份，但仍以伯爵领为玩法重点。
2. 地图至少要同时表达四种不同事实，不能只存一个“owner”：
   - 地理相邻关系；
   - 法理归属（de jure：某伯爵领依法属于哪个公国/王国/帝国）；
   - 现实统治（de facto：当前领主—封臣链，最终归属哪个最高领主）；
   - 战时占领（occupation：临时军事控制）。
3. **围下来不等于拿到地。**围城只产生临时占领和战争分数；战争结束时，才按开战理由（CB）规定的胜利结果转移称号、改换封臣关系或维持原状。
4. CK 的精华不是“地图染色”，而是**每块地背后都有一个人、继承关系、宣称和封臣网络**。地图只是人物关系的可视化结果。
5. 酒馆版本最值得移植的是：
   - 基于位置的会面与对话；
   - 信件提供远程但受限的互动；
   - 活动把“地点、宾客、目的、事件、奖励”串成一段可对话的剧情；
   - 出巡把领地管理、人物关系和地图旅行合成同一玩法；
   - 摄政让玩家离开首都真正有政治风险。
6. 不应让 LLM 直接判定领地转让、谋杀、婚姻或战争结果。LLM 负责人物语言、理由、反应与提议；规则引擎负责合法性、成本、接受度、掷骰和状态变更。

## 1. 地图、男爵领、伯爵领与称号层级

### 1.1 先把几个概念拆开

| 概念 | CK3 中的作用 | 酒馆移植建议 |
| --- | --- | --- |
| 男爵领 Barony | 最小地图省份；有地形，可供军队移动；可能包含城堡、城市、神殿或空地；不能作为独立可玩领地 | 首版可作为伯爵领内部地点/节点，不必成为独立政治单位 |
| 伯爵领 County | 最低可玩称号；由若干男爵领组成；领伯爵领称号者必定拥有其伯爵领首府 | **版图颜色、永久易主、征税与基本领主归属的核心单位** |
| 公爵领 Duchy | 一组法理伯爵领组成的高阶称号 | 作为伯爵领集合和封臣层级，不必另画一层几何 |
| 王国 Kingdom | 一组法理公爵领组成的高阶称号 | 同上；允许下辖公爵、伯爵与直属地 |
| 帝国 Empire | 一组法理王国组成的高阶称号 | 常规剧本最高层即可 |
| 霸权 Hegemony | 2025 年《All Under Heaven》加入、位于帝国之上的特殊称号层；主要服务中国等少数超大型政治体 | 非 MVP；除非剧本确实需要“皇帝之上的共主” |

CK3 的传统层级是“男爵领 → 伯爵领 → 公爵领 → 王国 → 帝国”。2025 年 10 月发布的《All Under Heaven》又加入了特殊的“霸权”层级，但官方将其定位为中国等少数特殊超帝国，而不是每局都要使用的通用层级。[官方发布说明](https://www.paradoxinteractive.com/media/press-releases/press-release/establish-a-new-hegemony-in-all-under-heaven)

男爵领还有两个重要约束：

- 一个伯爵领通常有 2–5 个男爵领（原版地图存在例外）。
- 男爵领不会离开其伯爵领，因此不会出现“同一伯爵领的一小块永久属于另一个国家”的 CK2 式飞地。CK3 的最低可玩等级仍是伯爵。

这些约束见 [CK3 Dev Diary #2：The Medieval Map](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-2-the-medieval-map.1274052/)；男爵领首府和地产的细节可对照 [CK3 Wiki 镜像：Barony](https://ck3wiki.popush.cloud/index.php/%E7%94%B7%E7%88%B5%E9%A0%98)。

CK2/CK3 在这里必须明确区分：**CK2 的地图最小省份是伯爵领，男爵领只存在于伯爵领界面中；CK3 才把男爵领做成可移动、可围攻的地图省份。**两代的最低可玩等级都仍是伯爵，因此酒馆版若以伯爵领作为主地图格，更接近 CK2 的地图粒度；若再给每县加入内部地点/要塞节点，则吸收了 CK3 的精华，而不必复制其完整省份规模。

### 1.2 法理归属不是现实统治

CK3 最值得保留的地图概念是 **de jure 与 de facto 分离**：

- **法理归属 de jure**：一块伯爵领“依法”属于哪个公国，公国属于哪个王国，王国属于哪个帝国。它提供创设、篡夺、宣称和“合法领主”的依据。
- **现实统治 de facto**：这块地现在实际处于谁的封臣链之下。诺曼底法理上可以属于法兰西，实际统治者却可能是英格兰国王的领地持有人。
- **角色所持称号**：一个人可以同时持有多个不连续称号；其最高阶的“主要称号”决定领国名称、纹章和地图主色。参见 [CK3 Wiki 镜像：Title](https://ck3wiki.popush.cloud/index.php/%E7%A7%B0%E5%8F%B7)。

因此，公国/王国/帝国不是地图上另造的一套小格，而是对同一批伯爵领的**法理分组与政治封装**。它们的边界可以通过聚合伯爵领得到。

### 1.3 推荐的数据分层

地图层最好至少分成以下对象，而不是互相嵌套到无法修改：

```text
Barony（地理/旅行/围城）
  id, countyId, geometry, neighbors, terrain, holding, fortLevel

County（永久版图原子）
  id, baronyIds, capitalBaronyId
  titleHolderId
  deJureDuchyId
  occupiedBaronyIds / occupyingSideId
  control, development, culture, faith

HigherTitle（公国/王国/帝国）
  id, tier, deJureChildTitleIds, holderId, capitalCountyId

VassalRelation（现实政治）
  liegeId, vassalId, contract, obligations

War（临时军事状态）
  attackerSide, defenderSide, casusBelli, targetTitleIds
  occupations, warScore, prisoners, status
```

关键不变量：

- `barony.countyId` 在普通玩法中不可改变。
- 地图政治主色应由 `county.titleHolder → topLiege → primaryTitle.color` 推导，而不是把颜色写死在伯爵领上。
- 战时占领只能写入 `War.occupations` 或临时占领字段，不能直接覆盖 `titleHolderId`。
- 公爵领、王国、帝国边界由法理子称号集合计算；实际领国边界则由最高领主链计算。

### 1.4 相邻线与地图渲染

用户提到“根据伯爵领的连接线”。这里应区分：

- **连接图**适合寻路、判定陆地接壤、战争前线、信使距离；
- **多边形几何**适合把领地涂色并显示动态边界。

若只保存节点和连线，可以做策略图，却很难获得 CK 式“区域填色”。推荐首版每个伯爵领使用一个 SVG polygon/path，再另存 `neighbors` 邻接表。点击伯爵领后，可在侧栏或局部放大图显示其内部男爵领节点。

首版不必画 CK3 规模的 2–5 个男爵领多边形。可以让：

- 伯爵领 = 可填色的主地图多边形；
- 男爵领 = 伯爵领详情中的城堡、城镇、寺院、野外地点节点；
- 伯爵领邻接 = 军队和普通旅行的基础边；
- 特殊山口、海峡、河流 = 邻接边上的通行条件与危险修正。

这保留了 CK3 的政治结构，同时大幅降低地图素材、寻路和围城复杂度。

## 2. 宣战、占领与领地变化

### 2.1 宣战不是自由圈地

CK3 的战争先选择**开战理由（Casus Belli，CB）**。CB 定义：

- 为什么可以开战（个人宣称、法理、征服、宗教、独立、废黜等）；
- 目标是谁、争夺哪些称号；
- 宣战成本（常见是威望或虔诚）；
- 胜利、白和平与失败分别发生什么。

官方 [CK3 Dev Diary #18](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-18-men-at-arms-mercenaries-and-cbs.1357939/) 直接说明“CB 决定战争获胜或失败时发生什么”。这条应成为本项目的硬规则。

### 2.2 围城与临时占领

CK3 的大致流程是：

1. 军队进入有要塞的男爵领并满足围城条件；
2. 围城完成后，占领该男爵领；
3. 一个伯爵领内所有要塞化地产都被占领后，整个伯爵领才算完全占领；
4. 占领战争目标、敌方首都，赢得战斗或俘虏重要人物都会产生战争分数；
5. 战争分数达到条件后，才能强制要求、接受投降或议和。

可对照 [CK3 Wiki 镜像：Warfare](https://ck3wiki.popush.cloud/index.php/%E6%88%A6%E4%BA%89) 的 Siege、Occupation、War score 与 Ending wars 小节。

**移植建议：**首版将“一个伯爵领内的多个要塞逐一围攻”压缩成一次伯爵领围城，但保留下列状态：

```text
未交战 → 被围城 → 被占领（条纹/火焰覆盖） →
  战争结束且 CB 转移称号：永久易主并重绘主色
  战争白和平/失败：撤销占领，恢复原主色
```

这样既满足“势力随占领变化”的视觉反馈，又不会把临时占领误当永久吞并：

- 永久势力颜色保持原领主色；
- 占领者用斜纹、描边、旗帜或半透明覆盖；
- 只有和平结算后才切换实色与称号持有人。

### 2.3 战后到底谁拿到地

不能写成“谁占了就归谁”。至少要区分：

| CB 类型 | 建议的胜利结果 |
| --- | --- |
| 玩家/某人的伯爵领宣称 | 争议伯爵领称号授予宣称者；若宣称者等级关系不合适，可能成为独立领主 |
| 法理夺取 | 将目标伯爵领或其持有人纳入合法上级的封臣链，具体取决于 CB 定义 |
| 征服 | 转移指定目标内的称号或使原领主臣服 |
| 圣战 | 按宗教规则剥夺、转封或臣服目标地的异教领主 |
| 独立战争 | 成功后切断对上级的封臣关系，不必改变各伯爵领持有人 |
| 废黜/拥立 | 更换高阶称号持有人，伯爵领本身可能仍由原封臣持有 |
| 白和平 | 通常不转移目标称号；解除占领，按 CB 给予代价或保留宣称 |

因此一次王位战争可以只更换“国王这个人”，地图伯爵领颜色甚至可能保持不变；一次伯爵领宣称战争则会让一个县永久易主。**这正是 CK 与普通吞并式地图游戏的重要差异。**

### 2.4 首版战争应保留与舍弃的内容

应保留：

- CB 和明确战争目标；
- 伯爵领邻接与前线；
- 围城、战斗、战争分数、重要俘虏；
- 临时占领覆盖与战后和平结算；
- 宣称者可能成为谁的封臣；
- 停战期和撕毁停战的信誉代价。

首版舍弃：

- 数十兵种克制；
- 每个男爵领单独驻军、补给、地形宽度；
- 复杂攻城阶段与攻城器械编制；
- 多个盟军的精确战争贡献分成；
- CK3 的全部 CB 特例。

## 3. 角色互动：应当移植的“人物驱动”核心

### 3.1 角色不是一张好感度卡

CK3 用人物能力与性格共同决定行为。官方 [CK3 Dev Diary #7](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-07-characters-portraits.1295264/) 强调：角色通常用少量醒目的人格特质概括，性格特质显著影响 AI 行为，而不是只提供小数值。

酒馆版角色的建议最小状态：

- 五项能力：外交、军事、管理、谋略、学识；武勇可作为第六项个人战斗能力；
- 3 个左右核心人格特质；
- 年龄、健康、压力、婚姻与亲属；
- 文化、信仰、语言；
- 所在男爵领/伯爵领、是否旅行、所属宫廷；
- 称号、领主、封臣、职位；
- 对重要人物的好感、恐惧、关系类型（朋友、情人、宿敌等）；
- 宣称、秘密、把柄（hook）、罪行；
- 短期目标与长期野心。

### 3.2 把所有互动做成同一种“规则外壳”

建议每项互动都使用统一字段：

```text
actor / target
channel: 当面 | 信件 | 使者 | 公开仪式
visibility: 公开 | 私下 | 秘密
preconditions: 位置、关系、身份、法律、距离、冷却
costs: 金钱、威望、虔诚、压力、把柄、行动时间
acceptance: 基础值 + 好感 + 性格 + 利益 + 恐惧 + 把柄 + 风险
resolution: 接受 | 拒绝 | 反提案 | 掷骰/计谋
effects: 状态变更
memory: 双方如何记住此事
```

这允许对话很多样，底层却保持可验证。

### 3.3 互动类别

首版可从下列类别中各取少量高价值互动：

1. **关系经营**：交谈、赠礼、称赞、安抚、结交、勾引、求爱、羞辱、挑战决斗。
2. **婚姻与家族**：提议婚约、安排监护、送出/接收人质、认亲或收养、要求离婚。
3. **宫廷与职位**：邀请入廷、招募、任命/撤换顾问、授予荣誉职位、赐予称号。
4. **领主—封臣**：修改义务、要求皈依、转封封臣、请求议席、请愿领主、要求停止战争。
5. **司法与强制**：逮捕、赎金、释放、放逐、处决、剥夺称号；没有合法理由会造成暴政或反抗。
6. **外交与战争**：结盟、召集盟友、臣服、要求效忠、宣战、议和。
7. **秘密政治**：打探秘密、揭露、勒索、伪造把柄、谋杀、绑架、招募同谋。

请愿领主是很适合酒馆对话化的原版例子：封臣可以要求议会席位、请求自己有宣称的称号、要求解决派系或债务；领主可拒绝，但拒绝和不合理回应会损害关系。[CK3 Dev Diary #74](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-74-please-kaiser-can-i-have-some-more.1491791/)

### 3.4 秘密、把柄与计谋

CK3 的经典链条是：

```text
发现秘密 → 揭露秘密造成社会/法律后果
         → 或勒索为把柄 → 强迫婚姻、改封建契约、拉人入伙等
```

原始设计见 [CK3 Dev Diary #5：Schemes, Secrets and Hooks](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-5-schemes-secrets-and-hooks.1289167/)。不过 2024 年免费 1.13 更新已经重做计谋，不应照抄旧版“固定十格进度”。当前更值得借鉴的结构见 [CK3 Dev Diary #157：Schemes & Stories](https://forum.paradoxplaza.com/forum/developer-diary/dev-diary-157-schemes-stories.1703863/)：

- 一项复杂计谋只需要少量关键同谋，且同谋有不同角色；
- 速度、潜力上限、保密性可以分别优化；
- 计谋按阶段增长成功机会，并产生可用于拉拢同谋或执行的优势；
- 泄密次数累积，达到上限则计谋崩溃；
- 玩家决定何时以当前成功率冒险执行；
- 安抚等简单计谋可用更轻量的自动流程。

**移植建议：**首版复杂计谋只做“谋杀、绑架、伪造把柄”三类，每类 2–4 个同谋职位；普通互动不必全部套计谋系统。

### 3.5 酒馆对话如何接入规则系统

建议一次对话由三层组成：

1. **会面资格层**：双方是否同地点、是否被允许进入、是否有信件/使者渠道、是否在外交距离内。
2. **叙事层（LLM）**：人物依性格、关系、记忆和当前议题说话，可提出条件或反提案。
3. **规则结算层**：把对话中的有效提议转成结构化互动，验证条件并结算；未通过验证的台词只算态度表达，不修改世界状态。

例如玩家说“我把北境给你，你支持我谋反”：

- LLM 可以让对方感兴趣、怀疑或索要人质；
- 系统检查玩家是否真拥有可许诺的称号、是否能转封、目标是否有资格、许诺是否登记；
- 对方接受后记录一个 `promise`，等谋反成功/失败后结算；
- LLM 不得仅凭一句台词直接把北境写到对方名下。

这能防止长对话把地图状态“聊崩”。

## 4. 活动、旅行与出巡

### 4.1 活动的通用结构

《Tours & Tournaments》重做后的活动不是单个随机事件，而是一个可复用框架：

```text
活动类型
→ 选择举办地点
→ 活动选项（预算、规模、准备）
→ 主办者目的 Intent
→ 邀请规则、手动宾客、特殊宾客
→ 主办者和宾客旅行
→ 若干阶段/场景与事件
→ 成功进度或成果等级
→ 关系、资源、特质、声望等奖励与长期记忆
```

官方概览指出宴会、狩猎和朝圣都被重做，并加入大巡游、比武大会、大婚礼；大型活动通过 Options 与 Intents 改变奖励和事件类型。[Tours and Tournaments 官方页面](https://www.paradoxinteractive.com/games/crusader-kings-iii/add-ons/crusader-kings-iii-tours-and-tournaments)、[Dev Diary #121：An Active Life](https://forum.paradoxplaza.com/forum/developer-diary/dev-diary-121-an-active-life.1576149/)

**适合移植的关键不是活动数量，而是这一套通用骨架。**首版做 4 种活动足够：宴会、狩猎、朝圣、领主出巡。

### 4.2 旅行系统

CK3 的旅行把人物从抽象“宫廷名单”重新钉回地图：

- 每个角色有真实位置；
- 活动不在当前位置时，主办者和宾客都要旅行；
- 旅行计划有速度与安全，沿途省份有危险；
- 可编辑路线、添加途经点；
- 随行人员、车队主管和旅行选项改变速度/安全；
- 沿途触发疾病、盗匪、奇遇、地标等事件；
- 部分互动受位置限制。官方举例：安抚或学习语言可在旅行时继续，勾引则会在双方不共处时冻结。

详见 [CK3 Dev Diary #119：Tours and Travel](https://forum.paradoxplaza.com/forum/developer-diary/dev-diary-119-tours-and-travel.1573700/)；Steam 的[官方公告聚合页](https://store.steampowered.com/news/posts/?appids=1158310&enddate=1680622976&feed=steam_community_announcements)保留了速度、安全、危险、路线编辑和出巡停靠点的摘要。

### 4.3 出巡是最适合酒馆的桥梁系统

CK3 的 Grand Tour 是君主带着宫廷依次拜访直属封臣。它把三种玩法连接起来：

- 地图：选择多站路线并承担旅途风险；
- 领地管理：提高地方控制、收税、展示君威、压制派系；
- 人物互动：与封臣私宴、结友、取得把柄、发现秘密、接触其家人和廷臣。

原版有三种总路线目的：

- **威严 Majesty**：展示正统性与声望；
- **恐吓 Intimidation**：提高恐惧，迫使敌对封臣退缩；
- **征税 Taxation**：收取额外财富。

单站又可选择巡视领地、参加私宴、观看文化庆典等不同内容。[Dev Diary #119](https://forum.paradoxplaza.com/forum/developer-diary/dev-diary-119-tours-and-travel.1573700/)

### 4.4 建议的“同地点人物”对话规则

用户提出“只有出巡到同一地点才可以交互”，这个方向很好，但若绝对化会让日常政治过于封闭。建议分级：

| 渠道 | 可做什么 | 不能或不适合做什么 |
| --- | --- | --- |
| 同地点当面 | 深度交谈、说服、私宴、勾引、决斗、交换人质、秘密协商 | 无 |
| 同一活动但不同阶段 | 简短寒暄、安排稍后会面、观察对方 | 深度私密互动需创造场景 |
| 信件 | 问候、请求、提议婚姻/联盟、威胁、谈判、持续安抚 | 需要身体接触、秘密安全环境或即时仪式的互动 |
| 使者 | 正式外交、递交礼物、宣战书、议和条件 | 难以建立亲密关系；信息可能失真 |
| 无渠道/超距离 | 只能通过间接情报了解 | 直接对话与即时请求 |

这样既奖励旅行和共处，也不会让领主无法治理远方封臣。

## 5. 摄政系统

### 5.1 何时产生摄政

CK3 的摄政用于领主不能亲自处理领国事务时，例如：

- 君主离开自己的领国旅行；
- 君主年幼；
- 君主失能；
- 君主被外国囚禁等。

短期离境通常只是普通摄政；持续太久或权力被摄政巩固后，可能成为更难解除的**根深蒂固摄政（Entrenched Regency）**。官方完整设计见 [Dev Diary #122：Regencies and Elegance of the Empire](https://forum.paradoxplaza.com/forum/developer-diary/dev-diary-122-regencies-and-elegance-of-the-empire.1576961/)；若官网触发验证，可参考保留正文的[土耳其语转载](https://forum.strategyturk.com/konu-gunluk-ck3-naiplikler-ve-elegance-of-the-empire)。

### 5.2 权力天平

摄政核心是领主与摄政之间的“权力天平”：

- 天平偏领主：摄政近似临时管家；
- 天平偏摄政：摄政获得更多仿照君权的能力，领主行使本来免费的权力也要付出政治代价；
- 天平有受局势影响的自然回归点；
- 双方可投入金钱、威望、虔诚等政治资本推动天平；
- 摄政完成领主交给的任务可以忠诚服务、分走利益或侵吞利益；
- 滥用摄政权会产生类似“同僚对其不满”的政治摩擦，使其他封臣更可能反对或参与针对摄政的阴谋。

摄政可逐步获得侵吞资金、逮捕、伪造宣称、剥夺称号、转移封臣、修改自身契约等权力；极端情况下可拉拢强力封臣发动政变。领主回归后，普通摄政容易结束，根深蒂固摄政则可能需要收买、斗争或强硬手段清除。

### 5.3 酒馆版简化模型

首版只需：

```text
regentId
cause: travel | child | incapable | captive
loyalty: loyal | selfInterested | ambitious
power: 0..100
mandate: stability | finance | defense | diplomacy
abuses: embezzlement, arrest, patronage, titlePlot
entrenched: boolean
```

推荐阈值：

- 0–29：代理签署与日常行政；
- 30–59：可影响任命、财政和对封臣的处置；
- 60–79：可为自己制造宣称、干预转封和契约；
- 80–100：可组织逼宫/政变。

每个时间回合让摄政做一次“履行授权 / 中饱私囊 / 扩张权力”的选择。玩家通过信件能有限干预；亲自回国才获得完整处理能力。这比复制原版所有摄政互动更适合对话 RPG。

## 6. 哪些是 CK 精华，哪些复杂度应舍弃

### 6.1 必须保留的精华

| 精华 | 为什么必须保留 |
| --- | --- |
| 人物而非国家 | 玩家扮演会死、会继承、会被爱恨的人；领地属于人物和称号，不属于抽象国家 |
| 伯爵领政治原子 | 可稳定染色、转移、征税、继承和作为战争目标 |
| 法理与现实统治分离 | 产生宣称、合法领主、不满、收复故土和边界故事 |
| 封臣链 | 让“我控制的地图”与“我亲自拥有的地”不同 |
| 宣称/CB/和平结果 | 防止战争退化为走到哪里吞到哪里 |
| 继承与王朝 | 这是 CK 长线故事的发动机，不能因本次研究重点不在此而漏掉 |
| 性格、关系、秘密、把柄 | 让同一个按钮面对不同人物得到不同故事 |
| 真实位置、旅行、活动 | 把人物互动重新连接到地图 |
| 摄政 | 让离开首都、幼主和失能都产生内部政治 |
| 派系/强力封臣 | 让稳定统治不仅取决于外战胜负 |

### 6.2 首版应压缩或舍弃

| 原作复杂度 | 首版处理 |
| --- | --- |
| 男爵领完整政治与地产建筑树 | 仅作地点、要塞和旅行节点 |
| 数十兵种、克制、补给与地形宽度 | 压成兵力、质量、统帅、地形、补给五项 |
| 全部文化传统、宗教教义、政府制 | 先做一套封建规则，文化/宗教只保留关系与合法性标签 |
| 精确税率、征召兵和封建契约条款 | 先做低/中/高义务和少量特权 |
| 百年法理漂移的精确模拟 | 可保留长期进度条，但不是 MVP |
| 数百互动、活动与事件 | 先做少量能互相组合的通用模板 |
| 原版全部计谋参数 | 保留阶段、关键同谋、泄密与执行时机 |
| 每个封臣全量 AI 每日运算 | 非重点角色低频批处理；当前场景角色才高精度 |
| 霸权、行政制、游牧制等特殊大系统 | 作为剧本扩展，不进入通用首版 |

### 6.3 用户当前构想中容易遗漏、但建议补入的系统

1. **继承与王朝**：人物死亡后谁接手哪些称号；分割继承会自然制造兄弟竞争和地图裂变。
2. **直辖领与封臣领区分**：君主不是亲自拥有全国每个伯爵领；过量直辖应有管理惩罚。
3. **强力封臣、派系与内战**：低好感不是单纯减税，应能形成独立、降权、拥立和废黜派系。
4. **合法性/暴政/罪行**：抓人、杀人、剥地不能只看玩家按钮是否可点；有理由与无理由的政治后果应不同。
5. **议会与宫廷职位**：用少量职位给重要 NPC 稳定的日常作用，并制造“不给我席位”的矛盾。原版职位会按人物能力与特质产生不同适任度，可参考 [CK3 Dev Diary #73](https://forum.paradoxplaza.com/forum/developer-diary/ck3-dev-diary-73-serving-on-her-majestys-court.1490806/)。
6. **压力**：角色违背人格做决定时付出压力，防止最优解把性格扮演完全覆盖。
7. **信息边界**：远方人物的精确数值、秘密与动机不应自动可见；靠来信、间谍、宾客和传闻逐步获得。
8. **承诺与人情债**：对话谈判产生可追踪承诺，违约影响信誉、关系和派系选择。
9. **时间成本**：活动、旅行、计谋和交涉都要推进时间，否则玩家可在一天内说服全世界。

## 7. 推荐的最小可玩循环

> 后续决定：用户已确认首条竖切使用 12—20 个伯爵领。下列 20—40 个伯爵领是本研究形成时对较完整 P0 的原始估计，不再作为首条竖切范围。

### P0：地图与政治骨架

- 20–40 个伯爵领多边形和邻接表；
- 每个伯爵领 1–3 个内部地点节点；
- 伯爵领持有人、最高领主、法理公国/王国；
- 点击地图查看领主、宣称、驻军、控制、文化/信仰；
- 主色表示现实领国，边框/图层切换显示法理层级。

### P1：人物与对话

- 玩家与 10–20 个重点角色；
- 位置、人格、能力、关系、记忆、称号和野心；
- 当面交谈与信件；
- 赠礼、请求、威胁、婚约、任命、赐地、逮捕、结盟等 10–15 个互动；
- LLM 负责对话，规则引擎负责状态结果。

### P2：战争与版图变化

- 宣称与 3–4 种 CB；
- 相邻移动、战斗、围城、战争分数；
- 占领覆盖与和平结算分离；
- 战后转移伯爵领称号或更换高阶称号持有人。

### P3：旅行、活动与摄政

- 出发、沿路径移动、抵达、回程；
- 宴会、狩猎、朝圣、出巡四种活动模板；
- 活动宾客创造同地点对话窗口；
- 离开领国触发摄政和权力增长。

### 每回合/月的世界推进顺序

1. 处理旅行和角色位置；
2. 处理当前地点可见人物与对话行动；
3. 推进活动、计谋、围城和战争；
4. NPC 依据性格、利益和野心选择行动；
5. 结算收入、封臣态度、派系、摄政与承诺；
6. 触发少量叙事事件；
7. 写入结构化状态与精简人物记忆，再生成玩家可读摘要。

## 8. 建议接下来向用户确认的问题

这些问题会实质改变数据结构和 MVP，不宜由开发者擅自决定：

1. 玩家是固定扮演一个不死角色，还是人物会死亡并继续扮演继承人？若无继承，CK 的王朝核心会被大幅削弱。
2. 地图规模希望是“一个王国 20–40 县”，还是“欧洲级数百县”？前者更适合酒馆上下文和前端性能。
3. 是否需要让玩家亲自带兵移动，还是战争以命令和阶段结算为主？
4. 一回合代表一天、一周还是一个月？对话、旅行、活动和战争都依赖统一时间尺度。
5. 成人/婚恋/背叛内容允许到什么程度？这决定勾引、婚姻、私生子、秘密和犯罪事件的边界。
6. AI 是否能主动发信、求见、威胁、宣战和组织阴谋，还是只有玩家主动点击才互动？建议必须允许 AI 主动，否则领主 RPG 会像静态菜单。
7. 玩家是否能自由和任何已知角色通信，还是信件也受外交距离、敌对封锁、身份和识字/使者限制？
8. 地图美术更偏历史地图、羊皮纸棋盘，还是低素材依赖的抽象政治图？这决定 SVG、Canvas/Pixi 和地点详情的方案。
