# 地图、领地层级与战争边界

## 先校正术语

CK 中从小到大的常规领地称号是：

`男爵领 Barony → 伯爵领 County → 公国 Duchy → 王国 Kingdom → 帝国 Empire`

这里不是“子爵领”。男爵领是最低级有地称号；伯爵领是最低可玩层级，也是最合适的战略地图基本单位。

CK3 中一个伯爵领包含 1—8 个男爵领。伯爵领首府是其中的主要男爵领，并随伯爵领称号持有者一起归属。一个伯爵领属于一个法理公国。来源可参见 [CK3 Wiki 镜像：男爵领](https://ck3wiki.popush.cloud/index.php/%E7%94%B7%E7%88%B5%E9%A0%98) 与 [CK3 Wiki 镜像：伯爵领](https://ck3wiki.popush.cloud/index.php/%E4%BC%AF%E7%88%B5%E9%A0%98)。

## 必须分开的三层地图状态

### 1. 法理归属（de jure）

回答“按传统和法律，这块地应属于哪个公国、王国、帝国”。它主要用于：

- 创建或宣称高阶称号；
- 判断谁是“正统上级”；
- 产生收复法理领地的战争理由；
- 形成长期政治目标。

首版建议法理结构固定。以后如果需要，再加入非常缓慢的法理漂移。

### 2. 实际统治（de facto）

回答“现在谁持有伯爵领、他效忠谁、最上层领主是谁”。地图常规势力着色来自这一层。

同一个法理公国的三个伯爵领可以分别被不同王国实际控制；一个国王也可以实际持有法理上属于别国的飞地。

### 3. 战争占领（occupation / controller）

回答“战争期间谁的军队暂时控制这里”。它不能覆盖所有权。建议用斜线、边框或旗标叠层显示，而不是直接把领地永久改成占领者颜色。

CK3 中包围完成后先占领男爵领；一个伯爵领内的全部要塞化据点被占领，才视为整个伯爵领被占领。占领带来战胜分和控制损失，战争结果才按战争理由转移称号。参见 [CK3 Wiki 镜像：战争](https://ck3wiki.popush.cloud/index.php/%E6%88%A6%E4%BA%89)。

## 推荐地图抽象

### 战略层：伯爵领多边形或节点

每个伯爵领必须具有：

- 唯一 ID；
- 名称与中心点；
- 地图形状（SVG path / polygon）；
- 相邻伯爵领 ID 列表；
- 地形与通行代价；
- 法理公国 ID；
- 当前伯爵领称号持有者；
- 当前战争占领者；
- 文化、信仰、发展、民意、控制度等地方状态。

相邻关系必须作为显式图保存，不要只依赖多边形是否视觉接触。旅行寻路、军队移动、外交距离与领土连通都使用这张图。

### 地点层：伯爵领内部男爵领

首版把男爵领当作县内地点而不是另一套大地图格：

- 城堡：领主住所、驻军、围城目标；
- 城市：贸易、旅店、行会、流言；
- 神殿：宗教互动、朝圣、学术或社团；
- 庄园/村落：狩猎、巡视、民情和生产事件；
- 特殊地点：大学、矿山、圣地、遗迹等。

这样既保留 CK 的县内层次，也不会让首版地图和寻路复杂度爆炸。角色的精确位置仍可保存为 `countyId + locationId`。

## 高阶称号不是“重复铺一张地图”

公国、王国、帝国应保存为称号对象，包含：

- 法理下属称号；
- 当前持有者；
- 继承法与特殊规则；
- 声望/合法性要求；
- 可能的法理首都；
- 当前实际封臣。

地图模式只是在同一批伯爵领上按不同字段着色：

- **领国模式**：按最上层实际领主着色；
- **直属封臣模式**：按玩家的直接封臣分色；
- **法理公国/王国模式**：按法理父称号分色；
- **战争模式**：所有权底色 + 占领斜线 + 战争目标描边；
- **人物位置模式**：显示玩家、重要角色、活动与军队。

## 最小数据语义示例

```ts
type CountyState = {
  id: string;
  deJureDuchyId: string;
  titleHolderId: string;
  topRealmRulerId: string;
  occupierRealmId: string | null;
  control: number;
  locationIds: string[];
  neighborCountyIds: string[];
};
```

这些字段不能合并成一个 `owner`。否则战争一占领，法理宣称、税收归属、封臣关系和停战后的恢复都会同时出错。

## 势力边界如何动态变化

地图渲染时不保存一条巨大“国家外轮廓”。每次根据伯爵领状态派生：

1. 取所有伯爵领的 `topRealmRulerId` 决定底色；
2. 相邻伯爵领的顶层领主不同，就绘制国境线；
3. 相同则只保留较淡的伯爵领内部线；
4. `occupierRealmId` 非空时加战争占领纹理；
5. 和平结算导致 `titleHolderId` 或领主链变化后，重新计算顶层领主和边界。

这会自然支持飞地、分裂领土、内战双方和封臣改换门庭。

## 领地变化的正确流程

### 战争期间

`宣战理由锁定目标 → 军队移动 → 围城男爵领要塞 → 临时占领 → 获得战胜分与事件 → 谈和`

### 和平结算

`校验战争结果 → 按战争理由确定被转移的称号 → 更新称号持有者/领主链 → 清除相关占领 → 产生休战、囚犯、控制度和关系后果 → 重绘地图`

占领不应自动吞并。否则所有战争都会变成无条件涂色扩张，宣称、继承、附庸化和有限战争目标就失去意义。

## 建议的首版地图规模

建议先做 24—60 个伯爵领、每县 2—5 个叙事地点。这个规模已经足以形成：

- 3—6 个主要领国；
- 多层封臣关系；
- 飞地和边境争端；
- 需要数段路程的巡游；
- 王国内战与外部战争；
- 足够密度的同地人物相遇。

如果一开始就做全欧洲，活跃角色、家谱、寻路、AI 上下文和月度模拟会同时失控。

## 需要后续决定的地图问题

- 使用历史欧洲缩略地图，还是原创大陆与原创贵族？
- 地图是否允许跨海相邻和海路风险？
- 军队是否显示为可移动棋子，还是只显示战役任务与路线？
- 男爵领是否只作地点列表，还是少数关键县可展开为县内小地图？
- 法理结构是否永远固定，还是允许数十年尺度的法理漂移？
