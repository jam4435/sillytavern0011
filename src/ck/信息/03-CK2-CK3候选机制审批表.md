# CK2 / CK3 候选机制审批表

> 用途：把 CK2、CK3 Wiki、官方手册、开发日志和主要扩展中的可迁移结构整理成可审批编号。它不是要求一次实现全部内容，而是帮助决定哪些进入核心版、扩展版、独立模式或明确舍弃。

> 审批状态（2026-08-10）：用户已原则同意本文默认路线。A 组进入首条竖切，B 组列入核心路线但不阻塞竖切，C 组在核心闭环稳定后扩展，D 组继续暂缓；默认历史剧本不启用明确超自然内容。

## 一、研究口径

这里的“看 Wiki 一遍”按**系统目录级审阅**执行：覆盖人物、王朝、领地、封臣、外交、战争、内阁、法律、阴谋、活动、旅行、摄政、社团、事件、宗教、文化、经济、疾病和主要特殊政体；不逐项复制数千个特质修正、事件文本、建筑数值或地区专属小事件。

筛选标准有四条：

1. 是否让“一个具体人物统治具体土地”更成立；
2. 是否能制造有条件、有后果的 AI 对话；
3. 是否能在 12—20 伯爵领的 HTML 小地图中形成可见反馈；
4. 是否值得为酒馆上下文、存档和规则复杂度付出成本。

标记说明：

| 标记 | 含义 |
|---|---|
| 竖切 | 第一条“出巡赴宴，争取两名封臣支持”需要 |
| 核心 | 完整领主 RPG 的通用骨架 |
| 扩展一 | 核心稳定后优先增加 |
| 扩展二 | 提供长期厚度，但可较晚加入 |
| 独立模式 | 会改变整套经济/身份/地图循环，单独制作 |
| 世界开关 | 依题材启用，默认不应强制 |
| 舍弃 | 不值得照搬，或只保留极简替代 |
| G / T / GT | 主要服务 HTML 游戏层 / 酒馆对话层 / 两者 |
| S / M / L / XL | 相对实现量，不代表实际工期 |

用户审批时可以直接回复：

> 通过 A、B、C 三组默认建议；SYS09 延后；CHR13 必须前置；ACT06 删除。

## 十三、仍需用户拍板的高影响问题

机制目录批准后，下一轮只需优先回答：

1. 真实欧洲的具体区域与开局年份；
2. 玩家固定为伯爵，还是拥有 2—3 县的小公爵；
3. 成功目标中的“两名封臣支持”具体支持什么：内阁议案、对抗派系、继承争议，还是一场即将发生的战争；
4. 是否接受“场景制暂停 + 日历按时段/天推进”的时间结构；AI 行动自动执行与协议记录已按用户反馈确立；
5. 角色死亡后是否继续扮演继承人；
6. 恋爱、通奸、私生子、酷刑和谋杀的内容尺度；
7. 超自然内容是完全禁用、保持暧昧，还是可用世界规则开启。
