# AI 正文追加脚本（普通 SillyTavern 角色卡）

## 用途

此脚本**不是武侠前端的一部分**，也不依赖武侠卡的 ChatInput、useMessageHandler、ERA、变量 AI 或 setChatMessages()。

入口参考「绑定Plus脚本」，但消息读写使用 SillyTavern 的**原生 API**：

- window.parent.SillyTavern.getContext().chat
- window.parent.SillyTavern.getContext().saveChat()
- 原生事件 MESSAGE_SENT
- updateMessageBlock()（可选，仅刷新现有 AI 气泡）

无需接管酒馆原有发送按钮、Enter、生成函数或重新生成流程。

## 示例

在酒馆普通输入栏输入：

~~~text
1:段誉的手边还有一页折叠的纸张。
我走到桌边，把纸张展开查看。
~~~

结果：

- 上一条 AI 回复的 active swipe 正文后追加「段誉的手边还有一页折叠的纸张。」
- 本轮 User 消息只保留「我走到桌边，把纸张展开查看。」
- 普通酒馆发送、模型选择、上下文构建和生成过程不变

多条标记行会逐行合并，行首前可以有空格。只有以标记开头的独立行会被识别，句子中途出现的标记不识别。

左下角 **扩展菜单 → AI 正文追加** 可以设置功能开关和自定义标记。设置存放在浏览器 localStorage，默认启用，默认标记为 1:。

## 真实执行时序

1. 酒馆正常发送；User 消息进入原生 chat。
2. 原生 sendMessageAsUser() 调用并等待 MESSAGE_SENT。
3. 此脚本读取新增 User 楼层和前一个 AI 楼层。
4. 标记内容追加到该 AI 的 mes，同时同步当前 swipes[swipe_id]。
5. User 的 mes 替换为没有标记行的文本。
6. 等待原生 saveChat() 保存，再让酒馆继续构建本轮 AI 上下文。

文本插入算法参考武侠前端：如果原 AI 回复尾部带有成对的 VariableThink / VariableInsert / VariableEdit / VariableDelete / era_data 系统标签，追加文字放在**这些尾部系统块之前**。没有系统尾块时就直接加在正文末尾。

## 保守策略

- **标记行和正常 User 内容必须同时存在**。只有标记没有 User 文字时，保留原文发送，避免产生空玩家楼层。
- 上一条不是 AI、聊天身份不可识别、swipe 与 mes 不一致、追加文本包含受保护系统标签时，不修改原聊天。
- saveChat() 抛错时恢复本次修改的内存字段，提示用户，原 User 内容作为正常消息继续发送。
- 此事件的调用时机在酒馆已经创建 User 楼层之后，因此发生错误时**不会**撤销该 User 楼层；这比尝试重写酒馆发送链更保守。
- 只处理原生 MESSAGE_SENT，不在生成、重新生成、切换 swipe 等场景重复追加。
- 某些其它扩展可能在同一事件中修改消息；这类扩展的监听顺序及复杂分支状态仍需要实机验证。
- 如果酒馆输入正则或宏在事件之前移除了标记，则无法识别标记。
- 若使用高度定制的第三方聊天发送框架（例如武侠前端），需另外校验它是否还触发标准 MESSAGE_SENT。

## 文件

- index.ts：扩展菜单、设置窗口、监听原生事件、读写聊天
- logic.ts：标记解析与系统尾块保护
- logic.test.ts：纯文本解析单元测试

## 手动回归测试

1. 无标记正常发信，不修改历史。
2. 一条标记 + 正常 User：分别落在目标 AI / User。
3. 多条标记合并顺序正确。
4. 回车和发送按钮触发效果相同。
5. swipe 只更新当前 active 回复，保留其他候选。
6. 有系统尾块时在其前面追加。
7. 关闭开关后原文发送。
8. 只有标记没有 User 文本或没有 AI 楼层：不修改历史。
9. 保存失败能恢复本次内存修改。
10. 聊天切换后不会写到上一个聊天。
