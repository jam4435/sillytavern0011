# 金庸群侠传前端架构入口

## 文档用途

本文件只保留稳定边界、关键入口和阅读顺序，不复述实现细节。

## 项目边界

金庸群侠传是运行在酒馆助手无沙盒 iframe 中的 React 武侠 RPG 前端。

- 聊天楼层保存 user/assistant 消息与 swipe。
- 聊天级 `stat_data` 保存当前游戏持久变量。
- React `GameState` 只是 UI 投影，不是持久源，也不是差分依据。
- 普通变量写入分两类：可回滚 ERA 写入、可重算或非版本化的酒馆助手变量函数直接写入。
- 消息边界事件负责刷新与兜底，不负责代替真实写入。
- 初始化链路独立于普通回合写入链路。

## 核心约定

### 1. `stat_data` 是唯一差分真相源

- 差分、归因、写入验证统一以 `getVariables({ type: 'chat' }).stat_data` 为准。
- `getAllVariables()` 只用于读取合并视图并投影到 `GameState`。
- 不要用 React 状态、事件 payload 或临时缓存判断“是否真的写入成功”。

### 2. 普通操作优先走 ERA

- AI 变量块、额外变量、功法普通操作、境界普通操作、后台补全，统一视为 ERA 写入链路。
- ERA 写入完成后等待匹配的 `era:writeDone`，再重读聊天级 `stat_data`。
- 同一事件开始、参与或结算涉及的多个对象操作使用 `era:transactionByObject`
  一次提交，必须保持 operation 顺序并只产生一次消息/API/EditLog 完成链。
- 事件、参与记录、人物占用、角色差分、世界归档和后续线索都是分支敏感状态，不得在正常流程中 direct write。

### 3. 直接写入走变量函数 + 专用事件

- 变量编辑器或其他直接聊天变量修改，使用酒馆助手变量函数，例如 `updateVariablesWith()`。
- 直接写入完成后发 `wuxia:directVariableWriteDone`。
- 直接写入不得伪造 `era:writeDone`。

### 4. 消息边界只做兜底

- `MESSAGE_RECEIVED`、`MESSAGE_UPDATED`、`MESSAGE_SWIPED`、`CHAT_CHANGED` 用于刷新正文、选项和补偿重读。
- 当写入完成事件缺失、延迟或来自外部操作时，消息边界负责兜底重读 `stat_data`。

### 5. 同一聊天固定 iframe 宿主

- 隐藏楼层脚本在当前聊天首次折叠时采用一个宿主 DOM，后续只删除其他楼层，不改写宿主 `mesid`，不调用
  `refreshOneMessage()`。
- 回合 lifecycle、ACK 和超时继续协调 ERA 屏障与楼层清理；它们不负责把宿主同步到最新楼层。
- 查看或覆写最新 assistant 原文必须直接读取聊天数据，并使用
  `setChatMessages(..., { refresh: 'none' })`；聊天切换和历史 checkout 才允许正常 iframe 换代。

### 6. 初始化独立

- 新游戏初始化、开局建档、已有存档接管是独立链路。
- 初始化负责建立首份可用 `stat_data` 与界面初值，不与普通功法/境界操作混成一条规则。
- 已有聊天初始化不得 direct 补做应归属于历史楼层的事件结算；聊天切换先等待 ERA 路径同步，再重算 direct 派生字段。

### 7. 历史树不保存状态快照

- 角色级 `wuxia_history_tree_v2` 只保存聊天/楼层/swipe locator、父子边、短预览和校验哈希。
- 每个成功完成事件处理的 assistant swipe 自动成为节点；题名和钉住不创建 checkpoint。
- 仅从历史节点继续时创建原生 branch chat；原聊天未来不修改。
- checkout 使用 120 秒 localStorage journal 跨 iframe 重载续接，并在 ERA full sync 与哈希校验完成前锁定新回合。
- 历史树按角色累积所有历史局的节点；谱牒默认用 `filterTreeToRelatedComponent`
  只展示与当前聊天连通的脉络（沿 parentId 无向连通分量），工具栏可切换"显示全部行迹"。过滤仅作用于展示，不改动持久化数据。
- `manual_full_sync` 在 ERA 框架内是异步合批任务；checkout 发起时必须携带唯一 `syncId`，只认 ERA 在
  `era:writeDone(actions.resync)` 的 `syncIds`
  中回传该 ID 的信号（写入链再静默一段时间）才能进行事件检查与封存校验。不能以 `eventEmit` 返回、也不能以任意一次 resync
  writeDone 作为完成信号——`/branch-create` 切聊天触发的 `chat_changed` 增量同步同样会发 resync
  writeDone，误认会让校验跑在完全重算中途的状态上。
- 变量状态由聊天路径、ERA `SelectedMks`/`EditLogs` 与可重算缓存恢复，不保存逐节点 `stat_data` 补丁。

### 8. 模型失败只在安全请求边界重试

- 正文发送、正文重新生成和额外变量模型遇到 HTTP 429 时，首次失败后最多自动重试 2 次；真实玩家发送与自动化 `runTurn()`
  共用该请求级策略，人物经历自动总结不参与。
- 优先遵循服务端 `Retry-After`，无法取得时依次等待 1 秒、2 秒。普通手动发送的非 429 错误不得自动重试。
- 设置页自动推进还会对正文模型和额外变量模型的非 429 请求异常、空回复与落盘前响应校验失败最多重试 2 次，依次等待 1 秒、2 秒。
- `inline` 的变量动作块在创建 assistant 楼层前校验；`extra`
  的模型回复在追加变量块前校验。楼层、变量块或 ERA 写入已经发生后的失败不得重放。
- 重试必须包住单次模型请求，且位于楼层、swipe、变量块和 ERA 持久化写入之前，避免同一逻辑回合重复落盘。
- CLI、Relay、浏览器桥和 `WuxiaAutomation.runTurn()` 不得重放整个回合；结果未知时必须读取快照对账。

### 9. 事件通知使用可选前端适配器

- 事件脚本通过版本化通知桥发布结构化 `EventNotice`，武侠前端以 `registerAdapter()` 注册当前 iframe 的展示器。
- 通知桥使用动态全局名和 `discover / ready / disposed`
  握手应对事件脚本与楼层 iframe 独立换代；只允许最新挂载的前端实例接管展示。
- 适配器同步返回 `true` 才表示已接管；缺失、拒绝、版本不兼容或抛错时立即回退酒馆 `toastr`，不得等待前端或影响事件事务。
- 前端事件通知栈与生成中/请求错误使用的 `StatusToast` 相互独立，通知关闭和超时没有确认、取消或回滚语义。

## 稳定约束

1. 持久游戏状态必须落在聊天变量或聊天楼层，不能只改 React 状态。
2. `readGameDataPure()` 只读；补全写回单独调度。
3. 差分与归因只认聊天级 `stat_data`。
4. 普通功法/境界操作走 ERA；初始化独立。
5. 直接写入使用变量函数并发 `wuxia:directVariableWriteDone`，不得伪造 `era:writeDone`。
6. 消息边界负责兜底重读，不替代显式写入完成信号。
7. AI 自动化必须复用真实玩家发送链；写入结论仍以最终 `stat_data` 和变量比较为准。
8. 创建真实 user 楼层前必须取得隐藏楼层脚本的回合锁 ACK；同一聊天不得主动重绑固定宿主，iframe 生命周期诊断必须跨换代持久化。
9. 模型 429 与设置页自动推进的普通模型失败最多各重试 2 次，且重试边界不得包含任何聊天楼层、swipe、ERA 持久化写入或整轮自动化调用。
10. 历史节点不保存状态补丁；分支敏感事件状态必须由 ERA 事务进入消息历史，direct
    write 仅用于派生、根初始化、版本迁移或非版本化用户操作。
11. 历史 checkout journal 存在且未超时时，任何发送、重新生成和事件检查都必须暂停；失败不得静默生成。
12. 事件通知适配失败只能回退酒馆弹窗，不能中断或改变事件读写链；旧前端实例不得覆盖新实例。
