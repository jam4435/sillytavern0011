# 变量变更追踪

## 目的与边界

变量变更条用于观察当前回合：

- `AI回复`：AI 声明了什么，哪些真正落地
- `后台变更`：ERA 补全、事件脚本、直接写入或其他外部变化

它只做观测，不负责写入。

## 唯一差分真相源

所有实际差分统一来自：

```text
getVariables({ type: 'chat' }).stat_data
```

不要直接拿以下内容做 diff：

- React `GameState`
- `era:writeDone` payload
- 直接写入完成事件 payload
- 临时缓存或合并视图

事件只负责告诉追踪器“该重读了”，真正的 before/after 仍以聊天级 `stat_data` 为准。

## 回合生命周期

```text
开始发送
  -> 建 baseline
  -> 记录 AI raw 声明
  -> 等待写入完成信号
  -> 重读 chat.stat_data
  -> 必要时用消息边界兜底补读
```

使用的信号：

- `MESSAGE_SENT`：建立回合与 baseline
- `era:writeDone`：ERA 写入完成
- `wuxia:directVariableWriteDone`：直接聊天变量写入完成
- `wuxia:eraVariableWriteDone`：带来源的 ERA 写入完成
- `MESSAGE_RECEIVED / MESSAGE_UPDATED / MESSAGE_SWIPED / CHAT_CHANGED`：消息边界兜底

## AI 与后台归因

进入 `AI回复` 的实际差分必须同时满足：

1. 属于当前回合的 ERA AI 写入。
2. 路径与 raw 回复声明一致。
3. 目标值与声明值一致；删除则要求目标节点不存在。

AI/后台的实际条数必须在 diff 遍历时分别计数、分别限量；不要先截取全局前 100 条再把未保留的溢出条数按当前信号来源整体归桶，否则大量后台变化会显示成 `AI回复` 的 `实`。

AI 声明的落地状态以同一路径的 AI 实际差分为优先依据；如果写入完成事件漏拍或延迟，也必须用当前最终 `stat_data` 快照兜底判定。内部路径不包含 `stat_data` 根，读取到 `{ stat_data: ... }` 包裹层时要先规整再比较，否则会把 `stat_data › 世界信息 › 时间 › 时` 误读成最终值 `未定义`。

其余差分都归 `后台变更`，包括：

- 属性/功法补全
- 事件脚本写入
- 变量编辑器或其他直接写入
- 未匹配声明的 ERA 写入
- 消息边界兜底补出的残余差分

直接写入永远是后台变更，不属于 AI。

`wuxia:eraVariableWriteDone` 的归因规则：

- `attribution: 'ai'`：按 AI 写入处理，可把同快照批次的 producer 从泛化 `era` 升级为真实来源，但不能把已归入 AI 的批次降回后台
- `attribution: 'background'`：按后台写入处理，可把泛化 `era` 批次纠正回后台
- 缺失 `attribution` 的 legacy 事件：兼容按后台处理

## 写入来源约定

### ERA 写入

- 以 `era:writeDone` 做完成信号
- 追踪器收到后重新读取聊天级 `stat_data`
- 不直接信任事件内的 `stat/statWithoutMeta`

### 带来源的 ERA 写入

- 以 `wuxia:eraVariableWriteDone` 补充真实来源和显式归因
- `extra-variable-api-write` 必须发送 `attribution: 'ai'`
- 其他前端补写默认发送 `attribution: 'background'`
- 追踪器收到后同样只重读聊天级 `stat_data`

### 直接写入

- 以 `wuxia:directVariableWriteDone` 做完成信号
- 直接写入不得伪造 `era:writeDone`
- 追踪器收到后同样只重读聊天级 `stat_data`

### 消息边界兜底

当完成信号缺失、延迟或来自外部操作时，消息边界负责补读，避免后台变化丢失。

## 必须保持的约束

1. 基线必须早于本轮后台写入。
2. 差分只认聊天级 `stat_data`。
3. AI 归因必须逐叶子匹配声明路径和值。
4. 直接写入只走 `wuxia:directVariableWriteDone`，不得伪造 `era:writeDone`。
5. 消息边界只兜底，不替代真实写入完成信号。
6. 切换聊天必须清空当前追踪状态。

## 常见故障

| 现象 | 优先检查 |
| --- | --- |
| AI 实际数远大于声明数 | 是否把整批 ERA 写入或全局 diff 溢出条数都算成 AI |
| AI 声明显示未落地且最终值未定义 | 是否把 `{ stat_data: ... }` 包裹层直接拿去按内部路径取值；是否缺少最终快照兜底判定 |
| 后台变化缺失 | 是否建立 baseline；消息边界兜底是否执行 |
| 直接写入被归成 AI | 是否错误复用了 `era:writeDone` |
| 差分和界面不一致 | 是否错把 `GameState` 当成真相源 |
| 刷新后仍显示旧统计 | `sessionStorage` 版本是否已提升 |
