# 物品、行囊与状态效果

## 目的与边界

本文记录 `user数据.包裹`、`user数据.装备栏`、`user数据.状态效果` 的当前模型，以及行囊按钮如何影响持久变量和属性计算。

这套模型只讨论前端可读写的游戏状态，不定义掉落表、商店价格、装备词条生成或丹药叠加规则。

## 三层数据模型

| 层 | 字段 | 职责 | 真值含义 |
| --- | --- | --- | --- |
| 包裹 | `user数据.包裹` | 物品持有关系和物品模板信息 | 玩家是否拥有、拥有几个、物品基础元信息 |
| 装备栏 | `user数据.装备栏` | 当前生效装备 | 哪个部位实际装备了哪个物品 |
| 状态效果 | `user数据.状态效果` | 当前持续中的临时效果 | 哪些丹药效果仍在持续、还剩几回合 |

`包裹.使用状态` 只保留为 UI 显示/同步字段。属性计算不以它为准，而是读取 `装备栏` 和 `状态效果`。

## 包裹结构

包裹物品以物品名为 key：

```yaml
user数据:
  包裹:
    玄铁重剑:
      类型: 装备
      品阶: 绝品
      物品描述: 重剑无锋，大巧不工。
      数量: 1
      部位: 武器
      属性修正:
        臂力: 20
      使用状态: 装备中
```

基础字段统一是：

- `类型`
- `品阶`
- `物品描述`
- `数量`

当前开发版底层字段已经从 `品质` 改为 `品阶`，不做旧 `品质` 兼容。

类型专属字段：

- 装备 / 兵器：`部位`、`属性修正`、`使用状态`
- 丹药：`属性修正`、`持续时间`
- 秘籍：包裹只保存持有关系；描述、功法品阶、参悟条件优先从功法数据库补全

## 装备栏

装备栏是装备是否生效的真值：

```yaml
user数据:
  装备栏:
    $template: ''
    武器: 玄铁重剑
    护甲: 软猬甲
```

规则：

- key 是装备的 `部位` 字段，value 是包裹里的物品名。
- 同一部位只能生效一件装备。
- 新装备同部位时，`itemManager.equipInventoryItem()` 会替换旧装备。
- 替换时会同步包裹里的 `使用状态`，但计算仍以 `装备栏` 为准。

## 状态效果

状态效果是丹药药效是否仍在持续的真值：

```yaml
user数据:
  状态效果:
    九花玉露丸_1234567890_abcd:
      类型: 丹药
      来源: 九花玉露丸
      属性修正:
        气血: 300
      持续时间: 3
      剩余时间: 2
```

规则：

- 吞服丹药会扣减包裹数量，并创建一个独立状态效果。
- `来源` 记录丹药物品名。
- `属性修正` 从丹药模板复制。
- `持续时间` 从丹药模板复制，默认至少为 1。
- `剩余时间` 在玩家消息成功发送后递减，归零后删除。
- 同名丹药再次服用当前先按独立效果处理，不做覆盖、互斥、刷新时长或叠层上限。

## 属性修正

`attributeCalculator.applyAttributeModifiers()` 在最终属性上平铺加减，不参与境界倍率放大。

生效来源：

1. `装备栏` 指向的包裹装备。
2. `状态效果` 中 `剩余时间 > 0` 的效果。

支持字段：

- 战斗属性：`臂力`、`根骨`、`机敏`、`洞察`
- 资源属性：`气血上限`、`内力上限`
- 资源别名：`气血` 等同 `气血上限`，`内力` 等同 `内力上限`

负数修正允许存在，但最终值下限为 0。

## 行囊交互链路

装备：

1. `InventoryPanel` 触发 `App.handleInventoryItemAction()`。
2. `App` 调用 `itemManager.equipInventoryItem(item.name)`。
3. `itemManager` 写入 `user数据.装备栏[部位]`。
4. 同步包裹内新旧装备的 `使用状态`。
5. `App` 重读 `readGameDataPure()` 刷新 UI。

吞服：

1. `InventoryPanel` 触发 `App.handleInventoryItemAction()`。
2. `App` 调用 `itemManager.useElixirItem(item.name)`。
3. `itemManager` 记录完整物品快照，扣减包裹数量，并创建 `状态效果`。
4. `App` 通过 `useCommandQueue.addUseItemCommand()` 追加待发送物品指令。
5. 取消待发送指令时，`useCommandQueue.cancelCommand()` 用完整快照恢复物品，并删除本次创建的状态效果。
6. 玩家消息成功发送后，`useCommandQueue.sendMessageWithCommands()` 调用 `decrementStatusEffectTurns()` 递减状态效果。

刷新 UI 不会扣减状态效果时间；只有成功发送玩家消息才会扣减。

## 读取与派生链路

`variableReader.ts` 负责把聊天变量映射为 `GameState`：

- `parseInventory()` 读取包裹，并把物品转换为行囊卡片数据。
- `parseEquipmentSlots()` 读取 `user数据.装备栏`。
- `parseStatusEffects()` 读取 `user数据.状态效果`。
- `collectActiveAttributeModifiers()` 汇总当前生效装备和有效状态效果。
- `calculateAllAttributes(..., modifiers)` 计算玩家最终属性。

`frontendDerivedVariables.ts` 也会读取同一套修正，用于生成 `前端变量.战力区`。因此提示词里看到的玩家战力区与角色面板属性使用同一个装备/药效模型。

## 必须保持的约束

1. 包裹是持有关系和模板信息，不是生效状态总表。
2. 装备是否生效只认 `user数据.装备栏`。
3. 丹药是否仍在持续只认 `user数据.状态效果`。
4. `包裹.使用状态` 只能服务显示和同步，不能作为属性计算真值。
5. 秘籍的功法描述、功法品阶、参悟条件优先读取功法数据库。
6. 属性修正是最终值加减，不能再次乘境界。
7. 玩家消息发送失败不能扣减状态效果时间。
8. 吞服指令取消必须恢复完整物品对象，不能只恢复数量。

## 修改后验证

- 包裹物品底层字段使用 `品阶`。
- 秘籍卡片能从功法数据库读取描述、功法品阶和参悟条件。
- 装备按钮写入 `装备栏`，同部位替换旧装备。
- 丹药按钮扣数量并创建 `状态效果`。
- 取消吞服指令能恢复完整物品元信息。
- 装备和丹药修正会影响角色属性与 `前端变量.战力区`。
- 成功发送玩家消息后状态效果递减，发送失败不递减。
