# 地图与指令

## 目的与边界

本文记录地图面板、地点索引、地图移动指令和周围地点同步的当前实现，以代码为准，不复述样式细节。

`修改方案.md` 是规划稿，不是运行时真相源；地图相关行为应以 `App.tsx`、`MapPanel.tsx`、`useCommandQueue.ts` 和 `locationContext.ts` 为准。

## 数据来源

地图模块有三层数据来源：

- [`../射雕神雕地点表.yaml`](../射雕神雕地点表.yaml)：地点层级真相源，定义大区域 -> 二级地点 -> 三级地点。
- [`../data/mapCoordinates.ts`](../data/mapCoordinates.ts)：地图底图上的区域和二级地点坐标，也负责显示用的大区印记位置。
- [`../地图.jpg`](../地图.jpg)：底图素材，坐标基准为 `1536 x 1024`。

[`../utils/mapLoader.ts`](../utils/mapLoader.ts) 会把 YAML 和坐标常量组装成运行时 `MapData`，并做内存缓存。当前没有独立的 JSON 地图文件。

显示层和数据层允许适度分离，例如大区印记可写成“吐蕃”“大清”，而真实可点击的二级地点仍来自 YAML 和 `REGION_COORDINATES`。

## UI 链路

地图入口在 [`../App.tsx`](../App.tsx)：

- 左侧导航点击“地图”后打开 `ActivePanel.MAP`。
- `App` 把 `gameState.currentLocation` 和 `mapPreviewLocations` 传给 [`../components/panels/MapPanel.tsx`](../components/panels/MapPanel.tsx)。

地图面板由三层组成：

- `MapPanel`：加载地图数据、读取已探索地点、管理移动端地点索引开关。
- [`../components/MapCanvas.tsx`](../components/MapCanvas.tsx)：绘制底图、二级地点圆点、当前位置、行程预览线和缩放拖拽交互。
- [`../components/MapSidebar.tsx`](../components/MapSidebar.tsx)：地点索引，负责搜索、分组展开和三级地点选择。

点击二级地点圆点后，[`../components/LocationPopover.tsx`](../components/LocationPopover.tsx) 会弹出当前二级地点下的三级地点列表。这里才是三级地点真正的选择入口；地图圆点本身不直接生成移动指令。

## 交互语义

### 地图画布

`MapCanvas` 当前支持：

- 鼠标滚轮缩放
- 双击放大
- 桌面端拖动画布
- 移动端单指拖动、双指缩放
- “放大 / 缩小 / 回到当前位置”按钮

二级地点名称会随 `camera.zoom` 反向缩放，避免放大后标签变得过大。大区印记也走同样的缩放处理。

地图上的可视元素分为：

- 大区印记：纯展示，不可点击。
- 二级地点圆点：点击后打开三级地点浮窗。
- 当前位置标记：根据当前所在位置解析后显示。
- 行程路线：根据当前位置和待发送地图指令预览。

### 地点索引

`MapSidebar` 是地图的第二条选择入口，也承担移动端主要导航职责。

- 支持按区域名、二级地点名、三级地点名和描述搜索。
- 搜索非空时自动展开匹配区域与地点。
- 未探索、未解锁的三级地点不会出现在可点击列表中。

### 地图移动指令

地图选择不会立即修改 `user数据.所在位置`，也不会立即发送消息。当前实现是两段式：

1. 在地图中选择三级地点时，只把结果暂存到 `App` 的 `mapDraftDestination`。
2. 关闭地图面板时，如果存在草稿地点，则调用 `useCommandQueue.setTravelCommand()` 生成唯一的地图移动指令。

指令文本格式固定为：

```text
[地图指令]从{起点完整三级路径}移动到{目标完整三级路径}
```

其中起点优先读取 `getUserCurrentLocation()`，回退到 `gameState.currentLocation`。

`useCommandQueue` 对地图移动有两个关键约束：

- 地图指令只保留一条；新的目标会替换旧的 `TRAVEL` 指令。
- 只处理最后一次选中的地图目标；中途改选不会累积多条移动指令。

## 指令队列与发送链路

指令队列是通用队列，但地图模块当前只写入 `TRAVEL` 指令。

发送入口在 [`../App.tsx`](../App.tsx) 的 `handlePlayerSend()`：

```text
ChatInput / 选项点击
  -> useCommandQueue.sendMessageWithCommands()
  -> 把待发送指令逐行附加到玩家输入后
  -> handleSendMessage()
```

这意味着：

- 普通输入和点击选项都会附加当前待发送指令。
- 指令队列浮窗不负责“发送全部”。
- 发送成功后，只移除本次实际附加出去的指令。
- 取消指令由 [`../components/CommandQueuePopover.tsx`](../components/CommandQueuePopover.tsx) 单条处理。

地图路线预览有一条额外规则：

- 地图面板打开且存在 `mapDraftDestination` 时，优先预览草稿目的地。
- 否则预览当前队列中的 `TRAVEL` 指令目的地。

## 探索与解锁

当前解锁逻辑在 [`../utils/mapUtils.ts`](../utils/mapUtils.ts)：

- 已在 `user数据.已探索地点` 中的地点可用。
- `初始探索: true` 的地点可用。
- 没有 `解锁条件` 的地点可用。

当前仍未实现“按已完成事件解锁地点”的判断；`解锁条件` 还没有接入事件完成表。

探索记录读写路径：

- 读取：`getAllVariables().stat_data.user数据.已探索地点`
- 写入：`addExploredLocation()` 通过 `emitSourcedEraVariableWriteAndWait()` 写回 `stat_data.user数据.已探索地点`

## 周围地点同步

地图模块还会在生成前同步一份派生变量，供世界书或额外变量提示词使用：

```text
getVariables({ type: 'chat' }).stat_data.前端变量.周围地点
```

结构固定为：

```yaml
周围地点:
  相邻三级地点: []
  相邻二级地点: []
```

[`../utils/locationContext.ts`](../utils/locationContext.ts) 负责：

- 根据 `stat_data.user数据.所在位置` 解析当前二级地点
- 计算当前二级地点内所有三级地点
- 按地图坐标距离计算相邻二级地点
- 在发送与重新生成前刷新 `前端变量.周围地点`
- 清理旧的 `地图上下文` 残留键

额外变量模板中的 `{{locationContext}}` 生成的是动态约束文本；`前端变量.周围地点` 则是给世界书或其他手工提示词读取的结构化变量。两者不是同一个字段。

## 必须保持的约束

1. 点击地图或地点索引时，不得直接修改 `user数据.所在位置`。
2. 点击二级地点圆点后，必须还能弹出三级地点列表；不能退化成只能靠地点索引选点。
3. 关闭地图时只提交最后一个草稿地点，并且地图移动指令始终唯一。
4. 地图指令必须通过正常玩家发送链路附加，不能另起一套发送实现。
5. `前端变量.周围地点` 是派生数据，发送和重新生成前都应按当前 `stat_data` 刷新。
6. 地图层级真相源应保持为 YAML + 坐标常量，不在组件内重复硬编码地点结构。

## 修改后验证

- 桌面端可滚轮缩放、拖动地图、点击二级地点弹出三级地点列表。
- 移动端可打开地点索引、搜索地点、单指拖动和双指缩放地图。
- 点击地图三级地点或地点索引三级地点后，关闭地图会生成一条唯一的地图指令。
- 已有地图指令时重新选点，旧地图指令会被替换而不是叠加。
- 普通发送和点击选项都会把待发送地图指令附加到玩家输入。
- 发送或重新生成后，`stat_data.前端变量.周围地点` 会按当前位置刷新。
