# 设置与自动推进

## 目的与边界

`SettingsPanel` 是运行时控制台，不只是外观设置。本文记录各页签的架构职责和自动推进规则，不记录具体表单布局。

## 设置页签

| 页签 | 职责 |
| --- | --- |
| `appearance` | 界面主题、正文、背景、周边栏目/弹窗透明度和 CSS 变量 |
| `regex` | 手动、全局酒馆和当前预设正则 |
| `summary` | 额外模型 API、自动总结、变量更新模式 |
| `variables` | 浏览、搜索和编辑聊天级 `stat_data` |
| `advance` | 串行自动发送并记录多轮回复 |
| `debug` | 最新一轮正文与额外变量调试信息 |

显示设置由 `settingsManager.ts` 统一默认化、迁移和保存。组件不应直接构造另一套持久化格式。

## 外观设置

`appearance` 页签的持久化入口只有 `utils/settingsManager.ts`。当前字段可分为四组：

- 主题：`uiTheme`，当前支持 `dark-gold` 与 `ink-wash`。
- 正文：`fontSize`、`fontColor`、`lineHeight`。
- 背景：`backgroundColor`、`backgroundOpacity`、`backgroundImage`、`backgroundBlur`。
- 外框与弹窗：`chromeOpacity`、`modalOpacity`。

稳定语义：

1. 水墨主题保留内置山水底图；自定义背景作为上层叠加，不替换底图。
2. `backgroundOpacity` / `backgroundBlur` 继续控制用户上传的背景层；当透明度调到 `100%` 时，应接近完全盖住底图。
3. `chromeOpacity` 负责左侧栏、顶栏、输入栏等常驻周边 UI。
4. `modalOpacity` 负责弹窗遮罩和弹窗主体。
5. `chromeOpacity` / `modalOpacity` 的默认值是“当前主题的设计基准”，不是上限；滑杆调到 `100%` 时应为完全不透明。
6. 新增常驻外框或新弹窗时，不要写死主题透明度；应接入 `applySettingsToDOM()` 输出的对应 CSS 变量。

重置语义：

- `重置外观` 恢复为 `dark-gold` 默认主题。
- 同时恢复主题默认的正文、背景、周边栏目与弹窗透明度。
- 清除自定义背景图片。

## 正则来源

显示正则分为：

- `manual`：前端内手动创建。
- `global`：从酒馆全局正则导入。
- `preset`：绑定当前预设名称。

正文显示使用合并后的启用规则。调试快照用于定位重复导入、来源识别和当前预设切换问题。

## 变量编辑

变量页读取聊天级 `stat_data`，按世界、玩家、角色等作用域浏览。保存前由 `variableEditorPolicy` 判断环境能力，再通过 `variableEditorState` 完成 clone、替换和写入事件通知。

变量页不能直接修改 `GameState` 代替变量写回。

## 自动推进

自动推进的控制循环位于 `SettingsPanel`：

```text
读取轮数和固定提示
  -> 调用 onAutoAdvanceTurn(prompt)
  -> 等待完整 Promise 完成
  -> 保存本轮结果
  -> 剩余轮数减一
  -> 开始下一轮
```

`onAutoAdvanceTurn` 对应 `useMessageHandler.handleAutoAdvanceTurn()`，内部复用 `handleSendMessage()`。因此自动推进与底部输入框共享：

- 用户楼层创建
- 正文生成
- assistant 楼层创建
- `inline/extra` 变量处理
- 错误处理
- 变量追踪

## 自动推进记录

每轮记录：

- 轮次
- 发送提示
- user 楼层 ID
- assistant 楼层 ID
- 纯文本回复
- 完整 raw 回复
- 是否观察到 `era:writeDone`
- 成功或错误状态

纯文本会移除 `<option>`，用于检查剧情质量；完整回复优先读取本轮实际 assistant 楼层，保留 inline 或 extra 模式最终存在的变量块。

## 停止语义

点击停止时：

- 不强行中断当前模型请求。
- 当前轮结束后停止后续轮次。
- 当前轮失败时记录错误并停止。

不需要轮间固定等待。下一轮应在上一轮完整 Promise 结束后立即开始。

## 关键入口文件

- `components/SettingsPanel.tsx`
- `utils/settingsManager.ts`
- `utils/variableEditorPolicy.ts`
- `utils/variableEditorState.ts`
- `hooks/useMessageHandler.ts`
- `App.tsx`

## 必须保持的约束

1. 自动推进不能维护独立发送实现。
2. 多轮必须严格串行。
3. 停止只影响后续轮次。
4. 导出的完整回复必须保留变量块。
5. 设置存储迁移必须兼容旧字段，包括新增的 `chromeOpacity` / `modalOpacity`。
6. 变量编辑必须通过能力检查和真实变量写回。

## 修改后验证

- 六个页签能正常切换且状态不互相污染。
- 切换预设后正则来源和显示规则更新。
- 自动推进 1 轮与底部手动发送结果一致。
- 自动推进 3 轮依次产生对应楼层和记录。
- 停止不会中断当前生成，但不会继续下一轮。
- 两类导出内容分别满足纯文本和完整 raw 回复用途。
