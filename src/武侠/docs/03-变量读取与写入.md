# 变量读取与写入

## 目的与边界

本文说明聊天级 `stat_data` 的读取边界、写入方式和变量编辑器约束。变量变更条见 [04-变量变更追踪](./04-变量变更追踪.md)。

## 唯一持久源

游戏持久变量统一落在：

```text
getVariables({ type: 'chat' }).stat_data
```

这是唯一差分真相源。

- 差分、归因、写入验证看这里。
- `GameState` 只是投影。
- `getAllVariables()` 只是 UI 合并读取入口。

## 读取链路

| 入口 | 用途 | 约束 |
| --- | --- | --- |
| `readGameDataPure()` | 把当前变量映射为 `GameState` | 只读，不写回 |
| `scheduleGameDataCompletion()` | 排队后台补全 | 只在需要时写回 |
| `flushPendingGameDataCompletion()` | 生成前清空补全队列 | 防止提示词读到旧值 |

界面展示通常读取合并视图；真正比较“写没写进去”时，必须回到聊天级 `stat_data`。

## 写入方式

### ERA 写入

普通游戏变量操作走 ERA：

- AI 回复变量块
- 额外变量模型
- 功法普通操作
- 境界普通操作
- 属性/功法后台补全

ERA 写入完成后，以匹配的原始 `era:writeDone` 为完成信号，然后重读聊天级 `stat_data`。等待器只等待该原始写入，不等待同一事件上可能较慢的 UI 刷新、事件结算或后台补全监听器；这些后处理仍会继续执行并单独记录异常。

### 直接写入

变量编辑器或少量特殊场景可直接使用酒馆助手变量函数：

- `updateVariablesWith()`
- `replaceVariables()`

直接写入完成后发：

```text
wuxia:directVariableWriteDone
```

直接写入不得伪造 `era:writeDone`。

前端派生变量当前有一条直接写入分支：

- [`../utils/frontendDerivedVariables.ts`](../utils/frontendDerivedVariables.ts) 会在发送和重新生成前，用 `updateVariablesWith()` 刷新 `stat_data.前端变量` 中的派生字段
- `前端变量` 是前端专用区：`周围地点 / 战力区 / 随机数 / 修为变化参考` 是派生上下文，`永久属性修正` 是前端药品按钮维护的持久子区，刷新派生字段时必须合并保留

### 初始化

初始化独立于普通回合写入：

- 新游戏建档负责创建首份 `stat_data`
- 读取已有存档负责接管已有状态
- 不把初始化混入“普通功法/境界/补全”规则

## 地图相关变量

地图和前端派生模块当前会读写这些聊天级变量：

- `stat_data.user数据.已探索地点`
- `stat_data.前端变量.周围地点`
- `stat_data.前端变量.战力区`
- `stat_data.前端变量.随机数`
- `stat_data.前端变量.修为变化参考`
- `stat_data.前端变量.永久属性修正`

语义不同：

- `已探索地点` 是持久游戏状态，决定地点是否解锁。
- `前端变量` 服务世界书和额外变量提示词；除前端维护的 `永久属性修正` 外，其余字段按当前 `stat_data` 实时推导。

`已探索地点` 目前通过 [`../utils/mapUtils.ts`](../utils/mapUtils.ts) 读写：

- `getExploredLocations()`：读取
- `addExploredLocation()`：通过 `emitSourcedEraVariableWriteAndWait()` 走 ERA 写回

`周围地点` 通过 [`../utils/locationContext.ts`](../utils/locationContext.ts) 写回到 `前端变量`，结构固定为：

```yaml
前端变量:
  周围地点:
    当前活动区: 大宋/临安府/牛家村
    普通移动: []
    事件目标: []
    地图指定: []
  战力区: ""
  随机数: ""
  修为变化参考: 0
  永久属性修正: {}
```

`所在位置` 只接受 `一级/二级/三级` 或 `一级/二级/三级/四级`。一级是世界大域或政权，二级是地图旅行区域，三级是地图和事件使用的严格活动区，第四级是可选的具体镜头场景。实际变量保存完整路径；地图高亮、探索记录、事件到场和活动区白名单只使用前三段。

任何 `VariableInsert` 或 `VariableEdit` 写入 `所在位置` 前都会确定性校验：同一严格活动区可改变第四级；跨活动区时目标前三段必须存在于 `周围地点` 四类路径的前三段并集中。段数错误、自造三级范围或非法跨区会在调用 ERA 前立即拒绝整次变量写入。`VariableDelete` 仍按通用的“目标必须已存在”规则校验，删除可选第四级表现为把完整位置 Edit 为对应三级路径，而不是删除字符串片段。

更多地图交互语义见 [09-地图与指令](./09-地图与指令.md)。

## 奇经八脉写入

`stat_data.前端变量.奇经八脉` 是玩家经脉的版本化分支状态；穴位定义和奖励公式由前端静态配置提供。旧档缺少该字段时只读投影为全未解锁，首次冲穴才写入，不允许 `readGameDataPure()` 隐式补字段。

玩家境界至少达到二流初期方可冲穴。冲穴必须使用一次 `era:transactionByObject` 原子完成修为扣除、经脉进度写入和可选的初始属性提升，并以唯一 `transactionId` 精确匹配 `era:writeDone.transactionId/transactionIds`。确认信号后还要重读聊天级 `stat_data` 验证全部结果；超时或结果未知时不得自动重放。

经脉百分比加成是前端计算输入，必须同时进入界面属性、持久属性补全和战力区计算。交会穴对 `user数据.初始属性` 的修改由前端结算，AI 不得重复写入。

## 变量编辑器

变量编辑器分三层：

- `variableEditorPolicy.ts`：判断当前环境是否允许编辑
- `variableEditorState.ts`：读取、冲突检测、保存
- `SettingsPanel.tsx`：搜索、详情与编辑 UI

保存时要点：

- 先记录打开详情时的 `beforeValue`
- 提交时重新读取当前 `stat_data`
- 只有当前值仍等于 `beforeValue` 才应用 draft
- 保留未知根节点和框架元数据
- 写完后发 `wuxia:directVariableWriteDone`

## 路径约定

显示路径：

```text
stat_data › user数据 › 所在位置
```

复制路径：

```text
stat_data.user数据.所在位置
```

特殊字符和数组索引统一走现有路径格式化工具，不在组件内手拼。

## 必须保持的约束

1. `readGameDataPure()` 不能隐式写变量。
2. 差分、归因、验证统一只认聊天级 `stat_data`。
3. 普通功法/境界操作走 ERA。
4. 直接写入用变量函数，并发 `wuxia:directVariableWriteDone`。
5. 直接写入不得伪造 `era:writeDone`。
6. 初始化独立，不与普通回合写入混用。
