# 变量读取与写入

## 目的与边界

本文说明聊天级 `stat_data` 的数据源、读取投影、写入方式和变量编辑器。变量变更条属于观测层，见 [04-变量变更追踪](./04-变量变更追踪.md)。

## 数据源

游戏持久变量保存在聊天级：

```text
getVariables({ type: 'chat' }).stat_data
```

主要根节点：

```text
stat_data
├── 世界信息
├── user数据
├── 角色数据
├── 事件系统
└── 其他世界或系统数据
```

`$meta`、`$template` 等框架字段不是普通游戏数据。遍历、差分和编辑时必须按现有工具规则过滤。

## 读取链路

[`../utils/variableReader.ts`](../utils/variableReader.ts) 分为两类入口：

| 类型 | 代表入口 | 要求 |
| --- | --- | --- |
| 纯读取 | `readGameDataPure()` | 只将当前变量映射为 `GameState`，不得触发写入 |
| 后台补全 | `scheduleGameDataCompletion()`、`flushPendingGameDataCompletion()` | 检测缺失字段并按队列写回 |

`App.tsx` 和消息事件刷新使用纯读取。初始化、消息边界或 MVU 更新会调度补全。

## `GameState` 映射

变量表中的中文字段会转换为 React 使用的 `GameState`：

- `user数据` -> `stats`
- `user数据.包裹` -> `inventory`
- `角色数据` -> `social`
- 事件相关节点 -> `events`
- `世界信息.时间` -> `worldTime` 和格式化时间

`GameState` 只服务 UI。修改 `GameState` 不会自动持久化到变量表。

界面展示的 `readGameDataPure()` 使用 `getAllVariables()` 合并视图；变量编辑器和变量变更追踪使用 `getVariables({ type: 'chat' }).stat_data`。前者适合展示合并后的值，后者才是本聊天实际写入与差分的边界。

## 写入方式

| 场景 | 写入方式 |
| --- | --- |
| ERA 回复变量块 | ERA `apply` |
| 额外变量模型 | 追加变量块后触发 `era:apiWrite` |
| 属性/功法补全 | `era:insertByObject`、`era:updateByObject` |
| 设置页变量编辑器 | `updateVariablesWith()` 原子更新，并发出带 `directChatWrite` 的 `era:writeDone` |
| 事件脚本 | 事件脚本的直接聊天变量写入辅助函数 |

写入完成后通常会出现 `Mvu.events.VARIABLE_UPDATE_ENDED` 或 `era:writeDone`。两者可能描述同一最终快照，消费方必须去重。

## 变量编辑器

设置页变量编辑由以下模块分工：

- `variableEditorPolicy.ts`：判断当前环境是否允许编辑。
- `variableEditorState.ts`：树形数据、值解析、写回和 `writeDone` 事件。
- `SettingsPanel.tsx`：搜索、作用域、详情和编辑 UI。

编辑器先保存打开详情时的 `beforeValue`，提交时通过 `updateVariablesWith()` 重新读取当前值。只有当前值仍等于 `beforeValue` 才应用 draft，避免覆盖后台同时发生的修改。写入时使用 `directChatWrite` 标记，使变量追踪能归入后台变更。

## 路径约定

显示路径：

```text
stat_data › user数据 › 所在位置
```

复制路径：

```text
stat_data.user数据.所在位置
```

包含特殊字符或数组索引的路径由 `utils/variableChanges.ts` 统一格式化，不要在组件中自行拼接。

## 关键入口文件

- `utils/variableReader.ts`
- `utils/variableEditorPolicy.ts`
- `utils/variableEditorState.ts`
- `utils/variableChanges.ts`
- `hooks/useGameState.ts`
- `hooks/useEventListeners.ts`

## 必须保持的约束

1. `readGameDataPure()` 不能隐式写变量。
2. 生成前必须 `flushPendingGameDataCompletion()`，防止模型读取旧状态。
3. 写入必须基于 clone 后的数据，不能原地修改酒馆返回对象。
4. 变量编辑器必须保留未知根节点和框架元数据，并执行 `beforeValue` 冲突检测。
5. 一次写入的 MVU 与 `era:writeDone` 通知可能重复，监听方不得重复计算。

## 修改后验证

- 刷新页面只读取变量，不产生循环写入。
- 变量编辑器能修改叶子值且不丢失其他根节点。
- 属性或功法补全完成后 UI 自动刷新。
- 同一次写入不会在变量条中重复出现。
- 特殊字符路径和数组路径显示、复制正确。
