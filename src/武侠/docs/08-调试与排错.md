# 调试与排错

## 目的与边界

本文提供跨模块故障的定位顺序。历史修复记录仍保存在 [`../CHANGELOG.md`](../CHANGELOG.md)，本文件只维护当前有效的调试入口。

## 调试信息层级

| 层级 | 位置 | 内容 |
| --- | --- | --- |
| 设置页调试 | `useDebugLogs` + `SettingsPanel` | 最新一轮输入、组合提示词、正文输出、额外变量输出和同步验证 |
| 分类控制台日志 | `utils/logger.ts` | 初始化、消息、事件、游戏、API、UI、数据 |
| 正则调试快照 | `settingsManager.ts` | 正则来源、去重、当前预设和最终显示规则 |
| 变量变更条 | `useVariableChangeTracker` | AI 声明、实际落地、后台差分 |
| 酒馆楼层 | `getChatMessages()` | user/assistant 楼层、swipe 和 raw 回复 |
| 聊天变量 | `getVariables({type:'chat'})` | 最终 `stat_data` |

## 开启分类日志

开发构建下可设置：

```js
localStorage.setItem('wuxia_debug_categories', 'message,event,data')
```

可用分类：

```text
init,message,event,game,api,ui,data
```

设置为 `all` 可全部开启。生产构建不会输出这些分类日志。

## 消息问题定位

### 没有新增楼层

1. 查看调试页 `main.status`。
2. 检查 user 楼层是否创建。
3. 检查 `generate()` 是否返回空文本。
4. 检查 assistant 楼层是否在发送前最新 ID 之后。

### 正文生成但 UI 未更新

1. 查看酒馆 raw assistant 楼层是否存在。
2. 检查 `setCurrentMaintext` 是否接收 raw 回复。
3. 检查显示正则是否把正文过滤为空。
4. 检查 `MESSAGE_UPDATED/RECEIVED` 是否触发边界刷新。

### 重新生成变量不一致

1. 检查临时 swipe 是否建立。
2. 检查 `manual_sync` 是否完成旧变量回滚。
3. 检查 `era:apiWrite` 是否匹配目标 assistant ID。
4. 检查失败恢复是否切回旧 swipe。

## 变量问题定位

### 最终变量未更新

1. 查看完整 raw 回复是否存在合法变量块。
2. 检查 ERA 是否发出 `era:writeDone`。
3. 对比 `getVariables({type:'chat'}).stat_data`，不要只看 React `GameState`。
4. `extra` 模式检查变量块是否确实追加到目标 swipe。

### 变量条分类错误

1. 检查追踪基线是否早于写入。
2. 检查 `actions`、`reason` 和 `message_id`。
3. AI 项必须匹配 raw 声明的路径和值。
4. 检查 MVU 与 `writeDone` 是否指向同一快照并已去重。
5. 修改归因结构后提升 sessionStorage 版本。

### 后台补全循环

1. 检查纯读取函数是否意外触发写入。
2. 检查更新锁和状态缓存。
3. 检查写入后再次读取是否仍判断为缺失。
4. 检查 `$meta`、`$template` 是否错误参与比较。

## 额外模型问题定位

1. 查看调试页变量阶段的输入和原始输出。
2. 检查 API 档案选择和请求模式。
3. 检查输出是否包含严格 JSON 的合法变量块。
4. 检查追加读回与同步读回验证。
5. 检查世界书变量指导条目是否在失败后恢复。

## 正则问题定位

1. 调用 `getRegexDebugSnapshot()` 查看规则来源。
2. 确认当前预设名称与 preset bucket 一致。
3. 检查全局 API 是否混入预设派生规则。
4. 检查规则 pattern、flags 和启用状态。
5. 对 raw 回复和显示后正文分别测试，避免把存储问题误判为显示问题。

## 构建与静态检查

常用命令：

```powershell
pnpm exec eslint "src/武侠/**/*.ts" "src/武侠/**/*.tsx"
pnpm build:dev
```

仓库级 TypeScript 检查可能包含其他项目的既有错误。修复武侠前端时至少保证改动文件 ESLint 通过，并完成 `build:dev`。

## 修改后最小回归

- 初始化或读取已有聊天。
- 底部手动发送一轮。
- 自动推进至少两轮。
- 重新生成一次。
- 分别验证 `inline` 与 `extra` 变量模式。
- 触发一次事件脚本或前端补全。
- 展开变量条的 AI 与后台分类。
- 切换聊天并返回。
