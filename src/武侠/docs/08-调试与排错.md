# 调试与排错

## 目的与边界

本文提供当前有效的定位顺序，不记录历史修复细节。

## 先看哪里

| 位置 | 主要用途 |
| --- | --- |
| 设置页调试 | 看最近一轮输入、正文、变量输出和同步验证 |
| 分类日志 | 看初始化、消息、事件、游戏、API、UI、数据 |
| 变量变更条 | 看 AI 声明、实际落地、后台差分 |
| 酒馆楼层 | 看 user/assistant 楼层、swipe、raw 回复 |
| `getVariables({ type: 'chat' }).stat_data` | 看最终持久变量真相 |

判断变量问题时，`stat_data` 是唯一差分真相源。

## 开启分类日志

开发构建下可设置：

```js
localStorage.setItem('wuxia_debug_categories', 'message,event,data')
```

可用分类：

```text
init,message,event,game,api,ui,data
```

## 变量问题定位

### 最终变量没变

1. 先看聊天级 `stat_data`，不要先看 React `GameState`。
2. 如果是普通操作，检查对应 ERA 写入和 `era:writeDone`。
3. 如果是变量编辑器或其他直接写入，检查 `wuxia:directVariableWriteDone`。
4. 如果两类完成信号都没抓到，再看消息边界兜底是否补读成功。

### 变量条归因错误

1. 检查 baseline 是否建立在写入之前。
2. 检查 AI 声明路径和值是否真的匹配实际差分。
3. 检查是否把直接写入错误伪装成 `era:writeDone`。
4. 检查追踪是否始终回读聊天级 `stat_data`。

### 后台补全循环

1. 检查 `readGameDataPure()` 是否意外触发写入。
2. 检查补全缓存、防重入和去重是否生效。
3. 检查写回后聊天级 `stat_data` 是否已与目标值一致。
4. 检查消息边界是否反复把同一轮补全重新排队。

## 消息问题定位

### 正文生成但界面没刷新

1. 检查 raw assistant 楼层是否存在。
2. 检查消息边界事件是否到达。
3. 检查 `readGameDataPure()` 是否成功重读。
4. 检查正文显示是否被正则过滤为空。

### 重新生成后变量不一致

1. 检查目标 swipe 是否正确。
2. 检查是否等待了匹配楼层的 ERA 完成信号。
3. 检查旧变量回滚和新变量重算是否都落到了聊天级 `stat_data`。

## 最小回归

- 初始化新档或读取已有聊天
- 手动发送一轮
- 自动推进至少两轮
- 重新生成一次
- 做一次普通功法或境界操作
- 做一次直接变量编辑
- 展开变量条检查 AI 与后台分类
- 切换聊天并返回
