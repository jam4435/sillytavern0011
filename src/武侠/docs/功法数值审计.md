## 四、其他一致性修复

- `鞭法` 已加入运行时功法类型、战力区类型列表、变量模板与功法提取模板；数据库原有 3 条鞭法不再属于未支持类型。
- `降魔掌` 的 `臂力: {max: 8}` 是合法的上限条件；数据库类型定义和提取模板现已支持数字最低门槛及 `min/max` 区间。
- 品阶基础值、掌握程度系数、精进基础消耗、悟性基准、升级系数与战斗系数预算集中在 `martialArtNumerics.ts`，移除属性计算模块中的重复基础值/掌握系数常量。
- 资源上限公式统一为 `floor(已乘境界的根骨 × (1 + 实际功法加成))`；修为变化参考明确为取最高单门内功加成而非累加。

## 五、审查建议

1. 先确认按比例归一化 90 条战斗系数的做法是否符合预期平衡；具体变更可在本次分支的 JSON diff 中逐条检查。
2. 对 110 条特性数量差异逐条决定：改品阶、补/删特性、调整解锁阶段，或登记为明确例外。
3. 对空战斗系数列表确认是否均为有意的非直接战斗条目；若某条应参与具名战斗，需要单独设计属性系数并符合品阶预算。
