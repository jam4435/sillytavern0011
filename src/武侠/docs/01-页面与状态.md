# 页面与状态

## 目的与边界

本文说明前端页面流转、React 本地状态与酒馆聊天状态之间的关系。组件的具体布局和样式不在此记录，直接查看对应组件即可。

## 页面流程

`PageState` 定义在 [`../types.ts`](../types.ts)：

```text
booting -> start -> splash -> setup -> opening -> game
```

实际入口由 [`../App.tsx`](../App.tsx) 初始化时调用 `detectGameSessionState()` 决定：

| 会话状态  | 页面      | 行为                                 |
| --------- | --------- | ------------------------------------ |
| `empty`   | `start`   | 没有可用游戏变量，显示启动页         |
| `opening` | `opening` | 已创建变量，但尚未产生正式剧情       |
| `active`  | `game`    | 读取变量和最新助手正文，直接进入游戏 |

新游戏由 `NewGameSetup` 收集七步表单数据，`initializeNewGameSession()`
负责生成并写入初始变量。初始化成功后会在进入开局输入页前显示一次实际酒馆聊天存档命名窗，默认
`角色名 · 开局地点`；玩家可以确认改名，也可以保留酒馆当前名称。开局输入完成后才进入正式游戏页面。首屏会话检查在用户进入新角色流程后不再覆盖页面；角色创建和初始命名期间会延后事件通知，避免抢占这项事务。

已有 `opening` 或 `active` 聊天没有返回 `setup`
更换开局事件的路由。自动化或人工测试不同开局事件时，应在酒馆宿主页创建新的空聊天，再走
`start -> splash -> setup -> opening -> game`；不得直接改写既有聊天的初始化变量伪造另一种开局。

## 状态分层

| 状态层       | 负责内容                                                  | 主要入口                                   |
| ------------ | --------------------------------------------------------- | ------------------------------------------ |
| 页面状态     | 当前页面、加载状态、是否已有存档                          | `hooks/usePageFlow.ts`                     |
| 游戏显示状态 | 玩家、物品、事件、人物、正文、选项                        | `hooks/useGameState.ts`                    |
| 酒馆持久状态 | 聊天楼层、聊天级 `stat_data`、角色级变量                  | 酒馆助手 API                               |
| 显示设置     | 主题、字体、背景、周边栏目/弹窗透明度、正则、额外模型配置 | `utils/settingsManager.ts`                 |
| 面板交互状态 | 指令队列弹窗、地图草稿目的地、移动端侧边栏开关            | `App.tsx`、`MapPanel.tsx`                  |
| 临时观测状态 | 最新调试轮次、变量变更条                                  | `useDebugLogs`、`useVariableChangeTracker` |

React 中的 `GameState` 是 `getAllVariables()`
合并变量视图的显示投影，不是最终数据源。需要持久化的游戏状态必须写回聊天级变量或聊天楼层。

## 主界面组合

`App.tsx` 负责组合：

- `GameContent`：最新助手正文和选项。
- `EventTracker`：主聊天正文左上方的“江湖事簿”，投影参与中、江湖中、后续线索，以及进入提前十天窗口的全域事件预告；预告地点可点击生成移动指令。折叠偏好只存于本地显示设置。
- `VariableChangeBar`：当前回合变量观测结果。
- `ChatInput`：底部手动输入和重新生成入口。
- `CommandQueueButton` / `CommandQueuePopover`：待发送指令查看与取消，以及当前聊天最近五次原始玩家输入的回填入口。
- `components/panels/`：角色、功法、背包、事件、社交和地图面板。
- `SettingsPanel`：设置、变量编辑、自动推进和调试。
- `SaveLoadPanel`：聚合多个实际聊天的自动逻辑历史树；节点选择本身不会切换聊天。

这些组件只应通过 props 和专用 Hook 交互，不应各自重复监听全局消息事件。

地图面板是模态面板中的一条独立交互链：`App -> MapPanel -> MapCanvas / MapSidebar / LocationPopover -> useCommandQueue`。细节见
[09-地图与指令](./09-地图与指令.md)。

## 自动历史与分支

[`../utils/saveLoadManager.ts`](../utils/saveLoadManager.ts) 将酒馆聊天楼层、swipe 与原生 branch chat 聚合成一棵逻辑树：

- 每个完整 assistant 回合的每个 swipe 都是一个自动节点；活动 swipe 才成为下一回合的父节点。
- `wuxia_history_tree_v2` 保存在角色级变量中，只记录定位、父子关系、短预览、题名、钉住状态与校验哈希，不复制正文或
  `stat_data`。
- 题名与钉住只是轻量元数据，不创建 checkpoint。
- 只有从历史节点继续时才调用 `/branch-create`
  创建实际聊天；创建前仅在酒馆内存快照中选择目标 swipe，不写回来源聊天，因此不需要在来源与新分支之间往返恢复。切换既有分支前先确认聊天文件存在，再按聊天 ID 调用
  `openCharacterChat` / `openGroupChat` 精确导航。
- 新分支停在所选 assistant 节点。若原路线在该节点后已有玩家行动，会把这段行动持久化为该分支的输入草稿并预填到武侠输入框；草稿不会自动发送，也不会触发生成，玩家可修改后手动发送。
- 跨 iframe 重载的 checkout 阶段保存在 `wuxia_history_checkout_journal_v1`；期间发送、重新生成和事件检查会锁定。
- 切换完成前必须恢复目标 swipe、执行 ERA full sync、重算事件派生字段并核对 MK/事件哈希。校验失败的分支不得继续生成。
- 仅在 `fork_branch` 完整提交后触发实际酒馆聊天自动命名：有节点题名时为 `根卷名 · 节点题名`，没有时为
  `根卷名 · 第N段`（N 为所选节点沿 `parentId` 到根的段数）。实际聊天列表重名时自动追加
  ` · 2`、` · 3`。既有分支切换、原地 swipe 和普通节点不会触发聊天改名。
- 谱牒标题旁的铅笔可随时手动修改当前实际聊天存档名。改名使用独立的 `wuxia_chat_rename_journal_v1`
  生命周期事务，重载后验证真实新名称，再迁移历史 locator/branch、头像缓存和未发送草稿；成功后会重开“存档与分叉”面板。
- 改名事务存在的 120 秒内，发送、重新生成、checkout 和前端派生变量写入都会锁定。自动命名失败不会回滚已经成功提交的分支。
- 旧 `wuxia_save_tree` 不读取、不迁移，也不主动删除。

角色创建配置的本地存档、剧情历史树节点题名和实际酒馆聊天存档名是三套机制，不要混用。

## 必须保持的约束

1. 酒馆聊天变量和楼层是持久数据源，React 状态只用于当前界面显示。
2. `readGameDataPure()` 必须保持纯读取；后台补全通过调度器单独执行。
3. 切换聊天时必须重新读取会话并清理当前回合的临时观测状态。
4. 正文显示应使用当前有效 assistant swipe，而不是假设最后一个数组元素就是有效回复。
5. 江湖事簿与完整事件页都只读取 `GameState.events` / `chronicle`；事件脚本负责维护
   `前端变量.可发现事件`，组件只展示开始倒计时并复用地图移动指令链，不得自行开始或参与事件。
6. 聊天改名不是 ERA 或普通变量写入；只有 journal 身份核对成功后才迁移引用，节点题名不能触发它。

## 修改后验证

- 空聊天进入启动页。
- 已初始化未开局的聊天进入开局输入页。
- 已有剧情的聊天直接进入游戏并显示最新正文。
- 切换聊天后角色状态、正文、变量条均来自新聊天。
- 每个成功完成事件结算的回合会自动入树；历史继续只新增一个聊天，原分支未来与变量保持不变。
- 主档初始化成功才显示一次命名窗；跳过不改名。新分支自动命名失败时，分支仍可继续使用酒馆自动名称。
