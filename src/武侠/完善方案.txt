武侠物品 / 品阶、装备栏与状态效果模型（2026-07-03）

一、当前已落地

1. 底层物品存档字段统一使用 `品阶`，不再使用 `品质`。
   - 当前开发版不做旧 `品质` 兼容。
   - 包裹物品基础字段仍是 `类型` / `品阶` / `物品描述` / `数量`。

2. 秘籍继续保持独立语义链。
   - 包裹里的秘籍只表示“持有关系”和数量。
   - 真实描述、功法品阶、参悟条件仍优先读取功法数据库。

3. 装备和丹药已有类型专属字段。
   - 装备：`部位` / `属性修正` / `使用状态`。
   - 丹药：`属性修正` / `持续时间`。
   - `使用状态` 保留为显示/同步字段，但不再作为属性计算真值。

4. 新增两个独立状态面。
   - `user数据.装备栏`：按 `部位 -> 物品名` 记录当前生效装备。
   - `user数据.状态效果`：记录生效中的丹药效果，包含 `来源`、`属性修正`、`持续时间`、`剩余时间`。

5. 属性计算已接入装备栏和状态效果。
   - `attributeCalculator` 支持最终属性修正，`属性修正` 中的数字统一表示百分比点。
   - `variableReader` 会从 `装备栏` 和仍有 `剩余时间` 的 `状态效果` 收集修正。
   - `气血` / `内力` 会按 `气血上限` / `内力上限` 的别名处理。
   - 战力区派生变量也会读取玩家的装备和状态效果修正。
   - 前端行囊栏会基于 `stats.baseAttributes` 预览装备后或服药后的实际属性变化。

6. 行囊按钮已经接入真实写入链。
   - 装备按钮写入 `装备栏`，同一部位会替换旧装备，并同步包裹里的 `使用状态`。
   - 吞服按钮会扣减丹药数量、创建 `状态效果`，并加入待发送指令队列。
   - 取消吞服指令会用完整物品快照恢复包裹，并删除本次创建的状态效果。
   - 玩家消息成功发送后，状态效果 `剩余时间` 递减，归零后删除。

二、当前数据模型

1. 普通杂物
   - 继续只需要基础字段。

2. 秘籍
   - 包裹负责是否持有与数量。
   - 功法数据库负责描述、品阶、参悟条件。

3. 装备
   - 包裹物品节点是装备模板。
   - `装备栏` 是装备是否生效的真值。
   - 包裹里的 `使用状态` 只是 UI 显示/同步字段。

4. 丹药
   - 包裹物品节点是可消耗物品模板。
   - `状态效果` 是药效是否仍在持续的真值。
   - 包裹里的 `持续时间` 是创建状态效果时使用的模板时长。

三、仍需注意的风险

1. 写入不是事务。
   - 装备栏、包裹状态、丹药扣减、状态效果创建仍可能拆成多次 ERA 写入。
   - 代码已对吞服失败做物品快照恢复，但运行时仍要把 ERA 超时当成真实风险。

2. 包裹仍是 `Record<物品名, 物品数据>`。
   - 适合标准丹药、标准秘籍、固定模板装备。
   - 不适合同名装备不同词条、不同耐久、同名多实例装备。
   - 如果以后要随机词条或耐久，包裹需要升级为实例化物品结构。

3. 丹药叠加规则仍是最小实现。
   - 同名丹药再次服用会创建独立状态效果。
   - 还没有做同名覆盖、同类互斥、刷新持续时间、叠层上限等规则。

四、当前结论

物品系统已经从“包裹展示模型”推进到“包裹模板 + 装备生效状态 + 丹药持续状态”的三层模型。下一步如果继续完善，优先设计同名装备实例化和丹药叠加/互斥规则，而不是继续往包裹单个物品节点堆字段。
