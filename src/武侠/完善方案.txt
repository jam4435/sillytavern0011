武侠物品 / 秘籍“品阶”与装备丹药扩展模型（2026-07-02）

一、当前已落地

1. 底层物品存档字段已经统一使用 `品阶`，不再使用 `品质`。
   - 当前开发版也不再兼容旧字段 `品质`
   - 新数据必须写 `品阶`

2. 包裹物品的基础结构仍然是：
   - `类型`
   - `品阶`
   - `物品描述`
   - `数量`

3. 在基础结构之上，装备和丹药现在允许携带类型专属字段。
   - 装备：
     - `部位`
     - `属性修正`
     - `使用状态`
   - 丹药：
     - `属性修正`
     - `持续时间`

4. 前端读取链已经能把这些类型专属字段解析出来。
   - `src/武侠/utils/variableReader.ts`
     - 装备会解析为 `equipInfo`
     - 丹药会解析为 `elixirInfo`
   - `src/武侠/types.ts`
     - `InventoryItem` 已增加：
       - `equipInfo`
       - `elixirInfo`
     - `OriginItemInfo` / `InventoryItemVariableData` 也已允许这些字段

5. 行囊详情窗口已经能显示这些字段。
   - `src/武侠/components/panels/InventoryPanel.tsx`
     - 装备可显示：
       - 部位
       - 使用状态
       - 属性修正
     - 丹药可显示：
       - 持续时间
       - 属性修正

6. 秘籍仍然保持原有的独立语义链路。
   - 包裹里的秘籍仍只负责“持有关系”
   - 真实描述 / 品阶 / 参悟条件仍优先取功法数据库

二、当前真实数据模型

1. 普通杂物
   - 仍然只需要基础四字段即可

2. 秘籍
   - 包裹字段负责：
     - 是否持有
     - 数量
   - 功法数据库负责：
     - 真实描述
     - 真实品阶
     - 参悟条件

3. 装备
   - 现在已经可以在物品节点上表达：
     - 这是装备在哪个部位
     - 它会修正哪些属性
     - 当前是否处于使用中 / 装备中

4. 丹药
   - 现在已经可以在物品节点上表达：
     - 服用后会修正哪些属性
     - 该效果模板的持续时间

三、当前还没有落地的部分

1. 这些新字段目前还是“存档真值 + 前端展示真值”，还没有正式接入属性计算。
   - `src/武侠/utils/attributeCalculator.ts`
   - 当前仍然只吃：
     - 初始属性
     - 境界
     - 功法
   - 还没有吃：
     - 装备属性修正
     - 丹药属性修正

2. `使用状态` 目前只是数据字段，不等于已经有完整装备栏系统。

3. `持续时间` 目前表示丹药效果模板时长，不等于已经有“生效中的丹药状态表”。
   - 如果以后要支持“服药后持续 3 回合 / 3 个时辰”，还需要单独的：
     - `状态效果`
     - 或 `临时效果`
     - 或类似的前端派生变量区

四、当前真实风险

1. `itemManager.ts` 仍然只完整处理数量，不完整处理整个物品对象。
   - 现在这个风险比之前更大了
   - 因为丢失的不再只是：
     - `类型`
     - `品阶`
     - `物品描述`
   - 还会丢失：
     - `部位`
     - `属性修正`
     - `使用状态`
     - `持续时间`

2. 当前包裹结构仍然是 `Record<物品名, 物品数据>`。
   - 这适合：
     - 标准丹药
     - 标准秘籍
     - 固定模板装备
   - 但不适合：
     - 同名装备不同词条
     - 同名装备不同耐久
     - 一件同名装备已装备，另一件未装备

3. 所以如果以后装备要做“实例化”，包裹结构迟早还得继续升级。

五、建议的下一步顺序

1. 先修 `itemManager` 的完整快照恢复。
   - 恢复时必须写回完整物品对象，而不是只写回数量

2. 再补“装备栏 / 状态效果”两个独立状态面。
   - 装备栏负责“哪些装备正在生效”
   - 状态效果负责“哪些丹药效果正在持续”

3. 然后再把属性计算链接上。
   - 装备：
     - 只读取 `使用状态 === 装备中` 或装备栏中的项目
   - 丹药：
     - 只读取当前仍在持续的状态效果

4. 如果以后要做随机词条、耐久、残损、版本差异，再考虑把装备从“按名字聚合”升级成“实例化物品”。

六、当前结论

1. 物品系统现在已经不只是“类型 / 品阶 / 描述 / 数量”的极简展示模型。
   - 装备和丹药已经开始有可扩展的结构化字段

2. 但这一步仍然属于“真实建模的第一层”。
   - 已经能存
   - 已经能读
   - 已经能显示
   - 还没有正式参与数值结算

3. 接下来最应该做的，不是继续往包裹节点堆字段，而是把：
   - 完整恢复链
   - 装备生效状态
   - 丹药持续状态
   这三条链补完整。
