# 金庸群侠传·势力与差事任务系统设计与架构规范

## 一、 系统定位与设计哲学

势力系统是连接「武学传承技能树」、「师友同门人际网」、「大世界合法地点」、「剧情事件」与「势力差事/历练」的核心枢纽。
本设计严格遵循金庸武侠世界观与项目底层《架构.md》规范：

1. **体系泛化为「势力」（Factions）**：
   金庸江湖兼具多种组织形态，系统统一划分为四大势力子类：
   * **宗门（门派）**：少林、武当、全真、古墓、峨嵋（走正统拜师、按辈分收录、传授玄门正宗）；
   * **帮会**：丐帮、铁掌帮、海沙帮（走结义纳投名状、立功升香主/舵主、受帮规约束）；
   * **世家（庄门）**：大理段氏、姑苏慕容、桃花岛、白驼山（走门客、客卿、客将或结缘家臣）；
   * **行伍（军旅）**：蒙古战阵行伍、岳家军（走投军应募、依战功升百夫长/偏将）。
2. **真实状态极简持久化**：
   * `stat_data` 是唯一差分真相源。玩家所属势力在 `stat_data.user数据.势力` 下；玩家已接取任务在顶层 `stat_data.任务` 下；后台生成但尚未接取的候选差事在 `stat_data.前端变量.可选任务.【势力名】` 下。
   * 静态武学谱系与势力描述打包进前端静态资产（`_合并后功法.json` 与 `sects.json`），不在存档中冗余存放。
3. **叙事与时序因果自然**：
   * 拜师、请教等需要剧情演播的动作：由 User 消息发送客观行动指引，由 Assistant 在回复中先完成收徒/传授考核剧情，**随后在文末携带标准的 `<VariableInsert>` / `<VariableEdit>` 标签落库**，杜绝“生成回复前先落库导致 AI 穿帮”的时序错误。
   * 数值增减（修为扣除、贡献发放）由前端读取当前绝对值后计算并提交，严禁直接向 ERA 传入负数或 `+=` 增量字符串。
4. **任务完成状态由 AI 闭环推进**：
   * 任务地点严格约束在当前区域的合法三级地点白名单内（如 `终南山/豺狼谷`、`终南山/重阳宫`）；
   * 任务完成后，AI 在相应剧情结尾通过 `<VariableEdit>` 将 `任务执行情况` 更新为 `"已完成"`；
   * 玩家在前端点击【交付差事 / 领取奖励】按钮，由前端完成安全绝对值结算并清除任务。

## 二、 真实持久化变量结构规范 (stat_data)

### 1. 玩家数据结构 (`stat_data.user数据.势力`)
采用以势力名为 Key 的扁平多势力结构，支持身兼多派、奇遇记名与叛门留档；不设置主势力，也不增加额外包装层：
```json
{
  "user数据": {
    "用户名": "墨逸",
    "身份": {
      "全真教": "三代亲传弟子"
    },
    "势力": {
      "全真教": {
        "体系类型": "宗门",
        "身份": "三代亲传弟子",
        "师承": "丘处机",
        "贡献": 150,
        "状态": "在籍"
      },
      "桃花岛": {
        "体系类型": "世家",
        "身份": "记名门客",
        "师承": "黄药师",
        "贡献": 50,
        "状态": "记名"
      }
    },
    "关系网": {
      "丘处机": "授业恩师/75",
      "赵志敬": "同门师兄/30"
    },
    "功法": {
      "玄门守一诀": { "掌握程度": "融会贯通" },
      "全真掌法": { "掌握程度": "略有小成" }
    },
    "修为": 320,
    "包裹": {
      "九转金丹": {
        "类型": "药品",
        "品阶": "绝品",
        "物品描述": "全真教秘制疗伤圣药。",
        "数量": 1
      }
    }
  }
}
```

### 2. 正式任务与可选任务变量结构
玩家已经接取的正式任务仍存放在顶层 `stat_data.任务`。后台生成但玩家尚未选择的候选差事存放在 `stat_data.前端变量.可选任务.【势力名】`，按势力分组。

**两处的单个任务对象结构完全一致**：候选差事不增加 id、难度、生成时间或其它包装字段。常规变量 AI 不得新增或删除正式任务，也不得修改 `所属势力 / 任务详情 / 任务地点 / 任务奖励`；已有正式任务只允许修改 `任务执行情况`。

候选池示意：
```json
{
  "前端变量": {
    "可选任务": {
      "全真教": {
        "终南豺狼谷除狼患": {
          "所属势力": "全真教",
          "任务详情": "近日终南山豺狼谷常有恶狼盘踞侵扰山民，速去剿除恶狼，护持山门清宁。",
          "任务地点": "大宋/终南山/豺狼谷",
          "任务执行情况": "未到达地点",
          "任务奖励": {
            "贡献增量": 30,
            "修为增量": 50,
            "获得物品": {
              "铜钱": { "类型": "货币", "品阶": "凡品", "物品描述": "流通铜钱。", "数量": 200 }
            }
          }
        }
      }
    }
  }
}
```

正式接取后只是把选中的同构任务对象从对应势力候选池搬入顶层 `任务.【任务名】`。

任务地点严格使用合法三级路径，奖励采用受控增量结构（由前端计算后安全写入）：
```json
{
  "任务": {
    "终南豺狼谷除狼患": {
      "所属势力": "全真教",
      "任务详情": "近日终南山豺狼谷常有恶狼盘踞侵扰山民，速去剿除恶狼，护持山门清宁。",
      "任务地点": "大宋/终南山/豺狼谷",
      "任务执行情况": "未到达地点",
      "任务奖励": {
        "贡献增量": 30,
        "修为增量": 50,
        "获得物品": {
          "铜钱": {
            "类型": "货币",
            "品阶": "凡品",
            "物品描述": "流通铜钱。",
            "数量": 200
          }
        }
      }
    }
  }
}
```
* **字段说明**：
  * **Key（任务名）**：如 `"终南豺狼谷除狼患"`，防止重复接取；
  * **`任务地点`**：必须为当前所在大区域的合法三级地点（严格白名单）；
  * **`任务执行情况`**：`"未到达地点"` $\rightarrow$ `"进行中"` $\rightarrow$ `"已完成"`；这是常规变量 AI 唯一允许修改的任务字段；
  * **`任务奖励`**：只保留受控的增量数值与物品对象，不直接使用自由补丁；创建后对常规变量 AI 只读。

## 三、 势力界面布局与模块化设计

在主导航栏新增 `[势力]` Tab：

### 1. 界面视图布局
* **视图 A：【我的势力】（已加入势力的玩家）**
  * **顶部信息栏**：势力徽标、势力名称、主峰驻地、玩家身份称号（如亲传弟子/香主/偏将）、师承领袖、当前贡献值；
  * **左侧/中央：传承武学树**：直观展示所属势力的武学节点树，区分「已掌握」、「可请教」、「未解锁」三种状态；
  * **右侧分栏：【势力差事】子组件 `<SectTaskList />`**：
    * 展示当前接取的势力差事卡片（任务详情、地点、执行情况、预计奖励）；
    * 提供【查看/刷新差事】生成候选池；候选卡片提供【接取此差事】，正式任务卡片提供【交付差事 / 领取奖励】；
  * **底部动作栏**：【向师请教】、【同门切磋】、【申请晋升】、【破门叛离】。
* **视图 B：【天下势力鉴赏】（散修默认显示 / 随时切换）**
  * 三份原著势力资料仍由 `factionIdentityMap.json` 做 54→46 的世界组织归一，但玩家列表只展示 `factionPublicCatalog.json` 中 `可加入 + sectId` 的 23 个正式可玩势力；
  * 正式可玩势力仍使用宗门/帮会/世家/行伍四种玩法类型；政权与普通组织只留在资料层，不占据天下势力鉴赏卡位；
  * “当前掌舵人”优先读取当前聊天 `角色数据.*.身份` 中的标准首领身份键，只认仍存活的有效人物；没有可靠动态身份时显示未确认，原著资料首领保留在考据层，不直接铺到正常玩家 UI；
  * 公开鉴赏页**不展示完整传承武学谱系**。只有 `可加入 + sectId` 的公开势力才桥回 `sects.json` 提供驻地导航和拜入入口；完整武学树只在【我的势力】展示。

## 四、 核心交互流程与提示词注入规范

### 1. 【拜入门派 / 投身势力】（属性判定 + AI 回复带 `<VariableInsert>`）
* **前置条件**：身处对应势力三级驻地（如 `终南山/重阳宫`），且前置属性达标（如全真悟性 $\ge 8$）。
* **自动触发 User 消息**：
  ```markdown
  User前去拜入全真教门下。

  [系统指令与剧情指引]
  - 交互动作：拜入门派
  - 考核维度：【道门心性与经籍悟性】（玩家悟性已达标）
  - 剧情要求：优先使用当前人物身份变量已确认的现任掌舵人或接引长辈；若未确认，则只写“本门长辈”，不得从静态历代掌舵人列表强行指定当前人物。
  - 变量写入：正文完成后，必须在回复最末尾原样附带以下标准变量插入块：
  <VariableInsert>
  {
    "user数据": {
      "身份": { "全真教": "入门弟子" },
      "势力": {
        "全真教": {
          "体系类型": "宗门",
          "身份": "入门弟子",
          "师承": "马钰",
          "贡献": 0,
          "状态": "在籍"
        }
      },
      "功法": {
        "玄门守一诀": { "掌握程度": "初窥门径" }
      }
    }
  }
  </VariableInsert>
  ```

### 2. 【查看/刷新势力差事】与【接取差事】
* **查看/刷新差事是后台生成，不创建聊天回合**：
  1. 玩家点击【查看差事】或【刷新差事】；
  2. 前端调用与额外变量模型相同的后台 API 配置，发送专用的“任务候选生成”提示词；该提示词包含完整任务结构、当前势力、玩家境界与合法三级地点白名单，但**绝不进入正文 User 输入**；
  3. 后台模型一次生成多项候选任务，只返回结构化 JSON；前端校验势力、地点白名单、任务名与字段结构；
  4. 使用 ERA 把本批候选结果写入 `stat_data.前端变量.可选任务.【势力名】`，刷新同一势力时整批替换旧候选；
  5. 同时向 Command Queue 加入一条“User前往势力查看到这些差事”的轻量叙事指令，等待玩家下一次真实发言时再交给正文 AI 自然承接。

* **候选任务结构**：
  后台模型只生成与正式任务完全相同的任务对象；返回根节点使用 `"任务"` 只是为了便于后台 JSON 解析。通过校验后，其内部任务键值对直接成为 `前端变量.可选任务.【势力名】` 的内容。

* **接取某一项差事完全由前端处理**：
  1. 玩家在候选列表点击【接取此差事】；
  2. 前端重新读取最新变量并检查正式任务上限、重名与候选是否仍存在；
  3. 发起一个 ERA 原子事务，把 `前端变量.可选任务.【势力名】.【任务名】` 的同构对象写入顶层 `任务.【任务名】`，并从候选池删除该项；
  4. 向 Command Queue 追加“User已正式接下《任务名》”的叙事指令；
  5. 整个接取过程不调用任何 AI，也不生成聊天楼层。

### 3. 【向师请教 / 武学进阶】（前端扣费 + AI 传功剧情）
* **流程时序**：
  1. 玩家点击【请教全真剑法】，前端检测修为与贡献是否充足（如需 150 修为、50 贡献）；
  2. 前端读出当前修为与贡献，在前端计算新值（`newCultivation = 320 - 150 = 170`），发起底层确定性事务写入扣减后的数值与已掌握功法；
  3. 扣费成功后，向聊天栏发送 User 消息请求 AI 生成生动教学剧情：
  ```markdown
  User向师尊丘处机请教《全真剑法》。

  [系统动作：向师请教]
  - 传功对象：丘处机
  - 研习功法：全真剑法（层级：基础）
  - 剧情要求：请结合师徒双方性格，生成丘处机考校剑招基础、亲自喂招拆解并传授运气口诀的生动叙事。
  ```

### 4. 【任务完成判定与结算】
* **AI 判定完成**：
  当玩家在目标地点完成剿狼战斗后，AI 在剧情演播末尾附带状态修改：
  ```xml
  <VariableEdit>
  {
    "任务": {
      "终南豺狼谷除狼患": {
        "任务执行情况": "已完成"
      }
    }
  }
  </VariableEdit>
  ```
* **前端结算**：
  1. 界面检测到 `任务执行情况 === "已完成"`，【交付差事 / 领取奖励】按钮亮起；
  2. 玩家点击领奖：
     - 前端读取 `任务奖励` 中的 `贡献增量`（+30）、`修为增量`（+50）与 `获得物品`；
     - 前端读取最新 `stat_data`，计算出新贡献（`150 + 30 = 180`）与新修为（`170 + 50 = 220`）；
     - 发起原子事务 `era:transactionByObject` 一次性完成：更新贡献、更新修为、插入新物品、删除已领取的任务键；
     - 弹出奖励浮层，数值即时安全到账；
  3. **可选剧情引导（Command Queue）**：
     - 向指令队列追加一条轻量提示：`🏷️ [师门汇报] 交付除狼差事`；
     - 玩家下次打字发言时，自动附带剧情提示供 AI 接戏，兼顾代入感且无需重度持久化。

## 五、 奇遇事件与修为奖励兼容方案

针对历史奇遇文件中出现的 `"武功"` 老字段与字符串 `"+3500"` 修为增量，制定双重保障：

1. **主流规范：奇遇发放道具/秘籍（推荐）**：
   奇遇事件优先通过 `insert` 发放可参悟的秘籍、残卷或灵药（如“琅嬛神仙卷”、“莽牯朱蛤内丹”）。玩家在背包中点击【使用 / 参悟】，由成熟稳定的 `itemManager` 计算绝对增量，RPG 爽快感与工程安全性兼备。
2. **底层安全防御（事件结算器预处理）**：
   在事件结算逻辑构建写入操作之前，进行增量前置拦截计算：
   若检测到更新值为 `"+数字"` 格式字符串（如 `"+3500"`），且目标字段为数值型（如 `修为`、`贡献`），在内存中读出原值并折算为绝对整数后再生成 ERA 事务，坚决阻止原始非数格式污染存档。

## 六、23 个正式可玩势力扩充约束

* 现有 17 个正式势力扩充为 23 个：新增灵鹫宫、大理天龙寺、青城派、蓬莱派、神农帮、西夏一品堂。
* 逍遥派与灵鹫宫分层：逍遥派保留北冥、小无相、凌波、白虹等隐世高阶传承；灵鹫宫承接天山六阳掌、生死符、天山折梅手、八荒六合唯我独尊功等天山系组织化传承。
* 大理段氏与天龙寺分层：大理段氏保留段氏内功、段家剑、一阳指及一灯门下支线；天龙寺独立承接禅息、枯荣禅功与六脉神剑体系。一阳指允许作为同一数据库功法存在多个合法传承入口。
* 青城、蓬莱不强制补造绝世镇派神功；神农帮侧重药毒、解毒与火攻；西夏一品堂侧重军中共训与客卿支线，不把客卿独门武功自动视为全体成员共有。
* `_合并后功法.json` 中为玩法完整度新编的功法使用 `来源类型: 合理补全`；事件或原著已有明确名称的新增功法使用 `来源类型: 原著明确`，便于开发审计，前端无需默认展示该字段。
* 当前运行数据以 `sects.json` 的 **23 个正式势力、220 个传承节点**为准；旧 `plans/武侠角色功法审计/门派功法谱系.json`（17/182）仅为历史审计快照。
* 新增驻地必须同时在 `武侠地点表.yaml` 注册三级地点，地图 `mapLoader` 才能解析导航坐标；`locationLore.ts` 只提供背景说明，不代替地图地点登记。
* 本阶段只完善静态谱系、公开 UI 和地点接驳，不引入组织级动态状态或分支 override。
