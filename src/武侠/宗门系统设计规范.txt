# 金庸群侠传·宗门与宗门任务系统设计与架构规范

## 一、 系统定位与设计哲学

宗门系统是连接「武学传承技能树」、「师徒同门人际网」、「世界三级地点」、「剧情事件」与「宗门差事/任务」的核心枢纽。
本设计严格遵循金庸武侠世界观与项目底层《架构.md》规范：
1. **真实状态极简持久化**：`stat_data` 是唯一差分真相源。玩家数据统一存储在 `stat_data.user数据` 下，宗门任务存储在顶层 `stat_data.任务` 下；静态门派武学谱系与描述打包进前端静态资产（`sects.json`），绝不在存档中冗余存放。
2. **纯函数衍生呈现**：17 大门派的 182 个武学传承节点、掌门与核心传人名单打包进前端，NPC 归属由 `角色数据[NPC名].身份` 及静态名单纯函数动态聚类。
3. **回退安全（Rollback-safe）与叙事驱动**：交互动作（拜师、请教、晋升、接取差事、切磋）采用「自动发送一轮 User 消息 + 消息体内嵌 ERA 变更块」的机制；自动发送的玩家行动提示必须保持简洁客观（如 `User前去查看宗门任务`），为不同性格角色的 AI 自由发挥留足空间。
4. **兼容金庸式奇遇**：宗门系统仅约束本门正统拜师学艺路线，玩家完全可通过野外奇遇、战利品、秘籍或高人指点自由兼修其他门派绝学。

## 二、 真实持久化变量结构规范 (stat_data)

严格匹配项目前端真实 `stat_data` 结构（玩家数据在 `user数据` 下，任务在顶层 `任务` 下）：

### 1. 玩家数据结构 (`stat_data.user数据`)
```json
{
  "user数据": {
    "用户名": "墨逸",
    "身份": {
      "全真教": "三代亲传弟子"
    },
    "宗门": {
      "当前门派": "全真教",
      "门派身份": "三代亲传弟子",
      "师承": "丘处机",
      "宗门贡献": 150
    },
    "关系网": {
      "丘处机": "授业恩师/75",
      "赵志敬": "同门师兄/30"
    },
    "功法": {
      "玄门守一诀": { "掌握程度": "融会贯通" },
      "全真掌法": { "掌握程度": "略有小成" }
    },
    "修为": 320,
    "包裹": {
      "九转金丹": {
        "类型": "药品",
        "品阶": "绝品",
        "物品描述": "全真教秘制疗伤圣药。",
        "数量": 1
      }
    }
  }
}
```

### 2. 任务变量结构 (`stat_data.任务`，顶层键值对)
任务数据采用同级键值对结构（以任务名为 Key），任务奖励遵循世界书事件系统的 `insert / update` 语法：
```json
{
  "任务": {
    "终南后山除狼患": {
      "任务详情": "近日后山常有恶狼盘踞侵扰山民，速去后山剿除恶狼，护持山门清宁。",
      "任务地点": "大宋/终南山/后山",
      "任务执行情况": "未到达地点",
      "任务奖励": {
        "insert": {
          "user数据": {
            "宗门": {
              "宗门贡献": 30
            },
            "修为": 50,
            "包裹": {
              "铜钱": {
                "类型": "货币",
                "品阶": "凡品",
                "物品描述": "流通铜钱。",
                "数量": 200
              }
            }
          }
        },
        "update": {
          "user数据": {
            "关系网": {
              "丘处机": "授业恩师/80"
            }
          }
        }
      }
    }
  }
}
```
* **字段说明**：
  * **Key（任务名）**：如 `"终南后山除狼患"`，天然防止重复接取同名差事；
  * **`任务地点`**：标准三级/四级地点路径；若为门内静坐/抄经类任务，此键可省略；
  * **`任务执行情况`**：`"未到达地点"` $\rightarrow$ `"进行中"` $\rightarrow$ `"已完成"`；
  * **`任务奖励`**：采用事件系统 `insert / update` 差分格式，目标对象为 `user数据`。

## 三、 宗门界面布局与子组件模块化设计

在主导航栏新增 `[宗门]` Tab。初期直接将任务列表作为子组件内嵌在宗门界面中，后期可平滑独立：

### 1. 界面视图布局
* **视图 A：【我的师门】（已入门派玩家）**
  * **顶部信息栏**：宗门徽标、门派名称、主峰驻地、玩家宗门身份（外门/入门/亲传/执事/掌门）、师承师尊、宗门贡献值；
  * **左侧/中央：本门传承树**：直观展示 182 节点武学树，区分「已掌握」、「可请教」、「未解锁」三种状态；
  * **右侧分栏：【师门差事】子组件 `<SectTaskList />`**：
    * 展示当前接取的宗门任务卡片（任务详情、地点、执行情况、预计奖励）；
    * 提供【接取门派差事】与【交付差事 / 领取奖励】按钮；
  * **底部动作栏**：【向师请教】、【同门切磋】、【申请晋升】、【破门叛逃】。
* **视图 B：【天下宗门鉴赏】（散修默认显示 / 随时切换）**
  * 17 大门派势力图谱、主峰地点、历代掌舵人与全门派武学图鉴。

### 2. 模块化扩展保障
* `<SectTaskList />` 独立封装，底层直接读取 `stat_data.任务`；
* **未来扩展**：若后续需要引入个人委托或江湖悬赏，仅需在左侧主导航栏新增 `[历练 / 任务]` 按钮并将组件移入独立面板，**底层变量结构和业务逻辑零改动**。

## 四、 核心交互流程与提示词注入规范

所有交互动作均遵循「简洁客观的玩家行动声明 + 结构化系统指令」原则，严禁预设主观对白，给不同性格的 User 留足模型演绎空间。

### 1. 【中途拜入山门】（属性前置判定 + 考校 Prompt + 单轮正文生成）
* **前置空间**：玩家必须身处该门派三级驻地（如 `终南山·重阳宫大殿`）；
* **前置属性**：全真要求悟性 $\ge 8$，少林要求根骨 $\ge 8$ 等。不满足则按钮置灰提示；
* **自动触发 User 消息**：
  ```markdown
  User前去拜入全真教门下。

  [系统指令与剧情指引]
  - 交互动作：拜入全真教
  - 考核维度：【道门心性与经籍悟性】（玩家悟性已达标）
  - 剧情要求：请结合玩家当前的性格与经历，生成重阳宫接引师长（如丘处机/马钰）出题考校道经玄理、见其悟性非凡欣然收录、并赐予道号与入门心法的精彩正文。
  <!--era:transaction
  {
    "user数据": {
      "身份": { "全真教": "入门弟子" },
      "宗门": {
        "当前门派": "全真教",
        "门派身份": "入门弟子",
        "师承": "马钰",
        "宗门贡献": 0
      },
      "功法": {
        "玄门守一诀": { "掌握程度": "初窥门径" }
      }
    }
  }
  -->
  ```

### 2. 【接取门派差事】（点击按钮触发自动生成）
* **触发方式**：在宗门界面点击【接取门派差事】按钮；
* **自动触发 User 消息**：
  ```markdown
  User前去查看宗门任务。

  [系统指令：生成门派差事]
  - 当前门派：全真教
  - 玩家境界：三流-中期
  - 所在位置：终南山·重阳宫
  - 剧情要求：
    1. 请结合玩家性格与全真教道家门派风貌，由门派长辈（如丘处机、马钰或知客道人）交代一段切合时宜的历练差事；
    2. 必须在回复末尾输出标准的 ```task 代码块，格式严格如下：
  ```task
  {
    "终南后山除狼患": {
      "任务详情": "近日后山常有恶狼盘踞侵扰山民，速去后山剿除恶狼，护持山门清宁。",
      "任务地点": "大宋/终南山/后山",
      "任务执行情况": "未到达地点",
      "任务奖励": {
        "insert": {
          "user数据": {
            "宗门": { "宗门贡献": 30 },
            "修为": 50
          }
        }
      }
    }
  }
  ```
  ```
* **前端捕获与入库**：前端拦截解析 ```task 块，通过 ERA 将该任务合入 `stat_data.任务`。

### 3. 【向师请教】（武学传承进阶）
* **前置检查**：身份达标、前置功法熟练度达标、师尊同处一地、扣除修为/宗门贡献；
* **自动触发 User 消息**：
  ```markdown
  User向师尊丘处机请教《全真剑法》。

  [系统动作：向师请教]
  - 传功对象：丘处机
  - 研习功法：全真剑法（层级：基础）
  - 剧情要求：请结合师徒双方性格，生成丘处机考校剑招基础、亲自喂招拆解并传授运气口诀的生动叙事。
  <!--era:transaction
  {
    "user数据": {
      "功法": { "全真剑法": { "掌握程度": "初窥门径" } },
      "修为": -150
    }
  }
  -->
  ```

### 4. 【任务结算机制】（按钮结算 + 指令栏回填 + ERA 变量修改）
当任务的 `任务执行情况` 变为 `"已完成"` 时，玩家在宗门面板点击【交付差事 / 领取奖励】：
1. **通道 1（前端即时 ERA 事务）**：
   - 前端直接读取 `任务[任务名].任务奖励`，发起 `era:transactionByObject`；
   - 自动执行奖励中的 `insert / update` 差分（如 `user数据.宗门.宗门贡献 += 30`，`user数据.修为 += 50`）；
   - 从 `stat_data.任务` 中删除该任务键；
   - 界面立即弹出奖励浮层，数值即时到账。
2. **通道 2（向指令栏 Command Queue 回填剧情提示）**：
   - 自动在指令栏追加一条待发送指令：
     `"【系统剧情提示】：玩家已在山门交付了宗门差事《终南后山除狼患》。请在下一轮生成师门长辈验看成果、点头嘉许并给予勉励的对话与神态描写。"`
   - 玩家下一轮主动发言或点击继续时，AI 顺理成章接戏，剧情与数值两全其美！
