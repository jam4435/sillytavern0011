# 金庸群侠传·势力与差事任务系统设计与架构规范

## 一、 系统定位与设计哲学

势力系统是连接「武学传承技能树」、「师友同门人际网」、「大世界合法地点」、「剧情事件」与「势力差事/历练」的核心枢纽。
本设计严格遵循金庸武侠世界观与项目底层《架构.md》规范：

1. **体系泛化为「势力」（Factions）**：
   金庸江湖兼具多种组织形态，系统统一划分为四大势力子类：
   * **宗门（门派）**：少林、武当、全真、古墓、峨嵋（走正统拜师、按辈分收录、传授玄门正宗）；
   * **帮会**：丐帮、铁掌帮、海沙帮（走结义纳投名状、立功升香主/舵主、受帮规约束）；
   * **世家（庄门）**：大理段氏、姑苏慕容、桃花岛、白驼山（走门客、客卿、客将或结缘家臣）；
   * **行伍（军旅）**：蒙古战阵行伍、岳家军（走投军应募、依战功升百夫长/偏将）。
2. **真实状态极简持久化**：
   * `stat_data` 是唯一差分真相源。玩家所属势力在 `stat_data.user数据.势力` 下，任务在顶层 `stat_data.任务` 下。
   * 静态武学谱系与势力描述打包进前端静态资产（`_合并后功法.json` 与 `sects.json`），不在存档中冗余存放。
   * **旧档向下兼容**：若旧档中仅有 `stat_data.user数据.宗门`，前端读取层自动映射投影为 `势力`，读写平滑无感。
3. **叙事与时序因果自然**：
   * 拜师、请教等需要剧情演播的动作：由 User 消息发送客观行动指引，由 Assistant 在回复中先完成收徒/传授考核剧情，**随后在文末携带标准的 `<VariableInsert>` / `<VariableEdit>` 标签落库**，杜绝“生成回复前先落库导致 AI 穿帮”的时序错误。
   * 数值增减（修为扣除、贡献发放）由前端读取当前绝对值后计算并提交，严禁直接向 ERA 传入负数或 `+=` 增量字符串。
4. **任务完成状态由 AI 闭环推进**：
   * 任务地点严格约束在当前区域的合法三级地点白名单内（如 `终南山/豺狼谷`、`终南山/重阳宫`）；
   * 任务完成后，AI 在相应剧情结尾通过 `<VariableEdit>` 将 `任务执行情况` 更新为 `"已完成"`；
   * 玩家在前端点击【交付差事 / 领取奖励】按钮，由前端完成安全绝对值结算并清除任务。

## 二、 真实持久化变量结构规范 (stat_data)

### 1. 玩家数据结构 (`stat_data.user数据.势力`)
采用以势力名为 Key 的多势力兼容结构，支持身兼多派、奇遇记名与叛门留档：
```json
{
  "user数据": {
    "用户名": "墨逸",
    "身份": {
      "全真教": "三代亲传弟子"
    },
    "势力": {
      "当前主势力": "全真教",
      "所属势力": {
        "全真教": {
          "体系类型": "宗门",
          "身份": "三代亲传弟子",
          "师承": "丘处机",
          "贡献": 150,
          "状态": "在籍"
        },
        "桃花岛": {
          "体系类型": "世家",
          "身份": "记名门客",
          "师承": "黄药师",
          "贡献": 50,
          "状态": "记名"
        }
      }
    },
    "关系网": {
      "丘处机": "授业恩师/75",
      "赵志敬": "同门师兄/30"
    },
    "功法": {
      "玄门守一诀": { "掌握程度": "融会贯通" },
      "全真掌法": { "掌握程度": "略有小成" }
    },
    "修为": 320,
    "包裹": {
      "九转金丹": {
        "类型": "药品",
        "品阶": "绝品",
        "物品描述": "全真教秘制疗伤圣药。",
        "数量": 1
      }
    }
  }
}
```

### 2. 任务变量结构 (`stat_data.任务`，顶层键值对)
任务地点严格使用合法三级路径，奖励采用受控增量结构（由前端计算后安全写入）：
```json
{
  "任务": {
    "终南豺狼谷除狼患": {
      "所属势力": "全真教",
      "任务详情": "近日终南山豺狼谷常有恶狼盘踞侵扰山民，速去剿除恶狼，护持山门清宁。",
      "任务地点": "大宋/终南山/豺狼谷",
      "任务执行情况": "未到达地点",
      "任务奖励": {
        "贡献增量": 30,
        "修为增量": 50,
        "获得物品": {
          "铜钱": {
            "类型": "货币",
            "品阶": "凡品",
            "物品描述": "流通铜钱。",
            "数量": 200
          }
        }
      }
    }
  }
}
```
* **字段说明**：
  * **Key（任务名）**：如 `"终南豺狼谷除狼患"`，防止重复接取；
  * **`任务地点`**：必须为当前所在大区域的合法三级地点（严格白名单）；
  * **`任务执行情况`**：`"未到达地点"` $\rightarrow$ `"进行中"` $\rightarrow$ `"已完成"`；
  * **`任务奖励`**：只保留受控的增量数值与物品对象，不直接使用自由补丁。

## 三、 势力界面布局与模块化设计

在主导航栏新增 `[势力]` Tab：

### 1. 界面视图布局
* **视图 A：【我的势力】（已加入势力的玩家）**
  * **顶部信息栏**：势力徽标、势力名称、主峰驻地、玩家身份称号（如亲传弟子/香主/偏将）、师承领袖、当前贡献值；
  * **左侧/中央：传承武学树**：直观展示所属势力的武学节点树，区分「已掌握」、「可请教」、「未解锁」三种状态；
  * **右侧分栏：【势力差事】子组件 `<SectTaskList />`**：
    * 展示当前接取的势力差事卡片（任务详情、地点、执行情况、预计奖励）；
    * 提供【接取门派差事】与【交付差事 / 领取奖励】按钮；
  * **底部动作栏**：【向师请教】、【同门切磋】、【申请晋升】、【破门叛离】。
* **视图 B：【天下势力鉴赏】（散修默认显示 / 随时切换）**
  * 势力图谱、势力分类（宗门/帮会/世家/行伍）、主峰地点、历代掌舵人与全势力武学图鉴。

## 四、 核心交互流程与提示词注入规范

### 1. 【拜入门派 / 投身势力】（属性判定 + AI 回复带 `<VariableInsert>`）
* **前置条件**：身处对应势力三级驻地（如 `终南山/重阳宫`），且前置属性达标（如全真悟性 $\ge 8$）。
* **自动触发 User 消息**：
  ```markdown
  User前去拜入全真教门下。

  [系统指令与剧情指引]
  - 交互动作：拜入门派
  - 考核维度：【道门心性与经籍悟性】（玩家悟性已达标）
  - 剧情要求：请结合玩家当前的性格与经历，生成重阳宫接引师长（如丘处机/马钰）出题考校道经玄理、见其悟性非凡欣然收录、并赐予道号与入门心法的精彩正文。
  - 变量写入：正文完成后，必须在回复最末尾原样附带以下标准变量插入块：
  <VariableInsert>
  {
    "user数据": {
      "身份": { "全真教": "入门弟子" },
      "势力": {
        "当前主势力": "全真教",
        "所属势力": {
          "全真教": {
            "体系类型": "宗门",
            "身份": "入门弟子",
            "师承": "马钰",
            "贡献": 0,
            "状态": "在籍"
          }
        }
      },
      "功法": {
        "玄门守一诀": { "掌握程度": "初窥门径" }
      }
    }
  }
  </VariableInsert>
  ```

### 2. 【接取势力差事】（点击按钮触发生成）
* **自动触发 User 消息**：
  ```markdown
  User前去查看势力差事。

  [系统指令：生成门派差事]
  - 当前势力：全真教
  - 玩家境界：三流-中期
  - 候选地点白名单：["大宋/终南山/重阳宫", "大宋/终南山/豺狼谷", "大宋/终南山/终南山脚"]
  - 剧情要求：
    1. 由势力长辈（如丘处机、马钰或知客道人）交代一段切合时宜的历练差事；
    2. 必须在回复末尾附带以下标准的 VariableInsert 块（地点只能从白名单中选择）：
  <VariableInsert>
  {
    "任务": {
      "终南豺狼谷除狼患": {
        "所属势力": "全真教",
        "任务详情": "近日终南山豺狼谷常有恶狼盘踞侵扰山民，速去剿除恶狼，护持山门清宁。",
        "任务地点": "大宋/终南山/豺狼谷",
        "任务执行情况": "未到达地点",
        "任务奖励": {
          "贡献增量": 30,
          "修为增量": 50,
          "获得物品": {
            "铜钱": { "类型": "货币", "品阶": "凡品", "物品描述": "流通铜钱。", "数量": 200 }
          }
        }
      }
    }
  }
  </VariableInsert>
  ```

### 3. 【向师请教 / 武学进阶】（前端扣费 + AI 传功剧情）
* **流程时序**：
  1. 玩家点击【请教全真剑法】，前端检测修为与贡献是否充足（如需 150 修为、50 贡献）；
  2. 前端读出当前修为与贡献，在前端计算新值（`newCultivation = 320 - 150 = 170`），发起底层确定性事务写入扣减后的数值与已掌握功法；
  3. 扣费成功后，向聊天栏发送 User 消息请求 AI 生成生动教学剧情：
  ```markdown
  User向师尊丘处机请教《全真剑法》。

  [系统动作：向师请教]
  - 传功对象：丘处机
  - 研习功法：全真剑法（层级：基础）
  - 剧情要求：请结合师徒双方性格，生成丘处机考校剑招基础、亲自喂招拆解并传授运气口诀的生动叙事。
  ```

### 4. 【任务完成判定与结算】
* **AI 判定完成**：
  当玩家在目标地点完成剿狼战斗后，AI 在剧情演播末尾附带状态修改：
  ```xml
  <VariableEdit>
  {
    "任务": {
      "终南豺狼谷除狼患": {
        "任务执行情况": "已完成"
      }
    }
  }
  </VariableEdit>
  ```
* **前端结算**：
  1. 界面检测到 `任务执行情况 === "已完成"`，【交付差事 / 领取奖励】按钮亮起；
  2. 玩家点击领奖：
     - 前端读取 `任务奖励` 中的 `贡献增量`（+30）、`修为增量`（+50）与 `获得物品`；
     - 前端读取最新 `stat_data`，计算出新贡献（`150 + 30 = 180`）与新修为（`170 + 50 = 220`）；
     - 发起原子事务 `era:transactionByObject` 一次性完成：更新贡献、更新修为、插入新物品、删除已领取的任务键；
     - 弹出奖励浮层，数值即时安全到账；
  3. **可选剧情引导（Command Queue）**：
     - 向指令队列追加一条轻量提示：`🏷️ [师门汇报] 交付除狼差事`；
     - 玩家下次打字发言时，自动附带剧情提示供 AI 接戏，兼顾代入感且无需重度持久化。

## 五、 奇遇事件与修为奖励兼容方案

针对历史奇遇文件中出现的 `"武功"` 老字段与字符串 `"+3500"` 修为增量，制定双重保障：

1. **主流规范：奇遇发放道具/秘籍（推荐）**：
   奇遇事件优先通过 `insert` 发放可参悟的秘籍、残卷或灵药（如“琅嬛神仙卷”、“莽牯朱蛤内丹”）。玩家在背包中点击【使用 / 参悟】，由成熟稳定的 `itemManager` 计算绝对增量，RPG 爽快感与工程安全性兼备。
2. **底层安全防御（事件结算器预处理）**：
   在事件结算逻辑构建写入操作之前，进行增量前置拦截计算：
   若检测到更新值为 `"+数字"` 格式字符串（如 `"+3500"`），且目标字段为数值型（如 `修为`、`贡献`），在内存中读出原值并折算为绝对整数后再生成 ERA 事务，坚决阻止原始非数格式污染存档。
