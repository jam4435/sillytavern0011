        '## 一、核心原则\n' +
        '\n' +
        '你需要在每次回应的结尾判断剧情是否引起了变量变化，并生成正确的 ERA 指令来更新数据。\n' +
        '\n' +
        '基本原则：\n' +
        '1. 无变化则不操作 - 如果剧情没有引起任何变量变化，禁止生成任何指令块\n' +
        '2. 思考先于行动 - 所有分析必须写在 `<VariableThink>` 中，指令块只包含纯净的 JSON\n' +
        '3. 事件进度同步 - 如果正在叙述「参与事件」或「所在地正在或将要发生的事件」，必须根据事件详情已经发生到哪一步， 同步更新相关时间、地点和角色状态\n' +

        '\n' +
        '---\n' +
        '\n' +
        '## 二、事件进度与时间结算规则\n' +
        '\n' +
        '当提示词中存在正在进行的事件时，你不能把事件详情当作只读背景，而要把它当作本轮剧情的进度标尺。\n' +
        '\n' +
        '- 若本轮只推进了事件详情的一部分，应根据叙事经过合理推进 `世界信息.时间`，并同步更新 `user数据.所在位置`、同场 角色 `所在位置`、临时状态等实际变化。\n' +
        '- 若本轮已经写完事件详情中的关键桥段，应将 `世界信息.时间` 直接更新到该事件的 `事件结束时间`。\n' +
        '- 若事件详情写明角色移动、分离、获得或失去物品、关系变化，即使事件尚未完全结束，也要及时写入对应变量。\n' +
        '- 若玩家明显打断、逆转或绕开事件，应按实际发生内容更新时间与地点，不得强行写到原事件结束时间；但仍要在 `<VariableThink>` 中说明事件进度是否偏离。\n' +
        '- 事件详情完成后，优先推进到后续事件线索或附近传闻所指向的下一处合理剧情入口。\n' +

        '  - 学会新技能\n' +
        '  - 获得新物品\n' +
        '  - 添加新的人物经历条目\n' +
        '\n' +
        '路径规则： 指定到父级容器，新数据作为子项插入\n' +
        '\n' +
        '### 2. `<VariableEdit>` - 修改数据\n' +
        '\n' +
        '使用时机：\n' +
        '- 修改已存在键的值\n' +
        '  - 更新角色的 `所在位置`\n' +
        '  - 改变角色的 `外貌`、`身材` 等描述性字段\n' +
        '  - 修改 `世界信息.时间` 变量来代表时间变迁\n' +
        '\n' +
        '路径规则： 指定到需要修改的具体字段\n' +
        '\n' +
        '### 3. `<VariableDelete>` - 删除数据\n' +
        '\n' +
        '使用时机：\n' +
        '- 移除某个数据节点或键值对\n' +

        '  - 移除过时的状态\n' +
        '  - 清除"无"技能等占位符\n' +
