# ERA 变量更新规则

## 1. 路径和操作

- 只有最新 assistant 正文中已经发生、且需要长期保存的变化才写变量；前序正文只读，无变化时不输出 Insert/Edit/Delete。
- 必须逐级对照<variable>中的路径标题、紧凑对象和记录行：目标键已经存在用 `<VariableEdit>`；目标键不存在才用 `<VariableInsert>`；删除已存在的键用 `<VariableDelete>`。
- 对象的父级存在不代表子键存在；判断的是最终目标键。反过来，最终目标键已经存在时，禁止对父级容器再次 Insert 同名键。

## 2. 时间和地点

- 修改时间必须满足“旧完整时间 + 正文耗时 = 新完整时间”。没有时间变化时不要只为补字段而操作，新时间跨过整点或日期时同时修改对应的`时/日/月/年`。
- 时间只能前推，禁止回拨。只有最新assistant正文实际呈现了可感知耗时，才修改时间；短暂反应、观察、思考和简短交谈可以不改时间，或只推进数分钟
- 按正文实际过程判断耗时：短途步行、仔细搜寻、用餐等可经过数十分钟；较长赶路、疗伤、修炼或等待可经过数小时；跨城远行、长期养伤、闭关修炼等可经过数日。不要按回复篇幅、回合数或事件总时长机械均摊，也不要为了方便而取整到下一小时。
- 修改任何 `所在位置` 时，新值的前三段必须逐字等于 `<可用地点>` 中 `当前地点/普通移动/事件目标/指令地点` 所对应的一条严格活动区；第四级不参加白名单匹配，可以在正文确实发生局部移动时追加一个具体场景。

## 3. 人物和物品

- `人物经历`只记录会长期改变人物人生、关系或认知的节点：完整事件结束；明确的关系阶段变化；身份/阵营/师承长期变化；生死、重伤、残疾等长期状态；重大人物、重要物品或关键武学的获得/失去；婚姻、结义、收徒、拜师、背叛等人生节点；或长时间跳跃后的阶段经历。
- 普通聊天、牵手、吃饭、一次战斗中的过程动作、短时情绪起伏、同一场景里的连续互动，禁止单独新增人物经历；这些只留在正文/摘要。一个尚未结束的事件也禁止按每回合拆成多条经历，原则上在事件完整结束后最多为真正受到长期影响的角色各写一条代表性经历。
- 新增或实质改写任何 `人物经历` 的值时，必须以该事实发生时的**游戏内日期**开头，格式固定为 `(年.月.日) 内容`，例如 `(1200.11.26) User在牛家村救下杨铁心，此后包惜弱对User建立深度信任`。日期来自 `世界信息.时间` 与正文实际发生时点，禁止使用现实日期；无法确认具体日期时不要编造时间，也不要为了补日期无意义改写旧经历。
- 已经存在同一长期事实时不要换句话重复新增经历；优先更新原有那条，只有出现新的独立人生节点才新增。
- 只有剧情中新获得或失去物品时才修改 `user数据.包裹`。新增物品至少包含 `类型/品阶/物品描述/数量`；装备再补 `部位/属性修正/使用状态`，药品再补 `功效类型`。
- 秘籍只是功法载体，不要给秘籍编造属性修正、部位、持续时间或参悟条件。
- <本轮User>中的前端指令若已注明装备属性变化、药品恢复或属性增加，表示前端已处理包裹、装备栏、属性或状态效果；不要重复写同一变化。

## 4. 事件
- 事件开始与结束时间用于描述事件时间窗口。时间应按正文实际耗时推进，可以跨过事件结束时间；事件结算由事件脚本在时间写入后统一处理。不得把该事件尚未结束的阶段性对话、观察、行动、冲突或关系变化按回合拆写为已经完成。
- `<参与事件>` 中以 `参与事件.【事件名】` 开头的是完整真实事件路径；其后的 `时间/地点/详情` 记录行只读，`可写:{...}` 只表示该事件当前允许检查的既有变量快照。
- `参与事件` 只由系统创建，禁止新增事件键。`结局`只有在人物生死、长期状态、关系、阵营、关键物品归属、事件目标或后续成立条件发生实质变化时才 Edit；原定发展未变时不要润色。
- `事件分支结果`是系统结算归档，始终只读；`后续事件`只表示既有事件之间的关联和可能出现的线索，均不得由 AI 新增、修改或删除。
- `insert/update/delete` 是 NPC 的原定结算快照。只能 Edit 或 Delete 其中已经存在、且被正文改变的差分项，禁止在参与事件中新增原本不存在的结果，也禁止写入 `user数据`。
- 命中已有 NPC 差分时修改快照，不把同一结果提前重复写入 `角色数据`；临时位置、伤势、状态或快照外的新变化仍直接写当前角色变量。
- 玩家自身的变化直接写 `user数据`。玩家打断、逆转或绕开事件时，以正文实际发生的变化为准，不强行套用原结局。
end
## 5. <VariableThink>检查与输出

按顺序输出以下列表：
if 参与事件
1. 事件与阶段：逐个检查当前参与事件及正文实际推进阶段，不因事件存在而默认推进。
2. 时间：仅在正文明确经过时间或事件实际推进时前推，并完整写五字段。
3. 地点：检查user与相关NPC是否真实移动、是否离开事件活动区。
4. 修炼与战斗：处理明确修为、消耗、伤势和长期后果；user变化直接写user数据。
5. NPC变化路由：参与事件insert/update/delete已有同人物同字段时，原定结果未变则不操作；结果改变只改参与事件快照；快照未覆盖的新长期变化才写角色数据。
6. 结局与差分：只有人物生死、长期状态、关系、阵营、关键物品、事件目标或后续成立条件实质改变时才修改。
7. 其他持久变化：检查快照未覆盖的身份、功法、物品、经历、关系、气血、内力和状态。
8. 最终路径：确定变量归属与完整绝对路径；存在用Edit，不存在用Insert，删除已有叶子用Delete。
elseif
1. 时间：最新正文是否明确经过时间；若是，核算旧完整时间+正文耗时=新完整时间，并完整写年/月/日/时/分。
2. 地点：user或NPC是否实际移动；只有真实移动才修改所在位置。
3. 修炼与战斗：是否产生明确修炼、磨炼、领悟、消耗、伤势或长期后果；修为可参考<修为>中的一天增幅值按实际时长/强度/成果估算。
4. user持久变化：检查修为、气血、内力、状态、物品、功法、身份、经历、关系。
5. NPC持久变化：检查相关角色的地点、状态、物品、功法、身份、经历、关系。
6. 最终路径：确定完整绝对路径；最终叶子存在用Edit，不存在用Insert，删除已有叶子用Delete。
end
最终执行：
- 本轮User表示意图、行动、指令及明确提供的对象/数量/目标；本轮正文表示实际结果，冲突时以正文实际结果为准。
- 前序完整轮次只用于理解上下文，不得重新结算。
- 正文没有改变的事实不得重复Insert或无意义Edit。
- 没有持久变量变化时只输出一个闭合的<VariableThink></VariableThink>。
- 有变化时先输出一个闭合的<VariableThink></VariableThink>，随后按需输出<VariableInsert>、<VariableEdit>、<VariableDelete>。
- VariableInsert/VariableEdit/VariableDelete内部只能放严格JSON对象；相同类型操作合并到一个块。
- 禁止寒暄、复述正文、续写剧情或输出其他XML。
