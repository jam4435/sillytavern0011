# ERA 变量操作规则

## 一、核心原则

你需要在每次回应的结尾判断剧情是否引起了变量变化，并生成正确的 ERA 指令来更新数据。

基本原则：
1. 严格限制可写范围 - AI 只允许修改 `世界信息.时间`、`user数据`、`角色数据`，以及当前提示词中已经存在的 `参与事件.<事件名>.结局/insert/update/delete`
2. 无变化则不操作 - 如果剧情没有引起任何变量变化，禁止生成任何 Insert/Edit/Delete 指令块
3. 先思考再行动 - 在 `<VariableThink>` 中完成简短的变量判断、当前值对照和写入选择，指令块只包含纯净的 JSON
4. 事件进度同步 - 如果正在叙述「参与事件」，必须根据事件详情已经发生到哪一步，同步处理相关时间、地点和角色状态
5. 事件完成即结算时间 - 当事件详情中的主要事情已经完整发生，必须使用 `<VariableEdit>` 将 `世界信息.时间` 更新到该事件的 `事件结束时间`，不得让世界时间继续停留在事件开始或中途
6. 时间只能前推，禁止回拨 - 若当前 `世界信息.时间` 已晚于事件的 `事件结束时间`，不得把时间改回较早时刻；应保持当前时间或按本轮实际剧情继续前推
7. 系统维护区只读 - `事件系统`、`世界事件`、`前端变量`、`附近传闻`、`后续事件线索`、`后续事件线索计数`均由前端或事件脚本维护，禁止 AI 对它们使用 Insert/Edit/Delete
8. 地点必须来自白名单 - 当当前提示词提供 `<可用地点>...</可用地点>` 时，修改任何 `所在位置` 的新值都必须与其中某个完整地点路径完全一致；禁止自造、缩写或改写地点。若已提供该区块但没有合适目标，本轮不要修改位置
9. 前端已结算的装备和药品不要重复写变量 - 如果玩家指令中已经出现“装备xxx，（属性已变化）”或“使用xxx，（气血已恢复/属性已增加）”，说明包裹、装备栏、状态效果或属性已经由前端处理；剧情只需承认结果，不要再写一遍同样的变量修改

---

## 二、事件进度与时间结算规则

当提示词中存在正在进行的事件时，你不能把事件详情当作只读背景，而要把它当作本轮剧情的进度标尺。

- 若本轮只推进了事件详情的一部分，应根据叙事经过合理推进 `世界信息.时间`。不影响事件最终结局的即时变化，直接更新 `user数据` 或 `角色数据`；当前提示词已提供 `<可用地点>` 时，地点写入必须遵守该白名单。
- 若本轮已经写完事件详情中的关键桥段，应将 `世界信息.时间` 直接更新到该事件的 `事件结束时间`。
- 若准备写入的 `事件结束时间` 早于当前 `世界信息.时间`，视为时间回拨，禁止这样写；此时只能保持当前时间或继续向后推进。
- `参与事件.insert/update/delete` 是原定结算快照。只有正文变化命中其中已经存在的差分项时，才修改或删除该项；禁止向参与事件差分新增原本不存在的结果。
- 正文产生的变化若没有对应到现有参与事件差分项，按已经发生的事实直接更新当前 `user数据` 或 `角色数据`。
- 事件实际走向与当前 `参与事件.结局` 有差异时，无论是否命中已有差分项，都要修改 `结局`；没有差异时禁止润色或重写。
- 命中已有差分项的 NPC 结果只修改或删除快照，不再把同一结果提前写入当前 `角色数据`。临时位置、伤势、状态以及快照外的新变化仍直接写当前变量。
- 参与事件差分只负责 NPC 的 `角色数据`，完全不负责 `user数据`。正文中玩家变量确实变化时，直接写 `user数据`；如果事件结局文字因此与现状不同，再同步修改 `结局`。
- 若玩家明显打断、逆转或绕开事件，应按实际发生内容更新时间与地点，不得强行写到原事件结束时间；并在 `<VariableThink>` 中说明最终选择了实时变量还是已有参与事件差分。
- 事件详情完成后，优先推进到后续事件线索或附近传闻所指向的下一处合理剧情入口。

### 参与事件结局快照

`参与事件` 只由系统创建，不要自行新增事件键，也不要写入 `事件名称`、`当前进度`、`MQ.*`、`任务进度` 这类对象。

每个参与事件的规范结构固定为：
```json
{
  "描述": "事件经过",
  "结局": "系统提供的当前预期最终结果",
  "insert": {},
  "update": {},
  "delete": {}
}
```

- `描述` 是系统生成的事件经过，不要改写。
- `结局` 是以事件概要初始化的当前预期最终结果。原定发展没有改变时，禁止润色、概括或重写该字段。
- 只有人物生死、长期状态、关系、阵营、关键物品归属、事件目标或后续事件成立条件发生实质变化时，才修改 `结局`。普通对话、行动顺序变化、短暂受伤、摔跤、绕路等无长期影响的插曲不得修改。
- `insert/update/delete` 是加入事件时复制的原定结算快照，事件结束时会按这三块落库。AI 只能修改或删除其中已经存在、且被正文改变的差分项，禁止新增原本不存在的差分结果。
- `insert/update/delete` 内部以 NPC 姓名为根，事件结算时会统一写入 `角色数据`；禁止在参与事件差分中写入 `user数据`。玩家自身已经发生的变化直接写 `user数据`。
- 修改 `结局` 时必须检查现有 `insert/update/delete` 是否也受影响；只有确实受影响的已有差分项才修改或删除。
- 修改已有差分值用 `<VariableEdit>`；移除不再发生的已有差分项用 `<VariableDelete>`；禁止对参与事件差分使用 `<VariableInsert>`新增结果。
- 路径中的事件名必须使用当前提示词里已经存在的 `参与事件` 键名，禁止自行缩写、改名或新建另一条。

## 三、前端结算与物品边界

物品和属性有一部分由前端按钮直接处理，变量指导只负责避免重复写入：

- 装备按钮：前端会更新 `user数据.装备栏`、同步包裹里的 `使用状态`，并重算属性。AI 不要为了同一次装备动作重复修改 `装备栏`、`包裹` 或 `属性`。
- 回复药品：前端会扣减药品数量并恢复当前气血/内力。AI 不要把回复药写成提高上限，也不要重复修改同一份当前气血/内力。
- 临时增幅药品：前端会扣减药品数量并写入 `user数据.状态效果`。AI 不要为同一次服药另建状态效果。
- 永久增幅药品：前端会扣减药品数量并写入 `前端变量.永久属性修正`，再重算属性。AI 不要重复写同一份属性增幅，也不要直接修改 `前端变量`。
- 世界事件：前端会在事件完成后自动归档实际结局。它是只读历史背景，AI 不要新增、修改或删除 `世界事件`。
- 特殊药品：前端只扣减数量，并把“物品描述，请在剧情中体现”放入指令。AI 应按描述处理剧情效果；需要记录后果时，可修改角色状态、人物经历、关系或事件差分，但不要自造数值型 `属性修正` 或 `状态效果`。
- 通过剧情新获得或失去物品时，才修改 `user数据.包裹`。新增物品应包含 `类型 / 品阶 / 物品描述 / 数量`；装备再补 `部位 / 属性修正 / 使用状态`，药品再补 `功效类型`，临时增幅药品才补 `持续时间`。
- 秘籍只表示持有功法载体。不要给秘籍写 `属性修正`、`部位`、`持续时间` 或自行编造参悟条件。

## 四、三大指令的使用场景

### 1. `<VariableInsert>` - 新增数据

使用时机：
- 创建全新的对象（如初次登场的新角色）
- 向已存在的对象或数组添加新条目（推荐用法）
  - 学会新功法
  - 获得新物品
  - 添加新的人物经历条目

路径规则： 指定到父级容器，新数据作为子项插入

### 2. `<VariableEdit>` - 修改数据

使用时机：
- 修改已存在键的值
  - 更新角色的 `所在位置`
  - 改变角色的 `外貌`、`身材` 等描述性字段
  - 修改 `世界信息.时间` 变量来代表时间变迁

路径规则： 指定到需要修改的具体字段

### 3. `<VariableDelete>` - 删除数据

使用时机：
- 移除某个数据节点或键值对
  - 角色失去物品
  - 移除过时的状态
  - 移除不再存在的功法、物品或状态条目

路径规则： 指定到需要删除的节点，值设为空对象 `{}`

## 五、输出格式要求

<VariableThink>
- 变化判断: [正文中真实发生了哪些需要持久化的变化？]
- 当前对照: [当前值是什么，目标路径是否已经存在？]
- 写入选择: [直接修改当前变量，还是修改/删除已有参与事件差分？]
- 最终操作: [需要使用哪些 Insert / Edit / Delete 路径？无变化时写“无”]
</VariableThink>

`<VariableThink>` 是通用的变量小思维链，不是事件专用字段。只有本轮涉及参与事件时才讨论事件差分；不要复述整段剧情。

<VariableInsert | VariableEdit | VariableDelete>
{
  "路径": {
    ...纯净的JSON数据...
  }
}
</VariableInsert | VariableEdit | VariableDelete>

注意：
- 可以连续使用多个不同类型的指令块，但是相同类型的变量修改指令要合并在一起
- 不要在指令块的JSON中添加注释
- 不要添加任何额外的XML标签

---

## 六、操作示例

### 示例1：学会新功法并消耗时间（修改+新增）

剧情： 你在导师的指点下苦练了三个时辰（6小时），终于在未时（下午2点）掌握了"基础拳法"。

<VariableThink>
- 变化判断: 修炼持续6小时，玩家已经学会“基础拳法”，需要持久化时间和新功法。
- 当前对照: `世界信息.时间`已存在；`user数据.功法.基础拳法`尚不存在。
- 写入选择: 本轮不涉及参与事件差分，直接修改当前变量。
- 最终操作: Edit `世界信息.时间`；Insert `user数据.功法.基础拳法`。
</VariableThink>

<VariableEdit>
{
  "世界信息": {
    "时间": {
      "时": 14
    }
  }
}
</VariableEdit>

<VariableInsert>
{
  "user数据": {
    "功法": {
      "基础拳法": {
        "类型": "拳掌",
        "掌握程度": "初窥门径"
      }
    }
  }
}
</VariableInsert>

其他行为正例和反例等实际游玩暴露稳定错误后再增加；当前只保留必要的新建结构示例。
