# ERA 变量操作规则

## 一、核心原则

你需要在每次回应的结尾判断剧情是否引起了变量变化，并生成正确的 ERA 指令来更新数据。

基本原则：
1. 严格限制可写范围 - AI 只允许修改 `世界信息.时间`、`user数据`、`角色数据`，以及当前提示词中已经存在的 `参与事件.<事件名>.结局/insert/update/delete`
2. 无变化则不操作 - 如果剧情没有引起任何变量变化，禁止生成任何 Insert/Edit/Delete 指令块
3. 先审计再行动 - 在 `<VariableThink>` 中只列变化来源、目标路径和动作类型，指令块只包含纯净的 JSON
4. 事件进度同步 - 如果正在叙述「参与事件」，必须根据事件详情已经发生到哪一步，同步处理相关时间、地点和角色状态
5. 事件完成即结算时间 - 当事件详情中的主要事情已经完整发生，必须使用 `<VariableEdit>` 将 `世界信息.时间` 更新到该事件的 `事件结束时间`，不得让世界时间继续停留在事件开始或中途
6. 时间只能前推，禁止回拨 - 若当前 `世界信息.时间` 已晚于事件的 `事件结束时间`，不得把时间改回较早时刻；应保持当前时间或按本轮实际剧情继续前推
7. 系统维护区只读 - `事件系统`、`世界事件`、`前端变量`、`附近传闻`、`后续事件线索`、`后续事件线索计数`均由前端或事件脚本维护，禁止 AI 对它们使用 Insert/Edit/Delete
8. 地点必须来自白名单 - 当当前提示词提供 `<可用地点>...</可用地点>` 时，修改任何 `所在位置` 的新值都必须与其中某个完整地点路径完全一致；禁止自造、缩写或改写地点。若已提供该区块但没有合适目标，本轮不要修改位置
9. 前端已结算的装备和药品不要重复写变量 - 如果玩家指令中已经出现“装备xxx，（属性已变化）”或“使用xxx，（气血已恢复/属性已增加）”，说明包裹、装备栏、状态效果或属性已经由前端处理；剧情只需承认结果，不要再写一遍同样的变量修改

## 二、事件进度与时间结算规则

当提示词中存在正在进行的事件时，你不能把事件详情当作只读背景，而要把它当作本轮剧情的进度标尺。

- 若本轮只推进了事件详情的一部分，应根据叙事经过合理推进 `世界信息.时间`。不影响事件最终结局的即时变化，直接更新 `user数据` 或 `角色数据`；当前提示词已提供 `<可用地点>` 时，地点写入必须遵守该白名单。
- 若本轮已经写完事件详情中的关键桥段，应将 `世界信息.时间` 直接更新到该事件的 `事件结束时间`。
- 若准备写入的 `事件结束时间` 早于当前 `世界信息.时间`，视为时间回拨，禁止这样写；此时只能保持当前时间或继续向后推进。
- 若事件中的变化不会影响预期最终结局，只按已经发生的事实及时更新实时变量，不改 `参与事件.结局/insert/update/delete`。
- 若玩家的介入改变了人物生死、长期状态、关系、阵营、关键物品归属、事件目标或后续事件成立条件，则应同步修改 `参与事件.结局` 与对应的 `insert/update/delete`，由事件结束结算统一落库；能够由差分结算的 NPC 长期结果不要提前重复写入实时变量。
- 同一份长期结果不得既直接写入实时变量、又保留在参与事件差分中，避免事件结束时重复结算。已经发生但不属于最终结算的临时位置、伤势或状态，仍可按实际情况写入实时变量。
- 当前参与事件差分只能结算到 NPC 的 `角色数据`。玩家长期变化若已经在正文中真实发生，应直接写入 `user数据`，同步更新事件 `结局`，并确保 NPC 差分中没有重复项；尚未真实发生的玩家预期结果只记录在 `结局`，等正文实际发生时再写入 `user数据`。
- 若玩家明显打断、逆转或绕开事件，应按实际发生内容更新时间与地点，不得强行写到原事件结束时间；但仍要在 `<VariableThink>` 中说明事件是否偏离及采用实时写入还是结局快照。
- 事件详情完成后，优先推进到后续事件线索或附近传闻所指向的下一处合理剧情入口。

### 参与事件结局快照

`参与事件` 只由系统创建，不要自行新增事件键，也不要写入 `事件名称`、`当前进度`、`MQ.*`、`任务进度` 这类对象。

每个参与事件的规范结构固定为：
```json
{
  "描述": "事件经过",
  "结局": "系统提供的当前预期最终结果",
  "insert": {},
  "update": {},
  "delete": {}
}
```

- `描述` 是系统生成的事件经过，不要改写。
- `结局` 是以事件概要初始化的当前预期最终结果。原定发展没有改变时，禁止润色、概括或重写该字段。
- 只有人物生死、长期状态、关系、阵营、关键物品归属、事件目标或后续事件成立条件发生实质变化时，才修改 `结局`。普通对话、行动顺序变化、短暂受伤、摔跤、绕路等无长期影响的插曲不得修改。
- `insert/update/delete` 是该事件当前结局快照，事件结束时会按这三块落库；如果玩家改变结局，应直接修改已有参与事件下的这三块。
- `insert/update/delete` 内部以 NPC 姓名为根，事件结算时会统一写入 `角色数据`；禁止在参与事件差分中写入 `user数据`。玩家自身已经发生的变化直接写 `user数据`。
- 修改 `结局` 时必须同步检查并修改 `insert/update/delete`；结局文本与差分必须描述同一个最终结果。
- 修改已有差分值用 `<VariableEdit>`；新增差分子项用 `<VariableInsert>`；移除不再发生的默认差分子项用 `<VariableDelete>`。
- 路径中的事件名必须使用当前提示词里已经存在的 `参与事件` 键名，禁止自行缩写、改名或新建另一条。

## 三、前端结算与物品边界

物品和属性有一部分由前端按钮直接处理，变量指导只负责避免重复写入：

- 装备按钮：前端会更新 `user数据.装备栏`、同步包裹里的 `使用状态`，并重算属性。AI 不要为了同一次装备动作重复修改 `装备栏`、`包裹` 或 `属性`。
- 回复药品：前端会扣减药品数量并恢复当前气血/内力。AI 不要把回复药写成提高上限，也不要重复修改同一份当前气血/内力。
- 临时增幅药品：前端会扣减药品数量并写入 `user数据.状态效果`。AI 不要为同一次服药另建状态效果。
- 永久增幅药品：前端会扣减药品数量并写入 `前端变量.永久属性修正`，再重算属性。AI 不要重复写同一份属性增幅，也不要直接修改 `前端变量`。
- 世界事件：前端会在事件完成后自动归档实际结局。它是只读历史背景，AI 不要新增、修改或删除 `世界事件`。
- 特殊药品：前端只扣减数量，并把“物品描述，请在剧情中体现”放入指令。AI 应按描述处理剧情效果；需要记录后果时，可修改角色状态、人物经历、关系或事件差分，但不要自造数值型 `属性修正` 或 `状态效果`。
- 通过剧情新获得或失去物品时，才修改 `user数据.包裹`。新增物品应包含 `类型 / 品阶 / 物品描述 / 数量`；装备再补 `部位 / 属性修正 / 使用状态`，药品再补 `功效类型`，临时增幅药品才补 `持续时间`。
- 秘籍只表示持有功法载体。不要给秘籍写 `属性修正`、`部位`、`持续时间` 或自行编造参悟条件。

## 四、三大指令的使用场景

### 1. `<VariableInsert>` - 新增数据

使用时机：
- 创建全新的对象（如初次登场的新角色）
- 向已存在的对象或数组添加新条目（推荐用法）
  - 学会新功法
  - 获得新物品
  - 添加新的人物经历条目

路径规则： 指定到父级容器，新数据作为子项插入

### 2. `<VariableEdit>` - 修改数据

使用时机：
- 修改已存在键的值
  - 更新角色的 `所在位置`
  - 改变角色的 `外貌`、`身材` 等描述性字段
  - 修改 `世界信息.时间` 变量来代表时间变迁

路径规则： 指定到需要修改的具体字段

### 3. `<VariableDelete>` - 删除数据

使用时机：
- 移除某个数据节点或键值对
  - 角色失去物品
  - 移除过时的状态
  - 移除不再存在的功法、物品或状态条目

路径规则： 指定到需要删除的节点，值设为空对象 `{}`

## 五、输出格式要求

<VariableThink>
- 变化来源: [只写触发变量变化的已发生事实，或改变事件结局的关键介入]
- 目标路径: [只列本轮需要写入的完整根路径；无变化时写“无”]
- 动作类型: [Insert / Edit / Delete；无变化时写“无”]
</VariableThink>

`<VariableThink>` 是简短的变量审计摘要，不要复述整段剧情，也不要展示详细推理过程。

<VariableInsert | VariableEdit | VariableDelete>
{
  "路径": {
    ...纯净的JSON数据...
  }
}
</VariableInsert | VariableEdit | VariableDelete>

注意：
- 可以连续使用多个不同类型的指令块，但是相同类型的变量修改指令要合并在一起
- 不要在指令块的JSON中添加注释
- 不要添加任何额外的XML标签

## 六、操作示例

### 示例1：学会新功法并消耗时间（修改+新增）

剧情： 你在导师的指点下苦练了三个时辰（6小时），终于在未时（下午2点）掌握了"基础拳法"。

<VariableThink>
- 变化来源: 修炼持续6小时，玩家已学会“基础拳法”。
- 目标路径: `世界信息.时间`、`user数据.功法.基础拳法`。
- 动作类型: Edit、Insert。
</VariableThink>

<VariableEdit>
{
  "世界信息": {
    "时间": {
      "时": 14
    }
  }
}
</VariableEdit>

<VariableInsert>
{
  "user数据": {
    "功法": {
      "基础拳法": {
        "类型": "拳掌",
        "掌握程度": "初窥门径"
      }
    }
  }
}
</VariableInsert>

---

### 示例2：修改事件结局差分

剧情： 你正在参与"某个试炼事件"，你巧妙地提示了角色A，那位大师大为赞赏，决定额外传授角色A一招"精妙指法"。

<VariableThink>
- 变化来源: 玩家介入改变试炼结局，大师将在结算时额外传授角色A“精妙指法”。
- 目标路径: `参与事件.某个试炼事件.结局`、`参与事件.某个试炼事件.insert.角色A.功法.精妙指法`。
- 动作类型: Edit、Insert。
</VariableThink>

<VariableEdit>
{
  "参与事件": {
    "某个试炼事件": {
      "结局": "你提示角色A通过考验，大师决定额外传授一门指法。"
    }
  }
}
</VariableEdit>

<VariableInsert>
{
  "参与事件": {
    "某个试炼事件": {
      "insert": {
        "角色A": {
          "功法": {
            "精妙指法": {
              "类型": "指法",
              "掌握程度": "初窥门径"
            }
          }
        }
      }
    }
  }
}
</VariableInsert>

---

### 示例3：位置变更 + 时间流逝

剧情： 当前 `<可用地点>` 中存在 `大宋/临安府/B城`。7月28日，你们一行人离开原地，用了五天时间赶路，在早上6时抵达该地。

<VariableThink>
- 变化来源: 一行人赶路5天，已抵达 `<可用地点>` 中的 `大宋/临安府/B城`。
- 目标路径: `世界信息.时间`、`user数据.所在位置`、`角色数据.角色A.所在位置`、`角色数据.角色B.所在位置`。
- 动作类型: Edit。
</VariableThink>

<VariableEdit>
{
  "世界信息": {
    "时间": {
      "月": 8,
      "日": 3,
      "时": 6
    }
  },
  "user数据": {
    "所在位置": "大宋/临安府/B城"
  },
  "角色数据": {
    "角色A": { "所在位置": "大宋/临安府/B城" },
    "角色B": { "所在位置": "大宋/临安府/B城" }
  }
}
</VariableEdit>

---

### 示例4：添加人物经历

剧情： 你在某个山庄与某个侠客团体相遇，双方发生了一些摩擦，最终化解了误会。

<VariableThink>
- 变化来源: 玩家与侠客团体的误会已经化解，形成一段新的亲历记录。
- 目标路径: `user数据.人物经历.山庄相遇`。
- 动作类型: Insert。
</VariableThink>

<VariableInsert>
{
  "user数据": {
    "人物经历": {
      "山庄相遇": "在某个山庄与某个侠客团体相遇，因误会发生冲突，后经一番周折，双方化解了误会，该团体对你的侠义之心颇为赞赏。"
    }
  }
}
</VariableInsert>

## 七、禁止模仿的反例

### 反例1：把玩家写入 NPC 根并使用废弃字段

错误写法（不得输出）：
```json
{
  "角色数据": {
    "你": {
      "技能": {
        "基础拳法": {}
      }
    }
  }
}
```

错误原因：玩家必须写入 `user数据`，武学字段必须使用 `功法`。正确目标路径是 `user数据.功法.基础拳法`。

### 反例2：同一长期结局同时实时写入并保留结局差分

错误做法：本轮既直接修改 `角色数据.角色A.功法.精妙指法`，又把同一门功法保留在 `参与事件.某个试炼事件.insert.角色A.功法.精妙指法`。

错误原因：事件结束时差分还会再次结算，可能造成重复写入或覆盖。影响事件最终结局的长期结果只保留在 `参与事件.结局/insert/update/delete`；不影响最终结局且已经真实发生的即时变化才直接写入当前变量。
