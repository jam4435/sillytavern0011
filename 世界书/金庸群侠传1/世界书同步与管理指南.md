# 金庸群侠传1 世界书条目管理与同步指南

本文档介绍《金庸群侠传1》世界书的条目结构、新事件/奇遇条目的添加方式、一键自动同步工具以及推送到酒馆时的注意事项。

---

## 一、世界书架构与 4 大文件夹

当前世界书将所有事件条目统一归入 **4 个主分类文件夹**（由隐藏元数据条目 `__WI_META_FOLDERS__` 驱动，供酒馆「世界书Plus」等脚本识别）：

| 文件夹名称 | 包含条目类型 | 命名范例 |
|---|---|---|
| **射雕** | 射雕主线回目事件、人物登场事件 | `射雕第一回01-郭杨邀饮说书人`、`射雕第一回00-人物登场` |
| **神雕** | 神雕主线回目事件、人物登场事件 | `神雕第一回01-南湖采莲遇武三通`、`神雕第一回00-人物登场` |
| **天龙** | 天龙主线回目事件、人物登场事件 | `天龙第一回01-龚光杰变招削落容子矩发髻`、`天龙第一回00-人物登场` |
| **奇遇** | 所有作品的江湖奇遇与机缘事件 | `奇遇事件-射雕-王府药房饮蛇血`、`奇遇事件-神雕-山洪巨浪炼重剑`、`奇遇事件-天龙-无量松林捕朱蛤` |

> 📌 **系统条目**（`变量指导`、`输出提示词`、`战斗骰子`、`cot`、`世界背景`）属于常驻规则或提示词注入层，不放入以上剧情文件夹。

## 二、如何添加新的事件与奇遇条目

只需在目录 `世界书/金庸群侠传1/世界书/` 中直接创建对应的 `.yaml` 文件即可，无需手动修改 `index.yaml`。

### 1. 命名规范
* **普通剧情事件**：`{作品名}第{中文数字}回{两位序号}-{标题}.yaml`
  * 示例：`射雕第一回01-郭杨邀饮说书人.yaml`、`天龙第二十回03-聚贤庄激战.yaml`
* **人物登场事件**：`{作品名}第{中文数字}回00-人物登场.yaml`
  * 示例：`神雕第一回00-人物登场.yaml`
* **奇遇事件**：`奇遇事件-{作品名}-{标题}.yaml` 或 `奇遇-{作品名}-{标题}.yaml`
  * 示例：`奇遇事件-射雕-牛家废店启密室.yaml`、`奇遇事件-天龙-琅嬛福地拜玉像.yaml`

### 2. 内容格式（JSON 结构）
虽然扩展名为 `.yaml`，为了兼容酒馆运行时解析，事件正文请使用标准 JSON 结构（或标准 YAML，同步脚本会自动将其格式化）：

```json
{
  "事件名称": "奇遇事件-射雕-王府药房饮蛇血",
  "事件地点": "金国/中都/赵王府",
  "触发条件": {
    "全部": [
      {
        "变量": "user数据.初始属性.机敏",
        "大于等于": 13
      }
    ]
  },
  "事件持续时间": {
    "时": 3
  },
  "事件引子": "赵王府幽深药房中药香浓郁……",
  "事件概要": "玩家夜探王府斩杀异种朱砂宝蛇，痛饮蛇血洗髓伐毛……",
  "事件详情": "玩家潜入赵王府后院静谧药房……",
  "参与人物": [
    "玩家"
  ],
  "insert": {
    "user数据": {
      "包裹": {
        "宝蛇胆囊": {
          "类型": "药品",
          "品阶": "绝品",
          "功效类型": "永久增幅",
          "数量": 1
        }
      }
    }
  },
  "update": {
    "user数据": {
      "修为": "+2200"
    }
  },
  "delete": {},
  "后续事件": {}
}
```

## 三、一键自动同步工具

当你新增、删除或修改了 `世界书/金庸群侠传1/世界书/` 下的条目文件后，只需在项目根目录运行一行命令：

```bash
pnpm sync:worldbook
# 或
node scripts/sync-worldbook-index.mjs
```

### 脚本会自动完成以下所有工作：
1. **自动格式检查与规范化**：如果新建的 `.yaml` 是纯 YAML 语法，会自动转换为符合酒馆要求的缩进 JSON 字符串。
2. **自动注册与分配 UID**：
   * 自动扫描新文件并为其分配唯一的 6 位数字 UID（保留已有条目的 UID 不变）。
   * 自动清理已删除条目。
3. **自动分类挂载文件夹**：
   * 自动将所有条目分类到「射雕」「神雕」「天龙」「奇遇」4 大文件夹。
   * 重新生成 `__WI_META_FOLDERS__` 元数据条目，确保 100% 覆盖所有条目映射。
4. **自动打包导出**：调用 `tavern_sync.mjs bundle 金庸群侠传1` 自动生成最新 `世界书/金庸群侠传1.json`。
5. **自动同步前端运行时资产**：调用 `scripts/generate-wuxia-event-assets.mjs` 刷新分片与索引缓存。

## 四、推送到酒馆的注意事项

### 为什么之前 `tavern_sync push -f` 会导致文件夹混乱？
* `tavern_sync.mjs` 在 push 时会自动检查酒馆端已存在的条目 UID 并尝试回填覆盖本地 UID。
* 但 `__WI_META_FOLDERS__` 是保存在文本内容中的静态 JSON 字典，`tavern_sync` 不会自动重写里面的 UID 映射。
* 一旦酒馆端已有条目使用了不同的 UID，文件夹映射就会因为 UID 对不上而失效。

### 推荐的酒馆更新流程：
* **方法 1（推荐，最干净）**：
  在运行 `pnpm sync:worldbook` 后，直接打开酒馆 Web 界面，在世界书管理中删除旧的 `金庸群侠传1`，然后直接导入生成的 `世界书/金庸群侠传1.json`。
* **方法 2（命令行推送）**：
  在酒馆中清空该世界书旧条目后，执行：
  ```bash
  node tavern_sync.mjs push 金庸群侠传1 -f
  ```
