# NBA2K16 生涯模拟角色卡 · 总设计文档

> 本卡仿照 `角色卡/金庸群侠传` 的复合结构：消息楼层 + 显示正则 + 前端 iframe + 变量层 + 世界书。
> 前端源码在 `src/nba2k`，打包产物 `dist/nba2k/index.html` 由 loader 正则从 `http://localhost:5500/dist/nba2k/index.html` 拉起；静态服务根目录必须是仓库根目录。

## 一、玩法定位

玩家扮演一名进入 2015-16 赛季 NBA 的新秀/球员（MyCareer 视角），核心循环分两层：

1. **场上比赛**：球场俯视图前端 + 回合制动作选择 + 数据/骰子判定 + AI 叙事。
2. **场外生涯**：训练、代言谈判、球队合同、经纪人、媒体、恋爱关系，全部由 AI 叙事驱动、变量层记账。

## 二、比赛核心循环（每个进攻/防守回合）

```
前端展示球场俯视图（双方10人圆形头像，按战术站位）
        │
玩家选择动作（突破/传球/组织/挡拆/投篮/无球跑动/防守策略…）
        │
判定引擎：相关属性 vs 对位防守属性 + 情境修正 + d100 骰子
        │
产出结构化判定结果（动作、掷骰、成功等级、数据变化）
        │
取得隐藏楼层回合锁，以 refresh:none 持久化 user 消息（深度世界书注入 {{ERA:$ALLDATA}} 快照）
        │
非流式生成 AI 输出：正文 + 选项 + ERA 增量变量块，再以 refresh:none 持久化 assistant
        │
等待该 assistant 楼层 ERA 写入完成 → 释放锁并同步最终楼层 → 重读状态 → 下一回合
```

**关键原则（与武侠卡一致）**：
- 判定在前端完成，AI 只负责"演出"判定结果并推进局势，不重掷骰子。
- `stat_data` 是唯一真相源；React 状态只是投影。
- 回合采用事务式持久化：assistant 落楼前失败回滚孤立 user；ERA 超时后保留完整回合供手动同步，不误删已经生成的回复。
- 建档与开赛初始化由前端直写聊天变量；其余变量写入走 ERA，消息边界兜底重读。

## 三、判定引擎

### 3.1 成功率公式

每种动作定义 进攻权重向量 与 防守权重向量，属性取 0-99：

| 动作 | 进攻方属性权重 | 防守方属性权重 |
| ---- | -------------- | -------------- |
| 突破 | ballHandle 0.40 / speed 0.30 / layup 0.30 | perimeterD 0.50 / speed 0.30 / steal 0.20 |
| 中投 | midRange 0.70 / offConsistency(=overall) 0.30 | perimeterD 0.60 / block 0.20 / height 0.20 |
| 三分 | threePoint 0.75 / stamina 0.25 | perimeterD 0.70 / speed 0.30 |
| 内线终结 | insideScoring 0.40 / layup 0.25 / dunk 0.20 / strength 0.15 | interiorD 0.50 / block 0.30 / strength 0.20 |
| 传球 | passing 0.70 / ballHandle 0.30 | steal 0.60 / perimeterD 0.40 |
| 组织（发起战术） | passing 0.45 / ballHandle 0.35 / overall 0.20 | 全队防守均值 |
| 挡拆（持球方） | ballHandle 0.35 / speed 0.25 / 掩护人 strength 0.40 | 对位二人 perimeterD/interiorD 均值 |
| 抢断（防守） | steal 0.65 / speed 0.35 | 持球人 ballHandle 0.70 / passing 0.30 |
| 盖帽 | block 0.70 / height 0.30 | 出手人 layup/dunk 相关 |
| 篮板 | offRebound 或 defRebound 0.60 / strength 0.25 / height 0.15 | 对位同项 |

```
attackScore  = Σ(进攻属性 × 权重)
defenseScore = Σ(防守属性 × 权重)
diff         = attackScore - defenseScore            // 一般 -40 ~ +40
baseRate     = clamp(50 + diff × 1.1, 15, 90)        // 百分比
finalRate    = clamp(baseRate + 情境修正合计, 5, 95)
```

### 3.2 情境修正

| 修正源 | 幅度 |
| ------ | ---- |
| 体力（stamina 当前值 <40 / <20） | -5 / -12 |
| 热手/冷手（连续命中或打铁 ≥2 次） | +4 / -4 |
| 关键时刻（第4节最后2分钟且分差≤5）× 球员 overall≥85 | +5（明星大心脏）否则 -5 |
| 挡拆创造的错位 | +8 |
| 空位程度（防守距离，由上回合结果推导） | 空位 +10 / 严防 -8 |
| 主客场 | 主 +2 / 客 -2 |
| 犯规陷阱（对位防守人犯规数≥4） | +5（对方收手） |

### 3.3 掷骰与成功等级

掷 1d100，低于 finalRate 为成功；按差值划分等级：

| 条件 | 等级 | 含义示例（突破） |
| ---- | ---- | ---------------- |
| roll ≤ finalRate × 0.25 | 大成功 | 过掉防守人造成杀伤，2+1 机会 |
| roll ≤ finalRate | 成功 | 突破得手，形成出手/分球机会 |
| roll ≤ finalRate + 15 | 部分成功 | 突入但被贴防，被迫勉强出手或回传 |
| roll ≤ 96 | 失败 | 被挡下 / 打铁，转入抢篮板 |
| roll ≥ 97 | 大失败 | 失误/被抢断/进攻犯规，攻防转换 |

判定结果以结构化文本注入 user 消息（前端拼接），AI 不得改判，只演出并结算。

## 五、前端（`src/nba2k`）

| 模块 | 职责 |
| ---- | ---- |
| `components/CourtView.tsx` | SVG 球场俯视图；按 `站位` 渲染 10 个圆形头像（队色描边、号码/姓名、持球标记、体力环） |
| `components/ActionPanel.tsx` | 依据球权/持球人/情境生成可选动作按钮（突破/传球/挡拆/组织/投篮/防守策略/暂停/换人） |
| `components/ScoreBoard.tsx` | 比分、节次、计时、球队犯规、暂停数 |
| `components/BoxScore.tsx` | 双方球员实时数据统计面板 |
| `components/CareerPanel.tsx` | 场外：日程、代言、合同、关系、训练 |
| `engine/attributes.ts` | 属性权重表 |
| `engine/resolveAction.ts` | 成功率计算 + d100 + 等级判定 |
| `engine/positioning.ts` | 战术站位模板（进攻/防守/挡拆后的坐标变换） |
| `engine/promptBuilder.ts` | 把判定结果+局势快照拼成发给 AI 的结构化指令 |
| `utils/turnTransaction.ts` | 回合锁、两侧楼层持久化、ERA 完成等待与失败回滚 |
| `utils/turnLifecycle.ts` | 与隐藏楼层脚本共享的 `nba2k:*` 锁协议 |
| `utils/eraWriteWait.ts` | 等待指定 assistant 楼层的 ERA 写入完成事件 |
| `data/teams.json` / `data/players.json` | 2K16 全部球队与球员数据 |
| `utils/variableReader.ts` | 读取 `stat_data` 投影到 UI（仿武侠卡） |

球场坐标系：横向球场，x 0-100（左端线→右端线），y 0-100（下边线→上边线）；进攻方向由 `球权` + 节次决定，前端负责镜像。

## 六、世界书结构（`世界书/`）

| 条目 | 类型 | 内容 |
| ---- | ---- | ---- |
| 输出提示词 | 系统深度条目 | AI 输出契约：叙事正文 + 变量块格式、禁止改判、必须消耗时钟 |
| 变量指导 | 系统深度条目 | `stat_data` 全字段说明与更新规则 |
| 当前变量快照 | 系统深度条目 | 每回合注入 `{{ERA:$ALLDATA}}` 的完整无 `$meta` 状态 |
| cot | 系统深度条目 | 仅供模型内部执行的回合核对清单，不允许外显 thinking |
| 比赛规则 | 常驻 | NBA 规则要点、回合节奏、犯规/暂停/换人逻辑 |
| 叙事风格 | 常驻 | 解说腔 + 队友对话 + 垃圾话 + 教练指令的写法与配比 |
| 球队档案-东部/西部 | 关键词触发 | 30 队风格、战术倾向、当家球星 |
| 明星球员档案 | 关键词触发 | 库里/科比/詹姆斯/KD 等的性格、说话风格（垃圾话素材） |
| 场外-代言系统 | 关键词触发 | 品牌列表、谈判规则、履约检查 |
| 场外-经纪人与合同 | 关键词触发 | 薪资规则简化版、谈判判定 |
| 场外-恋爱系统 | 关键词触发 | 关系阶段推进规则、明星 NPC 池 |
| 赛季事件 | 关键词/日期触发 | 全明星、交易截止日、季后赛等节点事件 |

## 七、扩展方向（预留）

- 训练小游戏与徽章升级树；伤病系统（大失败时低概率触发）。
- 交易流言与更衣室化学反应（队友好感影响挡拆/传球判定 ±3）。
- 季后赛模式：七场四胜、系列赛疲劳累积。
- 选秀/自建球员捏脸文本化：开局问卷生成初始属性模板。
