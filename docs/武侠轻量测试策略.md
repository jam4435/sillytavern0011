# 武侠项目轻量测试策略

## 目标

以酒馆内真实角色卡游玩作为**功能验收**；自动检查只负责低成本阻止不可解析的数据、断裂的事件引用、ERA 变量写回和存档/历史回退的明显损坏。避免历史功法数量、提示词逐字措辞、UI 文案和大量 mock 调用次数阻塞日常开发。

## 命令

| 命令 | 用途 |
| --- | --- |
| `pnpm test` / `pnpm test:safe` | 日常默认，只运行 11 个武侠核心安全测试文件 |
| `pnpm test:wuxia:smoke` | 同上；武侠 ERA CI 使用 |
| `pnpm build:src:fast` | 生成事件资源并进行源代码构建；提交前使用 |
| `pnpm test:full` | 显式运行仓库全部 Vitest 测试（包括其他游戏）；历史测试仍可能失败 |
| `pnpm test:wuxia:legacy-audit` | 人工专项复核 NPC 武学历史 batch 和 wave10 断言 |
| `pnpm test:watch` | 开发时自行选择测试文件，交互监听 |

`test` 不再代表全量回归；只有 `test:full` 才代表全量运行。轻量检查通过也不保证酒馆实际流程无误。

## CI

- `wuxia-era-history-tests`：主分支触发轻量安全检查和构建；旧消息/变量 Mock 回归只通过 `workflow_dispatch` 手动执行。
- `wuxia-npc-martial-arts-audit`：数据修改时运行功法审计算法及事件引用检查；逐 NPC 的历史 batch、完整事件重放及审计报告仅手动执行。
- NBA2K 有自己的测试 CI，本次不调整，避免影响其他游戏。
- 历史测试文件不批量删除；当确实需要定位旧行为时，仍能手动执行。

## 酒馆内人工验收清单

1. **开档**：在 SillyTavern 载入最新角色卡，建立新档，确认初始变量和正文正常。
2. **对话**：发送一轮 User 消息，核对生成、显示、变量变化、是否重复发送。
3. **重生成**：重新生成/滑动楼层，确认楼层内容和变量不会错位、重复提交。
4. **事件**：移动至事件地点，触发、推进和结算，核对参与状态、时间限制和后续事件地点。
5. **存档**：保存、刷新、读档，核对功法、物品、任务、关系和历史分支数据。
6. **专项验证**：新增 UI、提示词、武学或事件时，专门验证本次改动影响的玩法。

## 维护原则

- 日常门禁只保留稳定的安全不变量，例如 JSON/YAML 可解析、事件引用存在、唯一键、不丢数据的保存恢复。
- 别用固定 373 / 484 / 1119 等历史条目总数判定内容更新失败；如果需要数量回归，应放在专项统计审查中。
- 不为让旧测试通过而回填未经证实的 NPC 正式功法，不擅自修改剧情或变量语义。
- 遇到旧回归报错，先核对真实业务契约；复杂的消息处理和 ERA 写回仍要在酒馆里专项测试。
- 若只是改了提示词措辞、UI 标签、功法列表数量，默认不新增细碎的 Mock 和逐字断言。
