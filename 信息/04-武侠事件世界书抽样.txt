武侠事件世界书抽样梳理
======================

一、范围与抽样方法
------------------

- 目标目录：`F:\Develop\AI\世界书\世界书\武侠事件`
- 本次只做轻量抽样，不全量深读。
- 先用目录扫描确认总体规模，再抽 10 个代表文件：
  - 7 个普通事件 JSON
  - 1 个登场事件 JSON
  - 2 个说明/提示 TXT
- 额外做了两类定点检查：
  - 是否存在 `P-insert / P-update / P-delete`
  - 是否存在非时间触发的事件类型

二、目录概览
------------

- 总文件数：282
- 普通事件条目：256 个
- 登场事件条目：23 个
- 说明性 TXT：3 个

命名大致分三类：

1. `射雕事件条目-第X回-XX-事件名.json`
   - 主体内容，按《射雕英雄传》剧情分段。
   - 数量最多，决定事件推进、人物状态和变量变更。

2. `射雕登场事件-第X回人物.json`
   - 主要负责“新人物入场时的一次性建档”。
   - 更像角色资料包，而不是剧情结算包。

3. `变量指导.txt` / `输出提示词.txt` / `战斗骰子.txt`
   - 不是事件定义本体，而是给 AI 和规则层提供操作说明、提示词上下文、玩法约束。

四、条目结构
------------

1. 普通事件 JSON 的主结构

抽样里最常见的字段如下：

- `事件地点`
- `触发条件`
- `事件结束时间`
- `事件引子`
- `后续事件`
- `事件详情`
- `insert / update / delete`

典型形态是：

- 用 `触发条件` 决定何时进入“未发生 -> 进行中”
- 用 `事件结束时间` 决定何时结算
- 用 `事件引子` 生成“附近传闻”
- 用 `事件详情` 作为剧情摘要/背景说明
- 用 `insert / update / delete` 改写角色变量

2. 登场事件 JSON 的主结构

抽样到的 `射雕登场事件-第15回人物.json` 明显不同：

- 额外有 `事件类型: 登场事件`
- 有 `所属回目`
- `insert` 下直接放完整人物档案
- 典型字段包括：
  - `姓名 / 性别 / 外貌 / 性格`
  - `境界 / 初始属性 / 出生年份 / 状态 / 所在位置`
  - `身份 / 功法 / 重要物品 / 人物经历 / 关系网`

这类条目本质上是“角色数据模板注入包”。

3. 说明 / 提示 TXT 的作用

- `变量指导.txt`
  - 明确告诉 AI 什么时候输出 `<VariableInsert>`、`<VariableEdit>`、`<VariableDelete>`
  - 重点强调“无变化则不操作”
  - 这是 LLM 侧变量更新行为规范

- `输出提示词.txt`
  - 会把 `世界信息`、`user数据`、`参与事件`、`后续事件线索`、`附近传闻` 注入提示词
  - 还会把“同场景角色 JSON 数据结构”拼给 AI
  - 这是剧情生成时真正会看到的事件上下文桥接层

五、常见字段与关键词
--------------------

1. 触发相关

- 主流是 `触发条件.类型 = "时间"`
- 时间字段常见到 `年/月/日/时`
- 少量条目是 `触发条件.类型 = "前置事件"`
  - 全目录 grep 到 4 个，集中在第 8 回链条

2. 地点相关

- 地点统一使用层级路径：
  - 例如 `大宋/临安府/牛家村`
  - 例如 `蒙古/斡难河/大汗金帐`
- 这和 `src/事件脚本` 里的地点层级匹配是对得上的

3. 常见变量改动目标

普通事件里最常改的不是“纯剧情字段”，而是角色状态数据：

- `人物经历`
- `关系网`
- `所在位置`
- `状态`
- `境界`
- `功法`
- `身份`
- `重要物品`

其中高频变化模式包括：

- 学会功法、提升掌握程度
- 获得或失去关键物品
- 人物死亡 / 濒死 / 悲痛
- 角色地点迁移
- 关系值变化
- 主角阶段性成长（境界、功法、阵法、兵书等）

4. 事件链关键词

- `后续事件`
  - 常见字段：`事件名`、`描述`
  - 说明这些条目天然是串成剧情链的，不是孤立事件

- `事件引子`
  - 文案往往写成“听说……”“据说……”
  - 明显是为“附近传闻”设计的提示文本

六、与 src/事件脚本 的关系
-------------------------

1. 能直接对上的部分

当前 `src/事件脚本/README.md` 里定义的标准事件结构，与本目录主体格式总体一致：

- `触发条件`
- `事件结束时间`
- `事件地点`
- `事件引子`
- `事件详情`
- `insert / update / delete`
- `后续事件`

目录命名也能被加载器识别：

- `射雕事件条目-...`
- `射雕登场事件-...`

这和 `src/事件脚本/era-event-loader.js` 的正则/前缀识别规则是匹配的。

2. 明显的兼容边界

需要重点注意两点：

- 当前事件脚本只正式支持 `触发条件.类型 === "时间"`
  - `src/事件脚本/era-event-checker.js` 中 `isTimeForEvent()` 遇到非时间会直接返回 `false`
  - 但世界书里确实有少量 `前置事件`
  - 这意味着这几条如果直接依赖现有 `checkEvents()`，大概率会长期停留在“未发生事件”

- 全目录未检出 `P-insert / P-update / P-delete`
  - 而 `src/事件脚本/README.md` 和 `era-event-operations.js` 预留了“玩家参与版差分”机制
  - 现有世界书条目看起来主要还是走普通差分，不太像已经完整用上“参与后改写结局”这套分支

3. 观察到的结构不规整点

个别条目不是纯粹的顶层 `insert/update/delete` 分层，而是在 `update` 内部再嵌 `delete/insert` 语义。

抽样示例：

- `第21回-05-临危授命`
  - 在 `洪七公` 的 `update` 对象里又放了 `delete` 和 `insert`

这类写法对人类可读，但和当前事件脚本 README 里的标准结构并不完全一致。后续如果真要做自动化校验或批量修订，这类条目值得先筛出来。

七、与前端变量展示的关系
------------------------

1. 事件系统变量在前端初始化里是有位置的

`src/武侠/utils/gameInitializer.ts` 初始化了这些关键字段：

- `世界信息`
- `附近传闻`
- `事件系统`
- `参与事件`

说明这个世界书目录并不是完全“废数据”，它的目标变量位已经在项目里预留好了。

2. 当前前端 UI 对事件系统的直接展示并不强

`src/武侠/utils/variableReader.ts` 在读取游戏状态时，对事件部分目前基本是：

- `state.events = []`

也就是说，现有前端并没有把世界书事件条目系统性转换成成熟的 UI 列表。当前更像是：

- 后台事件脚本在跑事件状态
- 提示词层把事件相关信息喂给 AI
- UI 本身暂时没有把“事件系统全貌”完整展示出来

3. 事件世界书对 AI 提示的影响比对 UI 的影响更直接

从 `输出提示词.txt` 看，当前最直接的生效路径是：

- `世界信息` 提供时间背景
- `参与事件` 提供玩家已卷入的事件上下文
- `后续事件线索` 提供剧情钩子
- `附近传闻` 提供附近正在发生的事
- 同地点角色数据会被整包注入给 AI

所以这个目录对 AI 的剧情生成影响是直接且持续的，对前端展示的影响则更偏“间接依赖变量”。

八、后续修改角色卡时值得重点看的条目
-----------------------------------

1. `变量指导.txt`

- 如果后续要改 ERA 变量写法、控制 AI 何时写变量、减少无意义写入，这个文件必须先看。

2. `输出提示词.txt`

- 如果后续要改“AI 能看到哪些事件上下文”，或者想调整提示词体积、减少干扰信息，这个文件优先级很高。

3. 全部 `射雕登场事件-第X回人物.json`

- 如果后续要改角色卡的人物底档、人物外貌/性格/境界/初始关系，这类文件是第一落点。
- 它们比普通事件条目更像人物数据库。

4. 含关键成长的普通事件条目

建议优先盯这些会显著改变主角能力/身份/物品的事件：

- 学功法：如 `第5回-06-秘授玄功`、`第12回-03-亢龙有悔`
- 换身份：如 `第21回-05-临危授命`
- 得关键物品：如 `第28回-03-铁掌峰顶遇险得书`
- 兵法/阵法成长：如 `第36回-07-郭靖研读兵书`
- 大结局状态收束：如 `第40回-11-英雄论对`

5. `前置事件` 条目

- 数量不多，但这是和现有 `src/事件脚本` 兼容性最差的一块。
- 如果后续要让世界书与现有事件系统真正跑通，这 4 条应优先核查。

6. 含复杂删改的条目

- 尤其是同时改 `状态`、`所在位置`、`重要物品`、`关系网`，或者在 `update` 内嵌了额外操作语义的条目。
- 这类条目最容易在自动化结算、批量修订、前端展示映射时出错。

九、结论
--------

1. 这个目录虽然体量大、重复度高，但不是“完全没用”。
   - 它本质上是事件系统内容库 + AI 变量操作规则库。

2. 真正值得读的不是 256 个剧情条目的全文，而是它们的“结构模式”和“关键成长节点”。
   - 对后续改角色卡而言，抽样足以建立模型，不需要全量复盘剧情。

3. 当前项目里，这批世界书对 AI 提示的影响强于对前端 UI 的直接影响。
   - 前端变量位已经预留，但 UI 层对事件系统还没有做完整展示。

4. 现有世界书与 `src/事件脚本` 总体可对接，但存在两个明显风险点：
   - 少量 `前置事件` 不被当前时间检查器支持
   - 条目内部偶见非标准差分结构，后续自动化处理时要小心

5. 如果后续要做“角色卡全面修改”，建议先看：
   - `变量指导.txt`
   - `输出提示词.txt`
   - 对应回目的 `射雕登场事件-*.json`
   - 主角成长/身份/关键物品变化条目
