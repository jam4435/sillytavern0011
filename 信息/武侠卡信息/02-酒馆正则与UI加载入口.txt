酒馆正则与 UI 加载入口梳理
更新时间：2026-06-08

一、当前入口配置

当前主入口仍是角色卡里名为“游戏页面”的显示正则：

- 名称：`游戏页面`
- 启用：`true`
- 查找表达式：`/.+/s`
- 配置来源字段：`用户输入=true`、`AI输出=true`
- 作用于：`仅格式显示=true`
- 最大深度：`1`
- 正则内容：在楼层 iframe 中执行 `$('body').load('http://localhost:5500/dist/武侠/index.html')`

来源：角色卡/金庸群侠传/index.yaml:9035-9047；角色卡/金庸群侠传/正则/游戏页面.txt:1-7；@types/function/tavern_regex.d.ts:30-56

二、它如何把伪同层 UI 挂到楼层

1. 前端界面本来就是消息楼层 iframe 里的前台页面，`src/武侠/index.html` 只提供 `#root`，真正的界面由 `index.tsx` 在 iframe 内挂载。来源：.cursor/rules/前端界面.mdc:7-13；src/武侠/index.tsx:11-35
2. “游戏页面”正则改写的是显示结果，不是聊天原文；楼层里真实保存的正文和 ERA 变量块仍在，显示时才被 loader 壳覆盖。来源：@types/function/displayed_message.d.ts:28-46；角色卡/金庸群侠传/正则/游戏页面.txt:1-7
3. loader 拉起 `dist/武侠/index.html` 后，React 入口会立即执行 `ensureLoaderRegexSafety()`，把危险的 `run_on_edit` 配置关掉。来源：src/武侠/index.tsx:19-24；src/武侠/utils/loaderRegexGuard.ts:32-73

三、“复制”正则的定位

`复制` 不是当前主入口，而是一个被禁用的 display 正则，内容直接内联了一份前端构建快照。它更像角色卡导出时附带的“打包产物备份位”，不是当前开发期依赖的 loader URL。来源：角色卡/金庸群侠传/index.yaml:9048-9059；角色卡/金庸群侠传/正则/复制.txt:1-2

这份内联快照为什么会存在：

1. `tavern_sync pull` 会把长内容正则拆到 `正则/*.txt`。
2. `tavern_sync push/bundle` 会把外链正则再回填到角色卡。
3. 所以角色卡里既能保留开发期的 loader 正则，也能保留一次性内联的构建快照正则。

来源：tavern_sync.mjs:61903-62028,62120-62145,62542-62580

四、`仅格式显示` 为什么仍会影响编辑确认

`destination.display=true` 只说明这条正则不进入 prompt，不说明它不会参与楼层重建。酒馆在编辑确认后会重新格式化并重新渲染楼层，因此 display 正则仍会在编辑确认链中执行。来源：@types/function/tavern_regex.d.ts:41-56,92-130；@types/function/chat_message.d.ts:106-153

对当前卡来说，这意味着：

1. 旧 iframe 会先被销毁。
2. 楼层重新命中“游戏页面”正则。
3. loader 再次执行 `$('body').load(...)`。
4. 新前端稍后才重新挂回。

来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；src/武侠/index.tsx:11-35；src/武侠/utils/loaderRegexGuard.ts:32-73

五、为什么 `run_on_edit` 危险

1. `run_on_edit` 是正则配置的一部分，会直接决定编辑确认时是否参与这条链。来源：@types/function/tavern_regex.d.ts:48-56
2. 当前 loader guard 会扫描角色、全局、当前预设三类正则，只要匹配到“游戏页面”脚本名，或者替换内容中带有 `localhost:5500/dist/武侠/index.html`、`127.0.0.1:5500/dist/武侠/index.html`、`$('body').load(`，就自动把 `run_on_edit` 改成 `false`。来源：src/武侠/utils/loaderRegexGuard.ts:4-18,32-73
3. 这样做的目的不是优化审美，而是避免最新 assistant 楼层在编辑后退化成“只有 loader 壳”的消息，进而让前端正文回退到更早楼层。来源：src/武侠/utils/loaderRegexGuard.ts:57-73；src/武侠/utils/variableReader.ts:349-365,2470-2523

六、`variableReader` 对入口链的兜底

当前前端不把显示结果直接当正文，而是做了三层兜底：

1. `stripEraVariableBlocks()` 去掉 `<VariableInsert>` / `<VariableEdit>` / `<VariableDelete>`。来源：src/武侠/utils/variableReader.ts:230-331
2. `stripFrontendLoaderArtifacts()` 去掉 `<script>`、`<body>` 等 loader 壳残留。来源：src/武侠/utils/variableReader.ts:305-331
3. `getLastMessageContent()` 倒序扫描 assistant 楼层，遇到 `isFrontendLoaderOnlyMessage()` 判断为 loader-only 的消息就继续往前找。来源：src/武侠/utils/variableReader.ts:349-365,2470-2523

因此，当前前端的正确性依赖“loader URL / loader 特征识别规则”与外层正则保持同步。来源：src/武侠/utils/variableReader.ts:305-331,349-365；src/武侠/utils/loaderRegexGuard.ts:14-18,32-73

七、改入口时必须一起改的地方

1. 改 loader URL、端口、路径或脚本名时，要同步改 `loaderRegexGuard.ts` 的识别条件。来源：src/武侠/utils/loaderRegexGuard.ts:14-18,32-73
2. 还要同步改 `variableReader.ts` 对 loader-only 楼层的判断，否则它会把新 loader 壳误当正文。来源：src/武侠/utils/variableReader.ts:305-331,349-365
3. 如果改成新的挂载节点，`src/武侠/index.html` 与 `index.tsx` 的 `#root` 依赖也要同步处理。来源：src/武侠/index.tsx:13-20
4. 若要通过代码修改酒馆正则，优先 `updateTavernRegexesWith()`，不要轻易 `replaceTavernRegexes()`，因为后者会触发整聊天重载和 `CHAT_CHANGED`。来源：@types/function/tavern_regex.d.ts:92-130

八、构建与同步层面要记住的事

1. 当前开发主入口是 `localhost:5500/dist/武侠/index.html`，不是角色卡内联 HTML。来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；src/武侠/index.tsx:11-35
2. `webpack.config.ts` 会产出前端 bundle，并在 watch 模式下串上 tavern_sync；`npm run sync` 则单独走同步脚本。来源：webpack.config.ts:168-210；package.json:10-10；tavern_sync.mjs:62542-62630

九、结论

“游戏页面”是当前伪同层卡的真实显示入口，`复制` 只是备用的内联快照位；`run_on_edit` 是高风险项，loader guard 和 variableReader 的 loader-only 识别是这一入口能稳定工作的两道止血层。后续改入口时，至少要同步检查正则矩阵、loader guard、正文读取和构建/同步脚本这四处。来源：角色卡/金庸群侠传/index.yaml:9035-9059；src/武侠/utils/loaderRegexGuard.ts:32-73；src/武侠/utils/variableReader.ts:2470-2523；tavern_sync.mjs:61903-62145
