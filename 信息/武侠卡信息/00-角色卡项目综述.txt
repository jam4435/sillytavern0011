二、最小心智模型

这张卡不是单页网页，也不是普通文本角色卡，而是“消息楼层 + 显示正则 + 前端 iframe + MVU/ERA 变量层 + 后台事件脚本”拼出来的复合结构：

1. 酒馆真实持久化的是聊天楼层，最新 assistant 楼层既可能承载正文，也可能承载 ERA 变量补丁。来源：@types/function/chat_message.d.ts:1-20,31-59,106-153；src/武侠/utils/variableReader.ts:230-421,2285-2538
2. “游戏页面”显示正则把楼层显示结果替换成 loader，loader 再拉起 `http://localhost:5500/dist/武侠/index.html`。来源：角色卡/金庸群侠传/index.yaml:9035-9059；角色卡/金庸群侠传/正则/游戏页面.txt:1-7；src/武侠/utils/loaderRegexGuard.ts:32-73
3. `隐藏楼层.js` 只删除宿主页面上除 `.last_mes` 之外的 DOM，并在 `CHAT_CHANGED` 后重载自身，不会删除聊天记录。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；@types/function/displayed_message.d.ts:1-21,48-70；@types/iframe/event.d.ts:193-224,320-320
4. 真正游戏状态在 `stat_data`。前端主要通过 `getAllVariables()` / `readGameDataPure()` 纯读状态，MVU 提供变量更新事件，ERA 提供变量补丁写入通道。来源：@types/iframe/exported.mvu.d.ts:1-10,54-177；@types/function/variables.d.ts:65-148,197-203；src/武侠/utils/variableReader.ts:434-434,2285-2538
5. `src/事件脚本` 是独立后台状态机，从当前角色已绑定世界书中读取事件定义，按时间、地点与变量状态推进事件。来源：src/事件脚本/index.ts:1-7；src/事件脚本/era-main.js:76-201,369-431；src/事件脚本/era-event-loader.js:9-107
6. `src/武侠` React 前端负责 UI、状态映射、发送消息、正文剥离和补全调度，不是 authoritative state。来源：src/武侠/index.tsx:5-35；src/武侠/App.tsx:144-179,321-370；src/武侠/hooks/useMessageHandler.ts:18-226；src/武侠/utils/variableReader.ts:230-421,2225-2285

一句话记忆：消息楼层是存档载体，显示正则是 UI 入口，隐藏楼层脚本只做视觉收缩，`stat_data` 是真实状态，ERA 是写入通道，事件脚本是后台状态机，React 前端是交互外壳。来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；src/武侠/index.tsx:11-35；src/事件脚本/era-main.js:76-201

三、卡内容层与导出封装层

1. 角色卡头部在 `index.yaml` 中定义首条消息、头像和基础世界书挂载，`变量指导`、`输出提示词`、`cot` 都是系统深度条目，不是前端源码的一部分。当前仓内默认维护和单独 push/pull 的最新世界书目录是 `世界书/金庸群侠传1/金庸群侠传1`；`角色卡/金庸群侠传/世界书/*` 仍是完整卡拆分副本，但已过时，不作为默认编辑目标。来源：角色卡/金庸群侠传/index.yaml:1-45,9006-9019；世界书/金庸群侠传1/金庸群侠传1/变量指导.txt:1-60；世界书/金庸群侠传1/金庸群侠传1/输出提示词.txt:1-60；世界书/金庸群侠传1/金庸群侠传1/cot.txt:1-23
2. 当前世界书不是单线射雕库，`index.yaml` 同时保留了神雕事件条目与神雕登场事件的挂载位，因此整张卡的内容层应按“射雕 + 神雕双线”理解。来源：角色卡/金庸群侠传/index.yaml:3739-3750,8601-8612；世界书/金庸群侠传1/金庸群侠传1/射雕事件条目-第1回-01-郭杨邀饮说书人.json:1-70；世界书/金庸群侠传1/金庸群侠传1/神雕事件条目-第1回-01-南湖采莲遇武三通.json:1-50；世界书/金庸群侠传1/金庸群侠传1/神雕登场事件-第1回人物.json:1-80
3. `index.yaml` 同时记录正则矩阵、脚本库矩阵和事件脚本注入语句，因此它既是角色卡内容清单，也是“拆分文件重新打包回卡”的声明文件。来源：角色卡/金庸群侠传/index.yaml:9035-9059,9060-9111,11756-11779
4. 这个拆分/回填流程由 `tavern_sync.mjs` 完成：拉取时把正则、脚本、世界书拆成外链文件，推送/打包时再回填到角色卡 YAML；`npm run sync` 就是这条入口。来源：tavern_sync.mjs:61903-62028,62120-62185,62315-62366,62509-62630；package.json:10-10
5. 前端构建完成后，webpack 会做 bundle all，并在 watch 模式下启动 tavern_sync watch all，所以 `dist/武侠` / `dist/事件脚本` 和角色卡拆分文件是两层产物。来源：webpack.config.ts:168-210；tavern_sync.mjs:62509-62630

四、子系统职责

1. 聊天数据层：保存真实消息、楼层顺序、隐藏状态与刷新行为。任何“只剩最后一楼”的视觉效果都不等于消息被删。来源：@types/function/chat_message.d.ts:1-20,31-59,106-153,172-208
2. 显示层：酒馆正则决定楼层最终显示成什么；`formatAsDisplayedMessage` / `retrieveDisplayedMessage` 属于显示侧接口，不改消息源。来源：@types/function/displayed_message.d.ts:1-21,28-70；@types/function/tavern_regex.d.ts:21-130
3. 变量层：`getVariables` / `updateVariablesWith` 是通用变量读写接口，MVU 在此之上维护 `stat_data` 并广播变量更新事件。来源：@types/function/variables.d.ts:65-148,197-203；@types/iframe/exported.mvu.d.ts:54-177
4. 事件层：`eventOn` / `eventEmit` 与 `tavern_events` 提供统一的生命周期事件，前端、ERA、事件脚本都基于它们协作。来源：@types/iframe/event.d.ts:42-42,118-126,193-224,272-489
5. 前端层：`src/武侠` 读状态、展示正文、发送消息、调度补全；`src/事件脚本` 读世界书、跑事件、写变量；二者是并列脚本，不是父子关系。来源：src/武侠/架构.md:1-93,97-130,132-196；src/事件脚本/index.ts:1-7；src/事件脚本/era-main.js:76-201

五、关键生命周期

1. 首次加载或继续存档：loader 正则挂起 `dist/武侠/index.html`，`index.tsx` 渲染 `App`，`App` 用 `detectGameSessionState()` / `readGameDataPure()` / `getLastMessageContent()` 恢复状态与正文，并安排后台补全。来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；src/武侠/index.tsx:11-35；src/武侠/App.tsx:144-179；src/武侠/utils/variableReader.ts:2285-2538
2. 新开局：前端创建开场 assistant 楼层，发 `era:insertByObject` 写入初始变量，等待 `era:writeDone` 后再用全局初始化信号唤醒事件脚本。来源：src/武侠/App.tsx:321-370；src/武侠/utils/gameInitializer.ts:238-456；@types/iframe/event.d.ts:118-126
3. 用户发送消息：前端先创建 user 楼层，再 `flushPendingGameDataCompletion()`，然后调用 `generate({ should_stream: true })`，最后写入 assistant 楼层并解析正文/选项。来源：src/武侠/hooks/useMessageHandler.ts:18-226；@types/function/generate.d.ts:9-30,86-146
4. 变量更新后：MVU 触发 `VARIABLE_UPDATE_ENDED`，前端按 diff 调度 scoped completion，事件脚本收到 `era:writeDone` 后再决定是否跑事件检查。来源：src/武侠/hooks/useEventListeners.ts:18-113；@types/iframe/exported.mvu.d.ts:94-118,179-188；src/事件脚本/era-main.js:76-201
5. 编辑确认：酒馆先改消息，再重跑显示正则、变量重同步和外层事件处理，旧 iframe 会先被销毁，再由 loader 重新挂起前端。来源：@types/function/chat_message.d.ts:106-153；@types/function/tavern_regex.d.ts:92-130；src/武侠/utils/loaderRegexGuard.ts:32-73

七、结论

这套卡的复杂度不在某一个 React 组件，而在“角色卡 YAML 打包层、酒馆显示层、变量层、事件层、前端层”同时存在。后续改动时，先判断你碰的是哪一层，再决定要不要同步修改 `index.yaml`、拆分文件、前端识别逻辑和事件脚本；只要这四类边界没混，误改率会低很多。来源：角色卡/金庸群侠传/index.yaml:9035-9111,11756-11779；src/武侠/index.tsx:11-35；src/武侠/utils/variableReader.ts:230-421；src/事件脚本/era-main.js:76-201
