武侠事件世界书抽样梳理
更新时间: 2026-06-08

一、范围说明

本文不再引用旧的外部世界书目录，而是以角色卡已经拆分出的 `角色卡/金庸群侠传/世界书/*.txt` 为准。对当前仓内开发来说，这批拆分文件才是角色卡打包、事件脚本读取和提示词注入的实际内容源。来源：角色卡/金庸群侠传/index.yaml:1-45,3739-3750,8601-8612,9006-9019；tavern_sync.mjs:62315-62366

二、目录概览

当前世界书不是单线射雕库，而是“基础规则 + 射雕条目 + 神雕条目”的双线内容层：

1. 基础规则条目：`变量指导`、`输出提示词`、`cot`。来源：角色卡/金庸群侠传/index.yaml:1-45,9006-9019；角色卡/金庸群侠传/世界书/变量指导.txt:1-60；角色卡/金庸群侠传/世界书/输出提示词.txt:1-60；角色卡/金庸群侠传/世界书/cot.txt:1-23
2. 射雕事件线：大量 `射雕事件条目-*` 与 `射雕登场事件-*`。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:1-70；角色卡/金庸群侠传/世界书/射雕登场事件-第1回人物.txt:1-80
3. 神雕事件线：`index.yaml` 中已挂入神雕事件条目与神雕登场事件，说明这套卡内容层已预留神雕游玩链。来源：角色卡/金庸群侠传/index.yaml:3739-3750,8601-8612；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:1-50；角色卡/金庸群侠传/世界书/神雕登场事件-第1回人物.txt:1-80

三、条目结构

1. 普通事件条目

普通事件 JSON 的核心字段是：

- `事件地点`
- `触发条件`
- `事件结束时间`
- `事件引子`
- `事件详情`
- `insert / update / delete`
- `后续事件`

射雕与神雕样本都采用这一套骨架，只是具体人物和地点不同。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:1-70；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:1-50

2. 登场事件条目

登场事件会额外带上：

- `事件类型: 登场事件`
- `所属回目`
- `新登场人物`
- `insert` 下的人物完整档案

它更像“人物数据库注入包”，而不是普通结算事件。来源：角色卡/金庸群侠传/世界书/射雕登场事件-第1回人物.txt:1-80；角色卡/金庸群侠传/世界书/神雕登场事件-第1回人物.txt:1-80

四、三份基础规则文件各做什么

1. `变量指导.txt`

- 约束 AI 何时输出 `<VariableInsert>`、`<VariableEdit>`、`<VariableDelete>`。
- 明确“无变化则不操作”“思考写在 `<VariableThink>` 中，指令块只放纯 JSON”。

这决定的是模型写变量的协议，不是前端显示规则。来源：角色卡/金庸群侠传/世界书/变量指导.txt:1-60；角色卡/金庸群侠传/世界书/变量指导.txt:67-80

2. `输出提示词.txt`

- 把 `世界信息`、`user数据`、`参与事件`、`后续事件线索`、`附近传闻` 以及同场景角色数据拼给模型。
- 这说明事件世界书对 AI 的影响是直接的，很多事件上下文并不是前端 UI 展示出来才生效，而是在提示词层就已经进模型了。

来源：角色卡/金庸群侠传/世界书/输出提示词.txt:1-60,67-80

3. `cot.txt`

- 约束叙事一致性、时间推进、空间移动、参与事件优先、线索自然引出、同场景角色反应。
- 它不是事件 JSON，也不是前端脚本，而是整张卡的叙事边界说明。

来源：角色卡/金庸群侠传/index.yaml:9006-9019；角色卡/金庸群侠传/世界书/cot.txt:1-23

五、常见字段和运行期含义

1. `事件地点`

当前样本都使用层级路径地点，例如 `大宋/临安府/牛家村`、`大宋/嘉兴/南湖`。这与事件脚本按地点层级生成“附近传闻”和地点触发的逻辑是对得上的。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:1-19；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:1-23；src/事件脚本/era-main.js:76-201

2. `触发条件` / `事件结束时间`

当前样本主流仍是时间触发。事件脚本的检查器也以时间窗和结束时间为主路径。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:2-15；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:2-15；src/事件脚本/era-event-checker.js:16-54

3. `insert / update / delete`

它们最终对应事件脚本和 ERA 支持的差分写法：人物经历、关系网、所在位置、状态、功法、物品等都在这三类 patch 里结算。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:20-70；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:24-50；src/事件脚本/era-event-operations.js:543-745

4. `后续事件`

世界书里的事件不是孤立条目，而是天然链式推进的；事件脚本也会为这类事件生成后续线索与倒计时。来源：角色卡/金庸群侠传/世界书/射雕事件条目-第1回-01-郭杨邀饮说书人.txt:66-69；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:19-22；src/事件脚本/era-event-operations.js:885-944

六、与事件脚本的关系

1. 事件脚本并不硬编码某一条剧情，而是从当前角色绑定世界书里把这些 JSON 条目读进内存。来源：src/事件脚本/era-event-loader.js:9-107；@types/function/worldbook.d.ts:13-32,64-155
2. 初始化和常规检查会把条目分入 `未发生事件 / 进行中事件 / 已完成事件`，并按时间与地点推进。来源：src/事件脚本/era-main.js:76-201,369-431；src/事件脚本/era-event-operations.js:231-231,543-745
3. 事件结束后写回的状态，会继续通过 `附近传闻`、`后续事件线索`、`参与事件` 反向影响提示词与前端状态。来源：src/事件脚本/era-event-operations.js:885-944；角色卡/金庸群侠传/世界书/输出提示词.txt:48-80

七、与变量展示、前端读取的关系

1. 前端初始化和纯读状态都以 `stat_data` 为核心，因此世界书的事件结算结果不会直接映成前端源码常量，而是先落到变量层。来源：src/武侠/utils/gameInitializer.ts:238-456；src/武侠/utils/variableReader.ts:434-434,2285-2538
2. `输出提示词.txt` 直接读取 `stat_data.参与事件`、`stat_data.后续事件线索`、`stat_data.附近传闻`；这三块数据既是事件系统产物，也是模型叙事上下文。来源：角色卡/金庸群侠传/世界书/输出提示词.txt:48-80
3. `变量指导.txt` 决定 AI 产生的变量写入格式，`cot.txt` 决定它如何把事件和线索自然写进叙事，所以这两份规则文件和事件 JSON 一样，都会影响游玩结果。来源：角色卡/金庸群侠传/世界书/变量指导.txt:1-60；角色卡/金庸群侠传/世界书/cot.txt:1-23

八、当前最值得注意的结论

1. 现在应把这批世界书理解为“射雕 + 神雕双线事件库”，不是只剩射雕。来源：角色卡/金庸群侠传/index.yaml:3739-3750,8601-8612；角色卡/金庸群侠传/世界书/神雕事件条目-第1回-01-南湖采莲遇武三通.txt:1-50；角色卡/金庸群侠传/世界书/神雕登场事件-第1回人物.txt:1-80
2. 真正高优先级文件不是所有事件全文，而是 `变量指导.txt`、`输出提示词.txt`、`cot.txt` 和关键登场/成长事件。来源：角色卡/金庸群侠传/世界书/变量指导.txt:1-60；角色卡/金庸群侠传/世界书/输出提示词.txt:1-80；角色卡/金庸群侠传/世界书/cot.txt:1-23
3. 世界书对 AI 提示的直接影响，通常比对 React UI 的直接影响更大。来源：角色卡/金庸群侠传/世界书/输出提示词.txt:1-80；src/武侠/utils/variableReader.ts:2285-2538
