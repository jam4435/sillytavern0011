酒馆结构与伪同层卡运行链路
更新时间: 2026-06-08

一、先说结论

当前“武侠卡”不是原生同层组件，而是下面几层叠出来的伪同层效果：

1. 聊天文件里仍保存完整消息楼层，`getChatMessages()` / `setChatMessages()` 操作的也是完整消息对象。来源：@types/function/chat_message.d.ts:1-20,31-59,106-153
2. 酒馆显示正则把最新楼层显示替换成 loader，loader 再把 `dist/武侠/index.html` 拉进消息 iframe。来源：角色卡/金庸群侠传/index.yaml:9035-9047；角色卡/金庸群侠传/正则/游戏页面.txt:1-7
3. 后台脚本删掉旧楼层 DOM，只让用户在页面上看到 `.last_mes`。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13
4. 游戏状态不在 React store 里自足保存，而是回读 `stat_data`；变量变化主要通过 MVU 事件和 ERA 指令落库。来源：@types/iframe/exported.mvu.d.ts:1-10,54-177；@types/function/variables.d.ts:65-148；src/武侠/utils/variableReader.ts:434-434,2285-2538
5. 事件脚本是独立后台 iframe，会在 `CHAT_CHANGED`、`MESSAGE_SENT`、`era:writeDone` 等事件上继续读写变量。来源：@types/iframe/event.d.ts:193-224,289-320,381-385,473-478；src/事件脚本/era-main.js:76-201

二、什么叫“伪同层”

真正的“同层组件”更接近对某一条现有消息 DOM 做增强：消息本体仍在，界面只是附着在它上面。当前武侠卡不是这样，它是先让外层 TavernRegex 改写楼层显示，再让 loader 从楼层 iframe 中整页加载前端，最后再靠 `隐藏楼层.js` 把历史楼层从宿主 DOM 上移除，所以用户看起来像“同一块界面一直在更新”，实际上底层仍是多楼层聊天。来源：@types/function/displayed_message.d.ts:1-21,28-70；@types/function/tavern_regex.d.ts:21-130；角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；src/武侠/index.tsx:11-35

三、参与层级与职责

1. 聊天数据层

- `ChatMessage` 结构里有 `message_id`、`role`、`is_hidden`、`message`、`data`、`extra`，说明真实存档单元始终是消息对象。来源：@types/function/chat_message.d.ts:1-20
- `setChatMessages(..., { refresh: 'affected' })` 只是刷新受影响楼层；`refresh: 'all'` 会触发整聊天重载和 `CHAT_CHANGED`。来源：@types/function/chat_message.d.ts:106-153；@types/iframe/event.d.ts:204-205,320-320
- 因此 DOM 被删掉不等于消息被删，`is_hidden` 也不等于“当前前台是否可见”。来源：@types/function/chat_message.d.ts:23-29,31-59,106-153；@types/function/displayed_message.d.ts:1-21

2. 显示正则层

- 酒馆正则同时受 `source`、`destination`、`run_on_edit`、`min_depth`、`max_depth` 控制；当前“游戏页面”是 display 侧入口，不是 prompt 侧规则。来源：@types/function/tavern_regex.d.ts:23-56,79-130；角色卡/金庸群侠传/index.yaml:9035-9047
- `formatAsDisplayedMessage()` 会走“宏替换 -> 酒馆正则 -> HTML 化”这条显示链，所以楼层最终怎么显示，不取决于 React，而取决于外层正则先给它什么壳。来源：@types/function/displayed_message.d.ts:28-46；@types/function/tavern_regex.d.ts:21-28
- 当前 loader guard 会主动扫描角色/全局/预设正则，把命中的 loader 规则 `run_on_edit` 关掉，避免编辑确认时把加载壳卷进消息更新。来源：src/武侠/utils/loaderRegexGuard.ts:32-73；@types/function/tavern_regex.d.ts:79-130

3. 隐藏楼层层

- `隐藏楼层.js` 只做两件事：初始删除 `#chat > .mes` 中非 `.last_mes` 的节点；聊天切换后 `reloadIframe()`。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13
- 这意味着它只影响宿主页面显示，不修改聊天消息、不减小正文、不减少 ERA 指令块。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；@types/function/displayed_message.d.ts:14-18,48-70

4. 消息 iframe 层

- 前端界面运行在消息楼层 iframe 中，后台脚本运行在脚本 iframe 中；二者都通过 `eventOn` / `eventEmit` 和宿主交互。来源：@types/iframe/event.d.ts:42-42,118-126,278-390；src/武侠/index.tsx:11-35
- 当前武侠前端在 `$(() => {})` 中挂载 React，并在 `pagehide` 时卸载，因此 iframe 只是前端运行容器，不是状态源。来源：src/武侠/index.tsx:11-35

5. 变量层：MVU、通用变量接口、ERA

- MVU 侧：`Mvu.MvuData` 至少包含 `initialized_lorebooks` 和 `stat_data`，并暴露 `VARIABLE_UPDATE_ENDED`、`BEFORE_MESSAGE_UPDATE` 等事件。来源：@types/iframe/exported.mvu.d.ts:1-10,54-119,179-188
- 通用变量接口侧：`getVariables` / `replaceVariables` / `updateVariablesWith` 是高层变量 API，前端和事件脚本都用它们操作 `chat` 变量域。来源：@types/function/variables.d.ts:65-148
- 当前前端主读取口是 `getAllVariables()` -> `stat_data` -> `readGameDataPure()`，而不是直接 `Mvu.getMvuData()`。来源：src/武侠/utils/variableReader.ts:434-434,2285-2538
- ERA 侧：导出卡包里的 `ERA变量框架-魔改.js` 把 `era:insertByObject` / `era:updateByObject` / `era:deleteByObject` 实现为“向最后一条 AI 消息末尾追加 `<Variable*>` 指令块，再触发写入事件”。来源：角色卡/金庸群侠传/脚本/ERA变量框架-魔改.js:1-20；角色卡/金庸群侠传/index.yaml:9092-9111

6. 事件脚本层

- `src/事件脚本/index.ts` 只加载主控文件；`era-main.js` 负责初始化、监听与调度；`era-event-loader.js` 扫当前角色绑定世界书；`era-event-checker.js` 负责触发/结束判断；`era-event-operations.js` 负责状态迁移；`era-write-helper.js` 负责 direct write 与 ERA write。来源：src/事件脚本/index.ts:1-7；src/事件脚本/era-main.js:76-201,369-431；src/事件脚本/era-event-loader.js:9-107；src/事件脚本/era-event-checker.js:16-54；src/事件脚本/era-event-operations.js:71-112,231-231,543-745,885-944；src/事件脚本/era-write-helper.js:40-59,66-149,258-310

四、当前实际运行链路

1. 楼层显示链

- 酒馆渲染最新消息时命中“游戏页面”正则，显示结果被替换成 loader。来源：角色卡/金庸群侠传/index.yaml:9035-9047；角色卡/金庸群侠传/正则/游戏页面.txt:1-7
- loader 在楼层 iframe 中拉起 `dist/武侠/index.html`，`index.tsx` 再挂载 React。来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；src/武侠/index.tsx:11-35
- 隐藏楼层脚本删掉其它 `.mes`，于是视觉上只剩当前楼层。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13

2. 前端读链

- 前端状态读链是 `getAllVariables()` -> `getGameVariables()` -> `readGameDataPure()` -> `GameState`。来源：src/武侠/utils/variableReader.ts:434-434,2285-2538；src/武侠/App.tsx:144-179
- `getLastMessageContent()` 会倒序扫描 assistant 楼层，剥掉 ERA 变量块和 loader 壳，跳过只剩 loader 的消息。来源：src/武侠/utils/variableReader.ts:230-421,2470-2523

3. 发送链

- `handleSendMessage()` 会先写 user 楼层，再等补全完成，再 `generate({ should_stream: true })`，最后创建 assistant 楼层并刷新正文/选项。来源：src/武侠/hooks/useMessageHandler.ts:18-226；@types/function/generate.d.ts:9-30,86-146

4. 变量更新链

- MVU 变量更新结束后，前端只按 diff 调度 completion，不直接把“刷新 UI”和“再写变量”绑死在同一事件里。来源：src/武侠/hooks/useEventListeners.ts:47-61,78-113；@types/iframe/exported.mvu.d.ts:94-118,179-188
- 事件脚本收到 `era:writeDone` 后会按动作标记决定是否跳过，避免 direct write / apiWrite 自触发回环。来源：src/事件脚本/era-main.js:76-201；src/事件脚本/era-write-helper.js:258-310

五、最容易踩的结构性误区

1. “只剩最后一楼”只是视觉事实，不是存档事实。来源：角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；@types/function/chat_message.d.ts:31-59,106-153
2. “最新 assistant 楼层”不一定等于“最近剧情正文”，因为它可能只剩 loader 壳或变量补丁。来源：src/武侠/utils/variableReader.ts:230-421,2470-2523
3. `run_on_edit` 对 loader 型正则是高风险项，因为它会让编辑确认链把显示入口也卷进去。来源：@types/function/tavern_regex.d.ts:48-56,92-130；src/武侠/utils/loaderRegexGuard.ts:32-73
4. 事件脚本不是前端的附属模块，而是独立后台处理器，所以只改 React 页面并不能覆盖全部状态变化来源。来源：src/事件脚本/index.ts:1-7；src/事件脚本/era-main.js:76-201

六、最小心智模型

可以把当前结构记成一句话：

“聊天消息负责持久化，显示正则把最后一条 assistant 楼层改成前端入口，隐藏楼层脚本只把其它楼层从 DOM 上抹掉，`stat_data` 才是真状态，ERA 是变量补丁运输层，事件脚本和 React 前端都只是围绕它继续读写。”来源：角色卡/金庸群侠传/正则/游戏页面.txt:1-7；角色卡/金庸群侠传/脚本/隐藏楼层.js:1-13；src/武侠/utils/variableReader.ts:434-434,2285-2538；src/事件脚本/era-main.js:76-201
