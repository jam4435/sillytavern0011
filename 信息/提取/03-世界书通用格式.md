## 1.2 index.yaml 头部与工具链

```yaml
# yaml-language-server: $schema=https://testingcf.jsdelivr.net/gh/StageDog/tavern_sync/dist/schema/worldbook.zh.json
锚点: {}

条目:
  - 名称: ...
```

- 这是 **tavern_sync**（StageDog）的中文 worldbook schema。`index.yaml` 只存**元数据**，正文由 `文件:` 字段外链到同名文件，因此可以用普通编辑器/脚本批量生产条目。
- `锚点: {}` 为 YAML 锚点复用位，本项目未使用。
- **可原样照搬**：schema 行 + `锚点: {}` + `条目:` 三段骨架。

## 1.3 条目公共字段模板（这是最值得照搬的部分）

**普通事件条目 / 登场条目的标准块（689 个条目逐字相同，只有 名称/uid/文件 变化）：**

```yaml
  - 名称: 射雕事件条目-第12回-01-初遇洪七公
    uid: 494529
    启用: false
    激活策略:
      类型: 蓝灯
    插入位置:
      类型: 角色定义之后
      顺序: 100
    激活概率: 100
    递归:
      不可被其他条目激活: false
      不可激活其他条目: false
    文件: 世界书\射雕事件条目-第12回-01-初遇洪七公
```

逐字段说明：

| 字段 | 值 | 含义与设计意图 |
|---|---|---|
| `名称` | 与文件名一致 | 条目显示名；也是脚本按前缀分类的依据 |
| `uid` | 随机 6 位整数 | ST 世界书条目唯一 ID，新建时随机生成即可，不需连续 |
| `启用` | **false**（689 个事件/登场条目全部 false） | **关键架构点**：事件条目**不靠世界书关键词激活**，而是被前端事件脚本按"时间/地点"读取并注入。世界书在这里只当"数据仓库 + 版本同步载体"用 |
| `激活策略.类型` | `蓝灯`（693 个）/ `绿灯`（仅 1 个 meta） | 蓝灯=常驻（constant，不需关键词）；绿灯=关键词触发（selective）。**全书 `关键字` 字段出现 0 次** —— 完全放弃了关键词匹配这套机制 |
| `插入位置.类型` | `角色定义之后`（689）/ `角色定义之前`（1，世界背景）/ `指定深度`（4，系统提示） | |
| `插入位置.顺序` | 事件类一律 `100` | order 越小越靠前；100 让数据条目排在系统提示之后 |
| `激活概率` | `100` | 全书统一，无随机条目 |
| `递归.*` | 双 false | 全书统一 |
| `文件` | `世界书\<同名>` | tavern_sync 外链正文，**无扩展名** |

**系统提示注入顺序（深度 0，按 顺序 递增 = 越靠后越贴近用户消息）：**

```
顺序 3  输出提示词（当前变量快照 / 参与事件 / 可用地点 / 同场角色）
顺序 4  变量指导（写入规则）   ← 主版本已关闭
顺序 5  cot（叙事规范）
------- 深度 4 -------
顺序 0  战斗骰子（战力区 + 判定公式）
```

设计意图：**先给数据（输出提示词）→ 再给写数据的规则（变量指导）→ 最后给写正文的规则（cot）**，战斗协议单独放在深度 4（离最新消息更远，属于长期常驻规则）。

> **注意**：主版本里 `变量指导` 被设为 `启用: false`，而 `战斗骰子.txt` 从旧版 `变量指导.txt` 的"第五节"独立出来并大幅扩写。说明作者把"变量规则"迁移到了别处（预设 / 正则 / 角色卡主提示词），世界书只留叙事与战斗。**复刻时应该把 变量指导 打开或迁到主提示词，不要照抄 `启用: false`。**

```yaml
  - 名称: __WI_META_FOLDERS__
    uid: 90282
    启用: false
    激活策略: { 类型: 绿灯 }
    插入位置: { 类型: 角色定义之后, 顺序: 0 }
    内容: '{"version":1,"folders":[
             {"id":"folder_1783841869849_s2cgh6","name":"射雕事件条目"},
             {"id":"folder_1783844985874_xpxfjz","name":"射雕登场事件"},
             {"id":"folder_1783845008328_9qikc2","name":"神雕事件条目"},
             {"id":"folder_1783845032204_q5t5ld","name":"神雕登场事件"}],
           "entryFolderMap":{"228":"folder_...","5248":"folder_...", ...}}'
```

- 这是 ST 世界书 UI 的**文件夹分组**元数据，`启用: false` + `绿灯` 保证它永远不入提示词。
- **复刻价值**：条目一旦上百，没有文件夹会完全无法维护。换题材时把 4 个 folder 名换成你的"卷/篇 × 条目类型"即可。

**标注**：
- 条目公共字段模板 → **可原样照搬**（只改 名称/uid/文件）
- 五个系统条目的 深度/顺序 编排 → **可原样照搬**
- `__WI_META_FOLDERS__` 结构 → **可原样照搬**（folder 名需改写）
- `启用: false` 大规模禁用的前提是**你有配套的事件注入脚本**；若没有脚本，这套结构不成立，必须改成关键词绿灯或蓝灯常驻 → **需按实现方式改写**

## 2.1 `cot.txt`（思维链模板）

### 主版本全文（`世界书\金庸群侠传1\世界书\cot.txt`，2026-07-22）

```
<thinking>
## 叙事输出规范

### 数据一致性要求
1. 世界观一致：叙事内容必须符合当前「世界信息」中的时代背景、地理环境和社会规则
2. 角色行为约束：同场景角色的言行必须符合其 JSON 数据中的性格、功法和立场设定
3. 能力边界：角色使用的武功招式必须是其「功法」列表中已有的，不可凭空使用未习得的武学

### 时间与空间表达
1. 时间体现：在叙事中用古代时辰表达时间（如"日上三竿"、"暮色四合"、"月上中天"）
2. 时间流逝：若剧情涉及时间推进（如赶路、修炼、等待），需在叙事中明确描述
3. 位置变化：角色移动时需描述途中见闻，不可瞬间转移

### 事件处理规则
1. 参与事件优先：若玩家正处于某个事件中，叙事应围绕该事件展开，随着事件进行，按事件进行比例，去同步变更当前的时间
2. 结局可变性：玩家的选择可以改变事件的预设结局，但需合乎逻辑
3. 线索自然引出：「后续事件线索」和「附近传闻」应通过 NPC 对话、告示、偶遇等方式自然融入叙事

### 同场景角色互动
1. 在场角色反应：同场景的角色应对玩家行为有合理反应（旁观、参与、阻止等）
2. 关系影响行为：角色对玩家的态度应基于其数据中的「关系网」字段
3. 群体动态：多人在场时，考虑角色之间的关系和派系立场
</thinking>
```

### 与旧版（角色卡侧，2026-06-23）的差异

| 位置 | 旧版 | 主版本 | 说明 |
|---|---|---|---|
| 包裹标签 | `<cot>` … `<cot>`（**闭合标签写错，缺 `/`**） | `<thinking>` … `</thinking>` | 主版本修正为标准 thinking 标签 |
| 数据一致性 2/3 | 「技能」 | 「功法」 | 变量结构从通用 `技能` 改为武侠专名 `功法` |
| 事件处理规则 1 | `叙事应围绕该事件展开` | 追加 `随着事件进行，按事件进行比例，去同步变更当前的时间` | 补上时间同步职责 |
| 同场景互动 2 | 「关系」 | 「关系网」 | 字段名对齐实际变量 |

### 结构解释

四段式，每段 3 条，全是**约束式**而非流程式 —— 它不是"先想 A 再想 B"的推理链，而是一份**写正文前的自检清单**，被塞进 `<thinking>` 让模型在正文前先过一遍。

| 段落 | 约束的东西 | 依赖的变量字段 |
|---|---|---|
| 数据一致性要求 | 不 OOC、不超出能力边界 | `世界信息`、角色 `性格` / `功法` / `身份` |
| 时间与空间表达 | 时间的**文学表达**与**推进合理性**；禁止瞬移 | `世界信息.时间`、`所在位置` |
| 事件处理规则 | 事件优先级、结局可变、线索软植入 | `参与事件`、`后续事件线索`、`附近传闻` |
| 同场景角色互动 | 群戏调度 | `角色数据.*.关系网`、`所在位置` |

**标注（逐段）：**

| 段 | 结论 |
|---|---|
| 整体四段式框架 + `<thinking>` 包裹 | **可原样照搬** |
| 数据一致性 1（世界观一致） | **可原样照搬** |
| 数据一致性 2、3 | **需改字段名**：`功法` → 你的题材对应字段（`技能`/`异能`/`装备`/`法术`），语义完全通用 |

## 2.2 `变量指导.txt`

两份差异**极大**，是两代设计。**主版本是"极致压缩的约束清单"（3997 字节），旧版是"教科书式的示例文档"（9419 字节）。** 两份都有复刻价值，用途不同。

### 2.2.1 主版本全文（`世界书\金庸群侠传1\世界书\变量指导.txt`，2026-07-26，当前 `启用: false`）

```markdown
# ERA 变量更新规则

## 1. 路径和操作

- 只有最新 assistant 正文中已经发生、且需要长期保存的变化才写变量；前序正文只读，无变化时不输出 Insert/Edit/Delete。
- 可写根仅限 `世界信息.时间`、`user数据`、`角色数据`，以及提示词中已存在的 `参与事件.<事件键>.结局/insert/update/delete`。
- 输出前必须逐级对照当前 JSON：目标键已经存在用 `<VariableEdit>`；目标键不存在才用 `<VariableInsert>`；删除已存在的键用 `<VariableDelete>`。
- 对象的父级存在不代表子键存在；判断的是最终目标键。反过来，最终目标键已经存在时，禁止对父级容器再次 Insert 同名键。
- 同一事实已经存在且正文没有改变它时，不操作。尤其是 `人物经历`：同名经历已存在时禁止重复 Insert；只有正文改变了现有经历内容才 Edit，出现真正的新经历且新键不存在时才 Insert。
- JSON 中没有展示的根、系统区和只读说明均禁止写入；不要推测隐藏结构。

## 2. 时间、事件和地点

- 时间只能前推，禁止回拨。只推进事件一部分时按正文合理推进；关键桥段完整结束时，将时间推进到事件描述给出的结束时间，但不得早于当前时间。
- `<参与事件>` 的标签名是已经存在的真实事件键；方括号中的描述只读，禁止写回或改写。
- `参与事件` 只由系统创建，禁止新增事件键。`结局`只有在人物生死、长期状态、关系、阵营、关键物品归属、事件目标或后续成立条件发生实质变化时才 Edit；原定发展未变时不要润色。
- `insert/update/delete` 是 NPC 的原定结算快照。只能 Edit 或 Delete 其中已经存在、且被正文改变的差分项，禁止在参与事件中新增原本不存在的结果，也禁止写入 `user数据`。
- 命中已有 NPC 差分时修改快照，不把同一结果提前重复写入 `角色数据`；临时位置、伤势、状态或快照外的新变化仍直接写当前角色变量。
- 玩家自身的变化直接写 `user数据`。玩家打断、逆转或绕开事件时，以正文实际发生的变化为准，不强行套用原结局。
- 修改任何 `所在位置` 时，新值必须逐字等于 `<可用地点>` 中的一条完整路径；三组都为空时禁止修改位置。

## 3. 人物和物品

- 人物姓名由 `角色数据.<人物键>` 表达，角色对象内不要新增 `姓名`。新人物键不存在时才 Insert；已有角色的字段变化用 Edit。
- `身份`保持扁平结构 `{"身份名":"对剧情有意义的说明"}`，不要新增固定的姓名、称谓、别名或字字段。
- 只有剧情中新获得或失去物品时才修改 `user数据.包裹`。新增物品至少包含 `类型/品阶/物品描述/数量`；装备再补 `部位/属性修正/使用状态`，药品再补 `功效类型`。
- 秘籍只是功法载体，不要给秘籍编造属性修正、部位、持续时间或参悟条件。

## 4. 前端已经结算的操作

- 玩家指令若已注明装备属性变化、药品恢复或属性增加，表示前端已处理包裹、装备栏、属性或状态效果；不要重复写同一变化。
- 装备按钮会更新装备栏、包裹使用状态并重算属性；回复药会扣数量并恢复当前气血/内力；增幅药会写状态效果或前端修正。不要重复结算，也不要直接修改 `前端变量`。
- 特殊药品只由前端扣数量；正文造成的长期后果可写人物状态、经历、关系或已有事件差分，但不要自造数值型属性修正。

## 5. 输出

`<VariableThink>` 只列核对结果，不展开思维链：

    路径｜当前存在/不存在｜正文变化｜Edit/Insert/Delete/无

- Insert/Edit/Delete 块内只放严格 JSON，不要注释、尾随逗号或额外 XML 标签。
- 相同类型的操作合并到一个块；没有写入时只输出 VariableThink。
```

### 2.2.2 旧版全文（`角色卡\金庸群侠传\世界书\变量指导.txt`，2026-07-06）

### 2.2.4 变量指导的结构解剖

主版本五节的职责划分：

| 节 | 解决的问题 | 关键机制 |
|---|---|---|
| §1 路径和操作 | **Insert / Edit 误用**（LLM 最常犯的错） | "目标键存在→Edit，不存在→Insert"；"父级存在≠子键存在"；白名单可写根 |
| §2 时间、事件和地点 | **时间回拨**、**乱造事件**、**乱造地点** | 时间单调递增；`参与事件` 只读键名、差分只能改不能增；`所在位置` 必须逐字匹配 `<可用地点>` |

1. **EJS 前置脚本**：`selectWorldEventsForPrompt` —— 从 `stat_data.世界事件` 里挑最多 16 条注入"世界历史（只读）"，其中**优先塞 8 条 `事件结局状态 === '偏离' | '未知'` 的事件**（即玩家改变过或未确认的历史线），剩余按时间填满，最后按时间正序输出。**这是"历史偏移"机制的具体实现**。

- **基准 45**（略低于中位，默认偏向"难分胜负偏下"）

- **环境因素 / 状态因素** 各 `[-20,+20]`，是**模型的自由裁量口**，但被限幅
- 五档结果区间 `<=10 / 11-40 / 41-60 / 61-90 / >=91`

- "同一角色同一列多个功法时不得偷用同列最高值"
- "基础与具名功法只能二选一，不能相加"
- "查不到战力按 0 处理，禁止编造"
- "战力区已含装备与属性修正，不得在状态因素中重复加减"

```js
function sanitizePromptValue(value) {
  if (Array.isArray(value)) return value.map(item => sanitizePromptValue(item));
  if (!value || typeof value !== 'object') return value;
  return Object.fromEntries(
    Object.entries(value)
      .filter(([key]) => !key.startsWith('$'))
      .map(([key, child]) => [key, sanitizePromptValue(child)]),
  );
}
```

## 3.5 字段逐条 schema 说明

| 字段 | 类型 | 语义 | 消费方 | 换题材 |
|---|---|---|---|---|
| `事件地点` | `string`，三段路径 `国/路/地` | 事件发生地，必须与 `<可用地点>` 体系同源 | 前端判断玩家是否在场；提示词注入 | **格式照搬，层级名改写** |
| `触发条件` | `{类型:"时间", 年,月,日,时}` | 事件开始生效的时刻，全书 100% 时间型 | 事件调度器扫描时间轴 | **可原样照搬** |
| `事件结束时间` | `{年,月,日,时}` | 事件完整结束的时刻；变量指导要求"关键桥段写完必须把 `世界信息.时间` 推进到这里" | LLM 结算时间；前端算事件时长 | **可原样照搬** |
| `事件引子` | `string`，一句话，常以"你听说…"开头 | **玩家侧钩子**，投放到 `附近传闻`/`后续事件线索`。不含剧透 | 传闻/线索系统 | **格式照搬**，内容改写 |
| `后续事件` | `{事件名, 描述}` | 下一事件的**软引用**（见 §5.3） | 事件链推进；线索生成 | **可原样照搬** |
| `事件详情` | `string`，200-1000 字 | 剧情的完整散文复述，给 LLM 演的"剧本" | 注入 `<参与事件>` 只读方括号区 | **格式照搬**，内容全改写 |
| `事件概要` | `string`，一句话 | 事件的**结果性摘要**（不是过程）。引子勾人、概要记账 | 写入 `世界事件.<键>.概要`，供"世界历史（只读）"注入 | **可原样照搬** |
| `update` | `{角色名: {字段: 新值}}` | 修改已有字段的差分（位置/状态/境界…） | 事件结算 apply；也作为 `参与事件.<键>.update` 快照给 LLM 有条件改写 | **结构照搬，字段名改写** |
| `insert` | `{角色名: {容器: {新键: 值}}}` | 新增子键的差分（人物经历/关系网/物品/功法…） | 同上 | **结构照搬，容器名改写** |
| `delete` | `{角色名: {容器: {待删键: {}}}}` | 删除差分，目标值恒 `{}` | 同上 | **可原样照搬** |
| `参与人物` | `string[]` | 参与者名单（含只被提及的关键人） | 前端判断在场；调度器拉角色数据 | **可原样照搬** |

### 三差分 `insert / update / delete` 的写作规约（从 630 个样本归纳）

1. **`update` 只放"已存在字段的新值"** —— 高频是 `所在位置`、`状态`、`境界`。
2. **`insert` 只放"容器下的新条目"** —— 高频是 `人物经历`、`关系网`、`重要物品`、`功法`。
3. **`delete` 目标值恒为空对象 `{}`**，与 `<VariableDelete>` 协议一致。
4. **`delete` 有两种放置位置**（不一致，复刻时应二选一）：顶层平级（**推荐**，与 `参与事件` 快照四字段结构对齐）或嵌在 `insert.<角色>.delete` 内（不推荐）。
5. **`人物经历` 的键必须等于事件键**（`第N回-NN-标题`）—— "经历"天然可回溯到事件，且能被"同名键禁止重复 Insert"规则去重。**最值得照搬的一条约定。**
6. **`关系网` 值格式 `关系名/亲密度`**（`"结识/40"`、`"义父/95"`、`"父亲/已故"`）。数值 0-100，允许非数值特例。**格式照搬，关系名词表改写。**
7. **同一事件对多个角色的经历"各视角分别写"** —— 各自站在本人视角。直接决定后续 NPC 提起往事时的口吻正确性，**强烈建议照搬**。

# 五、命名规范、分回组织与引用关系

## 5.1 文件/条目命名规范

```
事件条目：  <作品简称><类型>-第<N>回-<NN>-<标题>
            射雕事件条目-第12回-01-初遇洪七公
            └作品┘└类型┘  └回目┘└序号┘└─标题─┘

登场条目：  <作品简称>登场事件-第<N>回人物
```

| 成分 | 规则 |
|---|---|
| 作品简称 | 2 字，做命名空间隔离 + 文件夹分组依据 |
| 类型 | `事件条目`（剧情）/ `登场事件`（建档） |
| 回目 | `第N回`，N 不补零 → 字典序会乱，但因有独立时间轴驱动，排序不影响运行 |
| 序号 | `NN` **补零两位**，保证回内有序 |
| 标题 | 4-30 字动宾/主谓短语，不含标点（唯一分隔符是 `-`） |
| 登场条目 | 一回一文件，无序号，固定后缀 `人物` |
| `index.yaml` 的 `名称`/`文件` | 与文件名**逐字一致**（`文件:` 无扩展名） |

**标注**：命名规范 → **可原样照搬**（`射雕/神雕` 换你的卷名，`回` 换 `章/幕/关/季`）。建议改进：`第NN回` 也补零。

## 5.2 分回组织方式

```
作品（射雕 / 神雕）
 └─ 回（第1回 … 第40回）              ← 原著章回，天然的剧情分段
     ├─ 登场事件-第N回人物            ← 本回首次出场角色的批量建档，最多 1 个
     └─ 事件条目-第N回-01…NN-标题     ← 本回拆出的 1-13 个可玩事件
```

- 回内事件按"场景/桥段"切分，粒度大致是"一个连续时空 + 一组固定参与人"；回内序号与时间轴同向。
- 有些回没有事件条目，有些没有登场条目 —— 两者不强制配对。
- **两部作品的时间轴不重叠**（射雕约 1200-1227，神雕约 1237-1259），共存于同一世界书，靠 `触发条件` 天然错开。这就是"多线共存原则"的落地方式。

**标注**：分回组织 → **可原样照搬**。新题材没有天然章回时用"幕/日/关卡/主线阶段"替代，关键是**保留"分组 + 组内补零序号"两层**。

## 5.3 条目间引用关系的表达方式

**全书没有任何 `前置`/`依赖`/`prerequisite` 字段**。事件顺序**完全由 `触发条件` 的绝对时间戳隐式表达**。

四种机制：

### (1) 时间戳偏序（唯一的硬约束）
前一事件的 `事件结束时间` 与后一事件的 `触发条件` 形成隐式链；变量指导的"时间只能前推"就是这套偏序的保护机制。

### (2) `后续事件` 软引用（前向单链）
- 只有 `事件名` 字符串，没有 uid —— 软引用，对不上不会崩，只是链断
- 规范格式 **`第N回-NN-标题`（不带作品/类型前缀）**
- 每个事件只有 1 个后续（无分支数组）→ 整体是**单链表**，不是 DAG
- `描述` 是钩子文案，写进 `后续事件线索`，由 cot 要求"通过 NPC 对话、告示、偶遇自然融入"

### (3) `人物经历` 键的反向溯源
经历键 = 事件键 → 从任意角色档案可反查"他参加过哪些事件"；也是**去重主键**。

### (4) 玩家偏离的表达：`事件结局状态`
不在世界书里，而在 `stat_data.前端变量.事件结局状态`（战斗骰子.txt 消费）：值为 `偏离`/`未知` 的事件被**优先注入**"世界历史（只读）"。这是"玩家改写历史"的可见化通道。

**标注**：
- 时间戳偏序 + 无显式前置 → **可原样照搬**（若做条件/旗标驱动就要加 `前置` 字段）
- `后续事件 {事件名, 描述}` 单链 → **可原样照搬**；需要分支时改成数组 `[{事件名, 描述, 条件}]`
- `人物经历` 键 = 事件键 → **可原样照搬**，强烈推荐
- `事件结局状态` 三态 → **可原样照搬**

## 6.3 复刻时应修正的已知不一致（不要照抄这些）

1. `后续事件.事件名` 前缀不统一（第1回残留 `事件条目-` 前缀）→ 统一为 `第N回-NN-标题`。
2. `人物经历` 键前缀不统一 → 同上。
3. `delete` 位置不统一（顶层 vs 嵌在 `insert.<角色>.delete`）→ **统一放顶层**。
4. 空 `update` 残留（`{"丘处机": {}}`）→ 删掉。
5. `所在位置` 段数不统一（`"大宋/宝应"` 两段会被三段校验丢弃）→ 建档时写满三段。
6. `境界` 小阶段混入掌握程度词（`"三流-融会贯通"`）→ 两套词表严格隔离。
7. 旧版 cot.txt 的 `<cot>…<cot>` 闭合标签缺 `/` → 主版本已修为 `<thinking>`。
8. `变量指导` 条目在主版本 `启用: false` → 若没把变量规则迁到别处，务必设为 `true`。
9. 旧版变量指导示例3 的 JSON 有尾随逗号 → 示例里的非法 JSON 会教坏模型。

## 6.4 最小可用复刻套件（建议生成顺序）

```
1. 定义变量结构（世界信息/user数据/角色数据/参与事件/后续事件线索/附近传闻/世界事件/前端变量）
2. 写 世界背景.yaml         ← 改写
3. 写 输出提示词.txt         ← 改字段名，逻辑照搬
4. 写 变量指导.txt           ← 改根名/字段名/物品分类/前端清单，规则照搬
5. 写 cot.txt               ← 改 3 处字段名 + 时间表达
6. 写 战斗骰子.txt           ← 改功法分类，公式照搬
7. 批量生成 登场条目          ← 每"卷·章"一个，人物建档，人物经历恒 {}
8. 批量生成 事件条目          ← 时间轴排序，后续事件串成单链
9. 生成 index.yaml           ← 脚本套用公共字段块，随机 uid
10. 生成 __WI_META_FOLDERS__ ← 按卷 × 类型分 folder
```

**规模参考**：本卡 630 事件 + 58 登场覆盖两部小说 80 回，平均每回 7.9 个事件。原创题材建议从"1 卷 10 章、每章 3-5 事件"起步（30-50 事件），验证时间轴与差分结算跑通后再扩。
