## 一句话心智模型

> **聊天楼层负责持久化；显示正则把最后一条 assistant 楼层改写成前端入口；隐藏楼层脚本把其余楼层从宿主 DOM 上抹掉；`stat_data` 才是真状态；ERA 是变量补丁运输层；后台事件脚本是独立状态机；React 前端只是交互外壳。**

复刻新卡时这七个角色一个都不能少，也一个都不能混。

## 最有复用价值的十个资产（速查）

1. **隐藏楼层.js** —— 折叠 DOM + 回合锁 ACK + 黑匣子诊断，已在两张卡之间零改动复用验证，整个文件照搬（详见 04 §2）。
2. **ERA 变量框架（魔改版）** —— 通用变量引擎，21 模块与题材完全无关；三个按钮名（写入变量修改/手动同步状态/强制完全重算）硬编码不能改（04 §1）。
3. **ERA基础正则** —— `<era_data>` + `<Variable*>` 块的显示&提示词双清除，一字不改照搬（02 §4.1）。
4. **双正则开发/发布切换** —— 开发态 `/.+/s` + `$('body').load(localhost)`，发布态字面量锚串 + 内联 bundle（02 §4.2-4.3）。
5. **"启用:false 世界书条目 = 随卡分发的 JSON 数据库"** —— 命名前缀 + `getWorldbook()` 读取，事件脚本不硬编码任何剧情（02 §2、03 §1.3）。
6. **事件条目 / 登场条目双 schema** —— 建档（人物经历恒 `{}`）与填档（差分写入、经历键=事件键）职责分离（03 §3-4）。
7. **变量指导的护栏体系** —— 存在性判定（存在→Edit/不存在→Insert）、时间只能前推、地点白名单逐字匹配、前端派生区只读、`<VariableThink>` 四栏格式（03 §2.2）。
8. **战斗判定协议** —— 前端预生成随机数 + LLM 只查表算术；45 基准 + 归一化战力差 + 双 ±20 限幅 + 五档区间（03 §2.3）。
9. **输出提示词 EJS 装配器** —— `$` 键剔除、出生年份→年龄、同场景角色过滤、`<参与事件>` 只读+可写双区、管道三段式压缩（02 §3.2、03 §2.4）。
10. **「原定/偏离/未知」事件结局状态机 + 提示词预算控制**（最多 16 条、优先 8 条偏离/未知）（01 §4.10-4.12）。

## 复刻新卡的推荐搭建顺序（摘自 01 §7.3）

1. 先定 `stat_data` 字段树（所有层的公共契约）
2. 搭最小伪同层链路：loader 正则 + 空白前端 + 隐藏楼层脚本 + loader guard
3. 接 ERA 框架，跑通"前端写初始变量 → `era:writeDone` → 读回状态"握手
4. 写变量指导，跑通 AI 输出 `<Variable*>` 块 → 落库 → 前端刷新
5. 写输出提示词 + cot，跑通剧情生成与正文/选项解析
6. 上事件系统：先 2~3 条事件条目验证前缀识别与时间/地点触发，再补参与快照、偏离判定、归档
7. 最后 UI 打磨与提示词预算调优

## 改动联动 checklist（最易漏）

改 loader URL / 端口 / 目录名 / 入口正则名时，必须**同时改四处**：
① 角色卡正则矩阵 ② loader guard 特征串 ③ 正文读取器 loader-only 判断 ④ 构建输出路径。

改 `wuxia:` 事件前缀时，必须同步隐藏楼层脚本与前端 `turnLock.ts` 两侧的全部常量，任一漏改 = 每回合抛"回合锁未确认"。
