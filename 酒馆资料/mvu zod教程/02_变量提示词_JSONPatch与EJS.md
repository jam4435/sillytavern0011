# 02. 变量提示词、JSON Patch 与 EJS

目标：让 AI 每回合看见最新变量，知道何时更新，并输出 MVU 能解析的 JSON Patch；需要时再按变量动态发送提示词。

## 1. 四个变量文件各做一件事

| 文件                | 职责                 | 是否常驻发送给 AI                   |
| ------------------- | -------------------- | ----------------------------------- |
| `initvar.yaml`      | 新聊天默认值         | 否；条目保持禁用，由 MVU 初始化扫描 |
| `变量列表.txt`      | 展示当前最新值       | 是                                  |
| `变量更新规则.yaml` | 解释何时、怎样更新   | 是                                  |
| `变量输出格式.yaml` | 规定可解析的输出协议 | 是                                  |

不要把四份内容混成一个大提示词。Schema 管数据合法性，更新规则管剧情语义，输出格式管命令语法。

## 2. 变量列表使用固定模板

```text
---
<status_current_variable>
{{format_message_variable::stat_data}}
</status_current_variable>
```

标签是单数 `<status_current_variable>`。宏会把最新消息楼层的 `stat_data` 格式化给 AI。

不要在这里重复变量解释、角色人设或更新规则；否则每回合浪费 token，还可能制造矛盾。

## 3. 更新规则怎么写

示例：

```yaml
---
变量更新规则:
  世界:
    当前时间:
      format: YYYY-MM-DD HH:mm
      check:
        - 根据本轮剧情真实经过的时间更新
        - 没有明确时间推进时保持不变
    当前地点:
      check:
        - 仅在角色实际抵达新地点后更新
    近期事务:
      type: |-
        {
          [事务名: string]: string; // 事务说明
        }
      check:
        - 新承诺、任务或明确待办出现时新增
        - 完成、取消或失效时移除
        - 只保留仍会影响后续剧情的 5~8 项

  角色:
    络络:
      好感度:
        type: number
        range: 0~100
        check:
          - 仅根据络络本轮实际感知到的<user>行为更新
          - 普通互动单次变化 ±1~3，重大事件可 ±4~8
          - 没有足够依据时保持不变
      心情:
        type: "'平静' | '开心' | '低落' | '愤怒'"
        check:
          - 记录本轮结束时占主导的短期心情
          - 不因一句普通台词频繁跳变
      着装.${上装|下装|鞋子|饰品}:
        check:
          - 仅在换装、脱下、损坏或新增配饰时更新对应字段

  主角:
    物品栏:
      type: |-
        {
          [物品名: string]: {
            描述: string;
            数量: number;
          }
        }
      check:
        - 获得、消耗、丢弃物品时更新
        - 数量归零时移除该物品
```

### 每个可更新字段至少回答

1. 什么事实触发更新？
2. 什么情况下保持不变？
3. 数字单次变化尺度是多少？
4. 动态条目何时新增、修改、删除？
5. 是否有数量上限、格式或跨字段约束？

更新规则不要重复固定人设，也不要写“根据剧情合理更新”这种没有约束力的空话。

### Schema 与规则分工

- Schema：最终校验和纠错，例如把好感度夹到 0~100。
- 更新规则：指导模型只在剧情有依据时改变好感度，并限制常规增幅。

两者不能互相替代。只有 Schema 没有规则，模型会乱改；只有规则没有 Schema，错误类型可能破坏变量表。

## 4. 输出格式直接复用当前模板

从 `初始模板/角色卡/新建为src文件夹中的文件夹/世界书/变量/变量输出格式.yaml` 复制，不要从旧资料重写成 `_.set()` 协议。

当前协议结构：

```text
<UpdateVariable>
<Analysis>简短分析</Analysis>
<JSONPatch>
[
  { "op": "...", "path": "/变量/路径", "value": ... }
]
</JSONPatch>
</UpdateVariable>
```

支持：

| 操作      | 用途               | 示例                                                                    |
| --------- | ------------------ | ----------------------------------------------------------------------- |
| `replace` | 替换已有值         | `{"op":"replace","path":"/角色/络络/心情","value":"开心"}`              |
| `delta`   | 给已有数字加减     | `{"op":"delta","path":"/角色/络络/好感度","value":3}`                   |
| `insert`  | 新增对象键或数组项 | `{"op":"insert","path":"/世界/近期事务/归还书籍","value":"周五前归还"}` |
| `remove`  | 删除对象键或数组项 | `{"op":"remove","path":"/主角/物品栏/旧车票"}`                          |
| `move`    | 移动已有数据       | `{"op":"move","from":"/旧路径","to":"/新路径"}`                         |

要求：

- `<JSONPatch>` 内必须是合法 JSON 数组；
- `value` 使用实际 JSON 类型，数字不要写成字符串；
- 路径从 Schema 根开始，不带 `/stat_data`；
- 更新最小必要路径；
- 不更新 `_` 开头的只读字段或 transform 派生字段；
- 不重复处理已经体现在当前变量列表中的旧事件。

一个合理的回复尾部可能是：

```text
<UpdateVariable>
<Analysis>
- About ten minutes passed; the location did not change
- Luoluo directly noticed the help, so favor increases slightly
- The protagonist received a locker key
</Analysis>
<JSONPatch>
[
  { "op": "replace", "path": "/世界/当前时间", "value": "2026-07-13 08:10" },
  { "op": "delta", "path": "/角色/络络/好感度", "value": 2 },
  {
    "op": "insert",
    "path": "/主角/物品栏/储物柜钥匙",
    "value": { "描述": "贴着 27 号标签的黄铜钥匙", "数量": 1 }
  }
]
</JSONPatch>
</UpdateVariable>
```

## 5. index.yaml 的变量条目

优先复制当前初始模板的整个变量文件夹配置。必须保留：

- `[initvar]变量初始化勿开`：禁用、蓝灯，供 MVU 初始化扫描；
- `变量列表`：启用、蓝灯；
- `[mvu_update]变量更新规则`：启用、蓝灯；
- `[mvu_update]变量输出格式`：启用、蓝灯；
- 三个常驻条目使用系统 D0，并禁止互相递归激活；
- 文件路径不写扩展名。

`[initvar]` 与 `[mvu_update]` 标记不能省略或随意改名。

同时保留当前模板的变量更新正则：

1. 不把历史 `<UpdateVariable>` 再发给 AI；
2. 流式生成时折叠未完成更新块；
3. 显示时折叠完整更新块。

具体正则与字段名以当前模板和同步 schema 为准，不在教程中维护第二份易过期副本。

## 6. 用 EJS 按变量动态发送提示词（可选）

只有角色卡明确依赖“提示词模板”插件时才使用 EJS。普通变量更新不需要 EJS。

### 核心模式

```ejs
<%_ const favor = getvar('stat_data.角色.络络.好感度') ?? 0; _%>
<%_ if (favor < 30) { _%>
络络仍然戒备，只会给出简短回应，不主动透露私事。
<%_ } else if (favor < 70) { _%>
络络已经愿意正常交流，会逐渐分享日常感受。
<%_ } else { _%>
络络高度信任<user>，会主动寻求陪伴并坦率表达需求。
<%_ } _%>
```

- `<%_ ... _%>` 执行代码，不直接发送代码文本；
- `getvar('stat_data....')` 读取变量；
- 对可能不存在的变量提供 `??` 默认值；
- 用 `if / else if / else` 保证互斥阶段只发送一份设定。

### 输出计算结果

```ejs
当前好感阶段：<%= getvar('stat_data.角色.络络.好感度') >= 70 ? '亲密' : '普通' _%>
```

复杂输出可在代码块内调用 `print(...)`。只有确实需要复用另一世界书条目时才用
`getwi()`；只有确实需要扫描聊天文本时才用消息匹配功能。

### 动态提示词的正确分层

- 变量保存当前事实：好感度是 42。
- EJS 决定发送哪段提示词：42 属于熟悉阶段。
- 阶段提示词描述行为倾向：愿意交流，但仍保留私人边界。

不要把三个互斥阶段全部常驻发送，再要求模型自己选择。这会浪费 token，并增加串阶段概率。

## 7. 变量提示词测试

至少测试：

1. 新聊天最终提示词中能看到 `<status_current_variable>` 和合法初始值；
2. 更新规则与输出格式实际发送给 AI；
3. 触发一个明确事件，AI 输出合法 `<UpdateVariable>`；
4. 变量管理器中的值发生预期变化；
5. 下一回合变量列表展示新值；
6. 同一旧事件不会再次重复更新；
7. 若使用 EJS，分别设置低/中/高值检查最终展开内容，确认只出现对应阶段。

若只看世界书源文本而不检查最终提示词，无法发现宏、EJS、正则或插入位置问题。
