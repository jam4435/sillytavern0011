# 03. 脚本与状态栏

目标：只在提示词和 Schema 不足以实现需求时增加代码，并用当前仓库推荐方式读写 MVU 数据。

## 1. 先选择正确层级

| 需求                                       | 放在哪里                |
| ------------------------------------------ | ----------------------- |
| 类型校验、范围夹取、清理无效集合项         | Schema transform        |
| 根据剧情判断是否更新、更新多少             | 变量更新规则            |
| 根据变量选择发送哪段设定                   | EJS 或提示词注入 filter |
| 播放音频、改世界书、主动生成、跨系统副作用 | 酒馆助手脚本            |
| 展示变量、允许玩家编辑                     | Vue + Pinia 状态栏      |

不要用事件脚本重复实现 Schema 已能保证的数值范围，也不要为了显示一个值就写后台脚本。

## 2. 使用 Mvu 前必须等待初始化

```ts
$(async () => {
  await waitGlobalInitialized('Mvu');
  // 此后再访问 Mvu
});
```

所有事件名通过 `Mvu.events.*` 访问，不手写事件字符串。

## 3. 精确选择变量作用域

消息楼层界面或需要修改特定楼层时：

```ts
const option = {
  type: 'message' as const,
  message_id: getCurrentMessageId(),
};

const mvu_data = Mvu.getMvuData(option);
console.info(mvu_data.stat_data);
```

不要省略 `message_id` 后默认操作最新楼层；查看旧楼层时会读错数据。

`getAllVariables()` 返回全局、角色、聊天、消息变量的合并结果，适合只读条件判断：

```ts
const favor = _.get(getAllVariables(), 'stat_data.角色.络络.好感度', 0);
```

它不适合作为状态栏的精确双向数据源。

## 4. 直接读写 MVU 数据

```ts
$(async () => {
  await waitGlobalInitialized('Mvu');

  const option = { type: 'message' as const, message_id: 'latest' as const };
  const mvu_data = Mvu.getMvuData(option);

  _.set(mvu_data, 'stat_data.角色.络络.好感度', 50);
  await Mvu.replaceMvuData(mvu_data, option);
});
```

这是整表替换，修改前必须取得目标作用域的完整 `MvuData`。普通状态栏应使用 `defineMvuDataStore`，不必手写这套流程。

## 5. 监听变量事件

### 更新完成

适合处理真正的跨字段业务约束或触发副作用：

```ts
$(async () => {
  await waitGlobalInitialized('Mvu');

  eventOn(Mvu.events.VARIABLE_UPDATE_ENDED, (variables, variables_before_update) => {
    const old_favor = _.get(variables_before_update, 'stat_data.角色.络络.好感度', 0);
    const new_favor = _.get(variables, 'stat_data.角色.络络.好感度', 0);

    if (old_favor < 70 && new_favor >= 70) {
      toastr.success('已进入亲密阶段');
    }
  });
});
```

如果只是把好感度限制到 0~100，应放进 Schema transform，而不是事件。

### 命令解析完成

当前签名是三个参数：

```ts
eventOn(Mvu.events.COMMAND_PARSED, (variables, commands, message_content) => {
  commands.forEach(command => {
    command.args[0] = command.args[0].replaceAll('-', '');
  });
});
```

`command.args` 此时仍是字符串字面量。若确需手工构造旧式命令参数，数值也应写成字符串字面量，例如
`'5'`。不要照搬旧资料里的单参数 `commands => {}` 示例。

只有遇到稳定、可识别的模型输出缺陷时才修改解析命令；正常路径问题应先修正变量提示词。

## 6. 主动请求生成并解析变量

`generate()` 只返回生成结果，不会自动创建新楼层，也不会自动把其中的变量命令写入指定变量表。

```ts
$(async () => {
  await waitGlobalInitialized('Mvu');

  const option = {
    type: 'message' as const,
    message_id: getCurrentMessageId(),
  };

  const old_data = Mvu.getMvuData(option);
  const result = await generate({
    user_input: '根据当前剧情补充一段简短的环境变化，并按既定格式更新变量。',
    should_silence: true,
  });

  if (typeof result !== 'string') {
    console.warn('生成返回了工具调用结果，未解析 MVU 变量');
    return;
  }

  const new_data = await Mvu.parseMessage(result, old_data);
  if (new_data) {
    await Mvu.replaceMvuData(new_data, option);
  }
});
```

运行时没有有效更新时，`parseMessage` 可能返回 `undefined`，即使本地声明较窄也必须判空。

## 7. 按变量注入提示词的脚本方案

如果不使用 EJS，但需要在发送请求时按变量激活提示词，可使用酒馆助手注入：

```ts
$(() => {
  injectPrompts([
    {
      id: '络络-亲密阶段',
      position: 'none',
      depth: 0,
      role: 'system',
      content: '【【络络-亲密阶段】】',
      filter: () => _.get(getAllVariables(), 'stat_data.角色.络络.好感度', 0) >= 70,
      should_scan: true,
    },
  ]);
});
```

对应世界书条目用绿灯关键词接收该内容。选择 EJS 还是脚本注入，取决于目标卡现有技术栈；不要同时实现两套相同逻辑。

## 8. 状态栏标准结构

只有用户需要可视化或玩家交互时才实现：

```text
界面/状态栏/
├─ index.html
├─ index.ts
├─ store.ts
├─ App.vue
└─ global.css
```

### index.html

```html
<head></head>
<body>
  <div id="app"></div>
</body>
```

Webpack 会注入脚本和样式，不写 `<script type="module">` 或本地 `<link>`。

### store.ts

```ts
import { defineMvuDataStore } from '@util/mvu';
import { Schema } from '../../schema';

export const useDataStore = defineMvuDataStore(Schema, {
  type: 'message',
  message_id: getCurrentMessageId(),
});
```

必须传描述完整 `stat_data` 的 canonical Schema。`z.object` 默认可能剥离未知键，而 store 会整块写回解析结果；传 partial
Schema 可能删除未声明变量。

### index.ts

```ts
import { waitUntil } from 'async-wait-until';
import App from './App.vue';
import './global.css';

$(async () => {
  await waitGlobalInitialized('Mvu');
  const message_id = getCurrentMessageId();

  await waitUntil(() => _.has(getVariables({ type: 'message', message_id }), 'stat_data'));

  createApp(App).use(createPinia()).mount('#app');
});
```

显式传 `message_id`，确保每个旧楼层状态栏读取自己的变量快照。

### App.vue

```vue
<template>
  <section class="status-card">
    <p>地点：{{ store.data.世界.当前地点 }}</p>
    <p>好感度：{{ store.data.角色.络络.好感度 }}</p>
    <button type="button" :disabled="store.data.角色.络络.好感度 >= 100" @click="store.data.角色.络络.好感度 += 1">
      增加好感
    </button>
  </section>
</template>

<script setup lang="ts">
import { useDataStore } from './store';

const store = useDataStore();
</script>

<style scoped lang="scss">
.status-card {
  width: 100%;
  max-width: 720px;
  margin: 0 auto;
}
</style>
```

直接修改 `store.data` 即可触发校验和回写，不再手写 `replaceVariables`。

## 9. defineMvuDataStore 的重要行为

- 首次读取目标变量表的 `stat_data` 并执行 `schema.parse`；
- deep watch `store.data`，修改后执行校验并写回；
- 每 2 秒读取一次外部变化并同步；
- coerce/transform 的规范化结果也可能写回；
- 后续 `safeParse` 失败时会跳过同步。

因此“按钮点了但变量没保存”时，先检查修改后的完整数据是否通过 Schema。

`additional_setup`
在内部持久化 watch 之前执行。它适合安装额外 watch/computed；不要依赖其中一次性直接改值自动保存，该值可能被下一次轮询覆盖。

## 10. 状态栏接入角色卡

1. 第一条消息显式放 `<StatusPlaceHolderImpl/>`；
2. `index.yaml` 增加仅格式显示正则，把占位符替换为加载编译后 `界面/状态栏/index.html` 的代码；
3. URL 中角色卡目录名必须替换正确；
4. 没有状态栏时，不生成占位符和这条正则。

界面还应遵守本仓库 iframe 规则：

- 主体保留文档流，避免绝对定位撑脱；
- 宽度自适应，不产生横向滚动；
- 不用 `vh` 强行决定高度；
- 避免 `min-height`、大面积 `overflow: auto` 强撑消息楼层；
- 优先 Vue、Tailwind 和 `<style scoped>`。

## 11. 脚本/界面完成条件

- [ ] 访问 `Mvu` 前等待初始化。
- [ ] 精确操作消息楼层时显式传 `message_id`。
- [ ] 事件签名与当前 `ListenerType` 一致。
- [ ] 主动生成处理非字符串结果，并对 `parseMessage` 判空。
- [ ] 状态栏使用完整 Schema 和 `defineMvuDataStore`。
- [ ] `store.data` 路径不带 `stat_data`。
- [ ] 第一条消息与状态栏正则成对存在。
- [ ] 没有重复实现 Schema、规则或 EJS 已负责的逻辑。
